## 目标

按已确认的 demo 改造 Desktop 输入框：

- **外观**：低对比细边加柔和阴影；单行时是胶囊形，多行时 18px 圆角。
- **布局**：多行工具行的左侧依次是 `+`、模式 chip、模型，右侧是发送；单行时隐藏模型。
- **`+` 面板**：改成与输入框同宽、浮在输入框上方的统一卡片，带搜索、模式、文件、Skills 和模型。
- **发送队列**：从输入框内部移到输入框上方，成为独立的托盘。
- **运行位置**：新建页用文字按钮和「本机 / 远端机器 ›」菜单，替换现有的远端原生 `<select>`；对话中只显示一行只读状态。

改造过程中不改 Runtime / Host 协议，也不改队列的发送语义。

## 设计规格（实现时以此为准）

### 外观 token

`tokens.css` 新增四个变量，浅色、深色和深色 media 块（`prefers-color-scheme`）各写一份，数值见 06 §5.1：

```css
--act-color-composer-border        /* 浅 rgb(0 0 0 / .07)，深 rgb(255 255 255 / .07) */
--act-color-composer-border-focus  /* 浅 rgb(0 0 0 / .11)，深 rgb(255 255 255 / .12) */
--act-shadow-composer
--act-shadow-composer-focus
```

`tailwind.css` 中映射为 `--color-composer`、`--color-composer-focus`、`--shadow-act-composer` 和 `--shadow-act-composer-focus`，对应的类是 `border-composer`、`border-composer-focus`、`shadow-act-composer`、`shadow-act-composer-focus`。

### 布局

| | 单行（inline） | 多行（stacked） |
| --- | --- | --- |
| 形状 | `rounded-full` | `rounded-act-xl` |
| grid | `"plus mode input send"` | `"input input input input input" / "plus mode model . send"` |
| 模型按钮 | 隐藏（`hidden`，仍在 DOM 中） | 显示 |
| 输入区 | 单行 | 最高 200px，超出后在内部滚动；新建页最少 2 行 |

进入多行的条件：输入在单行宽度下溢出（沿用 `:865-922` 的测量）、文本含换行、有附件、有 Skill chip、有回复引用，以及新建页（initial）。窄窗（≤ 600px，沿用现有断点）也强制多行。

回到单行：只在输入框**完全清空**、且没有附件、Skill 和引用时。新增状态 `stuckStacked`：进入多行时置 `true`，满足清空条件时置 `false`；测量逻辑在 `stuckStacked` 为 `true` 时不再把布局降回单行。

现有 chat followup 的 inline grid（`'plus_mode_input_model_context_send'`）把 context 用量放在输入框内。改造后 context 用量统一放在状态行（见「运行位置」），grid 与 Agent 一致。

### `+` 面板

- **定位**：`ui/Popover`，`PopoverAnchor` 包住整个 panel；`side="top"`、`align="start"`、`sideOffset={8}`，宽度为 `w-(--radix-popper-anchor-width)`。上方空间不足时由 Radix 的碰撞检测翻到下方（`avoidCollisions`、`collisionPadding={8}`）。portal 到 body，不再依赖 panel 的 `overflow-visible`。
- **外观**：`rounded-act-lg`、`bg-surface-raised`、1px `border-composer`、`shadow-act-popover`。
  - 行高 28px，行圆角 8px。
  - 行内依次是图标、名称（muted，hover 时变 main）和说明（faint）；说明紧跟名称，不右对齐。
  - 选中行使用 `bg-hover-overlay`。
  - 列表最高 280px。
- **主页内容**：

```text
🔍 搜索 Skills、文件、模型…
📋 Plan   先出计划，确认后再执行          ← 只列非默认模式
💬 Chat   纯对话，不使用工具
─────────────
📎 图片与文件 / 图片                     ← 由能力决定
📖 Skills                         ›
✨ 模型    {当前模型名}              ›
```

- **模式组规则**：
  - 空会话列 Plan / Chat。
  - 已开始的 Agent 会话只列 Plan。
  - 已开始的 Chat 会话不显示模式组（沿用现有 `isChatForm` 限制）。
  - 当前已处于 Plan 时不再列 Plan。
- **搜索**：打开面板时聚焦搜索框。在模式、入口、Skills 列表和模型列表中做本地过滤，结果按组显示（例如输入 `son` 会出现模型行 Sonnet 5.5）。
- **下钻**：Skills › 和模型 › 在同一张卡片内切换页面，搜索框左侧的图标换成 `‹` 返回。
- **键盘**：
  - ↑ ↓ 循环移动；Enter / Tab 选择；→ 下钻。
  - ← 或 Backspace（搜索框为空时）返回上一级。
  - Esc 在子页时返回主页，在主页时关闭面板并把焦点还给输入框。
- **斜杠菜单**：保持独立，不并入 `+` 面板。

## 风险

| 风险 | 缓解 |
| --- | --- |
| 单行 / 多行切换导致 textarea remount，丢焦点或丢 IME 状态 | 只切 class 和 grid area，不改变 textarea 在 React 树中的位置；T3 测试断言切换前后是同一个 DOM 节点 |
| `stuckStacked` 与测量逻辑互相打架，造成闪烁 | 测量只负责「是否需要进入多行」，退出只看清空条件；两者不对同一状态双向写 |
| `+` 面板 portal 到 body 后，与 panel 的宽度、位置不同步（窗口缩放、panel 由单行变多行） | 宽度用 `--radix-popper-anchor-width`，Radix 会跟随 anchor 尺寸变化；窄窗和单行↔多行切换都列入 CDP 截图 |
| 远端 `<select>` 删除后测试大面积失败 | T13 / T18 与对应的测试改写放在同一提交；`host-feedback.test.tsx` 先改成用 role 查询 |
| readiness 与「可发送」不一致 | 只有 15 的一份判定，15 T7 的测试已强制二者等价 |
| 发送按钮着色与 `accent` 主色冲突（用户选了绿色系 accent 时，Chat 的 operational 也是绿色） | 可以接受：两者都表示「可发送」；在验收截图中检查 accent 调色板的各个选项 |
| 「Esc 两级」与 Radix 的 Esc 栈冲突 | 用 `onEscapeKeyDown` 在子页时 `preventDefault`；`composer-palette.test.tsx` 覆盖 |
| P6 拆分时打断 P1 的「textarea 不 remount」约束 | T27 保留 T3 的同一节点断言 |

**回滚**：每个 T 一个提交；P1–P4、P6 各自可以单独 revert。token 新增不影响其它组件。
