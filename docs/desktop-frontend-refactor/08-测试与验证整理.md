## 3. 改写脆弱断言

### 3.1 color-semantics 系列

现状：读取组件源码，用正则断言其中出现 / 不出现某些类名（例如「Sidebar 不得出现 `text-green`」）。问题：

- 重构时只要把类名移到常量、子组件或 `cx()` 调用里，测试就会误报或漏报。
- 它们实际想守的是「颜色只走语义 token」，这已经是 `check:frontend-tokens` 的职责。

处理：

1. 把这些规则合并进 `scripts/check-frontend-design-tokens.mjs`（扫描整个 renderer，而不是三个文件）。
2. 删除三个 `*-color-semantics` 测试。
3. 如果有组件级语义（例如「运行中的会话行显示 operational 绿点」），改为渲染组件后断言 `data-state` / `aria-*`，不断言类名。

完整类名串这类正向快照（例如 `SESSION_ROW_ACTIVE_CLASS` 的完整字符串必须存在）不再保留：它们守的是写法而不是行为。见 [12 测试整理执行计划](../exec-plans/active/20261005-desktop-frontend-refactor/12-测试整理执行计划.md) 的决策记录。

> 本节和 §3.2 已在 12 执行：
> - 脚本新增两条 TSX 规则 `palette-color-literal`、`focus-ring-legacy`，以及 CSS 块规则 `CSS_BLOCK_RULES`（按选择器精确截取块，检查禁用值与必需声明）。
> - 三个 `*-color-semantics` 测试已删除，改为 `sidebar-semantics.test.tsx`、`settings-semantics.test.tsx`（断言 `aria-current`、`role="switch"` / `aria-checked`、状态点 `data-state`）。
> - brand / warm 旧命名本来就由 `check-frontend-theme-colors.mjs` 全局拦截。

### 3.2 `file-diff-block.test.tsx` 读 CSS

`readFileSync(resolve(__dirname, "../styles/diff.css"))` 断言 CSS 文本。改为：

- 行为部分（展开 / 折叠、行号、增删标记）用 DOM 断言。
- 样式约束（如果确实需要）移到 token 检查脚本。

> 已在 12 执行：读 CSS 的用例删除，有界滚动（`max-height`、`overflow-y: auto`、`overflow-x: auto`）由 CSS 块规则 `file-diff-content-bounded-scroll` 守住。

### 3.3 手写 bridge stub
