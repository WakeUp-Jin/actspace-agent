# 05 UI 基础组件与大组件拆分

> 范围：`renderer/components/ui/*`、所有自实现的弹层 / 菜单 / 对话框，以及 SettingsPage、Sidebar、ConversationView、WorkbenchLayout、Composer 五个大组件的拆分边界。
> 目标：弹层、菜单、对话框只有一套原语，键盘与焦点行为一致；大组件按职责拆到 300–500 行以内。
> 依赖：Popover / Menu 原语是 06（运行位置菜单、`+` 面板、队列 `⋯` 菜单）的前置。
> 迁移去向：合并进 `docs/design-docs/frontend/front-基础组件封装规范.md`。

### 1.2 弹层各自实现

| 类型 | 文件 | 实现方式 |
| --- | --- | --- |
| Portal 弹层 | Sidebar（右键菜单）、ConfirmDialog、SettingsPrimitives、MermaidPreviewDialog、ResponseAnnotationCommentPopover、ResponseSelectionMenu、MessageQueueTray（`⋯` 菜单）、WorkspaceChromeControls、ReviewToolbar | 各自 `createPortal` + 手算位置 |
| 内联绝对定位 | Composer（`+`、Skills、模型、模型选项、3 个上下文选择器、Context）、ContextPopup、OpenInAppMenu、RightPanelObjectMenu、ReviewScopeMenu、ResponseAnnotationPill | `absolute` + `overflow-visible` 祖先 |
| `role="dialog"` | OpenRouterModelCatalogDialog、ContextPopup、MermaidPreviewDialog、SettingsPage、ResponseAnnotationPill、WorkspaceChromeControls、ResponseAnnotationCommentPopover、ReviewWorkspace（另有 LabPage / Sheet，将删除） | 只有 3 处用了 `useDialogFocusTrap`（OpenRouterModelCatalogDialog、ConfirmDialog、SettingsPage） |

统计：25 个文件各自监听 `Escape`；16 个文件各自 `addEventListener("mousedown" | "pointerdown")` 做点外关闭。

由此产生的问题：

- **Esc 一次关多层**：例如 Composer 菜单打开时按 Esc，Composer 的 handler 和外层（右侧面板 / 对话框）的 handler 都会响应，没有「只关最上层」的栈。
- **焦点不回收**：大部分菜单关闭后焦点丢到 `body`，键盘用户要从头 Tab。
- **对话框无焦点陷阱**：MermaidPreviewDialog、ContextPopup、ResponseAnnotationCommentPopover 等，Tab 能跑到背景。
- **定位不一致**：有的用 portal 手算位置，有的依赖祖先 `overflow-visible`（`front-workspace-git-worktree-context.md` 专门写了「选择器行必须 overflow visible」，就是在为这种实现兜底）。窄窗和滚动容器里经常被裁剪。
- **Composer 用 6 个布尔手工互斥**（`Composer.tsx:602-627`：`commandOpen`、`skillsOpen`、`modelOpen`、`modelOptionsOpen`、`contextSelectorOpen`、`contextOpen`）。每加一个菜单就要在所有打开函数里多关一个。
- **`useDialogFocusTrap` 放在 `components/settings/` 下**，看起来是 Settings 专用，其他组件不知道有它。

## 2. 原语设计

**建议基于 Radix**（已经在用 `@radix-ui/react-tooltip` 和 hover-card）：Popover、DropdownMenu、Dialog、Select 都由它提供可访问性、焦点管理、Esc 栈和碰撞检测。我们只做样式封装，不自己写定位。

### 2.1 组件清单

```text
components/ui/
  Button.tsx  IconButton.tsx  Tooltip.tsx  HoverCard.tsx     (保留)
  Popover.tsx          ← Radix Popover；Composer 的 Context、模型选项
  Menu.tsx             ← Radix DropdownMenu；Item / CheckboxItem / Sub / SubTrigger / Separator / Label / Shortcut
  ContextMenu.tsx      ← Radix ContextMenu；Sidebar 右键
  Dialog.tsx           ← Radix Dialog；Header / Body / Footer；size: sm | md | lg | full
  ConfirmDialog.tsx    ← 由 settings/ConfirmDialog 迁入，基于 Dialog
  CommandPalette.tsx   ← 06 的 `+` 面板：搜索框 + 分组列表 + 子菜单，基于 Popover + cmdk 式键盘导航
  Select.tsx           ← 替换剩余原生 <select>
  SearchField.tsx
  Kbd.tsx
```

### 2.2 统一行为

| 行为 | 规则 |
| --- | --- |
| Esc | 只关闭最上层；由 Radix 的 DismissableLayer 栈处理，业务代码不再监听 `Escape` 关菜单 |
| 点外关闭 | 同上，业务代码不再挂 `mousedown` |
| 焦点 | 打开时焦点进入（菜单：第一项或当前项；对话框：第一个可聚焦元素或 `initialFocus`）；关闭时回到触发器 |
| 键盘 | 菜单 ↑↓ 移动、→ 进入子菜单、← 返回、Enter / Space 选择、Home / End、字母跳转 |
| 定位 | `side` + `align` + `collisionPadding={8}`，自动翻转；portal 到 body，**不再依赖祖先 `overflow-visible`** |
| 动效 | `--motion-fast`，尊重 `prefers-reduced-motion` |
| 样式 token | `bg-surface-raised`、`border-line-subtle`、`shadow-act-popover`、`rounded-act-md`；菜单项高度 28px，行内 padding `px-2` |
| 互斥 | 同一触发区域内的多个菜单天然互斥（Radix 一次只开一个 modal 层）；Composer 不再需要 6 个布尔 |

### 2.3 Composer 浮层状态

即使用了 Radix，Composer 仍然需要知道「当前打开的是哪个面板」（比如打开 `+` 面板时隐藏斜杠提示）。改为一个枚举：

```ts
type ComposerOverlay =
  | null
  | { kind: "palette"; page: "root" | "skills" | "models" }
  | { kind: "slash" }
  | { kind: "context" }
  | { kind: "run-target"; field: "workspace" | "branch" | "location" };
```

### 2.4 按钮收口

- 289 个原生 `<button>` 分三类处理：
  1. 视觉上就是按钮 → `Button` / `IconButton`。
  2. 菜单项 / 列表行 → `Menu.Item` 或列表组件内部的 `<button>`（允许，属于原语内部）。
  3. 纯点击区域（卡片、行）→ 保留原生，但必须有 `type="button"` 和可见 focus 样式。
- `check:frontend-tokens` 增加一条：`components/` 下（`ui/` 除外）新增原生 `<button` 需要白名单注释，防止回退。

### 3.5 Composer（2479 → 约 400 + 子组件）

拆分边界见 06 §5，这里只列原则：

- 输入核心（textarea、IME、粘贴图片、附件条）与「周边」（`+` 面板、模型、运行目标、状态行、队列）分开。
- 周边各自是独立组件，通过 `ComposerContext` 读写，不再通过 38 个 prop。

## 5. 验收

- `createPortal` 只出现在 `components/ui/`。
- 业务组件中 `key === "Escape"` 只用于输入框内的行为（如取消编辑），不用于关闭弹层。
- 所有 `role="dialog"` 都来自 `ui/Dialog`。
- 单文件行数：除 Composer 核心外均 < 500 行。
- 键盘走查（Electron）：Composer `+` 面板、运行位置菜单、Sidebar 右键、Settings 对话框，全程不用鼠标可完成，关闭后焦点位置正确。
- 480px 窄窗：所有菜单不被裁剪。
