# 03 运行目标抽象：本机与远端

> 范围：`renderer/hooks/useRemoteTarget.ts`、`hooks/remoteArtifact.ts`，以及 App / Composer / WorkbenchLayout / ConversationView / Sidebar / ApprovalParts / TurnOutputArtifacts 里的远端分支；main 侧 `remote-hosts/session-router.ts`、`fixed-renderer-ipc.ts` 的分流。
> 目标：「这个会话在哪台机器上跑、能用哪些能力」变成一个类型化的值 `RunTarget`，组件只问能力，不再判断 `hostId` 或字符串前缀。
> 依赖：02 的 S4（durable 单一事实源）之后做；06 的运行位置菜单依赖本文档。
> 已拍板：D2（只有本机 / 远端机器）、D3（对话中不能切换机器）。
> 迁移去向：合并进 `docs/design-docs/frontend/front-workspace-git-worktree-context.md`（改写 Run on 一节），并在 `docs/design-docs/agent-plugin-runtime/agent-host-guide.md` 的 Desktop 部分加链接。

## 1. 现状

### 1.1 远端会话怎么被识别

main 侧（`main/remote-hosts/session-router.ts:7-16`）：

```ts
/** Transitional UI cache key; the wire always receives the original structured SessionRef. */
export function remoteSessionKey(ref: SessionRef): string {
  return `host:${Buffer.from(JSON.stringify([ref.hostId, ref.sessionId])).toString("base64url")}`;
}
export function parseRemoteSessionKey(key: string): SessionRef | null { /* 校验数组长度、类型、长度 ≤128、round-trip */ }
```

注释本身写着 **Transitional**。renderer 侧另写了一份解码（`hooks/useRemoteTarget.ts:4-7`）：

```ts
const pair = JSON.parse(new TextDecoder().decode(Uint8Array.from(atob(sessionId.slice(5).replace(/-/g, "+").replace(/_/g, "/")), c => c.charCodeAt(0))));
return { hostId: pair[0], sessionId: pair[1] };
```

- 不校验数组形状、类型、长度；与 main 的 `parseRemoteSessionKey` 行为不一致。
- 失败时 `catch { return null; }`，一个损坏的 `host:` id 会被当作**本地会话**处理（走本地 IPC、读本地工作区）。

审批另有一套前缀：`remote-approval:${hostId}:${requestId}`（`desktop-adapter.ts:54/83/90/176/251` 生成，`fixed-renderer-ipc.ts:121` 分流，`ApprovalParts.tsx:104` 用 `slice + split(":")` 再解析一次）。

### 1.4 远端 UI（`Composer.tsx:2422-2444`）

- 「会话运行位置」原生 `<select>`：本机 / 各 Host 名（离线加「· 离线」）/ 已移除时「远端 · 未连接」。
- 选中 Host 后，Workspace 和 Branch 选择器被替换为第二个原生 `<select>`「远端工作区」，选项文案是 `{name} · {path}`。
- 模型选择是第三个原生 `<select>`（`:1773`），替换掉本地的模型面板。
- 状态行（`:2241`）再显示一次 Host 名。
- 原本的 Run on 菜单（`renderContextSelector("runtime")`，`:2366-2417`）里还留着「远程 SSH · 即将推出」的禁用项。远端能力实际已经实现，所以界面上同时出现两个运行位置入口，而且两者语义冲突。

这就是「远程 UI 简直是乱来」的根源。它不是样式问题，而是**没有运行目标模型**，于是只能在每个选择器旁边各插一个 `<select>`。

## 2. 目标模型

### 2.1 类型

```ts
// renderer/target/run-target.ts

/** 会话的运行目标。新建页可编辑；有首条消息后只读（D3）。 */
export type RunTarget =
  | { kind: "local"; workspace: LocalWorkspaceRef; branch?: string; placement: "in-place" | "new-worktree" }
  | { kind: "remote"; hostId: string; workspaceId: string };

export type LocalWorkspaceRef = { workspaceId?: string; root: string };

/** 解码后的会话身份，替代所有 startsWith("host:") 判断。 */
export type SessionLocator =
  | { kind: "local"; sessionId: string }
  | { kind: "remote"; key: string; hostId: string; remoteSessionId: string };

export function locateSession(key: string): SessionLocator;   // 与 main 的 parseRemoteSessionKey 同规则；非法 host: key 抛错，不回落为本地
```

- `locateSession` 是 renderer 中**唯一**解析 `host:` 的地方。shared 包里放一份纯函数实现（base64url + 校验 + round-trip），main 和 renderer 共用，删除 `useRemoteTarget.ts:4-7` 的手写版本。
- 审批 id 同理：`locateApproval(requestId)` 返回 `{ kind: "remote"; hostId; requestId } | { kind: "local"; requestId }`。更好的做法是让审批对象本身带 `hostId` 字段，renderer 不解析 id；这需要 main 的 `desktop-adapter` 配合，见 §5 开放问题 2。

### 2.2 能力表

```ts
export type RunTargetCapabilities = {
  gitContext: boolean;        // 读 branch / worktree 状态
  branchSwitch: boolean;      // 首次发送前切分支
  newWorktree: boolean;
  review: boolean;            // Git Review 标签页与摘要
  terminal: boolean;
  workspaceChrome: boolean;   // 右上角在 Finder / 编辑器打开、环境
  browserBridge: boolean;
  localFileRead: boolean;     // 对话中点文件 → 本地读取；false 时走 Host files.reference
  attachments: "local-path" | "upload";
  modelSource: "local-providers" | "host";
};

export function capabilitiesOf(target: RunTarget["kind"]): RunTargetCapabilities;
```

| 能力 | 本机 | 远端 | 来源 |
| --- | --- | --- | --- |
| gitContext / branchSwitch / newWorktree | ✓ | ✗ | `docs/design-docs/agent-plugin-runtime/agent-host-guide.md`：远端无本地 Git Review |
| review | ✓ | ✗ | 同上；对应现在 `WorkbenchLayout:478/608/609`、`Composer:2159` |
| terminal | ✓ | ✗ | 远端无本地 Terminal |
| workspaceChrome | ✓ | ✗ | `WorkbenchLayout:733` |
| browserBridge | ✓ | ✗ | 远端无浏览器转发 |
| localFileRead | ✓ | ✗（走 Host） | `ConversationView:895`、`TurnOutputArtifacts:212` |
| attachments | local-path | upload | `Composer:1004`、`session-router.upload` |
| modelSource | local-providers | host | `Composer:654/1773` |

组件改为：

```tsx
const { capabilities } = useRunTarget();
{capabilities.review ? <ReviewSummary … /> : null}
```

能力表是**一张表**，以后远端支持 Terminal 时只改这一处。

### 2.3 就绪状态

把 `canSend: boolean` 拆成可解释的状态：

```ts
export type RunTargetReadiness =
  | { state: "ready" }
  | { state: "connecting" }
  | { state: "offline"; error?: string }
  | { state: "revoked" }
  | { state: "incompatible" }
  | { state: "removed" }                         // 会话记录里有 hostId，但 Host 已删除
  | { state: "describing" }                      // 已连接，等待 host.describe
  | { state: "describe-failed"; error: string }
  | { state: "workspace-missing" }               // 会话绑定的工作区在 Host 上不存在了
  | { state: "model-missing" };
```

- 发送按钮禁用时，tooltip / 状态行直接显示对应文案（06 有完整文案表）。
- `HostConnectionState` 已经有 connected / connecting / offline / revoked / incompatible（`docs/design-docs/agent-plugin-runtime/agent-host-guide.md`），这里直接映射，不再自造 `"· 离线"` 字符串。

### 2.4 Store 与 hook

```ts
// renderer/target/host-directory.ts —— 全局唯一的 Host 订阅
interface HostDirectory {
  list(): readonly HostEntry[];                  // HostConnection + description + describeError
  get(hostId: string): HostEntry | undefined;
  subscribe(listener: () => void): () => void;
  refresh(hostId: string): Promise<void>;        // 重新 describe
}
type HostEntry = { connection: HostConnection; description?: HostDescription; describeError?: string };

// renderer/target/use-run-target.ts
function useRunTarget(): {
  target: RunTarget;                 // 新建页：草稿目标；会话页：会话事实
  editable: boolean;                 // !sessionId || 尚无首条消息（D3）
  capabilities: RunTargetCapabilities;
  readiness: RunTargetReadiness;
  host?: HostEntry;
  setTarget(next: RunTarget): void;  // editable=false 时 no-op 并在开发态报错
};
```

- `HostDirectory` 只订阅一次 `onChanged` / `onEvent`，替换 App:1309、App:1956、`useRemoteTarget`、`ApprovalParts:110` 四处订阅（`HostConnectionsSettings` 也改用它）。
- `activate(sessionId)` 只依赖 `sessionId` 和「该会话的 Host 从未连接变成已连接」这一事件，不依赖整个 hosts 数组。
- 会话页的 `target` 来自会话 meta：本地会话取 `workspaceId / workspaceRoot / worktree`；远端会话取 locator 的 `hostId` + meta 中的 `workspaceId`。**需要** Host 的会话列表 / 会话 meta 返回 `workspaceId`，不再靠 path 反查（§5 开放问题 1）。
- 新建页的草稿 target 放在 `RunTargetContext` 中，按「上次选择」初始化（本机记 workspaceId，远端记 hostId + workspaceId），存一个 key，不按会话累积。

### 2.5 模型选择统一

当前：本地模型走 `selectedModelId` + `userPickedChatModelRef`；远端模型走 `actspace:remote-models` 的 localStorage；Composer 里两个完全不同的 UI。

目标：

```ts
type ModelCatalog = { source: "local-providers" | "host"; groups: ModelOptionGroup[]; defaultModelId?: string };
function useModelCatalog(target: RunTarget): ModelCatalog;
```

- 远端模型列表来自 `host.describe().models`，转成与本地相同的 `ModelOptionGroup`（一个分组，标题为 Host 名）。
- Composer 只有一个模型面板（06 的 `+` → 模型 ›），不再有原生 `<select>`。
- 选择记忆：会话级选择写进会话配置（`taskCommand configure`，已经在做），不再写 localStorage；新建页只记「每个 target 上次用的模型」一项。
- 删除 `actspace:remote-models`，迁移时读一次旧值作为新建页默认，然后删除 key。

### 2.6 发送路径

`App.handleSend`（`:1860-1952`）里本地 / 远端交错的逻辑改为：

```ts
interface SessionGateway {
  create(input: CreateSessionInput, target: RunTarget): Promise<SessionMeta>;
  prepareFirstTurn(target: RunTarget, input): Promise<void>;   // 本地：分支切换 / worktree；远端：no-op
  submit(locator: SessionLocator, message, options): Promise<SubmitResult>;
  attachments: AttachmentStrategy;                              // local-path | upload
}
```

- 本地与远端各一个实现，按 `target.kind` 取。
- pending submission 的存储规则只在 gateway 内决定（02 §P1-7）。
- main 侧对应：`fixed-renderer-ipc.ts:116-128` 中按前缀分流的 `handle()` 下沉为 main 的 `SessionGateway`（01 §P1-3）。两边都按 locator 分流，而不是在每个 channel 上猜前缀。

## 5. 开放问题（2026-10-05 已拍板）

本轮不改 Host / Session 协议（需要改协议的部分以后单独做、综合考虑）。

1. `workspaceId`：Host 不返回；renderer 在建会话时**本地记录** `workspaceId`。
2. 审批对象带 `hostId`：**在 main 的 `desktop-adapter` 拼审批时加上**，属于 Desktop 内部改动，renderer 不再解析审批 id。
3. Host 删除后的历史会话：保持现状「远端 · 未连接」，**不新增**「从列表移除」。
4. 远端会话的「新建工作树」：**禁用并说明原因**。
