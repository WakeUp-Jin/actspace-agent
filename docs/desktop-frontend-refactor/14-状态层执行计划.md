## 目标

- App 不再自己拼正文，会话正文只有一个事实源：durable 部分来自 `ClientSessionStore`，live 部分来自 `live-run-store`，两者由纯函数 `transcript.ts` 合并。
- 去重依据改为类型化的 `runId` / `sourceSeq`，不再解析字符串。
- 按会话存放的本地状态集中到 `SessionLocalStore`，归档或移除会话时通过 `evict` 释放。
- 修复会话列表每次变化都触发 2N 次 IPC 的问题，以及几处吞掉错误的写法。
- 本地会话与远端会话的待确认提交走同一套规则。

## 决策记录

| 日期 | 决定 | 原因 |
| --- | --- | --- |
| 2026-10-05 | S2：每个会话 id 只做一次补齐（`hydratedSessionIdsRef`）。启动时对当前列表补齐；分页新增的 id 也补齐一次；之后靠事件驱动。删除「sessions 每次变化都全量刷新」 | 修掉 2N 风暴，同时保留后台会话的审批徽标（`app-approval-recovery` 的 mount 用例依赖它）。只补齐活动会话会让侧栏徽标缺失 |
| 2026-10-05 | S4：删除 `pageCacheRef` 后，由 `ClientSessionStore` 的 cell 充当缓存，并加 LRU：活动会话、运行中的会话常驻，其余最多保留 5 个最近查看的会话 | cell 本身没有上限，不加 LRU 只是把泄漏从 ref 搬进 store；5 比原先的 3 宽松，切换会话时更少闪烁 |
| 2026-10-05 | S4：早期历史经 `R/session/session-pages.ts` 的 `loadEarlier(sessionId)` 加载：调用 `getSessionPage({ beforeSeq })` 后交给 store。如果 `applyEnvelope` 不能前插早期页，就在 `C/sessions/session.ts` 新增 `prependPage`，并在 `packages/client` 中补测试 | store 没有 `loadEarlier`；App 不走 bridge 的 `open` |
| 2026-10-05 | S5：`transcript.ts` 的验收标准是「新旧合并结果在全部现有 fixture 上一致」。没有 durable 对应物的块（steer、workspace-preparation）保持现有显示行为，不套用「runId 完成后整组让位」 | 避免 run 结束时这些块突然消失；不一致即视为设计偏差，停下 |
| 2026-10-05 | S5：`runId` 只在有 `agentRunId` 时写入；`sourceSeq` 只在事件带 seq 时写入；都用条件展开 | 减少对 `toEqual` 断言的冲击。凡是有 `agentRunId` 的块，期望值仍要统一更新 |
| 2026-10-05 | S6：`terminalRunIdsRef` 改为有界集合，只保留最近 200 个 | 有界即可；保住 `app-approval-recovery:91` |
| 2026-10-05 | S7：本计划只做 3 个 Context：`ActiveSessionContext`、`ComposerContext`、`SessionActionsContext`；`RunTargetContext` 在 15 中做。prop 数量「< 10」在 15 结束时验收 | Context 与 RunTarget 有依赖 |
| 2026-10-05 | S10：所有会话统一用 `localStorage`，key 不变；renderer 侧类型命名为 `PendingSubmissionRecord`；新增 `createdAt`，启动时清理超过 7 天的记录；恢复前先查 snapshot，查询失败时降级为恢复草稿 | 已拍板（02-1）；7 天与远端会话缓存的保留期同一量级 |
| 2026-10-05 | 目录：不新建 `features/`。新模块放在 `R/session/`，Provider 放在 `R/app/providers.tsx`，`App.tsx` 保持在原位置 | 测试都从 `../App` 导入，搬家会产生大量噪音；`features/` 的迁移另行评估（见 16） |
| 2026-10-05 | App.tsx 的行数目标：14 结束时低于 600 行，15 结束时低于 400 行，只作为目标，不作为停止条件 | 02 定的「S7 < 400 行」依赖 15 的 RunTarget |
