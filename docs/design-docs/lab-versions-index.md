# Lab 版本路线

Lab 采用渐进式构建。先让实验生命周期和证据链成立，再逐步提高 Agent 自动化程度。

## 总览

| 版本 | 名称 | 核心目标 |
|---|---|---|
| V0 | 实验矩阵 | 建立 Lab 页面和手动实验记录 |
| V1 | 辅助实验 | Agent 能辅助研究、总结和整理实验记录 |
| V2 | 沙箱锻造 | 支持受控验证、原型产物和能力锻造 |
| V3 | 自主能力研发 | Agent 能主动发现缺口并推进完整实验闭环 |

## 版本原则

- V0 不追求自动化，先把实验矩阵和数据事实做稳。
- V1 增加 Agent 辅助，但不自动执行高风险动作。
- V2 引入沙箱和产物锻造，重点做验证和安全。
- V3 才讨论更高自治，不提前把高风险能力塞进早期版本。

## V0：实验矩阵

### 目标

建立 Lab 的基本产品形态：用户可以创建实验，在四阶段矩阵中记录假说、验证、锻造和评审。

### 范围

V0 做：

- Lab 页面入口。
- 实验矩阵视图。
- 创建实验。
- 编辑四阶段记录。
- 添加证据和产物引用。
- 基础状态：draft、active、blocked、candidate、promoted、rejected、abandoned。
- 手动评审结果。

V0 不做：

- 自动执行实验。
- 真沙箱。
- 自动生成 Rust CLI。
- 自动安装或启用 skill。
- Kairos 自动创建实验。
- 主 Agent 自动使用候选能力。

### 成功标准

- 用户能把一次想法完整记录为一轮实验。
- 一行实验能清楚展示四阶段推进状态。
- 产物和证据不会只停留在聊天上下文。
- 已晋升、已拒绝、已废弃实验可以通过 `已完成实验` 弹窗查看。

## V1：辅助实验

### 目标

让 Main Agent 能辅助用户推进 Lab 实验：研究资料、梳理假说、总结证据、生成阶段记录草稿。

### 范围

V1 做：

- Main Agent 根据用户指令创建实验。
- 从当前会话总结实验草稿。
- 辅助生成假说和成功标准。
- 辅助整理验证记录。
- 辅助生成 skill / doc / learning 草稿。
- 将 Agent 生成内容标记为草稿，等待用户确认。

V1 不做：

- 自动执行高风险命令。
- 自动晋升能力。
- 自动修改主 Agent 工具集。
- Kairos 后台自主推进完整实验。

### 成功标准

- 用户可以从聊天中一键沉淀实验。
- Agent 能把零散对话整理成结构化阶段记录。
- 人类仍清楚知道哪些内容是草稿，哪些内容已确认。

## V2：沙箱锻造

### 目标

让 Lab 支持受控实验执行和能力产物锻造，尤其是 CLI、skill、脚本和内部工具候选。

### 范围

V2 做：

- Lab 专用实验工作区或沙箱目录。
- 记录命令、工具调用、日志和测试结果。
- 支持 Rust CLI 原型 scaffold。
- 支持 skill 草稿 scaffold。
- 支持产物级验证命令。
- Promotion Gate 检查证据、测试和风险说明。

V2 不做：

- 无审批默认启用 CLI 或内部工具。
- 自动下载未知依赖。
- 在没有隔离策略时运行高风险命令。
- 让 Kairos 使用未晋升能力。

### 成功标准

- 一个 CLI 或 skill 候选可以从实验中被锻造出来。
- 实验结果可以复现。
- 晋升评审能看到证据、测试、风险和使用边界。

## V3：自主能力研发

### 目标

让 Agent 能更主动地发现能力缺口，并在用户设定的边界内推进完整 Lab 实验。

### 范围

V3 做：

- Kairos 根据重复失败和重复需求建议实验。
- Main Agent 在任务中发现缺口后创建实验候选。
- Agent 自动推进低风险研究和整理。
- Agent 在沙箱中执行批准后的验证计划。
- Agent 生成候选能力和晋升报告。
- 用户在 Promotion Gate 中集中审批。

V3 不做：

- 完全无监督自我改造。
- 自动放宽权限。
- 自动把高风险产物设为默认启用。
- 绕过 evidence / review 机制。

### 成功标准

- 用户能看到 Agent 主动提出的高质量能力研发候选。
- 实验推进过程可审计。
- 通过晋升的能力能稳定改善后续 Agent 任务。
- 失败实验也能沉淀为有价值的 learning。
