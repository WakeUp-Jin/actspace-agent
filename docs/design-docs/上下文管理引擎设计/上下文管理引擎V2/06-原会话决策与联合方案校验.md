## 3. 本次发现与修正

### 刷新不能把“按需”变成重复重算

原联合稿写可见时每秒请求，虽有缓存说明，却没规定不变响应和 SQL 边界。现在补上版本令牌/notModified：同版本不重复传清单、不聚合、不估算、不读 Journal；同步中、空闲、错误分别退避，隐藏停查，最后消费者离开后批次暂停。模型 facts 变化也参与令牌，不只比较 Journal 水位。1 秒与退避数值是新提案参数，需测空闲 CPU/IPC 后校准。

### 失败不等于删库，fallback 也有运行条件

当前 `usage-read-model.ts` 的查询主路径已保留 timeout 特殊分流及 owner 退出等待。联合设计原先只概述“失败后恢复”，现明确禁止超时、取消、无效 cursor、预算错误触发重建，禁止探测不断重试终态错误。单个坏 Session/缺 codec 继续隔离，恢复后重新入索引。fallback 在 Worker 临时 SQLite 中复用正式语义，需要驱动可用；不能承诺驱动坏了仍可降级查询。

### 升级必须承担重放成本，不能借升级绕过 Bug

schema 9 是本次新增提案，当前源码仍校验 schema 8。旧 M/L 冷投影约 35/91 分钟，不能省略升级成本。方案保留按需受控重建：空表先建索引，只导入当前查询需要的范围；跨 schema 重建不能声称旧 published 可读。U-08 曾在写入前漏筛行，仅增加表或改排序不足以纠正旧结果，需回读事实。U-05 的原生长 SQL 与退出/取消仍单独复验。

同 schema 的 building/published 方案需同步覆盖 FTS、rollup、run 去重和跨批关联状态，以 Session/投影为单位发布，不能将两代累计或同时复制整个库。这属于新增设计，尚无实现或性能通过证据。

### 保留已修复的旁路，避免重新引入全量恢复

原分支已经增加 `has_pending_tasks` 轻量提示、delegation lineage 预筛选、单来源错误隔离/恢复、codecDigest 失效、跨 workspace 预算和实际 Electron Worker 探针。联合任务不能只盯 U-01–U-10 而回退这些能力。已补进 T4/T8 与验收保留清单。

U-03 的延后 workspace admission 是新方案：除了选中会话，后台恢复和任何写入也必须先校验归属；不得把 SQLite 当授权事实，也不得借启动流程创建无消费者的索引任务。
