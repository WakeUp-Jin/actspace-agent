# 渐进式披露

> 长任务里读过、产生过的文件路径怎样登记，哪些直接列给模型（活跃），哪些收进索引文件（睡眠），压缩时怎样重排。引擎本身见[上下文引擎规范](agent-context-engine.md)，压缩见[上下文压缩](agent-context-compaction.md)，工具结果的体积上限与输出文件见[工具输出与引用](../tool-system/agent-tool-output-references.md)，界面上的路径卡片见 [front-Context面板规范](../frontend/front-Context面板规范.md) §4。
>
> 策略在 `packages/context/context-disclosure/src/`，状态事件的折叠在 `packages/context/context-engine/src/state.ts`，排序与选取只有一份实现，在 `packages/util/shared/src/context-panel.ts`。

## 要解决的问题

压缩把正文换成摘要，原始材料的入口不能跟着丢；路径本身也不能无限堆在窗口里。所以引擎单独维护一张路径表：正文被压缩，不等于路径被删除。

模块只提供路径和简短说明，读不读由模型决定。披露不自动展开正文，也不替工具控制输出大小。

## 模型看到什么

| 层 | 内容 |
|---|---|
| 活跃列表 | 最多 100 个具体文件，作为一条补充（id `navigation`）列在对话末尾 |
| 睡眠索引 | 其余路径写在一个文本文件里；补充的最后一行给出这个文件的路径，模型先读索引，再读具体文件 |

- 活跃和睡眠只是「列不列出来」，文件本身没有移动或删除。活跃也不代表正文在窗口里。
- 活跃列表只收文件，不收目录。睡眠索引不占这 100 个名额，自己也不会被登记成路径。
- 列表作为补充进入消息，不改系统提示词，不改对话；内容没变就不重写（规则见[上下文引擎规范](agent-context-engine.md)「补充与临时插槽」）。
- 路径可以同时出现在工具结果和活跃列表里：前者说明那次操作，后者是持续可见的入口。列表内部按路径去重。

## 路径从哪里来

**工具结果。** 每条成功的工具结果按下表登记，其他一律不登记：

| 来源 | 登记什么 | 算不算一次读取 |
|---|---|---|
| `read_file` | 读的文件 | 算。分页读每次都算，命中「文件未变化」缓存也算 |
| `write_file`、`edit_file` | 改的文件 | 不算 |
| 任何工具声明的记录文件（子智能体 transcript、后台 Bash 日志） | 该文件和工具给的说明 | 不算 |
| 工具结果里的文本 artifact（如 Bash 超长输出的完整文件） | 该文件 | 不算 |

- 不登记 glob / grep 的命中、目录列举，也不猜 Bash 命令碰过哪些文件。
- 失败的工具结果不登记、不计数。
- 每条工具结果只处理一次，恢复重放不会重复计数；没有路径的结果也记一条空事实，会话复制后不用重新解释。
- 工具用结果里带标签的 detail 声明路径（`actspace.context.file`、`actspace.context.trace`），披露不解析工具的正文。

**压缩。** 压缩成功时再登记两类：

- **被压缩内容里提到的文件。** 用正则从被压缩的原始内容和摘要正文里提取，压缩策略也可以直接给一份清单。只扫摘要不够：摘要漏掉的路径会一起丢。模型只写摘要，不负责输出路径清单。
- **历史引用。** 指向原始 `journal.jsonl`，带上被压缩条目的精确事件序号，并写明序号不是行号。不生成摘录文件，不转成另一种格式；多次压缩合并成同一条引用，序号取并集。

**所有路径都由 Host 验证后才登记**：相对路径按会话的工作区解析，必须是存在的普通文件。正则提取的只是候选，不是文件存在的证明。

历史文件的路径由存储层提供，披露不拼存储目录；不落盘的会话没有历史引用。列出路径不等于授权：读取仍走工具自己的权限检查。

## 周期规则

读取次数按「两次成功压缩之间」的周期统计，不用整个任务的累计值。

| 事件 | 处理 |
|---|---|
| 登记新路径 | 记下加入时的周期，进入活跃；活跃超过 100 时按排序裁到 100，其余睡眠 |
| 重复登记 | 合并说明和历史序号；不加读取次数，不重置加入周期，不唤醒睡眠路径 |
| 成功读取 | 本周期读取次数加一，记下读取时间；不改活跃 / 睡眠，不重排已展示的列表 |
| 压缩成功 | 在全部路径里选出「本周期读过」或「本周期加入」的，按排序取前 100 个活跃，其余睡眠；然后读取次数清零，周期加一 |
| 压缩失败 | 不登记压缩候选，不重排，不清零，不推进周期；之前记下的读取次数保留 |

排序依次比较：本周期读取次数多的在前 → 最近读过的在前（没读过的排最后）→ 加入周期晚的在前 → 路径 id 升序。先选完再清零。

- **100 是硬上限。** 周期中途超限时只在「当前活跃 + 这次新加的」里裁，不顺便唤醒睡眠路径。
- **睡眠路径只在下一次成功压缩时才可能恢复。** 读取只计数，恢复和淘汰统一在压缩时决定；读过但排到第 101 名的仍然睡眠。
- **没有压缩就没有周期。** 上限照样生效，但不推进周期，也不唤醒。
- 排序靠代码，不让模型逐条评估路径的重要性。

例：上次压缩后 A、B、C 活跃。本周期读了 A 两次、B 一次，没读 C，压缩产生历史引用 H。压缩成功后 A、B、H 活跃，C 进睡眠索引，计数清零。之后模型从索引里找到并读了 C：C 计数为一，仍然睡眠；到下一次压缩成功、排名在前 100 内，才恢复活跃。

## 和压缩一起提交

压缩与路径重排是一件事的两半，顺序固定：

1. 候选路径分批写成状态事件并 flush（单个事件不超过 256 KiB）。
2. 压缩协调器提交四条 core 事件并 flush。
3. 披露写入「已应用」：新的活跃集合和睡眠索引，周期加一。

第 2 步之后中断，下次使用这个会话时只补第 3 步；第 2 步没成功，候选不生效。每次应用把恢复边界推进到对应的 `compaction/end`，边界之后的工具结果照常登记。

## 会话复制与 fork

路径状态随 Journal 一起复制。复制出的会话第一次使用时：

- 历史引用改指新会话自己的 `journal.jsonl`，序号不变；睡眠索引重建。
- 继承来的导航补充移除，下次请求按新状态重写。`agent_fork` 的子智能体例外：它要原样带着父会话的消息前缀才能命中 provider 缓存（见[子智能体运行规范](../collaboration/agent-subagent-runtime.md)），随后写入的新列表自己说明「以后出现的为准」。

## 文件变化与读取缓存

- 路径表只记路径、说明和最近读取时间，不存文件版本，不监听文件；没读过的路径不伪造读取时间。再读拿到的是文件当前内容。
- `read_file` 的「未变化」缓存键里有会话和对话的替换代数。压缩之后正文可能已经不在窗口里，所以压缩后第一次读同一范围会重新返回正文，不提示复用旧内容。

## 启用条件

Host 提供披露端口（校验路径、给出历史文件路径、创建和解析索引文件）时才启用，实现在 `packages/core/runtime/src/harness/context-host.ts`。没有端口时不登记路径，也没有导航补充。

披露通过三处接入，Loop 不直接引用它：压缩协调器上的钩子与状态水合、`context.assembly` 上的 `disclosure` 来源、工具结果观察者。

状态存成 `plugin/actspace.context/state` 事件，由引擎包的 Codec 校验；活跃集合超过 100 或有重复的事件会被拒绝。

## 不做

检索 Agent、让模型给路径打分、文件版本快照、自动展开目录、给内存会话伪造历史文件。
