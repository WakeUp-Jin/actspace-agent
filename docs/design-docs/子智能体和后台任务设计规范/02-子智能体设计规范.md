# 02 子智能体设计规范

更新：2026-11-04。状态：已实施（S1–S6，分支 `feat/subagent-background-redesign`），待 Electron 实机验收；与本文不同的地方见[执行过程](../../exec-runs/20261103-subagent-background-redesign/execution-process.md)。依据：[01-设计决策](01-设计决策.md) 的 L1–L4、S1–S13、Q2–Q7。外部后端见 [04](04-外部子智能体设计规范.md)，界面见 [05](05-界面与设置设计规范.md)。

## 1. 概念

| 名词 | 含义 |
|---|---|
| 子智能体 | 由主智能体创建、在自己的子会话里工作的 Agent。`agent_id` 就是子会话 ID |
| 种类 `kind` | `local`（`agent` 创建）、`fork`（`agent_fork` 创建）、`codex`、`claude-code`（外部，见 04） |
| 预设 `preset` | 只有 `local` 有：`general`、`explore` |
| 一次激活 | 子智能体的一轮工作：创建时一次，之后每次 `send_message` 让空闲的子智能体再干一轮，又是一次 |
| 状态 | `running`（有激活在跑）/ `inactive`（空闲，可续派）/ `closed`（外部子智能体结束后不能续派） |
| 子智能体树 | 主会话 + 它的直接子智能体。深度固定 1 |

## 2. 工具

主会话在 `agent` 模式下看到下面七个工具（外部后端插件开启后再多两个，见 04）。`plan` 模式只看到 `agent`、`agent_fork` 和四个管理工具 + `list_subagent_models`，子智能体的工具不会超过 `plan` 模式的工具（见 §5）。`chat` 模式没有。原来的 `explore` 工具删除。

模型可见的文字一律英文，与现有工具一致；下面给出原文。

### 2.1 `agent`

参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `description` | string，必填，1–60 字符 | `A short (3-5 word) label for the task, shown in lists and the UI.` |
| `prompt` | string，必填 | `The complete, self-contained task. The subagent does not see this conversation, so include everything it needs: goal, relevant files, constraints and what to report.` |
| `agent_preset` | `"general" \| "explore"`，默认 `general` | `general: all of your tools; it can edit files and run commands. explore: read-only (read_file, list_directory, grep, glob), for searching and reading.` |
| `background` | boolean，默认 `true` | `Run in the background and return at once (default). false waits for the result; after 30 minutes the call returns and the subagent keeps running in the background.` |
| `model` | string，可选 | `Model key from list_subagent_models. Omit to use the default subagent model.` |
| `reasoning_effort` | string，可选 | `Reasoning effort id for the chosen model, from list_subagent_models. Omit to use that model's default.` |

原参数 `task` 改名 `prompt`，不保留旧名。

工具描述：

```text
Start a subagent: a separate agent with its own context that works on a task you hand it. It runs in the background by default; this call returns its id and transcript path at once, and you are notified when it finishes. The transcript file records every step it takes; read it when you need to check how it reached its result instead of trusting the summary alone.
Subagents cannot ask the user for approval: actions that would need approval fail and the subagent reports the failure. When several writing subagents run in parallel, give each a disjoint set of files.
Use send_message to add instructions or give a finished subagent more work, interrupt_agent to stop it, list_agents to see them, list_subagent_models to choose a model. At most 10 subagents run at once.
```

后台返回：

```text
Started subagent <agent_id> (<description>) in the background.
transcript: <transcript 绝对路径>
You will be notified when it finishes. Use send_message to add instructions; do not wait for it unless you have nothing else to do.
```

同步返回（`background: false`，30 分钟内结束）：

```text
Subagent <agent_id> (<description>) <status 文字，见 §6.2>.
transcript: <transcript 绝对路径>

<最终回复，最多 8KB；截断时末尾加 "[truncated; read the transcript for the full answer]">
```

同步等满 30 分钟：返回与后台启动相同的文字，首行改为 `Subagent <agent_id> (<description>) is still running and has moved to the background (30 minute wait limit).`，之后照后台处理、完成时通知。

### 2.2 `agent_fork`

参数：`description`、`prompt`、`background`、`model`、`reasoning_effort`，含义同 `agent`；没有 `agent_preset`。`prompt` 的说明：`What the forked subagent should do. It already sees this conversation, so state only what is new.` `model` 的说明：`Model key from list_subagent_models. Omit to use the parent's model (keeps the prompt cache).`（不给时用父会话的模型和思考档位。）

工具描述：

```text
Start a subagent that inherits this conversation: it sees everything up to your last completed step in this turn (not the step that contains this call), with your tools and model, so its first request reuses this conversation's prompt cache. Use it for work that builds on the current context, such as trying an alternative, reviewing what was just done, or a side investigation, without spending this conversation's context on it. Choosing a different model loses the cache. It cannot start subagents of its own. Otherwise it behaves like agent: background by default, transcript path returned, notified when it finishes, continued with send_message.
```

返回文字同 `agent`，首行写 `Started forked subagent …`。

### 2.3 `send_message`

参数：`agent_id`（必填，`The id of another agent in your subagent tree, as shown by list_agents.`）、`message`（必填，1–20000 字符）。

描述：`Send a message to another agent in your subagent tree. A running agent receives it at its next step; an inactive agent starts a new turn with it. Returns at once.`

规则：

- 主会话可以发给自己的任何子智能体；子智能体可以发给父会话和兄弟子智能体。不能发给自己。
- 目标 `running`：写进目标会话的收件箱，下一步开头被取走（插话）。
- 目标 `inactive`：开始一次新激活（续派），计入 10 个并发上限；满了返回错误。
- 目标是父会话且父会话空闲：照后台任务通知的方式唤醒父会话。
- 目标 `closed`（外部子智能体）：返回错误 `<agent_id> is an external subagent and cannot receive messages.`
- 返回：`Message delivered to <agent_id> (running; it will see it at its next step).` 或 `… (it was inactive and has started working on it).`

收件方看到的消息：

```text
<agent_message from="<发送方 agent_id>" relation="parent|child|sibling">
<message 原文>
</agent_message>
```

### 2.4 `wait_agent`

参数：`timeout_ms`（10000–3600000，默认 30000）。描述：`Wait until new input arrives for you: a subagent's completion notice, an agent message or a user message. Returns at once when such input is already pending. Use it only when you have nothing else to do.`

返回 `Input arrived.` 或 `Timed out after <n>s with no new input.`。等到的内容由下一步开头的收件箱照常送达，不在返回值里重复。

### 2.5 `list_agents`

无参数。描述：`List your subagent tree with ids, status and transcript paths. running means it is working; inactive means it is idle and can be given more work with send_message; closed means it cannot receive messages. You are notified when a subagent finishes; do not poll this list.`

返回每行一个，父会话在第一行：

```text
<main id> [running] (you)
<agent_id> [running] general · gpt-5.5 · started 14:02 — review auth module
  transcript: <路径>
<agent_id> [inactive] fork · 2 turns — try alternative layout
  transcript: <路径>
<agent_id> [closed] codex — port parser to rust
  transcript: <原生记录路径>
```

子智能体调用时，标出 `(you)` 与 `(parent)`。这是 L2 里「运行中查询」的位置。

### 2.6 `interrupt_agent`

参数：`agent_id`。描述：`Stop a subagent's current work. Returns without waiting. A local subagent keeps its conversation and can be continued later with send_message; an external subagent stops for good.` 只有主会话有这个工具。

### 2.7 `list_subagent_models`

无参数。描述：`List the models a subagent can use, with their reasoning efforts. Call it before choosing a model or reasoning effort for agent or agent_fork.`

返回：

```text
Default subagent model: <key>（设置里选的） | follows your current model (<key>)
- <model key> — <显示名> · <连接名> · efforts: low, medium, high (default medium)
- …
```

列出设置里所有可用（已启用、连接可用）的模型。外部后端的模型不在这里列，见 04。

## 3. 模型选择

一次激活用哪个模型：

1. 调用参数 `model`（只在创建时给；续派沿用该子智能体上次的模型）。
2. 设置「子智能体默认模型」（`subagentDefaultModel`，ModelKey 或空）。
3. 空着就用父会话**当前**的模型、思考开关与档位（从 `runs.configuration(parentSessionId)` 读，不读 `request/header`）。

`reasoning_effort` 缺省时用所选模型的默认档位；走第 3 条时连档位一起跟父会话。`model` 不在可用列表里：返回错误并提示先调 `list_subagent_models`。

这项设置取代原来的 explore 用途（`taskModels.exploreModel` / `taskBindings.explore` / `explore` 路由）。旧值**不迁移**：旧值多半是便宜的探索模型，带过来会让可写的 `general` 默认跑在弱模型上；迁移时删掉旧字段，新设置为空，即跟随主智能体。

可用模型列表由新 Host 端口 `actspace.host.models.listUsableModels()` 提供（Desktop 由 `ModelStoreService.listUsableModels` 实现；CLI 只返回当前模型）。

## 4. 生命周期与事件

### 4.1 父会话事件（替换 `delegation/*`）

| 事件 | 何时写 | 字段 |
|---|---|---|
| `subagent/spawned` | 创建时一次 | `agentId`、`callId`、`kind`、`preset?`、`description`、`transcriptPath`、`createdAt`、`inheritedThroughSeq?`（fork） |
| `subagent/activation` `op: "start"` | 每次激活开始 | `agentId`、`activationId`、`trigger: "spawn" \| "message"`、`senderId?`、`callId`、`background`、`model?`、`reasoningEffort?`、`startedAt` |
| `subagent/activation` `op: "settle"` | 每次激活结束 | `agentId`、`activationId`、`status`（§6.2）、`summary`、`result?`（≤8KB）、`resultTruncated?`、`delivery: "returned" \| "notified" \| "lost"`、`endedAt` |

- `delegation/requested`、`delegation/child-terminal`、`delegation/completed` 与 `background/task` 的 `kind: "agent"` 不再写入；编解码器保留，老会话照旧读取和显示，不做转换。
- 所有子智能体状态（列表、并发计数、面板）从这三类事件投影，不另存。

### 4.2 子会话

- 头部 `lineage`：`origin: "delegation"`、`parentSessionId`、`parentCallId`、`delegationDepth: 1`；fork 另有新增可选字段 `inheritedThroughSeq`（复制到哪个 seq 为止），头部校验随之放开。
- 每次激活开始，按父会话当时的权限模式在子会话写一条 `permission/mode-set`（见 §5.2），回放时能看出它在什么模式下跑的。
- 首次激活的用户消息 = `prompt` + §7 的说明；续派的用户消息是 §2.3 的 `<agent_message>`。

### 4.3 续派（冷恢复）

子智能体空闲后 `ManagedRun` 释放。`send_message` 让它再干一轮时：

1. `store.open(childSessionId)` 重新打开（不能走 `sessions.resume`：`createLoop` 里的 `sessions.registerExternal` 遇到已打开的会话会抛错）。
2. 若上次激活没有正常结束（崩溃、退出），先用主会话同一套恢复流程补上 `turn/end`。
3. 照首次激活的路径重新 `acquireRun`：`TaskLedger.open` → `registerExternalLedger` → `submit({ continuationOf })` → `start` → `createLoop` → `runTurn`。不经过 `AgentService.submit`。
4. 工具集沿用创建时算出的那一份（保证子会话前缀稳定、命中缓存）；权限模式与授权每次重新从父会话取。

插话与续派的竞态：子智能体最后一步结束后、激活收尾前收到的消息，收尾时转成一次续派，不丢。

### 4.4 重启

- Host 打开父会话时，有 `start` 没有 `settle` 且没有活着的运行的激活，补写 `settle`，`status: "lost"`，并把通知放进父会话收件箱：`Subagent <id> (<description>) was interrupted because the app exited. Its transcript shows how far it got. Send it a message with send_message to continue it.`
- `local` / `fork` 之后仍可续派（S11）；外部子智能体变为 `closed`。

### 4.5 停止与父会话的动作

- `interrupt_agent` 或用户在「子 Agent」面板点停止：取消当前激活，`status: "interrupted"`，照常发通知。
- 用户停止父会话这一轮：同步等待中的子智能体一起被中断；后台子智能体不受影响。
- 单次激活最多 1000 步；后台激活没有时长上限（有 `interrupt_agent`），同步等待 30 分钟后转后台（§2.1）。

## 5. 能力与权限

### 5.1 工具集

| 预设 | 子智能体能用的工具 |
|---|---|
| `general` | 父会话创建时所在 Agent 模式允许的工具 ∩ 已注册的工具，去掉：`agent`、`agent_fork`、`agent_codex`、`agent_claude_code`、`interrupt_agent`、`list_subagent_models`、`task_*`、`present`、`plugin_manager`、`harness_inspect`；再加上 `send_message`、`list_agents`、`wait_agent` |
| `explore` | `read_file`、`list_directory`、`grep`、`glob` + `send_message`、`list_agents`、`wait_agent` |
| fork | 与父会话**完全相同**的工具列表（为了缓存）；上面 `general` 去掉的那些在执行时拦下，返回 `Subagents cannot use <name>.` |

- 删除现在的只读限制：`provider.ts` 里 readOnly 的抛错、内容后缀「Subagent execution boundary: only read_file…」、`createBuiltInPresets([...4 tools])`。
- 父会话在 `plan` 模式下创建的 `general` 只拿到 `plan` 模式的工具，天然只读。
- 子会话里 Bash **不转后台**：`blockMs` 不生效，命令跑完才返回，最长 10 分钟，超时杀掉并返回失败。原因是子会话没有后台任务登记表与唤醒，后台 Bash 留给主会话管理。

### 5.2 审批

- 子智能体的工具环境不带 `approvalBroker`：需要审批（`ask`）时，`auto-review` 模式下先交给替我审批；没批或在其他模式下直接失败，`APPROVAL_REQUIRED` 的结果文字改为：`This action needs the user's approval, which a subagent cannot request. Report what you need to your parent instead.`
- 权限模式跟父会话：每次激活开始时读父会话当前的 `permission/mode-set`，写进子会话（§4.2）。
- 授权跟父会话：子智能体读取父会话的会话授权（如 Bash 命令前缀授权），只读，子智能体自己不能新增授权（`sessionGrantCapability: false`）。
- 沙箱不用改：子智能体的 Bash 照常进沙箱；`full-access` 下不进。子智能体请求出沙箱（`require_escalated`）在非 `full-access` 下就是一次 `ask`，按上面直接失败。

## 6. 留痕与通知

### 6.1 子会话 transcript（L1、L2）

- 路径 `sessions-v2/<agent_id>/transcript.md`，读取免审批（现有规则）。
- 写入时机：激活开始时（还没有第一步之前）写出头部和任务消息；子会话每个 `step/end` 后重写；激活结束时再写一次。由子智能体模块调用 transcript 服务新增的 `refresh(sessionId)`（同一会话重叠请求合并为再写一次，写法照旧临时文件 + rename）。
- 进行中的轮次：有调用没结果的工具写 `→ running`（轮次结束时仍是 `→ no result recorded`）。
- 头部增加：`- Description: …`、`- Preset: general`（或 `fork` / `explore`）、`- Model: …`；续派的消息渲染为 `## Message from <发送方> [#N]`。
- 父会话 transcript 里 `agent` / `agent_fork` 那一行保持现有格式，`send_message` 一行写目标 ID。

### 6.2 完成通知

激活结束且 `background` 为真时，放进父会话收件箱（父会话空闲则唤醒）：

```text
<subagent_notification>
<agent_id>…</agent_id>
<description>…</description>
<status>completed</status>
<summary>Subagent … finished and will do no further work unless you send it more.</summary>
<transcript>…/transcript.md</transcript>
<closing_message>
…（最多 8KB）
</closing_message>
</subagent_notification>
```

| `status` | `summary` |
|---|---|
| `completed` | `Subagent <id> finished and will do no further work unless you send it more.` |
| `interrupted` | `Subagent <id> was stopped before it finished. Send it a message to continue.` |
| `failed` | `Subagent <id> failed before it finished: <错误一句话>.` |
| `max_steps` | `Subagent <id> reached the step limit before it finished.` |
| `lost` | 见 §4.4 |

- 子智能体最后一个动作是 `send_message` 给父会话时，`<closing_message>` 换成 `<note>It sent you a message just before finishing, so its closing message is omitted.</note>`（照 DSH）。
- 外部子智能体的 summary 用 `finished. It cannot receive follow-up messages.`
- 收件箱事件 `agent/inbox/spliced` 的 `source` 增加 `subagent_notification` 与 `agent_message` 两个取值（现有 `task_notification` 只留给 Bash）。

### 6.3 进入活跃路径（L4）

- `agent` / `agent_fork` 的工具结果带一条 detail：`{ label: "actspace.context.trace", value: { kind: "trace", path, description } }`，`description` 为 `Subagent transcript: <description>`。
- 上下文引擎 `observe()` 从只认读写文件工具，扩展为接受**任何工具**结果里的 `actspace.context.trace`，按未读登记。路径登记仍是事件溯源的（来自 `tool/result`），回放一致。
- 登记要求文件存在，所以 transcript 必须在工具返回之前写出（§6.1 的第一次写入）。
- 之后照现有规则：一个压缩周期内没读过就转入睡眠，睡眠索引仍能找到。

### 6.4 运行中的子智能体清单（Q3）

新上下文来源 `context-subagents`（只给主会话，与 `context-background-tasks` 同一类），有运行中的子智能体时写一段 supplement：

```text
Running subagents (this list supersedes earlier ones):
- <agent_id> · <description> · general · started 14:02 · transcript: <路径>
```

没有运行中的就不输出。压缩、重启后模型仍知道谁在跑。

## 7. 子智能体的提示词

`local` 与 fork 首次激活的任务消息末尾追加：

```text
Your final answer is delivered to your parent automatically. Your parent can read your transcript file (<transcript 路径>) to see every step you took, so your final answer only needs the conclusion and the key evidence (file paths, line numbers, command results); do not retell the process. If your last action is a message to your parent, your final answer is not delivered; put the result in that message.
You cannot ask the user anything or request approval. If you are blocked, say so in your final answer.
Other agents may be editing files at the same time; change only the files your task covers.
```

`explore` 去掉最后一句。`local` 的系统提示词照现有子智能体的做法（不注册主会话专属提示词，如会话历史提示）。

## 8. Fork

1. **边界**：在父会话当前轮里，找到包含这次 `agent_fork` 调用的那一步；边界是它之前最后一个 `step/end` 的 seq。这一步就是本轮第一步时，边界是它的 `step/start` 前一个事件。边界内所有工具调用都有结果，能拼成合法上下文。
2. **复制**：用侧边对话的 `store.fork({ parentSessionId, boundarySeq, newSessionId, createdAt, createdWith, origin })` 把 `[0..boundary]` 原样复制到子会话，seq 不变；头部写 `inheritedThroughSeq`。上下文引擎状态是事件溯源的，压缩摘要、活跃 / 睡眠路径随之继承。
3. **补齐**：复制来的前缀里当前轮没结束。在子会话追加 `turn/end`（`reason: "forked"`），再以 `prompt` + §7 说明开始子智能体自己的第一轮。
4. **保住缓存**：子会话按主会话的方式组装：同一套系统提示词来源（含主会话专属的提示词扩展）、同一份工具列表、同一个模型与思考设置（`model` 未给时）。动态 supplement（`context-subagents`、`context-background-tasks`）不给 fork；它们在请求末尾，不影响前缀。验收以「fork 首个请求与父会话边界处的请求，系统提示词、工具和消息前缀逐字节一致」为准（§10）。
5. **其余同 `local`**：深度 1、并发计数、通知、续派、transcript（跳过继承段，头部指回父会话 `[#boundary]`）。

## 9. 并发与上限

- 每个主会话同时运行的子智能体最多 10 个，数正在跑的激活（同步 + 后台、各种 `kind` 合计），空闲的不算。超出返回 `10 subagents are already running. Wait for one to finish or interrupt one.`
- 深度 1：子会话里的委派工具在执行时拦下（§5.1）。
- 结果与通知里的最终回复最多 8KB（UTF-8），全文在 transcript。

## 10. 验收

| 编号 | 场景 | 期望 |
|---|---|---|
| A1 | `agent` 默认调用 | 立即返回 id 与 transcript 路径；文件已存在且有头部；路径出现在下一次请求的活跃路径里 |
| A2 | 子智能体跑了几步时读 transcript | 看到已完成的步骤，进行中的工具是 `→ running` |

## 11. 被排除的方案

- **保留 `explore` 工具或单独的 plan 预设**：用户决定一个工具 + 预设，暂不加 plan。
- **子智能体进后台任务登记表、用 `task_*` 管理**：与 Bash 混在一起，状态与续派都对不上；S3 决定分开。
- **另写一份留痕文件**：transcript 就是留痕（L1）。
- **结构化输出、ACP**：没有调用方（S12）。
- **嵌套委派**：用户不喜欢嵌套（S9）。
- **fork 时把委派工具从工具列表里去掉**：工具列表一变就用不上父会话的缓存（Q7）。
