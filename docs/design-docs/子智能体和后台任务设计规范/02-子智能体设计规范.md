# 02 子智能体设计规范

依据 [01-设计决策](01-设计决策.md) 的 L1–L4、S1–S13 与「2026-11-12 简化」R1–R12（R 系列取代 S1、S2、S3、S11、S12 互发消息部分、Q2、Q3 的对应内容）；现行结构与边界的摘要见 [子智能体运行规范](../collaboration/agent-subagent-runtime.md)，本文保留工具与模型可见文字的逐字规范。

子智能体是主智能体的「临时上下文窗口」：做完就结束，不管理生命周期，需要时再开一个。

## 1. 概念

| 名词 | 含义 |
|---|---|
| 子智能体 | 由主智能体创建、在自己的子会话里工作的 Agent。`agent_id` 就是子会话 ID |
| 种类 `kind` | `local`（`agent` 创建）、`fork`（`agent_fork` 创建）、`codex`、`claude-code`（外部，见 04） |
| 预设 `preset` | 只有 `local` 有：`general`、`explore` |
| 激活 | 子智能体的一次工作。每个子智能体只有一次激活（`trigger: "spawn"`），不续派 |
| 状态 | `running`（激活在跑）/ `closed`（已结束，不能再给它任务或消息）。老会话里的 `inactive` 一律按已结束只读显示 |
| 同步 / 后台 | 默认同步：调用等结果。`background: true` 立即返回，后台运行并登记进后台任务登记表（§4.3） |
| 子智能体树 | 主会话 + 它的直接子智能体。深度固定 1 |

## 2. 工具

主会话在 `agent` 模式下看到下面四个子智能体工具：`agent`、`agent_fork`、`send_message`、`list_subagent_models`（外部后端插件开启后再多两个，见 04）。已转后台的子智能体用后台任务工具 `task_list`、`task_output`、`task_stop` 管理（§2.4）。`plan` 模式只看到 `agent`、`agent_fork`、`list_subagent_models` 和任务工具，子智能体的工具不会超过 `plan` 模式的工具（见 §5）。`chat` 模式没有。没有单独的 `explore` 工具，它是 `agent` 的预设。

模型可见的文字一律英文，与现有工具一致；下面给出原文（以 `packages/subagent/subagent/src/messages.ts` 为准）。

### 2.1 `agent`

参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `description` | string，必填，1–60 字符 | `A short (3-5 word) label for the task, shown in lists and the UI.` |
| `prompt` | string，必填 | `The complete, self-contained task. The subagent does not see this conversation, so include everything it needs: goal, relevant files, constraints and what to report.` |
| `agent_preset` | `"general" \| "explore"`，默认 `general` | `general: all of your tools; it can edit files and run commands. explore: read-only (read_file, list_directory, grep, glob), for searching and reading.` |
| `background` | boolean，默认 `false` | `false (default) waits for the result; after 30 minutes the call returns and the subagent keeps running in the background. true returns at once and notifies you when it finishes.` |
| `model` | string，可选 | `Model key from list_subagent_models. Omit to use the default subagent model. Match the model to the task: a cheaper, faster model for searching and reading; a stronger model for editing code or work that needs judgment.` |
| `reasoning_effort` | string，可选 | `Reasoning effort id for the chosen model, from list_subagent_models. Omit to use that model's default.` |

工具描述：

```text
Start a subagent: a separate agent with its own context that works on a task you hand it and returns its final answer. Use it as a temporary context window: it does the work, reports, and is done; for more work, start a new one. By default the call waits for the result; several agent calls in one step run in parallel. The transcript file records every step it takes; read it when you need to check how it reached its result instead of trusting the summary alone.
Subagents cannot ask the user for approval: actions that would need approval fail and the subagent reports the failure. When several writing subagents run in parallel, give each a disjoint set of files.
With background: true the call returns at once and you are notified when it finishes; it is then a background task (task_list, task_stop). Use send_message to give a running subagent information it is missing, list_subagent_models to choose a model. At most 10 subagents run at once.
```

同一步里的多个同步 `agent` 调用并行执行（工具声明 `declared-safe`）。

后台返回（`background: true`）：

```text
Started subagent <agent_id> (<description>) in the background.
transcript: <transcript 绝对路径>
You will be notified when it finishes. Use send_message only to give it information it is missing; task_stop stops it.
```

同步返回（默认，30 分钟内结束）：

```text
Subagent <agent_id> (<description>) <status 文字，见 §6.2>.
transcript: <transcript 绝对路径>

<最终回复，最多 8KB；截断时末尾加 "[truncated; read the transcript for the full answer]">
```

用户在「子 Agent」面板停止同步等待中的子智能体时，首行是 `… was stopped by the user before it finished.`。

同步等满 30 分钟：返回与后台启动相同的文字，首行改为 `Subagent <agent_id> (<description>) is still running and has moved to the background (30 minute wait limit).`，此时把它登记进后台任务登记表（§4.3），之后照后台处理、完成时通知。

### 2.2 `agent_fork`

参数：`description`、`prompt`、`background`、`model`、`reasoning_effort`，含义同 `agent`；没有 `agent_preset`。`prompt` 的说明：`What the forked subagent should do. It already sees this conversation, so state only what is new.` `model` 的说明：`Model key from list_subagent_models. Omit to use the parent's model (keeps the prompt cache).`（不给时用父会话的模型和思考档位。）

工具描述：

```text
Start a subagent that inherits this conversation: it sees everything up to your last completed step in this turn (not the step that contains this call), with your tools and model, so its first request reuses this conversation's prompt cache. Use it for work that builds on the current context, such as trying an alternative, reviewing what was just done, or a side investigation, without spending this conversation's context on it. Choosing a different model loses the cache. It cannot start subagents of its own. Otherwise it behaves like agent: waits for the result by default (background: true returns at once and notifies you), transcript path returned, done once it answers.
```

返回文字同 `agent`，首行写 `Started forked subagent …`。

### 2.3 `send_message`

参数：`agent_id`（必填，`The recipient: the agent id of a running subagent you started, or your parent's id.`）、`message`（必填，1–20000 字符）。

描述：

```text
Send a message to a running subagent you started, or, from a subagent, to your parent. It is read at the recipient's next step; a parent that is idle wakes up to read it. Returns at once. A subagent that has finished cannot receive messages; start a new one instead.
Use it to add a fact the subagent is missing or to correct a wrong goal. Do not use it to make a subagent stop, send its result now, or stop reading and start writing. There is no time limit, however the subagent looks; trust it to finish unless it needs guidance or more information.
```

规则（只有两个方向）：

- 主会话 → 自己**运行中**的子智能体（插话）：写进子会话的收件箱，下一步开头被取走。
- 子智能体 → 父会话：写进父会话收件箱；父会话空闲则唤醒。
- 兄弟之间不能互发：返回 `A subagent can only send messages to its parent.`（`SIBLING_MESSAGE_BLOCKED`）。不能发给自己（`You cannot send a message to yourself.`）。
- 目标已结束（`closed`，含激活正在收尾）：返回错误 `Subagent <agent_id> has finished and cannot receive messages. Start a new subagent if there is more to do.`（`agentFinished`，不会开新一轮）。
- 目标是外部子智能体：返回 `<agent_id> is an external subagent and cannot receive messages.`
- 目标不是自己树里的子智能体：`Unknown agent <agent_id>. Use the agent id the agent call returned, or task_list for background subagents.`
- 返回：`Message delivered to <agent_id> (running; it will see it at its next step).`；发给空闲的父会话时是 `Message delivered to <agent_id> (it was idle and will read it now).`

主会话 → 子智能体的消息，在子智能体收件箱里是（来源 `agent_message`）：

```text
<agent_message from="<发送方 agent_id>" relation="parent">
<message 原文>
</agent_message>
```

子智能体 → 父会话时 `relation="child"`。老会话里 `relation="sibling"` 的消息照常显示。

### 2.4 管理后台子智能体：`task_list`、`task_output`、`task_stop`

没有 `wait_agent`、`list_agents`、`interrupt_agent`、`task_wait`：要结果就用同步调用；要停就 `task_stop`。这三个工具属于[后台任务](../collaboration/agent-background-tasks.md)的工具插件，同时管 Bash 与后台子智能体，`taskId` 就是 `agent_id`：

- `task_list`：列出本会话的后台任务，子智能体多一行 `transcript: <路径>`。描述里说明不要轮询：完成会通知。
- `task_output`：对子智能体返回 transcript 尾部。描述写明：`For a subagent: the tail of its transcript; you rarely need this, since you are notified when it finishes and send_message gives it more information.` 不在代码里拦截读取。
- `task_stop`：`Stop a running background task: kill a Bash command or end a subagent for good. The returned status is its result; no completion notification follows. A finished task is returned as is.` 停止就是终止，不能再继续；不再发完成通知。

同步子智能体运行时父会话正在等它，不在任务清单里，也不能用 `task_stop` 停；用户可在界面停止。

### 2.5 `list_subagent_models`

无参数。描述：`List the models a subagent can use, with their reasoning efforts. Call it before choosing a model or reasoning effort for agent or agent_fork.`

返回：

```text
Default subagent model: <key>（设置里选的） | follows your current model (<key>)
- <model key> — <显示名> · <连接名> · efforts: low, medium, high (default medium)
- …
```

列出设置里所有可用（已启用、连接可用）的模型。外部后端的模型不在这里列，见 04。

## 3. 模型选择

一次激活用哪个模型：

1. 调用参数 `model`（只在创建时给）。
2. 设置「子智能体默认模型」（`subagentDefaultModel`，ModelKey 或空）。
3. 空着就用父会话**当前**的模型、思考开关与档位（从 `runs.configuration(parentSessionId)` 读，不读 `request/header`）。

`reasoning_effort` 缺省时用所选模型的默认档位；走第 3 条时连档位一起跟父会话。`model` 不在可用列表里：返回错误并提示先调 `list_subagent_models`。

这项设置取代原来的 explore 用途（`taskModels.exploreModel` / `taskBindings.explore` / `explore` 路由）。旧值**不迁移**：旧值多半是便宜的探索模型，带过来会让可写的 `general` 默认跑在弱模型上；迁移时删掉旧字段，新设置为空，即跟随主智能体。

可用模型列表由新 Host 端口 `actspace.host.models.listUsableModels()` 提供（Desktop 由 `ModelStoreService.listUsableModels` 实现；CLI 只返回当前模型）。

## 4. 生命周期与事件

### 4.1 父会话事件（替换 `delegation/*`）

| 事件 | 何时写 | 字段 |
|---|---|---|
| `subagent/spawned` | 创建时一次 | `agentId`、`callId`、`kind`、`preset?`、`description`、`transcriptPath`、`createdAt`、`inheritedThroughSeq?`（fork） |
| `subagent/activation` `op: "start"` | 激活开始（每个子智能体一次） | `agentId`、`activationId`、`trigger: "spawn"`、`callId`、`background`、`model?`、`reasoningEffort?`、`startedAt` |
| `subagent/activation` `op: "settle"` | 激活结束 | `agentId`、`activationId`、`status`（§6.2）、`summary`、`result?`（≤8KB）、`resultTruncated?`、`delivery`、`endedAt` |

`delivery`：`returned`（同步调用带回了结果）、`notified`（后台任务登记表发了完成通知）、`stopped`（`task_stop` 或用户停止，停止结果就是交付，不再通知）、`lost`（没有人被告知：退出重启、编辑重发回退）。

- 所有子智能体状态（列表、并发计数、面板）从这三类事件投影，不另存；状态只有 `running` 与 `closed`。
- 老会话：`delegation/*`、`background/task` 的 `kind: "agent"`（旧格式）、`trigger: "message"` 的激活、`delivery: "wait"`、状态 `inactive` 的子智能体，编解码器保留，只读显示（`inactive` 按已结束），不迁移。

### 4.2 子会话

- 头部 `lineage`：`origin: "delegation"`、`parentSessionId`、`parentCallId`、`delegationDepth: 1`；fork 另有新增可选字段 `inheritedThroughSeq`（复制到哪个 seq 为止），头部校验随之放开。
- 激活开始时，按父会话当时的权限模式在子会话写一条 `permission/mode-set`（见 §5.2），回放时能看出它在什么模式下跑的。
- 用户消息 = `prompt` + §7 的说明。

### 4.3 后台登记（R2）

后台子智能体（`background: true`，或同步等满 30 分钟后）登记进 `BackgroundTaskRegistry`（见[后台任务](../collaboration/agent-background-tasks.md)）：

- `kind: "agent"`，`taskId` 就是 `agent_id`；登记信息带 transcript 路径和种类标签；输出是 transcript 尾部；停止就是中断这次激活。
- 登记表负责完成通知、`task_list` / `task_output` / `task_stop`、重启后标 `lost` 并通知；子智能体管理器只负责跑子会话，不自己投递通知。登记时机在 `subagent/*` 开始事件写完之后。
- 同步调用不登记：父会话正在等它，结果由工具调用带回。

### 4.4 重启

- 登记表打开会话时对账：`kind: "agent"` 的任务有 `start` 没有 `settle` 且不在当前进程里，标 `lost`，并把通知放进父会话收件箱（不唤醒）：`Subagent <id> (<description>) was interrupted because the app exited. Its transcript shows how far it got; start a new subagent if the work still needs doing.`
- 管理器的 `recoverLost` 只给子智能体树补写 `settle`（`status: "lost"`、`delivery: "lost"`），不发通知。
- 不续派：`lost` 的子智能体不能继续，要继续就开一个新的。

### 4.5 停止与父会话的动作

- `task_stop`（后台）：登记表压掉完成通知，取消激活，`status: "interrupted"`，`delivery: "stopped"`；结果里的任务状态就是交付。
- 用户在「子 Agent」面板点停止：后台的走登记表的用户停止（`stopByUser`），模型在下一步读到 `The user stopped subagent <id> (<description>) from the app.`，不唤醒；同步的直接中断，父会话那次 `agent` 调用返回 `… was stopped by the user before it finished.`。
- 用户停止父会话这一轮：同步等待中的子智能体一起被中断；后台子智能体不受影响。
- 编辑重发回退：主会话的子智能体全部停掉，已登记的走登记表 `stop(…, "rewind")`，不发通知，`delivery: "lost"`。
- 退出应用：先关登记表（停掉后台任务，不写结果），再关管理器；退出造成的结束不写任何事件，下次启动按 §4.4 补记。
- 单次激活最多 1000 步；后台激活没有时长上限（有 `task_stop`），同步等待 30 分钟后转后台（§2.1）。

## 5. 能力与权限

### 5.1 工具集

| 预设 | 子智能体能用的工具 |
|---|---|
| `general` | 父会话创建时所在 Agent 模式允许的工具 ∩ 已注册的工具，去掉：`agent`、`agent_fork`、`agent_codex`、`agent_claude_code`、`list_subagent_models`、`task_*`、`present`、`plugin_manager`、`harness_inspect`；再加上 `send_message` |
| `explore` | `read_file`、`list_directory`、`grep`、`glob` + `send_message` |
| fork | 与父会话**完全相同**的工具列表（为了缓存）；上面 `general` 去掉的那些在执行时拦下，返回 `Subagents cannot use <name>.` |

- 父会话在 `plan` 模式下创建的 `general` 只拿到 `plan` 模式的工具，天然只读。
- 子会话里 Bash **不转后台**：`blockMs` 不生效，命令跑完才返回，最长 10 分钟，超时杀掉并返回失败。原因是后台任务只属于主会话，后台 Bash 留给主会话管理。

### 5.2 审批

- 子智能体的工具环境不带 `approvalBroker`：需要审批（`ask`）时，`auto-review` 模式下先交给替我审批；没批或在其他模式下直接失败，`APPROVAL_REQUIRED` 的结果文字改为：`This action needs the user's approval, which a subagent cannot request. Report what you need to your parent instead.`
- 权限模式跟父会话：每次激活开始时读父会话当前的 `permission/mode-set`，写进子会话（§4.2）。
- 授权跟父会话：子智能体读取父会话的会话授权（如 Bash 命令前缀授权），只读，子智能体自己不能新增授权（`sessionGrantCapability: false`）。
- 沙箱不用改：子智能体的 Bash 照常进沙箱；`full-access` 下不进。子智能体请求出沙箱（`require_escalated`）在非 `full-access` 下就是一次 `ask`，按上面直接失败。

## 6. 留痕与通知

### 6.1 子会话 transcript（L1、L2）

- 路径 `sessions-v2/<agent_id>/transcript.md`，读取免审批（现有规则）。
- 写入时机：激活开始时（还没有第一步之前）写出头部和任务消息；子会话每个 `step/end` 后重写；激活结束时再写一次。由子智能体模块调用 transcript 服务新增的 `refresh(sessionId)`（同一会话重叠请求合并为再写一次，写法照旧临时文件 + rename）。
- 进行中的轮次：有调用没结果的工具写 `→ running`（轮次结束时仍是 `→ no result recorded`）。
- 头部增加：`- Description: …`、`- Preset: general`（或 `fork` / `explore`）、`- Model: …`；收到的消息渲染为 `## Message from <发送方> [#N]`。
- 父会话 transcript 里 `agent` / `agent_fork` 那一行保持现有格式，`send_message` 一行写目标 ID。

### 6.2 完成通知

同步调用的结果由工具调用带回（§2.1）。后台子智能体的激活结束时，由后台任务登记表放进父会话收件箱（来源 `task_notification`，通知类型 `subagent`；父会话空闲则唤醒），格式与 Bash 共用 `<task_notification>`：

```text
<task_notification>
<task_id>…</task_id>
<kind>agent</kind>
<description>…</description>
<status>completed</status>
<summary>Subagent … finished.</summary>
<transcript>…/transcript.md</transcript>
<closing_message>
…（最多 8KB，原文不转义）
</closing_message>
</task_notification>
```

| `status` | `summary` |
|---|---|
| `completed` | `Subagent <id> finished.` |
| `interrupted` | `Subagent <id> was stopped before it finished.` |
| `failed` | `Subagent <id> failed before it finished: <错误一句话>.` |
| `max_steps` | `Subagent <id> reached the step limit before it finished.` |
| `lost` | 见 §4.4 |

- 子智能体最后一个动作是 `send_message` 给父会话时，`<closing_message>` 换成 `<note>It sent you a message just before finishing, so its closing message is omitted.</note>`（照 DSH）。
- 外部子智能体同样走登记表，summary 沿用上表。
- `task_stop` 与用户停止不发完成通知（§4.5）；`lost` 与 `stopped` 没有结论时不写 `<closing_message>`。
- 收件箱事件 `agent/inbox/spliced` 的 `source`：`task_notification`（后台 Bash 与后台子智能体）、`agent_message`（`send_message`）。`subagent_notification` 与 `steer` 只在老会话里读，不再写入。

### 6.3 进入活跃路径（L4）

- `agent` / `agent_fork` 的工具结果带一条 detail：`{ label: "actspace.context.trace", value: { kind: "trace", path, description } }`，`description` 为 `Subagent transcript: <description>`。
- 上下文引擎 `observe()` 从只认读写文件工具，扩展为接受**任何工具**结果里的 `actspace.context.trace`，按未读登记。路径登记仍是事件溯源的（来自 `tool/result`），回放一致。
- 登记要求文件存在，所以 transcript 必须在工具返回之前写出（§6.1 的第一次写入）。
- 之后照现有规则：一个压缩周期内没读过就转入睡眠，睡眠索引仍能找到。

### 6.4 运行中的后台子智能体清单（Q3、R10）

没有单独的子智能体清单来源（`context-subagents` 已删除）。运行中的后台子智能体和后台 Bash 一起列在 `context-background-tasks` 的清单里，只给主会话：

```text
Background tasks still running (this list supersedes earlier lists; completion notifications supersede it):
- <task_id> · agent · <description> · <种类标签> · started <本地时间> · transcript: <路径>
- <task_id> · bash · <description> · started <本地时间>
Do not start duplicates. You are notified when each one finishes; task_stop stops one.
```

同步子智能体运行时父会话正在等它，不进清单。全部结束后写 `No background tasks are running.`；从未有过后台任务则不输出。压缩、重启后模型仍知道谁在跑。

## 7. 子智能体的提示词

`local` 与 fork 的任务消息末尾追加：

```text
Your final answer is delivered to your parent automatically. Your parent can read your transcript file (<transcript 路径>) to see every step you took, so your final answer only needs the conclusion and the key evidence (file paths, line numbers, command results); do not retell the process. If your last action is a message to your parent, your final answer is not delivered; put the result in that message.
You cannot ask the user anything or request approval. If you are blocked, say so in your final answer.
Other agents may be editing files at the same time; change only the files your task covers.
```

`explore` 去掉最后一句。`local` 的系统提示词照现有子智能体的做法（不注册主会话专属提示词，如会话历史提示）。

## 8. Fork

1. **边界**：在父会话当前轮里，找到包含这次 `agent_fork` 调用的那一步；边界是它之前最后一个 `step/end` 的 seq。这一步就是本轮第一步时，边界是它的 `step/start` 前一个事件。边界内所有工具调用都有结果，能拼成合法上下文。
2. **复制**：用侧边对话的 `store.fork({ parentSessionId, boundarySeq, newSessionId, createdAt, createdWith, origin })` 把 `[0..boundary]` 原样复制到子会话，seq 不变；头部写 `inheritedThroughSeq`。上下文引擎状态是事件溯源的，压缩摘要、活跃 / 睡眠路径随之继承。
3. **补齐**：复制来的前缀里当前轮没结束。在子会话追加 `turn/end`（`reason: "forked"`），再以 `prompt` + §7 说明开始子智能体自己的第一轮。
4. **保住缓存**：子会话按主会话的方式组装：同一套系统提示词来源（含主会话专属的提示词扩展）、同一份工具列表、同一个模型与思考设置（`model` 未给时）。动态 supplement（`context-background-tasks`）不给 fork；它们在请求末尾，不影响前缀。验收以「fork 首个请求与父会话边界处的请求，系统提示词、工具和消息前缀逐字节一致」为准（§10）。
5. **其余同 `local`**：深度 1、并发计数、通知、transcript（跳过继承段，头部指回父会话 `[#boundary]`）。

## 9. 并发与上限

并发上限按种类分开（R9）：每个主会话最多 **10 个**正在运行的子智能体（同步加后台、含外部），超出返回 `10 subagents are already running. Wait for one to finish, or stop a background one with task_stop.`；后台 Bash 最多 **5 个**（见 [03](03-后台Bash设计规范.md)）。深度固定 1；结果与通知里的最终回复最多 8KB（UTF-8），全文在 transcript。口径见[运行规范](../collaboration/agent-subagent-runtime.md)「能力与权限」。

## 10. 验收

| 编号 | 场景 | 期望 |
|---|---|---|
| A1 | `agent` 默认调用 | 同步等结果，返回最终回复与 transcript 路径；文件已存在且有头部；路径出现在下一次请求的活跃路径里；同一步里多个调用并行 |
| A2 | 子智能体跑了几步时读 transcript | 看到已完成的步骤，进行中的工具是 `→ running` |
| A3 | `background: true` 完成 | 立即返回 id 与路径；登记表发 `<task_notification>`（`<kind>agent</kind>`），带路径与结论；父空闲时被唤醒 |
| A4 | 同步等满 30 分钟 | 返回转后台说明，登记进登记表，之后照后台处理 |
| A5 | `general` 改文件、跑命令 | 工作区内写入成功；需要审批的命令直接失败并在结果里说明，不弹窗 |
| A6 | 插话 | 运行中 `send_message` 在下一步生效；发给已结束的返回 `agentFinished` 错误，不开新一轮 |
| A7 | 重启 | 运行中退出 → 重开收到 lost 通知，子智能体树补 `lost`；不能续 |
| A8 | 第 11 个 | 返回上限错误 |
| A9 | 模型 | 不设默认时跟父会话当前模型；设了用设置；`model` 参数优先；`list_subagent_models` 列出可用模型 |
| A10 | fork 缓存 | 首个请求的系统提示词、工具、消息前缀与父会话一致（测试比对）；真实模型上缓存命中 |
| A11 | 兄弟互发 | 返回 `SIBLING_MESSAGE_BLOCKED`；发给父会话能唤醒空闲的父会话 |
| A12 | `task_stop` 后台子智能体 | 激活被取消，返回任务状态，不再有完成通知；用户在面板停止则模型下一步读到用户停止的说明 |
| A13 | 编辑重发 | 子智能体停掉，不发通知 |
| A14 | 老会话 | 带 `delegation/*`、`subagent_notification`、`trigger: "message"`、`inactive` 的老会话仍能打开和显示（空闲的按已结束） |

## 11. 被排除的方案

- **保留 `explore` 工具或单独的 plan 预设**：用户决定一个工具 + 预设，暂不加 plan。
- **续派、`wait_agent`、`list_agents`、`interrupt_agent`、`task_wait`**：子智能体是临时上下文窗口，不管生命周期（R3、R4）。
- **在代码里拦 `task_output` 读子智能体**：太严，描述约束就够（R8）。
- **另写一份留痕文件**：transcript 就是留痕（L1）。
- **结构化输出、ACP**：没有调用方（S12）。
- **嵌套委派**：用户不喜欢嵌套（S9）。
- **fork 时把委派工具从工具列表里去掉**：工具列表一变就用不上父会话的缓存（Q7）。
