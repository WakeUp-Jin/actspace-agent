# 05 界面与设置设计规范

更新：2026-11-04。状态：已实施（S1–S6，分支 `feat/subagent-background-redesign`），待 Electron 实机验收；与本文不同的地方见[执行过程](../../exec-runs/20261103-subagent-background-redesign/execution-process.md)。只改造现有界面，复用现有组件和样式（`AgentRunBlock`、`BackgroundTag`、`BackgroundNoticeRow`、`SubagentsPanel`、设置的 `SettingGroup` 等），不引入新的视觉元素；实施中如果确实需要新的视觉元素，先做 HTML demo 给用户看。

## 1. 对话区

| 位置 | 变化 |
|---|---|
| `agent` / `agent_fork` / `agent_codex` / `agent_claude_code` 卡片（`AgentRunBlock`） | 种类文字从「Agent / Explore」改为：通用、探索、Fork、Codex、Claude Code；标题用 `description`，没有时退回任务首行；模型名照旧；后台运行显示「后台」标签。点卡片打开右侧「子 Agent」并选中这个子智能体 |
| `send_message` | 一行工具行：「发消息给 ‹描述›」，展开看消息原文；点目标名打开该子智能体 |
| `wait_agent` / `list_agents` / `list_subagent_models` | 一行工具行：「等待子智能体」「查看子智能体」「查看可选模型」 |
| `interrupt_agent` | 一行工具行：「停止 ‹描述›」 |
| 子智能体完成通知（收件箱 `subagent_notification`） | 复用 `BackgroundNoticeRow`：「子智能体 ‹描述› 已完成 / 已中断 / 失败 / 中断（应用退出）」，展开看结论；点击打开该子智能体 |
| 子智能体发来的消息（`agent_message`） | 同一种行：「‹描述› 发来消息」，展开看原文 |
| Bash 后台通知 | 不变；`taskKind` 只剩 bash |
| 通知行的位置（2026-11-04 验收修复） | 收件箱里每条通知都显示一行，不看会话是否空闲：唤醒空闲会话的通知开一轮，作为该轮第一行；主会话运行中读到的通知（含退出重开后补的 lost 通知在下一轮被读到）留在这一轮里它被读到的位置，不拆轮，该轮有工具时收在过程组里。由领取事件的 `opensTurn` 区分 |

## 2. 右侧「子 Agent」面板

- 列表按**子智能体**列（一个子会话一行），不再按调用列。分「运行中 / 其他」两组，外观用 [子 Agent 列表与详情顶部栏](../frontend/front-子Agent列表与详情顶部栏.md) 的分组卡：头像、描述、最近一句（运行中「正在执行」，结束后是结果第一行），右上 token，右下状态、激活次数（>1 时显示「第 N 轮」）和最近一次激活的耗时。种类和模型不在行里，放到详情顶部栏和标题悬停提示。
- 状态文字：运行中、空闲（可续派）、已中断、失败、已结束（外部，不能续派）。
- 运行中的行有「停止」按钮，调用新 IPC `interruptSubagent(sessionId, agentId)`，效果同 `interrupt_agent`。
- 详情：
  - 通用 / 探索 / Fork：沿用对话 / 轨迹切换。Fork 只显示分出之后的部分，顶部一行「从主会话 [#N] 分出」。
  - Codex / Claude Code：只显示最终回复和原生记录路径（复制、在 Finder 中显示），不显示轨迹。
- 右侧「后台任务」面板只显示 Bash。

## 3. 设置

| 位置 | 变化 |
|---|---|
| 设置 › 模型 › 用途 | 「子 Agent 探索」一行改为「子智能体」，下拉选可用模型，第一项「跟随主智能体」（默认）。保存到 `subagentDefaultModel` |
| 设置 › 子 Agent（`SubagentSection`） | 「Explore」一组改为「子智能体」：说明两个预设（通用：和主智能体一样的工具，能改文件、跑命令，不弹审批；探索：只读）、并发上限 10，链接到模型设置 |
| 扩展 › 插件 | 新增「Codex 子智能体」「Claude Code 子智能体」两个插件，默认关闭；说明它们用本机 CLI 和 CLI 自己的权限；没装 CLI 时显示不可用原因；插件设置见 [04 §4](04-外部子智能体设计规范.md) |

## 4. 其他界面

- 轨迹（`TrajectoryView` 及 `subagents.ts`、`RecordOverview`、`DetailPanel`）：父轨迹里委派一行按新事件取种类、描述与子会话；`send_message` 续派在父轨迹里也是一行，指向同一个子会话。
- 设置 › Harness 统计 › 运行（`RuntimeTab`）：子智能体按种类 / 预设统计次数与耗时，数据来自 `subagent/activation`。
- Web 客户端（`apps/web` 的 `EventRow`）：与桌面端同样的种类文字和通知行。
- 浏览器 mock（`?mock=`）：子智能体与后台任务的 mock 数据改为新结构，覆盖：运行中、空闲多轮、fork、Codex、已中断、lost。
