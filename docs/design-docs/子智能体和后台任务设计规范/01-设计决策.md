# 01 设计决策

逐项拍板的决策记录；设计规范见 02–05，现行结构与边界见 [子智能体运行规范](../collaboration/agent-subagent-runtime.md) 与 [后台任务](../collaboration/agent-background-tasks.md)。

## 与 DSH 的取舍

子智能体的运行模型照 DSH（默认后台、可续聊、可写、预设与模型可选、独立管理工具）；留痕是 ActSpace 补上的部分：子智能体和后台 Bash 的执行记录写进文件，并在启动、运行中、结束时把路径交给主智能体。

## 已确认

### 留痕与路径

| 编号 | 决定 |
|---|---|
| L1 | 子智能体的留痕文件就是子会话自己的 `sessions-v2/<childSessionId>/transcript.md`，不另写一份。启动时先写出带头部的文件，此后子智能体**每走完一步就增量重写**（不再等父会话一轮结束）。工具结果保持一行，每条带 `[#seq]`，需要时按 seq 回到 Journal |
| L2 | 子会话 transcript 路径在四处返回给主智能体：同步结果、后台启动返回、运行中查询、完成通知 |
| L3 | 后台 Bash 日志从临时目录移到会话目录下长期保留，跟随会话；读取免审批（同 transcript）。目录名与删除时机见「待确认 Q1」 |
| L4 | 子会话 transcript 与 Bash 日志在任务启动时注册为活跃路径，描述写明来源（如「子智能体轨迹：<任务首行>」「后台 Bash 日志：<命令>」）。沿用现有规则：一个压缩周期内没读过就转入睡眠，睡眠索引里仍能找到；不为运行中任务开特例 |

### 子智能体（参考 DSH）

| 编号 | 决定 |
|---|---|
| S1 | **默认异步**（后台运行、立即返回、完成自动通知），可以选择同步 |
| S2 | 做续聊：可以给运行中的子智能体插话，也可以给已结束的子智能体继续派活（从磁盘恢复） |
| S3 | 照 DSH 用**独立的子智能体管理工具**，与 Bash 后台任务分开；以后有必要再融合 |
| S4 | 能力照 DSH：由预设决定，可以写文件、跑命令；子智能体不弹审批，沿用父会话的沙箱与授权，越权直接失败并把失败返回给模型 |
| S5 | 一个子智能体工具 + 预设参数，取代现在的 `agent` / `explore` 两个工具。工具名保留 `agent`，参数 `agent_preset`；内置两个预设 `general`（全部工具，可写）与 `explore`（只读四件套），暂不加 `plan`；提示词要求并行的写任务分开文件范围 |
| S6 | 模型：设置里只有一项「子智能体默认模型」（取代现在的 explore 用途）。没设就跟随主智能体当前模型；Agent 可以为每次委派自己选模型 |
| S7 | 加 `description` 参数：3–5 个词的短标签，给 UI 和列表用 |
| S8 | 子智能体提示词参考 DSH，改写为「父能看到你的轨迹文件，最终回复写结论和关键证据即可」 |
| S9 | 嵌套深度保持 1，子智能体不能再委派子智能体 |
| S10 | 每会话最多 10 个运行中的子智能体；后台 Bash 任务最多 5 个（现为 8） |
| S11 | 重启后运行中的子智能体仍标为中断，但因为有了续聊，可以对它继续派活 |
| S12 | 做：继承父上下文的 fork 变体（设计见 Q7）、子智能体之间互发消息、外部后端插件 Claude Code 与 Codex。**不做**：结构化输出（没有 SDK 调用方）、ACP |
| S13 | Claude Code / Codex 子智能体：**不续聊**；**不打包**可执行文件，用用户本机安装的；**不另存留痕**，直接把它们原生的会话记录路径返回给主智能体 |

## 细节决定 Q1–Q8

### Q1 Bash 日志目录与删除时机（L3）

日志放 `sessions-v2/<sessionId>/bash-log/<id>.log`，前台命令结束即删、转后台的跟会话走、单会话合计 50MB 封顶；应用退出只删沙箱临时目录。完整规则见 [03 §1](03-后台Bash设计规范.md)。

### Q2 同步 / 异步的参数（S1）

沿用参数名 `background`，默认改为 `true`；传 `false` 时同步等待结果。

### Q3 管理工具（S3）

工具名照 DSH：`send_message`（插话 / 续派）、`wait_agent`、`list_agents`、`interrupt_agent`（停当前这轮，之后还能续派）。随之而来：

- 子智能体退出后台任务登记表，`task_*` 只管 Bash；右侧「后台任务」面板只显示 Bash，子智能体只在「子 Agent」面板。
- 子智能体完成通知改用自己的格式（DSH 的结束通知 + transcript 路径）。
- 补 DSH 的短板：每轮开头注入一份「运行中的子智能体」清单（id、标签、transcript 路径、开始时间），压缩或重启后模型仍知道谁在跑。

### Q5 列出可选模型（S6）

Agent 要自己选模型，就得知道有哪些。照 DSH 用单独的 `list_subagent_models` 工具列出设置里已启用的模型，不写进工具描述（模型列表变化会改动工具描述，破坏 prompt cache）。

### Q6 并发计数（S10）

「10 个」只数正在运行的子智能体（同步 + 异步合计），已结束但可续派的不算。

### Q7 Fork

DSH 的做法（其 `subagent-fork-in-process` 包，外部参考仓库）：

- 种子是父会话日志里**到最后一个 `turn/end` 为止**的事件，正在进行的这一轮不含（里面有还没结果的工具调用，拼不成合法会话）。
- 种子在创建时截一次，写进子会话自己的日志；之后父会话的新内容不再进来，续聊时重放的是这份种子。
- 子会话记录 `inheritedEventCount`，统计、结果、目录投影只算子智能体自己的部分。
- 不能选预设，沿用父的工具组合；工具描述换一套措辞：「它已经看到本会话已完成的轮次，只需写新的内容」。
- 灵性所在：子智能体的开头就是父会话的原样前缀，系统提示词、工具、模型都相同，第一次请求能直接命中父会话的 prompt cache，继承上下文几乎不花钱。

ActSpace 的做法：复用侧边对话的复制机制按边界复制父会话 Journal；边界比 DSH 往前多走一步，切在当前轮最后一个完整步骤；fork 与父会话用同一份系统提示词、工具列表和默认模型以保住 prompt cache，深度限制在运行时拦截而不是删工具；单独工具 `agent_fork`，没有 `agent_preset`。细节见 [02 §8](02-子智能体设计规范.md)。

### Q8 Claude Code / Codex 的细节（S13）

- **原生记录路径**：
  - Codex：经 `codex app-server` 开**非临时**线程（DSH 用的是临时线程，不留记录），记录在 `~/.codex/sessions/YYYY/MM/DD/rollout-…-<threadId>.jsonl`，实现时以 app-server 返回的路径为准。
  - Claude Code：记录在 `~/.claude/projects/<编码后的 cwd>/<session_id>.jsonl`，`session_id` 从流式输出里拿。
- **代价**：两者都是 JSONL，单行可能很长，读文件工具按行截断，模型读起来不如 `transcript.md` 顺；「子 Agent」面板里外部子智能体只显示结果，不显示轨迹。用户接受。
- **读取权限**：这两个文件在工作区外，只对这两个具体文件免审批（不是整个目录）。
- **调用方式**：Codex 用 `codex app-server`（JSON-RPC over stdio）；Claude Code 用 `claude -p --output-format stream-json`，不引入新的 npm 依赖。
- **权限模式**：照 DSH 默认，Codex `approvalPolicy: never`，Claude Code `dontAsk`（没授权的操作直接拒绝，不弹）；在插件设置里可改。
- **形态**：可选插件，扩展 › 插件 中开启，默认关闭；本机没装对应 CLI 时插件不可用并提示。

## 2026-11-12 简化：子智能体是临时上下文窗口

用户对照自己的《Agent 的子智能体开发详解》重新拍板，把子智能体定位为主智能体的「临时上下文窗口」：做完就结束，不管理生命周期，需要时再开一个。下表**取代**上面 S1、S2、S3、S11、S12（互发消息部分）、Q2、Q3 的对应内容；fork、外部子智能体、预设、留痕、并发上限不变。

| 编号 | 决定 |
|---|---|
| R1 | `agent` / `agent_fork` / 外部子智能体的 `background` 默认 **`false`**（同步）。同一步里的多个同步调用照常并行（工具声明 `declared-safe`）。同步等满 30 分钟仍转后台，和 Bash 超时转后台同一思路 |
| R2 | 后台子智能体**登记进后台任务登记表**，种类 `kind: "agent"`，`taskId` 就是 `agent_id`。登记表统一负责完成通知、重启后标 `lost`、`task_list` / `task_output` / `task_stop`。子智能体管理器只负责跑子会话。以后的生图、workflow 也按同样方式接入 |
| R3 | 删除 `wait_agent` 与 `task_wait`。需要等结果就用同步调用 |
| R4 | **不续派**：一次子智能体只有一次激活，结束即 `closed`；停止就是终止；重启后标 `lost` 只通知、不能继续。删除 `list_agents`、`interrupt_agent`，由 `task_list`、`task_stop` 替代 |
| R5 | `send_message` 只有两个方向：主会话发给自己**运行中**的子智能体（插话），子智能体发给父会话（父会话空闲时唤醒）。兄弟之间不能互发；发给已结束的子智能体返回错误，提示开一个新的 |
| R6 | `send_message` 描述写明用法约束（参考 grok-build）：只用来补充事实或纠正目标；不要用来催它停下、马上交结果或别读了开始写；没有时间限制，信任它跑完 |
| R7 | `agent` 的 `model` 参数说明加选模型引导：检索、阅读用便宜快的模型，编辑和需要判断的任务用强模型 |
| R8 | 完成通知统一成 `<task_notification>`，`<kind>agent</kind>`，带 `<transcript>` 与 `<closing_message>`；收件箱 `source` 用 `task_notification`。`task_output` 对子智能体返回 transcript 尾部；描述里说明子智能体一般不需要它（结束会通知，补充信息用 `send_message`），不在代码里硬拦 |
| R9 | 并发上限按种类分开：后台 Bash 5 个，子智能体 10 个（同步 + 后台合计） |
| R10 | 「运行中的子智能体」清单并入「后台任务」清单（`context-subagents` 删除），后台子智能体在清单里带 transcript 路径；同步子智能体运行时父会话正在等它，不进清单 |
| R11 | 界面保留两个面板：「后台任务」只列 Bash，「子 Agent」列全部子智能体。「子 Agent」面板的停止按钮：后台的走登记表的用户停止，同步的直接中断 |
| R12 | 老会话：已经是 `inactive` 的子智能体一律按已结束只读展示；`trigger: "message"`、`subagent_notification`、`delivery: "wait"` 等老事件照常读取，不迁移 |

被排除：在代码里硬拦 `task_output` 读子智能体（太严，描述约束就够）；合并两个界面面板（子 Agent 面板要看轨迹，和 Bash 输出差别大）。
