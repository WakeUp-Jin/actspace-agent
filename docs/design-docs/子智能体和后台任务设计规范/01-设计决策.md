# 01 设计决策

更新：2026-11-03。状态：全部决策已由用户确认（「已确认」与「细节决定 Q1–Q8」两节）；设计规范见 02–05。

## 现状与 DSH 的差别（调研结论）

| 方面 | ActSpace 现在 | DSH |
|---|---|---|
| 调用模式 | 默认同步，`background: true` 转后台 | 一律后台，立即返回子智能体 id |
| 续聊 | 一次性，结束即止 | `send_message` 给运行中的插话、给已结束的续派（从磁盘冷恢复） |
| 管理工具 | 与 Bash 共用 `task_list / task_output / task_stop / task_wait` | 独立的 `send_message / wait_agent / list_agents / interrupt_agent` |
| 能力 | 只读四件套（read_file、list_directory、grep、glob） | 由预设决定，可写可跑命令；审批固定为不弹，沿用父的沙箱与授权 |
| 预设 | 两个工具 `agent` / `explore` | 一个工具 + `agent_preset` 参数 |
| 模型 | 固定，走设置里的 explore 用途 | 默认父会话当前模型，可由模型选 provider / model / effort |
| 嵌套 | 1 | 默认 1，可配置 |
| 留痕 | 后台模式只返回 `child_session_id`；子会话 `transcript.md` 要等父会话一轮结束才写 | 只返回子智能体 id，从不给路径或过程 |
| 后台 Bash 日志 | 启动时返回 `output_path`，但文件在临时目录 `bash-v2/`，Harness 卸载即删；完成通知不带路径 | 启动只返回 job id；只有内存环形缓冲丢了数据时才露出文件路径 |

结论：子智能体的运行模型照 DSH；留痕是 DSH 也没做好的部分，由 ActSpace 补上。

### Bash 输出文件现状（2026-11-03 核对 `packages/shell/tool-shell/src/node-ports.ts`）

- **每一次** Bash 调用（前台、后台都算）启动时都会在 `<tmpRoot>/bash-v2/<随机目录>/<uuid>.log` 建一个文件，stdout / stderr 全部追加写入，上限 5MB。
- 前台命令在 `blockMs` 内结束：结果内联最多 8000 字；超出时把整个 `.log` **复制**成会话 artifact，存在 `sessions-v2/<id>/artifacts/`，标签「Full Bash output」。这份已经长期保存，也已经通过 `text/*` artifact 进入活跃路径。
- 超过 `blockMs` 或 `blockMs=0`：转后台，返回 `output_path` 指向那个 `.log`。
- 临时目录里的 `.log` **从不单个删除**，只在 Harness 卸载（应用退出、Harness 重载）时整个目录删掉。前台的 `.log` 用完后一直留到那时；后台日志也会跟着一起没了。

## 已确认

### 留痕与路径

| 编号 | 决定 |
|---|---|
| L1 | 子智能体的留痕文件就是子会话自己的 `sessions-v2/<childSessionId>/transcript.md`，不另写一份。启动时先写出带头部的文件，此后子智能体**每走完一步就增量重写**（不再等父会话一轮结束）。工具结果保持一行，每条带 `[#seq]`，需要时按 seq 回到 Journal |
| L2 | 子会话 transcript 路径在四处返回给主智能体：同步结果、后台启动返回、运行中查询、完成通知 |
| L3 | 后台 Bash 日志从临时目录移到会话目录下长期保留，跟随会话；读取免审批（同 transcript）。目录名与删除时机见「待确认 Q1」 |
| L4 | 子会话 transcript 与 Bash 日志在任务启动时注册为活跃路径，描述写明来源（如「子智能体轨迹：<任务首行>」「后台 Bash 日志：<命令>」）。沿用现有规则：一个压缩周期内没读过就转入睡眠，睡眠索引里仍能找到；不为运行中任务开特例 |

### 子智能体（参考 DSH）

| 编号 | 决定 |
|---|---|
| S1 | **默认异步**（后台运行、立即返回、完成自动通知），可以选择同步 |
| S2 | 做续聊：可以给运行中的子智能体插话，也可以给已结束的子智能体继续派活（从磁盘恢复） |
| S3 | 照 DSH 用**独立的子智能体管理工具**，与 Bash 后台任务分开；以后有必要再融合 |
| S4 | 能力照 DSH：由预设决定，可以写文件、跑命令；子智能体不弹审批，沿用父会话的沙箱与授权，越权直接失败并把失败返回给模型 |
| S5 | 一个子智能体工具 + 预设参数，取代现在的 `agent` / `explore` 两个工具。工具名保留 `agent`，参数 `agent_preset`；内置两个预设 `general`（全部工具，可写）与 `explore`（只读四件套），暂不加 `plan`；提示词要求并行的写任务分开文件范围 |
| S6 | 模型：设置里只有一项「子智能体默认模型」（取代现在的 explore 用途）。没设就跟随主智能体当前模型；Agent 可以为每次委派自己选模型 |
| S7 | 加 `description` 参数：3–5 个词的短标签，给 UI 和列表用 |
| S8 | 子智能体提示词参考 DSH，改写为「父能看到你的轨迹文件，最终回复写结论和关键证据即可」 |
| S9 | 嵌套深度保持 1，子智能体不能再委派子智能体 |
| S10 | 每会话最多 10 个运行中的子智能体；后台 Bash 任务最多 5 个（现为 8） |
| S11 | 重启后运行中的子智能体仍标为中断，但因为有了续聊，可以对它继续派活 |
| S12 | 做：继承父上下文的 fork 变体（设计见 Q7）、子智能体之间互发消息、外部后端插件 Claude Code 与 Codex。**不做**：结构化输出（没有 SDK 调用方）、ACP |
| S13 | Claude Code / Codex 子智能体：**不续聊**；**不打包**可执行文件，用用户本机安装的；**不另存留痕**，直接把它们原生的会话记录路径返回给主智能体 |

### 后台 Bash（参考 DSH）

| 编号 | 决定 |
|---|---|
| B1 | 借 DSH 的增量读：`task_output` 增加 `since`（偏移量）参数，只返回该位置之后的新输出 |
| B2 | 超时自动转后台、完成通知内联输出、通知去重，我们已有，保持不变 |

## 细节决定 Q1–Q8（2026-11-03 用户全部认同）

### Q1 Bash 日志目录与删除时机（L3）

目录用 **`sessions-v2/<sessionId>/bash-log/<id>.log`**，不要 `tasks/` 这一层：文件在命令启动时就建好，那时还不知道会不会转后台；`<id>` 用启动时分配的 `bash_<uuid>`，转后台后它就是 `taskId`。子智能体自己跑的 Bash，日志在子会话目录下。

删除时机：

| 情况 | 处理 |
|---|---|
| 前台命令在 `blockMs` 内结束 | 结果生成后**立即删掉**这个 `.log`。超长的完整输出已经复制成 artifact，不受影响 |
| 转了后台的命令 | 日志就是留痕，跟会话一起保留 |
| 删除会话 | 整个会话目录一起删 |
| 单文件 | 沿用 5MB 上限，超出后不再写入并在末尾标注 |
| 单会话合计 | 超过 50MB 时，从最早**已结束**的后台日志开始删，运行中的不删；被删的日志在 transcript 和 `task_output` 里注明「日志已清理」 |

前台超长输出继续留在 `artifacts/`，不搬到 `bash-log/`：它已经长期保存、已经进活跃路径，搬了反而要改 artifact 链路。

**应用退出时的清理**：

- 现在 Harness 卸载（应用退出、Harness 重载）会删掉整个 `bash-v2/<随机目录>`。里面有两样东西：所有 Bash 的 `.log`，以及沙箱里命令的临时目录（沙箱命令的 `TMPDIR` 指向这里）。所以今天退出应用、明天打开继续聊，后台日志的路径就失效了。
- 改造后 `.log` 都在会话目录，退出时不再碰它们；退出时只删沙箱临时目录（纯一次性文件），会话继续不受影响。Journal、transcript、artifact、`bash-log/` 都在会话目录里。
- 退出时还在跑的命令会被杀掉，日志保留；重开会话时后台任务照旧标为 `lost`，日志仍可读，模型能看到它跑到哪一步。前台命令被打断留下的日志同样保留，计入单会话 50MB 上限。
- 应用崩溃时来不及清理：启动时扫一遍，删掉不属于当前进程、且超过 1 天的沙箱临时目录。

### Q2 同步 / 异步的参数（S1）

沿用参数名 `background`，默认改为 `true`；传 `false` 时同步等待结果。

### Q3 管理工具（S3）

工具名照 DSH：`send_message`（插话 / 续派）、`wait_agent`、`list_agents`、`interrupt_agent`（停当前这轮，之后还能续派）。随之而来：

- 子智能体退出后台任务登记表，`task_*` 只管 Bash；右侧「后台任务」面板只显示 Bash，子智能体只在「子 Agent」面板。
- 子智能体完成通知改用自己的格式（DSH 的结束通知 + transcript 路径）。
- 补 DSH 的短板：每轮开头注入一份「运行中的子智能体」清单（id、标签、transcript 路径、开始时间），压缩或重启后模型仍知道谁在跑。

### Q5 列出可选模型（S6）

Agent 要自己选模型，就得知道有哪些。照 DSH 用单独的 `list_subagent_models` 工具列出设置里已启用的模型，不写进工具描述（模型列表变化会改动工具描述，破坏 prompt cache）。

### Q6 并发计数（S10）

「10 个」只数正在运行的子智能体（同步 + 异步合计），已结束但可续派的不算。

### Q7 Fork

DSH 的做法（`packages/subagent/subagent-fork-in-process`）：

- 种子是父会话日志里**到最后一个 `turn/end` 为止**的事件，正在进行的这一轮不含（里面有还没结果的工具调用，拼不成合法会话）。
- 种子在创建时截一次，写进子会话自己的日志；之后父会话的新内容不再进来，续聊时重放的是这份种子。
- 子会话记录 `inheritedEventCount`，统计、结果、目录投影只算子智能体自己的部分。
- 不能选预设，沿用父的工具组合；工具描述换一套措辞：「它已经看到本会话已完成的轮次，只需写新的内容」。
- 灵性所在：子智能体的开头就是父会话的原样前缀，系统提示词、工具、模型都相同，第一次请求能直接命中父会话的 prompt cache，继承上下文几乎不花钱。

ActSpace 的做法：

1. **复用侧边对话的复制机制**：按边界把父会话 Journal 事件原样复制到子会话（seq 不变），transcript 跳过继承段、头部指回父会话。上下文引擎的状态本来就是事件溯源，压缩摘要、活跃 / 睡眠路径随之继承，子智能体看到的就是父模型当时看到的上下文，而不是原始全文。
2. **边界比 DSH 往前多走一步**：DSH 不含当前这一轮，子智能体看不到用户这一轮刚提的要求。切在**当前轮里最后一个完整的步骤**（这一步的工具调用都有结果），只去掉包含 fork 调用的那一步，子智能体能看到用户本轮的要求和到目前为止的工作。
3. **保住 prompt cache**：fork 出来的子智能体与父会话用同一份系统提示词、同一份工具列表（包括 `agent` 等委派工具）、默认同一个模型。深度限制在运行时拦截，调用委派工具直接返回错误，而不是把工具从列表里去掉；委派说明写进任务消息，不改系统提示词。Agent 换模型可以，但工具描述里说明换模型就用不上缓存。
4. **单独的工具 `agent_fork`**：参数 `prompt`、`description`、`background`、`model`，没有 `agent_preset`（沿用父的工具与授权）。用单独工具是为了措辞不同，和 DSH 一致。
5. 「子 Agent」面板里标出 fork；与侧边对话的区别是：侧边对话给人用，fork 给主智能体用。

### Q8 Claude Code / Codex 的细节（S13）

- **原生记录路径**：
  - Codex：经 `codex app-server` 开**非临时**线程（DSH 用的是临时线程，不留记录），记录在 `~/.codex/sessions/YYYY/MM/DD/rollout-…-<threadId>.jsonl`，实现时以 app-server 返回的路径为准。
  - Claude Code：记录在 `~/.claude/projects/<编码后的 cwd>/<session_id>.jsonl`，`session_id` 从流式输出里拿。
- **代价**：两者都是 JSONL，单行可能很长，读文件工具按行截断，模型读起来不如 `transcript.md` 顺；「子 Agent」面板里外部子智能体只显示结果，不显示轨迹。用户接受。
- **读取权限**：这两个文件在工作区外，只对这两个具体文件免审批（不是整个目录）。
- **调用方式**：Codex 用 `codex app-server`（JSON-RPC over stdio）；Claude Code 用 `claude -p --output-format stream-json`，不引入新的 npm 依赖。
- **权限模式**：照 DSH 默认，Codex `approvalPolicy: never`，Claude Code `dontAsk`（没授权的操作直接拒绝，不弹）；在插件设置里可改。
- **形态**：可选插件，扩展 › 插件 中开启，默认关闭；本机没装对应 CLI 时插件不可用并提示。
