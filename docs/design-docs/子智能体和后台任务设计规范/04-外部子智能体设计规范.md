# 04 外部子智能体设计规范（Codex / Claude Code）

依据：[01-设计决策](01-设计决策.md) 的 S12、S13、Q8 与 R1、R2、R4、R9。

## 1. 形态

| 项 | 规则 |
|---|---|
| 插件 | 两个可选插件 `@actspace/subagent-codex`（`packages/subagent/subagent-codex`）、`@actspace/subagent-claude-code`（`packages/subagent/subagent-claude-code`）；扩展 › 插件 中开启，**默认关闭** |
| 可执行文件 | 用本机已装的 `codex` / `claude`，不打包。用登录 shell 查找（`$SHELL -lc 'command -v codex'`），因为从 Dock 启动的 Electron 拿不到终端里的 `PATH`；结果缓存到插件重载 |
| 不可用 | 找不到 CLI：插件页显示「本机没有找到 codex（或 claude）命令」，工具不注册 |
| 工具 | `agent_codex`、`agent_claude_code`，只在 `agent` 模式出现（会改文件，不进 `plan` 模式） |
| 续聊 | 不续聊：一次调用 = 一个进程 = 一轮。结束后状态 `closed`，`send_message` 返回 `<agent_id> is an external subagent and cannot receive messages.` |
| 留痕 | 不另存，返回它们原生的会话记录路径 |
| 依赖 | 不加 npm 依赖，直接起子进程 |

插件开启就是用户的授权：外部 CLI 不走 ActSpace 的审批与沙箱，用它们自己的权限设置。插件页的说明写明这一点。

## 2. 工具

参数（两者相同）：

| 参数 | 说明 |
|---|---|
| `description` | 同 `agent` |
| `prompt` | `The complete, self-contained task. It does not see this conversation.` |
| `background` | 同 `agent`，默认 `false`（同步等结果；等满 30 分钟转后台） |
| `model` | 可选，原样传给 CLI（`--model` / `thread/start.model`）；不给用 CLI 自己的默认。不列在 `list_subagent_models` 里 |

`agent_codex` 描述：

```text
Run a task with the local Codex CLI as a subagent, in this workspace. It runs once and cannot receive messages. It uses Codex's own permissions (no approval prompts) and its own model settings. You get its final message and the path of its native session log (JSONL; long lines). By default the call waits for the result; with background: true it returns at once, you are notified when it finishes, and task_stop stops it.
```

`agent_claude_code` 描述同上，把 Codex 换成 Claude Code（以 `messages.ts` 的 `externalAgentDescription` 为准）。

返回文字同 `agent`，首行 `Started Codex subagent …` / `Started Claude Code subagent …`，`transcript:` 一行给原生记录路径。

## 3. 运行方式

### 3.1 Codex

1. 启动 `codex app-server`（JSON-RPC over stdio），`cwd` 为工作区。
2. `initialize` → `initialized` → `thread/start`：`{ cwd, approvalPolicy, sandbox, model?, ephemeral: false }`。**不用临时线程**，否则没有记录文件。
3. 记录路径取 `thread/start` 返回的 `thread.path`。
4. `turn/start` 发送 `prompt`；收集 `item/completed` 里 `agentMessage` 的文字，最后一条为最终回复；`turn/completed` 结束。
5. 收到服务端发来的审批请求：一律拒绝（`approvalPolicy: never` 时不会发生；用户改了设置时防御）。
6. 停止：`turn/interrupt`，2 秒内没结束就杀进程。

### 3.2 Claude Code

1. ActSpace 先生成 `session_id`（UUID），所以启动前就知道记录路径：`~/.claude/projects/<编码后的 cwd>/<session_id>.jsonl`；编码规则与 Claude Code 一致（把路径里非字母数字的字符换成 `-`），实现时用真实运行核对。
2. 启动 `claude -p --output-format stream-json --verbose --session-id <uuid> --permission-mode <模式> [--model <model>]`，`cwd` 为工作区，`prompt` 走 stdin。
3. 读流式 JSON：`type: "result"` 的 `result` 字段为最终回复，`is_error` 决定成功失败。
4. 停止：`SIGTERM`，2 秒后 `SIGKILL`。

### 3.3 共同规则

- 返回前等记录文件出现（最多 10 秒）再返回，这样路径能登记进活跃路径；超时仍然返回路径，结果里加 `(the log file does not exist yet)`，这次不登记。
- 记录文件只对**这一个文件**免审批读取。路径记在父会话 `subagent/spawned.transcriptPath`，重启后从事件投影恢复放行名单。
- 计入每会话 10 个的并发上限；父会话事件、后台登记（后台运行时 `kind: "agent"`）、完成通知、`task_*` 管理与 [02](02-子智能体设计规范.md) 共用，子智能体 `kind` 为 `codex` / `claude-code`。
- 进程退出码非 0、流里报错、CLI 没登录：`status: "failed"`，summary 带 CLI 的错误首行（如 `Codex is not logged in. Run codex login in a terminal.`）。
- 应用退出时杀掉进程（不写结果）；重开后后台登记表标 `lost` 并通知，该子智能体 `closed`。
- 子进程环境继承用户环境（需要 CLI 自己的登录信息），不进 ActSpace 的沙箱。

## 4. 插件设置

| 插件 | 设置 | 默认 |
|---|---|---|
| Codex | 审批策略 `approvalPolicy` | `never` |
| Codex | 沙箱 `sandbox` | `workspace-write` |
| Claude Code | 权限模式 `permissionMode` | `dontAsk`（没授权的操作直接拒绝，不弹） |

只在插件设置里改，不跟随 ActSpace 的权限模式。

## 5. 界面

「子 Agent」面板里外部子智能体只显示：标签（Codex / Claude Code）、描述、状态、耗时、最终回复、原生记录路径（可复制、可在 Finder 中显示）。不显示轨迹（Q8）。

## 6. 验收

| 编号 | 场景 | 期望 |
|---|---|---|
| E1 | 未装 CLI | 插件页显示不可用，工具不出现 |
| E2 | Codex `background: true` | 返回 `~/.codex/sessions/…/rollout-…-<threadId>.jsonl`，文件存在、读取免审批；完成通知带最终回复 |
| E3 | Claude Code 同步任务 | 返回最终回复与 `~/.claude/projects/…/<uuid>.jsonl` |
| E4 | `task_stop`（后台）/ 面板停止 | 进程结束，状态 `interrupted`，之后 `closed`；`task_stop` 不再发完成通知 |
| E5 | `send_message` 给外部子智能体 | 返回不能续聊的错误 |
| E6 | 读别的 `~/.codex` / `~/.claude` 文件 | 仍走工作区外审批 |
