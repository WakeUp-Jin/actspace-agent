# 交付版本与验收边界

日期：2026-10-07。状态：V1 已实施，V2 留待后续；实际 API 与逐项证据见 [10](10-V1实现与使用说明.md) 及[执行摘要](../../exec-runs/20261007-harness-evolution-v1/execution-summary.md)。入口：[导航](README.md)。

## 1. 两个产品版本

V1 / V2 指自进化功能的版本，与仓库现有 v2 Runtime 无关。取消 A / B / C 开发阶段命名；旧 B 的自动续跑不再列为交付项或 V2 前置依赖。

| 版本 | 目标与触发 | 交付结果 |
|---|---|---|
| V1：用户驱动自进化 | 用户在 Agent 模式明确要求新增或修改工具 | 官方开发 Skill、inspect、Manager、源码工作区与固定构建、局部分支、HMR 提交与恢复；当前 Run 用旧版本，提交成功后的下一条用户消息用新版本 |
| V2：失败驱动与评估 | 失败数据满足触发策略后自动启动演化流程 | 失败证据分析、候选生成、独立评估沙箱、效果与回归门禁；通过后允许替换或交给未来 Actor 模块 |

V1 单独发布即可使用，不依赖 V2。创造模式可以后续提供聚焦交互，但不作为入口前提；Actor 身份、记忆、名册和多智能体协作由独立工作实现。V1 不做自动失败触发、同 Run 换插件、自动续跑、任意 npm 安装平台或在线 Skill 市场。

## 2. V1 的实际开发落点

| 接入位置 | 新增还是扩展 | 工作内容 |
|---|---|---|
| 官方 Skill 集合 | 新增资源模块 | 首个插件开发 Skill、模板、契约、版本清单，随应用发布 |
| 现有 Skill 发现、正文读取、管理列表和 Host 打包 | 扩展已有模块 | 注入官方来源，统一 id/遮蔽语义，显示来源和启停，安装版无需手动安装；详见 [06](06-Agent开发Skill与PluginManager.md) |
| Plugin Manager | 新增插件模块 | 模型工具代理和稳定 Host 服务；工作区、构建、来源与候选管理，inspect 归属此模块 |
| HMR | 新增插件模块 | Host 级显式应用队列、选择与绑定提交、恢复及诊断，不自动创建新 Run |
| [HarnessControl](../../../packages/harness-control/src/service.ts) | 扩展现有服务 | 从确定版本准备局部分支、授权、选择及恢复扩展 |
| [Runtime](../../../packages/runtime/src/harness/managed-runs.ts) / [AgentService](../../../packages/agent-service/src/run-manager.ts) | 扩展现有接线 | 新 Run 解析会话绑定；在途 Run 固定租约；覆盖执行、压缩、查询和已有子 Agent 路径 |
| [Cordis / 工具生命周期](../../../packages/tools/runtime/src/activation-lease.ts) | 复用并验证 | 注册、实例共存、工具排空和释放；只补验收发现的缺口 |
| Host 协议与现有 UI | 扩展状态投影 | 显示构建、选择、绑定、实际使用和检查结果，不混成单个成功状态 |

两个新运行时插件模块和一个内容资源模块承担不同职责；工作区、构建和版本存储是 Manager 内的逻辑，不各建一套服务。用户最终生成的业务工具插件，与上述管理基础设施是不同实体。

## 3. 实施契约

以下工程细节已在[文件级计划](../../exec-plans/completed/20261007-harness-evolution-v1.md)和 [10](10-V1实现与使用说明.md) 固定；此处保留契约检查清单：

1. 首个工具模板、打包器、构建运行时与受支持依赖闭包；固定安装版资源布局、许可和兼容性检查。
2. 官方 Skill 资源包 exports、Host 资源根接线、身份/来源/启停规则及只读访问；复用当前 Skill 链路。
3. 源码快照和版本来源 schema、会话绑定的写入所有者、提交意图及恢复顺序。
4. Manager actions、HMR 状态与幂等键、Control 的新分支准备契约；声明各操作何时执行代码。
5. 初始化、构建和试跑的 Host 执行许可与最终选用授权；不使用模型自报批准，也不把同进程运行称为评估沙箱。
6. 全部租约解析入口、普通新消息与指定补充旧 Run 的区别、停止与提交竞争的确定结果。

最脆弱的前提是安装版具有可重建源码、类型和构建依赖；若某插件不满足，inspect 明确标记不可编辑，不能假装任意插件都能修改。首版不要求新的外部账号或密钥，真实模型验收沿用已有配置。

## 4. V1 验收

| 编号 | 验收与预期 |
|---|---|
| V1-01 | 干净安装、无源码 checkout、无手动 Skill 安装时，可发现默认开发 Skill 并读取正文、引用材料、模板与契约 |
| V1-02 | 官方与用户 Skill 的启停、同 ID 遮蔽、来源展示和模型实际读取一致；更新不覆盖用户副本 |
| V1-03 | 用户显式要求新增工具后完成构建与应用；下一条消息实际调用新代码，schema、输出和权限链均有效 |
| V1-04 | 从确定版本复制源码修改；基座源码与旧 artifact 字节不变；新产物和父版本可追溯 |
| V1-05 | 同基座派生两分支互不覆盖；甲会话变化不影响乙与 main；重启可恢复局部绑定或明确报告阻塞 |
| V1-06 | 发布版本不依赖工作区；删除开发目录后仍可加载，变化依赖均固定 |
| V1-07 | 构建、准备、兼容性检查失败或未授权时不启用；检查结果不能由模型自报覆盖 |
| V1-08 | 当前 Run 多轮模型与并行工具均保持旧租约；提交成功后普通新消息的新 Run 获得新版本，不被静默补充到旧 Run |
| V1-09 | 提交/恢复期间新 Run 不读取半完成绑定；未完成构建时不宣称新版本已经可用 |
| V1-10 | 新旧 generation 共存无同 Scope 重复注册；不再被使用的旧实例释放工具、监听器与托管资源，清理失败可见 |
| V1-11 | 两候选竞争基线、重复请求和请求 ID 冲突均得到确定结果 |
| V1-12 | 在意图、选择提交、绑定提交处中断可恢复；不会凭恢复记录额外生成业务任务 |
| V1-13 | 提交前后停止/取消保留准确事实；无自动续跑；回退可恢复后续能力，不宣称撤销外部副作用 |
| V1-14 | 能力版本可脱离临时路径和 Session 身份被其他消费者引用；配套 Skill 可追溯，不包含凭据和聊天历史 |
| V1-15 | 仅有失败数据而无用户修改意图时，不自动进入自进化流程；新旧版本实际使用状态与检查状态分开 |

自动化测试覆盖版本、生命周期、控制和恢复；真实 Agent 验证覆盖能力使用；界面验收检查状态与交互，分别报告。Computer Use 按仓库规定先列验收点、再分组，由指定模型执行；本轮真实桌面覆盖与真实模型未覆盖范围见执行摘要。

## 5. V2：失败触发 → 独立评估 → 通过后晋升

V2 比旧 C 的“重复失败发起修改”更完整，其关键增量是自动流程与客观门禁，不是仅增加一个失败监听器。

```text
失败数据 → 证据归类与触发策略 → 创建演化工作流
  → 复用 Skill / Manager 生成固定候选
  → 在独立沙箱加载候选并评估
  → 未通过：保留原选择，记录原因，限额修复或结束
  → 通过：生成绑定候选摘要的评估结果
  → 重新核验基线、兼容性与授权
  → 提交会话版本；或输出可交付版本给未来 Actor 模块
```

V2 必须满足的边界，留给 V2 实施计划详细定义：

- 触发有失败证据、去重和预算上限，区分工具缺陷与网络、权限、输入问题；自动启动本身有明确用户配置和授权范围。
- 评估包含原失败任务、必要回归样例，以及效果、权限边界和成本指标；不能只让生成代码的 Agent 自报通过。
- 沙箱隔离进程和状态，限定文件、网络、凭据及副作用。现有生产 Host 的 Control.prepare 会运行候选初始化，不能先在生产环境 prepare 任意候选，再宣称它经过沙箱准入；应先由独立评估 Host 加载检查。
- 评估结果绑定候选内容摘要、评估集与环境版本。候选变化必须重评，失败或证据缺失不得提交替换。
- 通过只获得晋升资格，不绕过 Control 的基线、兼容性和授权。评估期间线上版本可能变化；冲突需要重新派生并按变化范围重评。
- 向 Actor 输出的是经过评估的能力版本及报告引用，Actor 创建/发布仍由其模块和相应用户意图控制。V2 不在此替其他工作承诺实现 Actor。

V1 仍有构建、schema、兼容性及针对性功能检查，V2 才增加独立评估环境和自动晋升门禁。原任务是否自动重试另行设计，旧 B 不因此恢复为强制阶段。

## 6. 停用与验证范围

停用 Manager / HMR 的新请求入口不删除已有产物、来源或会话选择；已提交应用必须可恢复。关闭协调器停止接纳新变更，回退通过 Control 校验授权；损坏或不兼容如实报告。官方 Skill 可以禁用，不影响已有业务插件运行。

V1 已实现三个 package 与现有模块接线，并补自动化和真实桌面验收记录；不将参考仓库测试、源码推断或受控模型适配器测试当成真实模型自主开发验收。
