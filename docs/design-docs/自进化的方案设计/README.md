# Harness 自进化方案

更新：2026-10-07。状态：用户已批准并实施 V1；实际 API 与限制见 [10-V1实现与使用说明](10-V1实现与使用说明.md)，验收证据见[执行摘要](../../exec-runs/20261007-harness-evolution-v1/execution-summary.md)。

## 当前结论

Agent 通过开发 Skill 和只读能力查询编写插件。新增从模板开始，修改从确定版本的源码副本开始；工作区内容经检查后发布成固定产物。Plugin Manager 管理这条流程，HMR 协调运行时应用，通过切换组合条目引用的版本改变能力，由现有 Cordis 生命周期挂载和释放实例。

**不覆盖正在运行的源码或产物。** 一个基座可以派生多个 Harness 分支；成果可以只在当前会话使用，也可以在未来由 Actor 模块引用。Actor 的身份、场景、记忆、名册和协作不在本轮实施范围。

已确认按两个产品版本推进，不再使用 A / B / C 阶段：

- **V1：用户主动提出修改。** 当前 Run 的多轮模型执行继续使用旧 Harness；新版本成功提交后，用户下一次发送消息启动的 Run 使用新 Harness。不自动中断、交接或续跑。官方 Skill 集合作为新增内容模块，插件开发 Skill 随应用交付并默认可用。
- **V2：失败数据自动触发与评估。** 复用 V1 的候选生产链，在独立评估沙箱中检查效果和回归，评估通过后才允许提交替换或交给未来 Actor 模块。V2 不是本次实施范围。

旧 B 所指的“改完无需用户消息就自动续跑”从交付计划移除，不作为通往 V2 的必经阶段。此处 V1 / V2 是自进化产品版本，与仓库现有 v2 Runtime 的命名不同。
