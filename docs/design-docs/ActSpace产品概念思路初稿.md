# ActSpace 产品概念思路（初稿）

> 文档等级：product-concept，初稿。2026-10-04 与用户讨论确定。
>
> 本文是 ActSpace 的产品形象：它是什么、相信什么、有哪些概念、每个概念为什么存在。本文不涉及交互细节和实现机制。视觉方向、Actor 形象和文案语气示例待定，见第 8 节。

## 1. 一句话定位

> **ActSpace：会自我进化的 Agent 运行空间。**

名字本身就是定位：**Act** 是运行，**Space** 是空间。在开发者的语言里，运行空间就是 harness，也就是承载模型运行的那一层。

## 2. 信念

> **唯变所适。**
> **每一个问题，都有它的空间。**

“唯变所适”出自《易·系辞》：“不可为典要，唯变所适”，意思是没有可以当作固定法则的东西，只能随变化而调整。

世界是动态的，任何解法都只在某些前提下成立。天热的时候，在沙漠里脱掉外衣能散热；天冷的时候觉得有点热，就把衣服脱了扔掉，同样的动作就成了错误。所以不存在一个能解决所有问题的 Agent。

“空间”在这句话里有三层意思：

1. **前提**：一个解法只在它的空间里成立。
2. **余地**：每一个问题，都有被解决的空间。
3. **产品**：ActSpace 就是给问题的那个空间。

## 3. 为什么它会进化

ActSpace 的一切都是插件。模型之外的部分，包括工具、上下文、行为方式，都由插件组装而成。

插件化是进化最基本的条件：既然每一部分都可以替换，空间就可以随着问题调整自己，加上需要的，去掉多余的。不同的问题会把空间塑造成不同的形状，于是出现了各不相同的个体。

对用户来说，插件就是**能力**，指它会什么。用户不需要理解插件，只需要知道它会什么、为什么而存在。

## 4. 故事线

> **从 Agent 开始 → 在场景中长成 Actor → 和你的 Actor 直接对话 → 在空间里一起解决专业问题**

## 5. 核心概念

### Agent

打开 ActSpace 时，所有人拿到的都是同一个 Agent，界面上就叫 Agent（也可以直接叫 ActSpace）。它是一切的起点，不需要任何设置，直接聊就可以。

**为什么要有它**：开始使用不应该有门槛。在还没有遇到具体问题之前，用户不需要任何专门的东西。

### 场景

场景是一个 Actor 存在的理由：它为什么样的问题而来，在什么前提下合适，在什么前提下不合适。

**为什么要有它**：这是信念在产品里的落点。没有场景，Actor 就只是换了个名字的 Agent。

### Actor

> 计算机科学里本来就存在 Actor 模型：一个拥有自己的状态、通过消息和外界交流、独立运行的完整计算个体。

ActSpace 里的 Actor 就是这样一个个体：它在某个场景中由 Agent 长成，有自己的名字、自己的能力和自己的记忆。在形象上，它是一个专业又亲近的精灵。

- Actor 只能在场景中长成。没有场景，就没有 Actor。
- 每个 Actor 都是独立的。只能选择已有的 Actor，或者在新的场景里长成新的，不能复制。
- 一个 Actor 可以有很多段对话。

**为什么要有它**：唯变所适。专门的问题，需要专门的个体。写测试这件事，最适合的是一个只带测试能力、只关心测试上下文的 Actor，而不是一个什么都会一点的 Agent。

### Actor 名册

点开就能看到你所有的 Actor，选一个，直接和它对话。

**为什么要有它**：Actor 是长期相处的伙伴，你回来找的应该是同一个它，而不是翻找一条旧对话。

### 空间

空间把几个 Actor 聚到一起，共同解决一个专业问题。每个 Actor 在空间里依然保留自己的能力和记忆。

**为什么要有它**：有些问题跨越了好几个场景，比如开发、测试和审查，靠一个 Actor 解决不了，需要几个 Actor 一起讨论、协作。

## 6. 意象：宇宙与计算

ActSpace 的意象底色是**宇宙空间**加上**计算**：广阔、精确、理性的空间里，有一个个独立运行、各自发光的计算个体。

意象只用于叙事和视觉，不进入概念名。界面上的词保持朴素：Agent、场景、Actor、Actor 名册、空间。

## 7. 气质

> **有分寸。**

- **对事有分寸**：知道自己的场景在哪里，不越界、不硬做，所以专业。
- **对人有分寸**：知道什么时候说、什么时候安静，尊重你的判断，所以有温度。

落到不同的概念上，侧重点有所不同：

- **Actor** 是专业又有温度的伙伴；
- **空间**是为专业问题准备的，严谨而专注。
