# Agent Room 产品设计

> 文档等级：future-product-design。当前 v2 尚未实现本产品形态；本文只保留产品意图和不变量，不作为当前 Runtime、存储或接口规范。
>
> 含旧实现细节的[完整 v1 稿](../../archive/v1/design-docs/agent-form-room.md)已归档。当前一次性委派见 [Subagent](agent-subagent-runtime.md)。

## 目标与角色

Room 面向开放讨论、搜索、分析、辩论和头脑风暴。用户与多个平等 Member 共享消息流；搜索者、分析师、质疑者、创想者、总结者是思考视角，不是固定流水线。

Room 引用[持久 Member](agent-members.md)，保留各成员在本 Room 的私有运行历史。共享消息与私有上下文分开，其他 Room 的原始对话不自动注入。

## 讨论规则

- 用户普通消息邀请房间成员参与，显式 @ 则只邀请指定成员。
- 成员可以回复，也可以判断没有补充价值而沉默；沉默是正常完成，不等于失败，仍可能产生模型费用。
- 思考可并行，消息按提交顺序展示。较晚完成的草稿在发布前检查新消息，重复内容放弃，有补充价值的内容可修订后发布。
- 普通成员回复不自动唤醒全体；显式 @ 可邀请后续参与者，但本轮接力、回复数量与实际运行预算必须有界。
- 无运行成员、无待处理邀请时，本轮结束；用户可主动停止本轮或发送新消息继续。
- 单个成员失败不抹掉其他成员已提交的结果，失败、主动沉默和用户停止应分别可见。

## 产品交互与验收目标

单一时间线展示成员身份、回复、引用及搜索结果；顶部显示本轮状态与停止入口。详细运行信息按需展开，消息流不承担原始工具日志展示。达到讨论上限时说明原因，允许用户继续发起下一轮。

验收应覆盖 @ 定向响应、并行回复去重、主动沉默、单成员失败、用户停止和预算耗尽，确保没有无限互相唤醒或停止后继续发布的行为。
