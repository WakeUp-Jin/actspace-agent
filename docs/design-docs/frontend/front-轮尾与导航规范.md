# 轮尾与导航规范

管每个用户 turn 结束之后和之间的内容：回复尾栏（操作、用量、时间）、轮尾卡片（改动、交付、图片）、步数上限提示、上下文压缩分隔线，以及长会话的提问条、轮次导航轨和回到底部按钮。消息块本身见 [front-中间消息区规范.md](front-中间消息区规范.md)。实现目录：`components/conversation/`、`components/turn-tail/`、`components/messages/`。

## 回复尾栏

每个用户 turn 的最终可见助手回复下方有一条轻量尾栏：`TurnActions.tsx`、`TurnUsagePill.tsx`、`turn-usage.ts`。

- 从左到右：复制回复、更多操作（分叉会话 / 复制消息 / 复制请求 ID）、「用量 88K tok」胶囊、回复时间（`HH:mm`）。分叉在当前轮运行中或该回复没有落盘 `turnId` 时禁用，提示「请等待当前轮次结束后再分叉」。
- 最新一轮（已结束）的尾栏一直显示；更早的轮次默认透明且不响应鼠标，hover 或键盘 focus 进入该轮时淡入（`data-turn-actions-reveal="always" | "hover"`），用透明度藏，布局不跳。
- 用户消息、Thinking、工具日志和压缩分隔线不单独展示用量尾栏。
- 胶囊点开是「本轮用量」弹窗（`ui/Popover`）：标题行右侧是精确总数，下面依次是提供方 / 模型、缓存命中、未缓存输入、缓存读取、缓存写入、输出（有推理时附「其中推理 …」）、花费。弹窗内容组件 `stats/StatDialog.tsx` 与输入框状态栏的统计胶囊共用。480px 以下胶囊只留数据库图标，弹窗里照常有文字。

### 用量语义

- 本轮用量按 run 聚合该轮全部 `llm_usage`（`createMessageBlocks`），只挂到该 turn 最后一条可见助手回复；包括工具调用前后多次模型请求和失败重试（`llm/retry`）的真实消耗。
- `llm_usage` 由 `packages/client/client/src/sessions/chat.ts` 从 `step/end` 和 `llm/retry` 投影，每次请求一条；没有 usage 的 `step/end`（中断、失败）不记；`assistant/message` 带的是同一份 usage，不重复计。
- 提供方 / 模型取每次请求计价快照里的 `providerId/apiModel`；拿不到真实值时整行不显示。
- 外部接口返回 CNY 时按 `7.2 CNY = 1 USD` 转 USD；费用最多 6 位小数，避免低成本调用舍成 `$0.00`。
- 花费按请求的计价口径汇总：全部能算出价格时显示金额，有按参考价预估的请求时后面标灰色「预估」；有请求算不出价格时不给偏小的数，显示「部分未知」或「未知」。
- 一个 token 都没有（旧会话、全部中断）时不显示胶囊，只显示操作和时间，不伪造 token 或费用。

## 轮尾卡片

位置：最终回复之后、图片列表之前，接在尾栏上方，分「改了什么」「交给你什么」两张卡（`turn-tail/TurnTail.tsx`）。数据全部由本轮已完成的工具事件推导，不读 Git，也不从回复正文猜。两张卡都在本轮最终回复完成后才出现，流式、工具执行、审批期间不出现；本轮既无改动又无交付时尾栏退回原形态，不渲染空卡。

### 改动卡

- 头部「已编辑 N 个文件」，单文件时「已编辑 {文件名}」，右侧 `+additions -deletions` 合计。行数按文件累加本轮 `write_file` / `edit_file` 的 diff，不冒充 Git 的工作区净 diff。
- 新建文件去掉 diff 旧侧的幽灵空行，不显示成「删除了 1 行」；同一文件多次编辑的 hunk 按时间排列，不合并、不重算行号。本轮新建又在同轮删掉的文件不算改动；删除本轮之外已存在的文件保留该行并标记删除。
- 文件列表超过 4 行折叠，展开后按顺序显示 workspace 相对路径、增删行数和新建 / 删除标记。
- 悬停卡头或文件行 500ms 弹出该文件的 diff 浮层（宽 = 卡片宽 - 48，最高 420px，鼠标移出 200ms 后关闭）。点击文件行在右侧面板打开「第 N 轮改动」标签：左侧文件列表，右侧左右对比 / 单栏、自动换行、文件菜单和「打开整个文件」；纯新增文件即使开着左右对比也只渲染单栏。
- 远端会话只能预览或下载，不显示原生应用按钮。设置中心「通用」里的「显示本轮代码改动」默认开，只隐藏改动卡（交付卡和图片列表不受影响），切换立即生效。

### 交付卡

- 数据来自 Agent 调用的 `present` 工具，只收录工作区内的相对路径；同一路径多次声明保留第一次出现的顺序、描述取最后一次；描述末尾的括注去掉，没有描述时显示扩展名。
- 文件以卡片网格展示（两列，单个或窄于 620px 一列），带文件类型图标与描述，超过 4 个折叠。
- 点击卡片在右侧面板预览（远端经 Host 读取）；卡片右侧的分体按钮用系统默认应用打开，下拉列出关联应用，最后一项「显示文件位置」；打开 / 显示的结果提示（「已请求打开」等）停留约 5 秒后淡出。右键卡片：本地会话弹 main 的文件菜单（在 Finder 中显示、拷贝路径等），远端会话改为经 Host 下载。
- 关联应用列表由 main 提供（macOS 查询并缓存）；renderer 只传 workspace 相对路径，main 重新校验 realpath 边界。

### 图片列表

- 只收录本轮生成的图片（`image_generation` 产物和工具 `artifacts` 中的图片），按路径去重；只有当前 Agent Run 结束、最终回复完成后才在回复下发布紧凑列表，流式、工具执行和审批期间不提前出现。折叠 `Worked for` 不应隐藏这一栏。
- 列表只显示文件名和短路径；悬浮行用 Tooltip 显示完整绝对路径。点击打开右侧面板，加载中只在对应行显示小型 spinner，错误在组件底部显示轻量说明。
- 右键图片行打开 Electron 原生菜单（复制图片内容、在 Finder 中定位）；renderer 只传会话产物身份，main 重新校验 realpath 边界。

## 步数上限提示

一轮步数打满（`turn/end` 的 `reason` 为 `step-limit`）时，轮尾追加一行中性灰 muted 状态：`本轮达到 N 步上限，已停止。发送「继续」可以接着做。`，不用红色错误样式；N 取本轮实际步数，窗口里数不出来时省略数字。main / chat 上限 1000 步，最后一步不给工具，模型会先输出已有发现和未完成部分，所以提示通常紧跟一段总结。这一轮在 Run 层仍记为 failed，但不使消息队列暂停。

## 上下文压缩分隔线

手动 `/compact` 与自动压缩共用同一消息块（`context_compaction`，`CompactCommandBlock.tsx`）和同一套 UI，消息流里不区分、不标注触发方式（触发方式只在轨迹详情里显示）。它是系统执行事件，不是工具调用，不渲染为 Tool Preview；必须作为独立 timeline item 占据消息流位置，不能贴到上一条回复里。

- 共同结构：居中分隔线，左右两段 1px 细线（线色比普通分隔线深一档，`compact-divider-line`），中间一组图标 + 文字，字号 `text-act-xs`；窄窗时中间一组换行，数据挪到第二行，不截断 token 和耗时。
- running：小转圈 + `正在压缩上下文` + 已用时间（`8s`，每秒刷新，来自 `startedAt`）；两侧细线各有一道 `operational` 色的光从外端收向中间（`compact-divider-running`，减少动态效果时不显示）。进行中不显示条数，文本不做 opacity pulse、扫光或省略号动画。手动 `/compact` 被任务服务领取后进入 running，等待时显示在队列中，不再显示淡色 `/compact` 命令行。
- completed：归档图标 + `以上 48 条消息已压缩` + `182K → 约 9.1K tokens · 23s` + `·` + `在轨迹中查看 ›`。
  - 条数来自压缩区间大小；token 来自 `compaction/end.data.beforeTokens` / `afterTokens` / `beforeEstimated`：压缩前 = 最近一次有效实测用量（往前跳过没有 usage 或 usage 全空的回复；之后若又发生过压缩，改用那次压缩后的数）+ 之后新加内容的估算；压缩后 = 压缩前 - 被替换条目估算 + 摘要估算，总是写「约」；压缩前含估算（`beforeEstimated: true`）时也写「约」。旧 journal 缺这两项时只显示条数和耗时。
  - 耗时优先取 `compaction/end.data.durationMs`（含事务提交前的模型摘要等待），旧 journal 回退 `compaction/start` 与 `compaction/end` 的时间差。
  - `在轨迹中查看` 调用 `revealInTrajectory({ compactionId })` 切到轨迹并选中这次压缩的行；没有 `compactionId` 或不在工作台里时不显示。摘要不在消息流里展开，只在轨迹详情里看。
- failed：红色分隔线（`text-on-danger` + `bg-danger-soft`），中间警告图标 + `上下文压缩失败` + 原因 + 下划线文字按钮 `重试`（走同一 `/compact` 路径）。压缩未成功不提交摘要事务；任务失败状态由 TaskSnapshot 恢复；自动压缩的非取消类失败不使主运行失败，live run 结束后改由对应会话的本地状态显示，直到下一次发送或压缩状态更新，不跨应用重启持久化。
- skipped（对话太短）：不进消息流，只在 Composer 输入框顶部显示一行 `对话还很短，暂时不需要压缩`，约 3 秒后消失。
- 被压缩的旧消息和工具调用继续在分隔线上方照常显示，不置灰；摘要不投影成用户消息卡片。
- `/compact` 经统一 `submitTask` 接纳，繁忙时排队，不作为普通用户消息写入模型历史（契约见 [Task/Run 规范](../agent-plugin-runtime/agent-task-run-lifecycle.md)）。自动压缩属于当前 Agent Run：输入框为空时停止按钮可用并沿用 Run 的取消信号；独立 `/compact` 没有可取消的 Loop Run，停止按钮置灰并提示 `压缩完成后可继续`。自动压缩在工具批次全部完成后的 Step 安全点判断阈值，触发时先完成压缩再发下一模型请求；无工具的最终回复仍保留 Turn 收尾检查。

## 提问条（PinnedTurnPrompt）

用户提问卡片不吸顶，跟着内容滚走；滚出视野后在消息区顶部叠一条一行高的同款卡片（`conversation/PinnedTurnPrompt.tsx`）。

- 叠加层 `absolute` 不占布局，出现、消失都不推动下面的消息；提问卡片底边离开视野 8px 后才出现，这一轮剩余不足 72px 时不再叠，避免盖住下一轮提问。
- 只有一行：提问（截断）+ 任务进度胶囊（`任务 3/5`，有 Todo 时），没有展开面板。没有文字只有附件时显示「N 个附件」。
- 整行是按钮（`回到提问：…`）：点击平滑滚动到这一轮的提问卡片（顶部留 8px），这一轮可编辑时直接进入原地编辑（见 [front-中间消息区规范.md](front-中间消息区规范.md)「编辑提问重发」）。编辑时提问条隐藏。

## 轮次导航轨

会话内容超过消息视口且至少 3 个用户 turn、消息视口宽度 ≥ 640px 时，消息区左侧显示一条紧凑导航轨（`ConversationTurnRail.tsx`、`conversation/TurnNavigator.tsx`）。它服务于长会话定位，不是新的会话 Sidebar，不改变 session 数据契约。

- 每条短横线对应一个由用户消息开始的 turn；Thinking、工具调用、助手中间旁白和压缩分隔线不生成刻度。当前阅读位置的刻度加长并用主文字色；普通、hover、focus 用中性灰阶，不用 operational green 表达选中。
- hover 或键盘 focus 某刻度时，以它为峰值按相邻距离逐级缩短相邻标记宽度，形成稳定的山峰波形；按钮命中宽度不变，离开后恢复安静状态。轮次超过 14 个时压缩刻度间距。视口窄于 640px 隐藏导航轨，优先保护正文与 Composer。
- hover / focus 刻度时在右侧显示摘要卡（宽 ≤ 340px）：用户输入最多两行，最终助手回复最多三行；正在执行且没有最终回复显示 `正在执行…`，无回复显示「本轮没有最终回复」。
- 点击刻度滚动到该 turn 的用户消息并暂停贴底跟随，回到底部后恢复。当前 turn 由消息滚动容器内的阅读基准线（视口顶部下 `min(32% 视口高, 180px)`）计算，不依赖重读 session events，也不为导航复制消息状态。

## 回到底部按钮

- 消息区可滚动且距底部至少 80px 时，在 Composer 上方居中显示圆形向下按钮；hover 显示 `滚动到底部` Tooltip，支持键盘 focus 和主题感知 focus ring。
- 点击直接滚到底部、恢复流式自动跟随并隐藏按钮；用户手动滚回距底 80px 内时自动隐藏；点击历史刻度或主动上滚后出现。不显示「未读消息数」，避免建立第二套 unread 语义。

## 滚动状态边界

- `ConversationView` 的消息滚动容器是轮次导航、回底按钮和外层流式自动跟随的共同事实来源。
- `ResizeObserver` 只在用户仍贴底（距底 < 80px）时跟随内容增长；用户已上滚时只能更新导航和按钮状态，不能把用户拉回底部。
- `FileDiffBlock` 等内部滚动容器维护自己的贴底状态，不与会话外层合并；右栏这类简单列表用 `use-stick-to-bottom.ts`。
