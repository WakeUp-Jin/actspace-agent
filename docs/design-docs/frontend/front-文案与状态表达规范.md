# 文案与状态表达规范

管桌面端界面上所有「字」和「状态」怎么写：用什么语言、写不写说明、同一信息放几处、状态怎么表达、空 / 零 / 未知 / 错误 / 加载怎么显示。每条一句话能判对错；反例都是本仓库真实出过的问题。视觉数值见 [视觉 token 规范](front-视觉token规范.md)，控件与交互见 [组件与交互模式规范](front-组件与交互模式规范.md)。

## 1. 中文取舍

1. 界面文字用简体中文：按钮、占位符、空态、菜单、Tooltip、无障碍名称、错误主提示都是中文，同一个概念全界面一个叫法。
2. 保留英文的只有：模式与档位（Chat、Plan、Thinking、Effort 及 Auto … Ultra）、工具执行名称与状态、Agent / Skills / Token / Git / API / SSH、模型 / 服务商 / 外部应用 / 协议名、功能名 Review。
3. 用户数据原样显示，不翻译：会话名、工作区名、模型回复、Skill 原始描述、路径、分支名、外部错误详情。反例：把已保存的会话名 `New chat` 批量改成「新聊天」。
4. 常用叫法固定：新建会话、已置顶、工作区、分叉、归档、上下文、本机、新建工作树、最近一轮 / 未提交 / 未暂存 / 已暂存。
5. 显示状态与机器状态分离：界面写「已退出」，属性值仍是 `exited`；错误里的 IPC 通道名等技术前缀收进可展开详情，主提示写中文。
6. 时间、数字用简体中文格式；金额单位与时区不变。
7. 按钮写具体动作，不写「确定」「确认」「OK」：确认框写「开启」「移除」，失败后写「重试」，撤销条写「撤销」；进行中换成进行时（「开启中…」）。

## 2. 说明文字默认不写

灰色小字最容易越写越多。默认不写；写之前先问「删掉这行，用户会选错、会误花钱、会误以为安全吗」，不会就不写。

1. 解释删，不改成悬停或 ⓘ 图标。原理、公式、「去哪里设置」「什么时候生效」都不写；看不出来的东西改名字或交互，不靠补一句话。反例：Context 面板 Bash 卡标题旁的 ⓘ（统计口径）、设置里「密钥只在 main 进程解密使用；保存后从下一次调用生效」。
2. 页面副标题和分组说明默认不写；`PageHeader` / `SettingGroup` 的 `description` 只在这行字本身是数据时才用（如连接详情页的状态与余额）。反例：设置各页的「管理……」副标题，使用统计浮层里的灰色说明小字，权限菜单里每个选项下面的提示。
3. 数据和警示可以留，而且只写一句短话：价格、额度、路径、余额、协议名、数量、状态、校验错误是数据；会花钱、会外发、会绕过审批、会丢东西的是警示。不带背景和来龙去脉。正例：「通用子智能体可改文件、跑命令，不弹审批」。
4. 数据缺口注脚是数据：「有 N 次请求缺少用量或定价，数值为已知部分的合计」留，一行，不挪进悬停。
5. 名字要自解释。标签能说清楚做什么，就不需要下面的小字。正例：「按页面节点操作」「按选择器操作页面」，替代「浏览器 DOM CUA」加一行说明。
6. 选择依据是例外的内容，不是例外的位置：模型用途（`PURPOSES`）每行一句「这个用途干什么」保留，但不能再叠加副标题或分组说明。
7. 不写使用教程式文案：不写「点击这里……」，Tooltip 写动词短语（「发送消息」「停止 Agent」「刷新」），不重复图标名（「加号」「三个点」）。

## 3. 同一信息只出现一次

1. 同一个意思在一个区域只说一遍，不在页面、分组、行、输入框占位里各说一遍。反例：「Key 只保存在本机」原先在页面副标题、分组说明、输入框下方各出现一次，现在每个 Key 输入处最多一次。
2. 同一状态在一行里只表达一次。反例：审批卡里已有「运行 ls」按钮，又多一行「等待确认」和「Running ls」；子 Agent 行没有结果时，左侧不再重复写右侧已有的状态。
3. 有可见文字就不加图标：按钮、标签、状态已经有文字，不再加装饰图标；只有展开箭头这类纯功能指示可以保留。反例：子 Agent 状态用播放 / 方块图标加「运行中」文字。
4. 同组内一致的标记放组标题，不放每行：分组内每行都一样的标记只写一次。反例：沙盒盾牌出现在每条已完成的 Bash 行尾，一轮十几条命令把右侧铺满；现在盾牌只在命令运行中显示，结束后收掉，环境写进展开详情，主行只留「未执行」这类例外。
5. 不写流水号式计数：「第 N 轮」「第 N 次」只有在用户需要据此定位时才显示。反例：子 Agent 行的「第 N 轮」已删除。

## 4. 状态表达

1. 状态不能只靠颜色：必须有文字，或者有图标 / 形状；文字与图标二选一，再配颜色，不叠加。
2. 有文字位置的状态只写文字（颜色可变）：正例「运行中」用 `text-operational`、「失败」用 `text-on-danger`、「等待审批」用 warning 色。反例：同一状态前面再放图标或点。
3. 没有文字位置（窄空间）才用单独的图标或点，并且悬停或点击给出文字：侧栏会话行的状态点是这条的例外，悬停显示「运行中 / 等待审批 / 失败 / 已完成 / 空闲」。
4. 颜色只表达真实状态，语义按 [视觉 token 规范](front-视觉token规范.md) 第 1 节：运行与成功用 operational，风险与等待审批用 warning，错误与失败用 danger；已完成回到中性，普通功能图标保持中性。
5. 同一属性的颜色类按状态二选一，不叠加两个颜色类。
6. 警示句（`InlineWarning`：会花钱、会外发、服务未配置）不是状态标签，可以带一个警示图标。
7. 现状待改：设置页 `StatusDot`（圆点加文字）是叠加写法，改版触及时改成只留文字。

## 5. 空值、零值、未知、错误、加载

固定写法，全界面统一：

| 情况 | 显示 | 规则 |
|---|---|---|
| 真实的零 | `0`、`$0`、`¥0` | 服务商明确返回的零、有效零价照实显示 |
| 缺失 / 未知 | 「—」，需要时提供查看原因 | 反例：缓存命中率有已知数据却显示「—」，应按已知部分合计算 |
| 部分未知 | 显示已知部分的合计，未知次数写在下方一行注脚 | 全部未知才显示「—」；金额不给偏小的数，显示「部分未知」或「未知」 |
| 空列表 | 一句「暂无××」或「没有符合筛选条件的记录」 | 不画插画、不引导文案 |
| 加载 | 局部显示读取状态；刷新时保留已有结果 | 不整页清空再重画 |
| 失败 | 中文主提示 + 「重试」；技术详情收进可展开区 | 不把失败伪装成「没有数据」，不悄悄换另一种统计口径；窄窗口下重试按钮不换行 |
| 进度 | 没有真实百分比就用不确定样式 | 不伪造百分比 |

- 金额小数最多 6 位，非零且低于最小精度时显示阈值提示，避免低成本调用被舍成 `$0.00`。

## 6. 不伪造数据，不放占位入口

1. 缺失的值不补默认：缺 `exitCode` / `durationMs` 不显示 0；缺 `sandboxed` 表示未知，不显示「沙盒」；未执行的命令不显示输出或成功退出码。
2. 一个 token 都没有（旧会话、全部中断）就不显示用量胶囊，不显示 0 token 或 $0。
3. 未知成本显示「未知」或明确的预估标记（灰色「预估」），不显示虚假零成本。
4. 没有真实行为的入口不放：不做占位菜单项、「即将推出」、空的 MCP 页、没有产品能力的 `Scheduled` 分区、没有功能的语音按钮。
5. 功能项必须对应真实行为；用户不触发时不增加常驻按钮、标签或提示条。
