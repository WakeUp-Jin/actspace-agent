# Space 工作台设计

> **状态：前端设计稿（2026-10-03 修订），待 demo 评审后定稿，未进入实现。**
> 交互 demo：[space-demo.html](space-demo.html)（打开即可点，数据全部是 mock）。
> 上一版按「主会话 + 线程」设计，已按 2026-10-03 的讨论改为「协调 Agent + 工作 Agent」，结构、术语与布局都做了调整。
> 参考：Anthropic 博客《Projects redesigned: from folder to conversation》（2026-09-17）、[Claude Projects 视频资料](../../references/claude-projects-NDTbUObZTlM/README.md)，以及本机 Cursor 3.22.7 的 Agents 窗口实现。

## 0. 一句话

**Space 是围绕一个目标长期运作的容器：你只和协调 Agent 说话，它把要动手的事派给工作 Agent 并行去做；这些工作 Agent 和协调 Agent 一样，都是中间区域里的一个标签页。**

---

## 1. 术语

| 概念 | 界面名 | 代码 / 协议名 | 说明 |
| --- | --- | --- | --- |
| 容器 | **Space** | `Space` | 不翻译，与产品名 actspace 同源 |
| 你对话的那个 | **协调 Agent** | `coordinator` | 每个 Space 一个，长期存在，只读 + 派活 |
| 被派出去干活的 | **工作 Agent** | `worker` | 一个完整的 actspace 会话，和协调 Agent 平级 |
| 右栏汇总 | **概览** | `overview` | Agents / 库 / 记忆 三个分段 |
| 用户写的规则 | **指令** | `instructions` | 等价于 Space 级 AGENTS.md |
| 模型记下的事实 | **记忆** | `memory` | 逐条，可改可删 |
| 文件与产出 | **库** | `library` | 磁盘上的真实目录 |
| 现有的临时只读助手 | **子智能体** | `subagent` | 保持现状，只在单个对话内部出现，不参与 Space |

**为什么用「协调 Agent + 工作 Agent」**：两个名字都带 Agent，一眼能看出是同一类东西、只是分工不同；和现有「子智能体」形成平行结构，不会混。右栏分段的标题「Agents」也顺理成章。对比「主 Agent + Agent」——「主」会让人以为是层级上的从属，而实际上工作 Agent 只是干不同的活，地位并不低。

## 2. 已确定的决策

### 2.1 2026-10-02 确认

| # | 问题 | 决定 |
| --- | --- | --- |
| D1 | 协调 Agent 的工具边界 | **只读 + 派活**：可读文件、搜索来回答简单问题；可开工作 Agent、给它发消息、读它的状态、写记忆。不能写文件、不能执行命令 |
| D2 | 多个工作 Agent 改同一 git 仓库 | **自动判断**：一个目录只有一个在写时直接改；第二个要写的自动开工作树（`space/<slug>` 分支）。非 git 目录一律直接改 |
| D3 | 工作 Agent 在左栏的可见性 | **只在 Space 内显示**：左栏只有 Space 行和「等你处理」计数，工作 Agent 不进普通会话列表 |
| D4 | 场景侧重 | **编码为主，兼顾文档**：结果突出改动与 Review，库以产物和文档为主 |

## 3. 概念模型

```
Space ─┬─ 目标（一行，可空）
       ├─ 目录：1..n 个工作区目录 + 添加的文件
       ├─ 指令（用户写）        ─┐
       ├─ 记忆（协调 Agent 写） ─┴─▶ 工作 Agent 开工时注入快照，之后按轮次追加增量
       ├─ 库：<dataRoot>/spaces/<id>/library/
       ├─ 协调 Agent × 1 ── 只读 + 派活
       └─ 工作 Agent × n ── 完整会话；各自落在一个目录（必要时一个工作树）
```

### 3.1 职责对照

| 能力 | 协调 Agent | 工作 Agent |
| --- | --- | --- |
| 和你对话 | ✓ | ✓（在它自己的标签页里） |
| 持有指令与全部记忆、看得到所有工作 Agent | ✓ | 开工时拿快照，之后只看自己的工作 |
| 开工作 Agent、给它发消息 | ✓ | ✗（工作 Agent 不能再开） |
| 读文件、搜索 | ✓ | ✓ |
| 写文件、执行命令、浏览器 | ✗ | ✓ |
| 用子智能体拆分自己的任务 | ✗ | ✓（沿用现有能力） |
| 写记忆 | ✓ | ✗，只能在交回结果时**提议**，由协调 Agent 决定 |
| 审批请求 | 不代答 | 在它自己的对话里原地弹出 |

只有协调 Agent 能写记忆，这样多个工作 Agent 不会同时写出互相矛盾的条目。

### 3.2 工作 Agent = 完整会话

现有子智能体只运行一次、只读，也不能直接对话，撑不起工作 Agent。工作 Agent 直接复用会话：

- `SessionMeta` 增加 `space?: { spaceId, role: "coordinator" | "worker" }`；journal lineage 的 `origin` 增加 `"space"`。
- 沿用现有的审批、工具流、Review、上下文压缩、消息队列，不新做执行通道。
- 只属于一个目录（与现有会话「单 `workspaceRoot`」一致），由协调 Agent 派活时选定。
- 隔离按 D2：派活时检查该目录是否已有活跃的写入 Agent，有则走现有「新建工作树」能力。

> 这一节涉及产品代码，本次只做设计，实现细节等前端定稿后再展开。

## 4. 布局

### 4.1 三栏骨架

```
┌ 左栏 260px ────────┬ 中间区域 ──────────────────────────────┬ 概览 340~440px ─────────────┐
│ 新会话  搜索        │ [ 支付链路提速 ][ ● quote N+1 × ][ … ] │ Agents │ 库 │ 记忆            │
│                    │                                        │                             │
│ SPACE              │   当前标签页的完整对话                  │ ⌄ 等你处理 1                │
│  ⚡ 支付链路提速 ①  │                                        │   quote N+1  批准…  ◔4/6 3分钟│
│  🚀 结算页重构      │                                        │ ⌄ 运行中 2                  │
│                    │                                        │   web 报价缓存  补…   ◔3/5  │
│ 最近               │                                        │ ⌄ 空闲 1                    │
│  修复登录页样式     │  [⚠ 1 等你处理] [◔ 2 运行中] [○ 1 空闲] │   慢查询分析  结论…  • 1小时 │
│  给设置页加搜索     │  ┌ 告诉协调 Agent 下一步…          ┐    │ › 已完成 3                  │
│                    │  └──────────────────────────────────┘    │                             │
└────────────────────┴────────────────────────────────────────┴─────────────────────────────┘
```

- 左栏 260px 固定。概览打开时占 `clamp(340px, 30%, 440px)`，收起时宽度归零并带 0.26s 过渡。
- 中间区域的对话列宽上限 720px，居中。窗口小于 1180px 时左栏变为覆盖层，小于 900px 时概览变为全屏覆盖层。

### 4.2 左栏：普通会话列表

跟现在完全一样，只是多了一个 Space 分区：

- **Space 分区**：每个 Space 一行，图标 + 名字，右侧显示「N 等你处理」或「N 个 Agent」。分区标题右侧有一个 `+` 新建。
- **最近分区**：普通会话，和 Space 的会话混在同一个列表里，行为不变。
- 底部一行主题切换（跟随系统 / 浅色 / 深色）。

**工作 Agent 不出现在左栏**（D3）。左栏那行 Space 上的「等你处理」计数，只用来提示「这个 Space 里有事等你」，不展开。

### 4.3 中间区域：标签栏 + 内容 + 输入区

**标签栏（44px 高）：**

- 第一个标签固定是 Space 名字（即协调 Agent），不可关闭。
- 点右栏的工作 Agent，在标签栏追加一个标签页，带状态点和未读点。
- **预览标签页**：单击只复用同一个预览位，在标签页里发过消息或处理过审批之后才固定下来。避免多看几个 Agent 就把标签栏撑满。
- 标签用 `aria-selected` 表达选中，关闭按钮只在悬停和选中时出现。

**内容区：**

- **协调 Agent 标签页**：只有两种东西——你的消息（右对齐的卡片）和协调 Agent 的回复。回复里的工作 Agent 名字是可点的引用（`[[a1]]` 这种标记渲染成一个小胶囊），点开那个 Agent 的标签页。
  - 回复先显示三个跳动的点，然后逐字出现，末尾带光标。
  - 记忆写入显示成一行脚注：「✓ 记下了「…」· 撤销」。
- **工作 Agent 标签页**：顶部是固定的头部（状态胶囊、标题、目录、工作树），下面是它的完整对话，最后是审批卡（如果需要）。
- **空 Space**：一个图标 + 名字 + 一句话说明，加三条示例指令，点了直接发出去。

**输入区：**

- 输入框上方是**状态胶囊**：`⚠ N 等你处理`、`◔ N 运行中`、`○ N 空闲`、`✓ N 已完成`、`! N 出错`。数量为 0 的不显示。
- 再上方是**审批托盘**，默认收起（高度 0），点胶囊才展开。
- 输入框占位符随标签页变化：「告诉协调 Agent 下一步…」/「引导这个 Agent…」。
- 左下角一行小字：协调 Agent 显示「Sonnet 5 · 协调」，工作 Agent 显示「Sonnet 5 · 工作 Agent」。

### 4.4 右栏：概览

三个分段用一个滑动的指示块表示（`transform` 过渡 0.22s）：

**Agents 分段**

按状态分组，顺序是 等你处理 → 运行中 → 空闲 → 出错 → 已完成。

**分组标题**是一条 30px 高的浅灰底条：`⌄ 运行中 2`，折叠箭头在最左。

- 每个分组都能点标题折叠 / 展开，「已完成」默认折叠。
- 「等你处理」的分组条用琥珀色（浅琥珀底 + 琥珀色字）。行上不再有状态点，这个分组被折叠时，琥珀色的分组条就是唯一的提示，所以要比其他分组醒目。

**每一行只有一行**，34px 高，从左到右：

```
quote N+1 修复  批准新索引的迁移 ……………  ◔ 4/6   3 分钟
└ 标题 ──────┘  └ 说明（灰，截断）┘      └ 待办 ┘ └ 时间 ┘
```

- **标题**：最多占行宽约 62%，超出截断。
- **说明**：一句话，写它在做什么或等你什么。灰色，占满剩余空间，超出截断。
- **待办进度**（可能有）：只有这个 Agent 调用过 todo 工具时才显示，是一个小圆环加 `完成数/总数`，用细边框胶囊包住。
- **时间**（可能有）：右对齐的小字，比如「3 分钟」「1 小时」「昨天」。没有就不占位。
- 不再有状态点。状态已经由所在分组表达，行上再加点就重复了。
- 未读：说明后面一个小蓝点，点开后消失。
- 工作树不在行上显示，放在 Agent 标签页的头部。
- 悬停时用 `title` 显示完整的「标题 · 说明」。

**库 分段**

`Agent 产出`（`artifacts/`）和 `你放进去的`（`added/`）两组，每行是文件名 + 来源 + 日期。底部一行提示说明库就是磁盘上的真实目录。

**记忆 分段**

上下两块：

1. **指令**：只读展示，右上角一个「编辑」。
2. **记忆**：逐条列出，悬停时出现「忘记」。顶部一行说明：只有协调 Agent 会写记忆，工作 Agent 只能提议。

> 原本独立的 Space 设置弹窗取消，内容并进这里。新建 Space 仍然用弹窗（一次性，字段少）。

### 4.5 新建 Space

弹窗，字段从上到下：名字、图标（5 个预设色）、相关目录（选填）、指令（选填）。创建后进入这个 Space，显示空状态。

## 5. 关键交互

### 5.1 审批（D8）

这是整个设计里最需要说清楚的一段。审批分三层：

**第一层 · 源头。** 审批卡永远在那个 Agent 自己的对话里，就在它请求的位置。设置项和 Cursor 一样：Agent 请求卡在对话里始终显示。按钮文案跟着操作类型走：

| 请求类型 | 按钮 |
| --- | --- |
| 运行命令 | 运行 / 拒绝 |
| 改文件 | 保留 / 撤销 |
| 访问网络 | 继续 / 取消 |

**第二层 · 提醒。** 同一个待处理项在四个地方同时出现：

| 位置 | 形态 |
| --- | --- |
| 右栏 Agents | 移到置顶的琥珀色「等你处理」分组，说明写它想干什么 |
| 标签页 | 标题前一个琥珀色点 |
| 左栏 Space 行 | 「N 等你处理」计数 |
| 输入框上方 | 琥珀色胶囊，新来的会轻微跳动两下 |

**如果当前看的就是那个 Agent，不再重复提醒**，避免同一条信息在视野里出现三次。

**第三层 · 快捷处理。** 点琥珀色胶囊，托盘在输入框上方展开（0.26s）：

```
⚠ quote N+1 修复 想运行一条命令                        ‹ 1/3 ›
  pnpm db:migrate --env staging-2     [查看] [拒绝] [运行]
```

- 多个待处理项时用 ‹ › 切换，显示「1/3」。
- 「查看」跳到那个 Agent 的标签页；「运行」「拒绝」就地处理，托盘自动收起并切换下一个。
- 处理完，右栏那一行平滑移到新分组（见 5.4）。

**默认不自动展开托盘。** 新审批来了只让胶囊变成琥珀色并入轻微跳动，不打断你正在输入的内容。

### 5.2 消息路由

你在协调 Agent 的输入框里说话，它做三件事之一：

1. 能直接回答的，直接回答（不改文件，不派活）。
2. 提到已有工作 Agent 的事，转给那个 Agent（回复里显示「已转给 ×××」）。
3. 需要动手的，开新的工作 Agent，回复里列出它们。

无论哪种，回复都是一段自然的文字，不再有单独的「结果卡」「建议卡」这类块。

### 5.3 打开与关闭

- 点右栏任一工作 Agent → 中间开标签页（预览位复用）。
- 标签页最多同时可见约 5 个，超出横向滚动。
- 关标签页不影响 Agent 本身，它继续在后台跑；右栏那一行仍然在。
- 协调 Agent 的标签页不能关。

### 5.4 动效清单

| 场景 | 动效 |
| --- | --- |
| 概览打开 / 收起 | 宽度 0.26s 过渡，内容淡入 |
| 分段切换 | 指示块 `translateX` 0.22s |
| 协调 Agent 回复 | 先三个跳动点，再逐字出现（26ms / 字符），末尾光标 |
| Agent 状态变化 | 右栏那一行 `FLIP` 平移 0.3s 滑到新分组 |
| 分组折叠 / 展开 | `grid-template-rows` 在 `1fr` 和 `0fr` 之间过渡 0.22s，带淡出，箭头旋转 -90° |
| 新审批到达 | 胶囊变琥珀色并跳动两下；托盘若开着则内容淡入 |
| 新 Agent 出现 | 那一行从下方 5px 淡入 |
| 弹窗 | 遮罩淡入 0.16s，弹窗上移 6px + 轻微放大 0.2s |
| 输入框发送 | 按钮按下缩放 0.94 |

`prefers-reduced-motion` 时全部关闭。

### 5.5 状态与颜色

| 状态 | 表意 | 颜色 |
| --- | --- | --- |
| 运行中 | Agent 正在做事 | 翡翠绿（`--act-color-operational`）+ 脉冲 |
| 等你处理 | 审批、提问 | 琥珀色（`--act-color-warning`）+ 脉冲 |
| 出错 | 会话失败 | 红色（`--act-color-danger`） |
| 空闲 | 一轮结束，等你说话 | 灰（`--act-color-text-faint`） |
| 已完成 | 你或协调 Agent 标记 | 空心圈 |

这些颜色用在状态胶囊和标签页的点上。右栏的行不带状态点，只有「等你处理」的分组条是琥珀色。

**翡翠绿只用于运行与成功，琥珀只用于等你处理。** 全部走主题 token，深浅两套主题各自成立。

### 5.6 术语在界面上的位置

- 标签栏第一个：「支付链路提速」（Space 名字，不写「协调 Agent」）
- 输入框左下：「Sonnet 5 · 协调」/「Sonnet 5 · 工作 Agent」
- 右栏分段标题：「Agents」「库」「记忆」
- 右栏分组标题：「等你处理」「运行中」「空闲」「出错」「已完成」
- 不出现：「线程」「主会话」「派活」这类内部说法

## 7. 后端与运行时（后续再定）

本次只做前端。以下已经在设计里假定成立，但实现方式留到前端定稿之后：

| 项 | 设计假定 | 待定 |
| --- | --- | --- |
| 数据模型 | `SessionMeta.space`、lineage `origin: "space"` | 具体字段与迁移 |
| 工作 Agent 执行 | 复用完整会话 | 与现有 run 生命周期的接法 |
| 工作树隔离 | 按 D2 自动判断 | 分支命名、冲突处理、清理时机 |
| 记忆注入 | 开工时快照 + 按轮追加增量（保护 prompt cache） | 增量的边界与失败重试 |
| 记忆写入权 | 只有协调 Agent 能写 | 提议的传递方式 |
