## 0. 一句话

**Space 是围绕一个目标长期运作的容器：你只和主会话说话，主会话把要动手的事派给线程并行去做；指令、记忆和产物沉淀在 Space 里，下一个线程直接站在前面的结果上开工。**

## 1. 命名

| 概念 | 界面名 | 代码 / 协议名 | 说明 |
| --- | --- | --- | --- |
| 容器 | Space | `Space` | 不翻译，与产品名 actspace 同源 |
| 协调对话 | 主会话 | `coordinator` | 每个 Space 一个，长期存在 |
| 工作单元 | 线程 | `thread` | 一个完整的 actspace 会话 |
| 右栏汇总 | 概览 | `overview` | 线程 / 库 / 记忆 三个页签 |
| 用户写的规则 | 指令 | `instructions` | 等价于 Space 级 AGENTS.md |
| 模型记下的事实 | 记忆 | `memory` | 逐条，可改可删 |
| 文件与产出 | 库 | `library` | 磁盘上的真实目录 |

## 2. 已确定的决策

2026-10-02 讨论确认：

| # | 问题 | 决定 |
| --- | --- | --- |
| D1 | 主会话的工具边界 | **只读 + 派活**：可读文件、搜索来回答简单问题；可开线程、给线程发消息、读线程状态、写记忆。不能写文件、不能执行命令 |
| D2 | 多线程改同一 git 仓库 | **自动判断**：一个目录只有一个线程在写时直接改；第二个要写的线程自动开工作树（`space/<slug>` 分支）。非 git 目录一律直接改 |
| D3 | 线程在左栏的可见性 | **只在 Space 内显示**：左栏只有 Space 行与「等你处理」计数，线程不进工作区会话列表 |
| D4 | 场景侧重 | **编码为主，兼顾文档**：线程结果突出改动与 Review，库以产物和文档为主 |

## 3. 概念模型

```
Space ─┬─ 目标（一行，可空）
       ├─ 上下文：1..n 个工作区目录 + 添加的文件
       ├─ 指令（用户写）  ─┐
       ├─ 记忆（主会话写） ─┴─▶ 线程启动时注入快照，之后按轮次追加增量
       ├─ 库：<dataRoot>/spaces/<id>/library/
       ├─ 主会话 × 1  ── 只读 + 派活
       └─ 线程 × n    ── 完整会话；各自落在一个目录（必要时一个工作树）
```

### 3.1 主会话与线程的职责

| 能力 | 主会话 | 线程 |
| --- | --- | --- |
| 和你对话 | ✓ | ✓（右栏线程详情里的输入框） |
| 持有指令与全部记忆、看得到所有线程 | ✓ | 启动时拿快照，之后只看自己的工作 |
| 开线程、给线程发消息 | ✓ | ✗（线程不能再开线程） |
| 读文件、搜索 | ✓ | ✓ |
| 写文件、执行命令、浏览器 | ✗ | ✓ |
| 用子 Agent 拆分自己的任务 | ✗ | ✓（沿用现有子 Agent） |
| 写记忆 | ✓ | ✗，只能在交回结果时**提议**，由主会话决定 |
| 审批请求 | 不代答 | 在线程里原地弹出 |

只有主会话能写记忆，这样多个线程不会同时写出互相矛盾的条目。每次写入都在主会话里显示一条「记下了：…」并带撤销。

### 3.2 线程 = 完整会话

现有子 Agent 只运行一次、只读，也不能直接对话，撑不起线程。线程直接复用会话：

- `SessionMeta` 增加 `space?: { spaceId, role: "coordinator" | "thread" }`；journal lineage 的 `origin` 增加 `"space"`。
- 线程沿用现有的审批、工具流、Review、上下文压缩、消息队列，不新做执行通道。
- 线程只属于一个目录（与现有会话「单 `workspaceRoot`」一致），由主会话派活时选定。
- 隔离按 D2：派活时检查该目录是否已有活跃的写入线程，有则走现有「新建工作树」能力。

### 3.3 线程状态

由会话状态派生，不新增运行时状态机。只加一个用户态字段 `resolved`。

| 分组 | 进入条件 | 状态点 |
| --- | --- | --- |
| 等你处理 | `waiting_approval`、线程向你提问、`failed` | `warning`；失败用 `danger` |
| 进行中 | `running` | `operational` 脉冲 |
| 空闲 | 一轮结束，未标记完成 | `text-faint` |
| 已完成 | 你或主会话标记完成；7 天无活动自动收起 | `text-subtle`，可「重新打开」 |

RunSpace 草案中的「待审查 / 落地中」不再单独成组。actspace 没有托管 PR 平台，有改动的线程在行尾显示 `+48 −12`，详情里提供 Review / 合并入口。

### 3.4 指令与记忆

- **指令**：纯文本，存为 `<dataRoot>/spaces/<id>/SPACE.md`，上限 16000 字符。它是用户级 AGENTS.md 和工作区 AGENTS.md 之后的第三层。
- **记忆**：逐条存储 `{ id, text, sourceThreadId?, createdAt, updatedAt }`，在概览「记忆」页签可读可改可删。
- **线程获取方式**：启动时注入「指令 + 全部记忆」快照；运行期间有新增或修改时，在该线程下一轮用户消息之前追加一条增量。线程里显示分隔行「已同步 2 条新记忆」。增量只往后追加，不重写前缀，不破坏提示词缓存。

### 3.5 库

- 库是真实目录 `<dataRoot>/spaces/<id>/library/`，分 `artifacts/`（线程产出）与 `added/`（你添加的）。
- 线程默认把文档类产物写到 `artifacts/`；代码改动仍留在各自目录或工作树，库里不复制代码。
- 线程消息里的产物卡片与库条目指向同一文件。索引记录 `sourceThreadId`，从库可跳回生成它的线程。
- 打开文件复用右栏现有的 Markdown / HTML / 图片 / CSV 渲染视图。

## 4. 布局

沿用现有三栏底座（左栏 260 / 中栏 ≥560 / 右栏可开合），不新开布局。

```
┌ 左栏 ──────────┬ 中栏：主会话 ────────────────────┬ 右栏：概览 ──────────────────┐
│ 新建会话        │ ◆ 支付链路提速                    │ 线程 ① · 库 · 记忆        ×  │
│ 扩展            │   把 checkout p75 降到 200ms 以下  │ 1 个线程等你处理              │
│ Space        +  │                  [概览•] [⚙] [···] │ ▾ 等你处理 1                  │
│ ◆ 支付链路提速 ① │ 你：……                            │   ● quote N+1 修复  需要审批   │
│ ◆ v1 接口下线   │ 主会话：开了 2 个线程             │ ▾ 进行中 2                    │
│ 已置顶          │  ● quote N+1 修复 · 等你审批      │ ▸ 空闲 2   ▸ 已完成 3          │
│ 工作区          │  ● web 端报价缓存 · 3/6           │                              │
│ 设置            │ ✓ 记下了：压测只用 staging-2 [撤销]│                              │
│                 │ [ 交代事情，或问一个问题…       ]  │                              │
└─────────────────┴───────────────────────────────────┴──────────────────────────────┘
```

### 4.1 左栏

- 「Space」分区位于主操作之下、「已置顶」之上。分组标题沿用 `NavSectionHeader`，右侧 `+` 新建 Space。
- 行结构 `[图标 14 | 名称 1fr | 计数]`，与工作区行同构。图标是用户选的字形 + 颜色，属于身份数据。
- 计数只表达「等你处理」，用琥珀色数字；有线程在跑而无人等你时，图标右上角显示翡翠绿小点。
- 线程不在左栏出现（D3）。超过 8 个 Space 时用 `See more`。

### 4.2 中栏：主会话

- chrome 中列：Space 图标 + 名称，第二行灰色目标；右侧 `概览` 开关（有待处理时带琥珀点）、`⚙` Space 设置、`···`。
- 输入框复用 Composer，占位符「交代事情，或问一个问题…」，模型档位单独显示为「主会话 · 模型 · 档位」。
- 消息流里新增四种块，都复用现有消息排版：

| 块 | 出现时机 | 内容 |
| --- | --- | --- |
| 线程引用 | 主会话开线程或转交消息时 | 状态点 + 线程名 + 当前步骤；点击在右栏打开该线程 |
| 线程结果 | 线程一轮结束并交回 | 一句结论 + 改动 `+N −M` / 产物卡片 + 动作（查看 Review、打开产物、继续） |
| 记忆提示 | 主会话写入或修改记忆 | 「记下了：…」+ 撤销 |
| 建议线程 | 新 Space 欢迎页，或主会话判断应先确认再开工 | 若干条建议，每条「开始」/ 忽略，底部「全部开始」 |

- 转交给已有线程时，在你的消息下方显示「↳ 已转给 quote N+1 修复」。

### 4.3 右栏：概览

- 进入 Space 时默认打开，中栏与右栏约 1 : 1（右栏默认 50%，最小 360）。普通会话的右栏默认 390px，放不下一段线程对话。
- 页签：**线程**（默认）/ **库** / **记忆**。没有「例行」：现在没有定时能力，不放灰色占位。
- **线程页**：顶部一句状态摘要（「1 个线程等你处理」），按 §3.3 分组，可折叠。行内容为状态点、标题、副行（当前步骤或阻塞原因）、所在目录或工作树、改动 / 产物计数、相对时间。
- **线程详情**：点击线程行后在右栏原位替换，顶部是路径导航「线程 › 名称」。
  - 元信息：目录、分支或工作树、模型、档位。
  - 操作：标记完成、在主区打开、`···`。
  - 正文：完整对话，最上方是「主会话交代」卡片，说明这个线程为什么存在。
  - 审批卡片在这里原地弹出。
  - 底部：线程自己的输入框，占位符「引导这个线程…」。消息直达线程，不经过主会话。
- **库页**：类型筛选（全部 / 产物 / 我添加的）+ `添加`。按目录分组列出，产物行带来源线程；点开后在右栏预览，可跳回来源线程。
- **记忆页**：上半部分「指令 · 你写的」，可编辑；下半部分「记忆 · 它记的」，逐条列出来源与时间，悬停出现编辑 / 删除。

### 4.4 新建 Space

对话框只有三项，规则类内容留到创建后的指令里：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 名称 + 图标 | 是 | 图标按钮打开字形 / 颜色浮层 |
| 目标 | 否 | 一行；显示在主会话标题下，主会话据此判断要不要开线程 |
| 上下文 | 否 | 添加工作区目录（可多个）和文件；文件复制到 `library/added/` |

创建后，主会话发一条欢迎消息，并给出建议线程。如果挂了 git 目录，可建议一个只读的「熟悉代码库」线程，让空 Space 有第一件可做的事。

### 4.5 Space 设置

复用设置中心的内嵌分组样式，以对话框打开：

- **通用**：名称、目标、图标；主会话模型 / 档位；线程模型 / 档位；同时运行的线程上限（默认 3）。
- **上下文**：目录列表、各目录当前的写入线程、隔离策略说明（D2）。
- **用量**：线程数、总 Token、缓存命中率、主会话占比、按线程列表。统计复用现有使用统计口径，Space 只按 `spaceId` 汇总，不重复计数。

## 5. 关键交互

1. **消息路由**：主会话收到消息后有三种去向，必须让你看得出走了哪一种：
   - 直接回答：只读工具够用时。
   - 开新线程：消息下方出现线程引用。
   - 转交已有线程：出现「↳ 已转给 …」。
2. **审批不越级**：线程的审批只在线程里处理。主会话最多告诉你「quote N+1 修复 在等你审批」并给一个打开入口，不提供代答按钮。
3. **调节靠对话**：并发数、汇报频率、是否先给方案，主要靠跟主会话说。设置里只放「线程上限」这一个最常用的。
4. **完成与重开**：线程标记完成后收进「已完成」。已完成的线程在详情里点「重新打开」，或主会话向它转交新消息，都会让它回到活跃分组。

## 6. 首版范围

**做**：
- Space 增删改与左栏分区
- 主会话（只读 + 派活工具，以及四种消息块）
- 线程作为完整会话：自动隔离、状态分组、线程详情与线程输入框
- 概览：线程 / 库 / 记忆
- 指令与记忆注入
- Space 设置

**不做**：
- 主会话完全自主拆分并启动大量线程。首版靠你明确说「开 N 个线程」，或点建议卡片的「开始」
- 定时任务 / 例行
- 分享与多人协作
- 手机端与远程控制
- 产物局部评论
- 跨 Space 的记忆检索
- 云端执行
