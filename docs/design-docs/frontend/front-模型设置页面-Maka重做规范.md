# 模型设置页面 Maka 风格重做规范

> 2026-09-06 范围更新：分析观测功能与专用 Analysis / Trace 接口已退役。下文保留该页面或验收其入口的原计划条目已失效；Journal、聊天、Trajectory、Context 与 Usage 仍保留。

## 文档状态

- **状态**：已确认，实施中。
- **适用范围**：ActSpace Desktop 设置中心的“模型”页面，包括连接列表、连接详情、添加服务目录、连接配置和模型目录。
- **上位规范**：`front-设置中心重构规范.md`、`front-全局视觉语言规范.md`、`front-主题与配色规范.md`。
- **参考证据**：`tmp/maka/apps/desktop/src/renderer/settings/providers-panel.tsx`、`provider-catalog-page.tsx`、`provider-connection-detail.tsx`、`settings-route-header.tsx`、`settings-rows.tsx`。

本文是 ActSpace 模型页面的具体实现规范。它参考 Maka 的页面语法和交互，不复制 ActSpace 不具备的 Runtime Host、账号订阅和远程能力。

## 1. 重做目标

当前模型页面的问题不是某个颜色或间距，而是用户模型错误：Provider 连接、余额、接入信息和模型目录被堆成多层卡片，配置流程被拆成卡片与 Dialog，用户看不到“我现在处于连接列表、连接详情还是服务商目录”。

重做后的模型页面必须让用户在一个连续流程中完成：

```text
连接列表 → 添加服务目录 → 连接配置 → 连接详情 → 模型管理
```

视觉目标是 Maka 的安静、连续、低装饰设置页：列表优先、路由优先、开放式行优先，卡片只用于真正独立的摘要或警告。

## 2. 参考结论

### 2.1 直接采用

| Maka 机制 | ActSpace 采用方式 |
| --- | --- |
| `ProvidersPanel` 的 list / catalog / setup / detail 路由 | 模型页面内部状态路由，所有子页共用页面壳层 |
| `SettingsRouteHeader` | 子页统一使用返回、图标、标题和副标题 |
| Provider catalog 的搜索与分类 | 添加服务目录使用搜索和筛选，服务商使用平铺列表 |
| `SettingsRows` / `SettingsExpandableRow` | 连接详情使用两列开放式设置行，短值默认只读，编辑时局部展开 |
| Provider connection detail | 连接、请求设置、模型和删除操作分区展示 |
| 空态、Banner、retry 和 loading 状态 | 每个异步路由都有明确的加载、空、错误和恢复状态 |

### 2.2 明确不复制

- 不增加 `Local`、Runtime Host、远程项目或账号订阅选择器。
- 不引入 Maka 的 Bot Chat、记忆、宠物、每日回顾等功能。
- 不把图片生成、图片分析和联网搜索伪装成普通文本模型连接。
- 不改变 ActSpace 的 Provider、ModelKey、凭据存储、Session Journal 或 Usage 数据边界。

## 3. 页面层级与布局

### 3.1 标题层级

模型页面及其子路由共享同一个页面级标题：

```text
h2 模型
├── h3 模型连接
├── h3 添加连接
├── h3 连接详情标题（当前 Provider 名称）
└── h3 模型目录
```

规则：

- 页面主内容区域始终只有一个页面级 `h2`。
- 连接列表、目录、详情和模型目录是页面内的 `h3` 路由分组。
- 连接详情里的“连接”“高级请求设置”“模型”“删除连接”使用 `h4`，Provider 名称仍使用 `h3`。
- Dialog 内部的 `h2` 只属于 Dialog 局部语义，不计入页面标题。
- 子路由切换时不重复渲染第二个“模型”大标题。

### 3.2 页面壳层

```text
┌──────────────┬──────────────────────────────────────────────┐
│ 设置导航     │ 模型                                         │
│              │ 模型连接、API key 与模型目录管理。           │
│              │                                              │
│              │ 当前路由内容                                 │
└──────────────┴──────────────────────────────────────────────┘
```

- 设置侧栏继续由 `SettingsNav` 管理。
- 内容列使用稳定的宽度和左边缘，桌面端建议 `max-width: 880px`，不使用当前过窄的 `720px` 卡片列。
- 页面标题、路由标题和列表内容共享同一左边缘。
- 页面背景使用主题 token，连接行使用开放表面和 hairline 分隔线。
- 不用“白底大卡片套灰底小卡片”的默认组合。

## 4. 四种路由状态

### 4.1 连接列表 `list`

```text
模型
模型连接、API key 与模型目录管理。

模型连接 · 2                                      添加连接

[图标] DeepSeek        默认
       DeepSeek · deepseek-v4-flash                    ›
──────────────────────────────────────────────────────
[图标] OpenRouter
       OpenRouter · openai/gpt-5.6-luna                 ›
```

连接行规则：

- 整行可点击进入详情。
- Provider 图标、名称、默认标记、已启用模型摘要和状态是主要信息。
- 列表行不显示测试、编辑、删除等操作按钮，只保留右侧方向箭头；所有管理动作进入详情页。
- Logo 使用 Provider 官方/品牌图形，放在中性背景盘中，不能用通用 Lucide 图标替代。
- Logo 映射必须通过显式 Provider registry；未知 Provider 使用中性占位标识，禁止复用其他供应商 Logo。首批十家 API Key 供应商品牌资源已接入；资源出处与许可证见 `apps/desktop/src/renderer/assets/provider-marks/README.md`。自定义连接按 catalogId 选择品牌，不能用 runtimeProviderId 推断品牌。
- 余额、Base URL、代理和凭据状态不在列表中展开。
- 不使用“官方 API / 第三方兼容”作为视觉分组；兼容性作为行内辅助信息或详情内容。
- 连接数量显示在 `h3` 标题旁，不创建额外统计卡片。
- 添加按钮使用主题 action，文案为“添加连接”。

### 4.2 添加服务目录 `catalog`

```text
←  添加连接
选择一个服务商，然后配置 API Key 和连接参数。

[⌕ 搜索服务商                         ]       全部 ▾

[图标] DeepSeek
       DeepSeek 官方接入                              ›
──────────────────────────────────────────────────────
[图标] Kimi
       Moonshot 官方接入                              ›
```

- 目录是页面路由，不使用选择 Provider 的 Dialog。
- 搜索框自动获得焦点，支持中文名、英文名、描述和 Provider ID。
- 服务商使用整行列表，行高不低于 64px。
- 空结果必须提供清除搜索动作。
- 返回时保留搜索关键词和筛选条件。

### 4.3 连接配置 `setup`

```text
←  连接 DeepSeek
完成必要配置后，连接会出现在模型页上方。

API Key · 必填
[输入或粘贴 API Key                              ◉]

展开高级连接设置                                    ⌄

取消                                      保存供应商
```

- 配置页是页面路由，不使用普通 Dialog。
- API Key 输入提供显示 / 隐藏控制，但任何已保存 Key 都不回显。
- 内置连接把 Base URL、代理和 OpenRouter Management Key 放入默认折叠的“高级连接设置”。编辑已有连接时展开现有配置。
- Header/额外 JSON 尚无完整编辑与持久化链路，本阶段不展示其编辑按钮。
- 兼容连接按顺序展示 Key、连接标识、显示名称、服务地址、默认模型；预设自动填写后四项，编辑时连接标识锁定。
- 首次配置缺少必填 Key 时，错误显示在字段附近。
- 保存成功后回到连接列表；保存失败保留草稿并显示错误。新连接行的精确焦点恢复仍作为最终键盘验收项。
- 取消从目录进入时返回目录，从列表快捷进入时返回列表。

### 4.4 连接详情 `detail`

```text
←  [图标] DeepSeek        默认

连接
密钥只保存在本机                              模型密钥   更换

高级请求设置
为请求添加自定义 Header                        自定义请求头  编辑
额外请求体（JSON）                             未设置      编辑

模型
这些模型会出现在任务的模型选择器中             [模型选择器]
                                              测试连接  更新模型目录

──────────────────────────────────────────────────────
删除连接                                      删除
```

- 详情不使用外层卡片、余额卡片或信息卡片。
- 详情路由保留页面级 `h2 模型` 和副标题，只在内容区增加 Provider 路由头；不能把 Provider 名称提升为新的页面标题。
- 路由头只包含返回箭头、品牌 Logo、Provider 名称、默认标记、连接状态和副标题，不放测试、编辑、移除操作组。
- 连接状态、余额和凭据状态作为行式信息呈现。
- 余额只在详情页显示，并保留刷新、失败和上次结果。
- 余额使用紧凑的两列设置行，不使用占据大面积的灰色卡片；左侧为余额与刷新说明，右侧为数值和刷新动作。
- 接入地址和代理仍属于连接分区，但使用普通设置行，不额外创建摘要卡片。
- 高级连接设置使用左侧说明、右侧值与操作结构，当前只提供服务地址和代理的真实编辑入口。
- 删除连接固定在详情底部危险分区，按钮文案为“删除”，确认弹窗才使用“移除服务商”作为破坏性确认动作。
- 普通编辑使用行内展开或独立子页，不能退回到“所有操作都弹 Dialog”。
- 删除操作固定在底部危险分区，明确说明模型定义、Session、Journal 和历史 Usage 会保留。

## 5. 模型目录与模型能力

模型目录属于模型页面，但不是连接列表下方的无限滚动卡片。

- 连接详情的“模型”分区使用单一多选下拉，显示当前启用模型名称；下拉支持搜索、全部启用和逐项勾选。
- 多选下拉关闭后只保留一行摘要，不把模型逐项开关堆叠在详情首屏。
- “更新模型目录”触发已有 Provider 模型发现能力。
- 非嵌入式模型目录仍可使用开放式模型行，用于显示上下文、来源、能力、凭据和删除等高级管理信息。
- 每行显示模型名称、API Model、上下文窗口、来源和能力状态。
- 启用状态使用现有主题 Toggle，删除只对可删除来源显示。
- 模型引用始终使用 Provider-qualified `ModelKey`，禁止以裸模型名称作为唯一键。
- 任务默认模型仍属于“通用”，模型页面不显示任务默认选择器。

## 6. 交互与状态

### 6.1 路由状态

```ts
type ModelRoute =
  | { kind: "list" }
  | { kind: "catalog"; query: string; category: CatalogCategory }
  | { kind: "setup"; provider: LlmProviderId; origin: "list" | "catalog" }
  | { kind: "detail"; provider: LlmProviderId };
```

- 路由状态只保存在 renderer 页面状态，不写入设置数据。
- 返回目标由 `origin` 决定，不通过全局历史栈猜测。
- Provider 被其他窗口删除时，详情路由退回列表并显示可恢复状态。
- 路由切换后焦点进入路由头或首个主要控件。

### 6.2 异步状态

所有列表、目录、余额、模型发现和保存动作必须区分：

- 初始加载：使用三条单列连接行骨架，行高与正式列表一致，包含 Logo、两行文字和箭头占位；不使用卡片网格。骨架与连接列表互斥，本地连接设置读完后立即替换。远程余额独立加载，其延迟或失败不得阻塞列表和添加连接入口。
- 成功：显示真实数据和下一步动作。
- 空态：说明原因并提供主动作。
- 失败：错误靠近受影响内容，保留重试入口。
- 保存中：禁用重复提交，保留当前表单草稿。
- 保存成功：更新连接列表，不泄露密钥。

### 6.3 操作反馈

- 所有可点击连接行在按下时有轻微 scale 或背景反馈，频繁导航不使用页面动画。
- 普通路由切换不做大幅滑动动画。
- 余额刷新仅对刷新图标使用旋转状态，并遵守 reduced motion。
- 目录搜索不使用延迟弹跳或自动滚动。

## 7. 数据与安全边界

保留现有数据和 IPC，不因视觉重做重新设计存储：

- API Key、Management Key、搜索 Key 和图片 Key 只在 main / secret store 可用。
- renderer 只接收凭据存在状态、连接状态和脱敏地址。
- 断开或删除连接不删除 Model definition、Session、Journal 或 Usage。
- 失效模型保留原引用并显示原因，不静默换成另一个模型。
- Provider 余额、代理和模型发现继续使用现有 typed preload API。
- `tmp/maka` 只作为参考源码，不参与 ActSpace runtime、构建或数据目录。

## 8. 响应式和可访问性

- 桌面宽度 1280px：内容列稳定、列表不压缩，详情两列设置行保持标签和控件对齐。
- 375px：详情行折叠为上下结构，操作按钮自然换行，触控目标至少 40px。
- 所有图标按钮提供 `aria-label`。
- 连接行使用真实 `<button>`，详情分组使用语义标题。
- 目录搜索、返回、保存、取消和删除动作支持键盘操作。
- Dialog 仅用于真正需要确认的危险操作，必须有焦点陷阱和恢复焦点。

## 9. 当前实施边界

2026-09-06 用户最终确认覆盖此前目录范围：Moonshot、DeepSeek、MiniMax、OpenAI、Anthropic、Z.AI、Xiaomi、火山方舟 Coding Plan、OpenRouter；接着排列自定义服务（OpenAI Chat）、自定义服务（OpenAI Responses）、自定义服务（Anthropic）。十二个入口共用 Logo、标题、描述与箭头的平面列表行。分类提供全部、官方直连、Coding Plan、第三方兼容、自定义；不增加 OAuth 登录。

自定义三种协议对应 openai-completions、openai-responses、anthropic-messages。每条连接持久化协议，生成独立连接标识；未含协议的旧连接保持原 Chat 行为。默认模型在保存时进入连接自己的已安装模型目录，不修改任务默认模型。同协议/同模型的多条连接不能相互覆盖。新预设和自定义连接首版使用手填模型，不声称已实现自动发现目录。

新建连接表单将连接标识放入高级设置，空值由主进程生成；普通区域顺序为 Key、显示名称、服务地址、默认模型。编辑时协议与连接标识固定，Key 留空保留。已有 xAI/Mistral/Qwen/Groq 连接不删除，只从添加目录移除预设。

第一阶段只实现真实可用的 API Key 连接，不实现 OAuth 或订阅登录流程。

- 内置连接为 Moonshot、DeepSeek、OpenRouter，其余六家及三种自定义协议使用独立 connectionId。存储保留历史 kimi/openrouter 命名空间，显示名称与传输协议独立，不能从命名空间推断协议或借用默认 Key。
- OpenAI 使用 Responses；Anthropic 使用 Messages；MiniMax、Z.AI、Xiaomi、火山方舟 Coding Plan 使用 Chat。Coding Plan 使用专用 Key 及专用服务地址，不属于 OAuth 登录。
- OAuth、订阅和其他帐号型供应商先不展示，避免出现只能进入但无法保存的假连接。
- API Key setup 使用 Maka 的单页路由表单：路由头、必填 Key、普通高级设置行和主题主按钮。
- 供应商目录和连接列表使用扁平行，不使用外围圆角卡片，不在列表放测试、编辑、删除按钮。
- 后续扩展供应商前，必须先为其补齐 Provider registry、logoKey、凭据能力和 IPC/runtime 支持。

## 10. 验收标准

### 视觉

- 连接列表不再出现 Provider 大卡片、余额嵌套卡片和信息嵌套卡片。
- 添加目录、配置页和详情页与 Maka 截图的布局语法一致。
- 页面首屏可以通过标题和行摘要理解当前状态，不依赖滚动寻找主要动作。
- 页面主内容只有一个 `h2`，分组为 `h3`，子分组为 `h4`。

### 功能

- 可从连接列表进入详情并返回。
- 可从添加连接进入目录、搜索 Provider、进入配置并保存。
- 可测试连接、刷新余额、编辑连接和删除连接。
- 可在详情中查看和管理模型目录。
- 通用页继续承载任务默认模型和媒体默认选择。

### 工程

- 保留现有 Provider / Model IPC 和安全边界。
- 新增路由和标题契约测试。
- 通过 Desktop typecheck、renderer 测试和 Desktop build。
- 完成浏览器 Renderer 截图检查，并在可用时完成 Electron 窗口验收。

## 10. 明确不做

- 本阶段不增加 OAuth/订阅协议；目录预设不等同于新增专用运行时适配器。
- 不改变 `SettingsV4`、`ModelKey` 或 Session Journal schema。
- 不把分析观测页面并入模型页。
- 不为了模拟 Maka 而添加 ActSpace 当前不存在的环境选择器或远程账号能力。
- 不保留旧 Provider 卡片作为第二套并行 UI。
