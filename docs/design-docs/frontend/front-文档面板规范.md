# 文档面板规范

「MD 文档」面板是右侧面板里**唯一的文件阅读入口**，取代原来的工作区文件树。它只处理 Markdown：Markdown 是人和 Agent 共用的语言，Agent 能直接读写，人也能直接阅读；其他文件交给系统默认应用或各自的 Tab。正文的预览与源码编辑器是 CodeMirror 6，渲染与编辑规则见 [front-Markdown编辑与渲染规范.md](front-Markdown编辑与渲染规范.md)，本文管面板的布局、文件树、操作栏、草稿保存、新鲜度与打开入口。右侧面板整体见 [front-右侧面板与文件渲染规范.md](front-右侧面板与文件渲染规范.md)。

它不是文件管理器：不新建、不重命名、不删除文件。能做三件事：预览、看源码、在预览或源码里编辑并保存。

## 布局

```text
┌ 聊天区 ┐┌──────────── 右侧面板 ────────────┐
│        ││ 标签：上下文 轨迹 后台任务 [MD 文档] 改动│
│        ││┌──────── 正文 ────────┐┌─ 文件树 ─┐│
│        │││ 路径    [大纲][Finder][打开][复制][⇤]││ 搜索     ││
│        │││  Markdown 正文        ││ 全部/本会话││
│        │││                      ││ 目录树   ││
│        ││└──────────────────────┘└──────────┘│
└────────┘└───────────────────────────────────┘
```

- 从左到右是聊天 → 正文 → 文件树：正文紧挨聊天区，视线从消息移到文档不用跨过文件树，文件树作为导航在最外侧。
- 文件树默认宽 260px，可收起；收起按钮在正文操作栏最右端，离文件树最近。文档标签自己的默认宽度 720px（`WorkbenchLayout`）。
- 右侧面板可展开盖住聊天区专心阅读（`rightExpanded`），再点一次还原；展开时顶栏中间的会话标题和中间栏操作隐藏（`data-right-expanded`），避免与面板标签行叠在一起，顶栏空白处仍可拖动窗口。
- 大纲收在操作栏的「大纲」按钮里（点开是浮层），正文保持最大宽度，不做右侧常驻大纲栏。

## 文件树

### 显示什么

- 保持原有目录结构，**只列 Markdown**（`.md`、`.markdown`）；不含 Markdown 的文件夹（含所有子孙层都没有的）整个隐藏；按 `.gitignore` 排除，不列依赖目录里的 README。
- 文件夹右侧显示其中 Markdown 篇数；同级文件夹在前、文件在后，各自按名称排序。

### 数据从哪来

一次性取得整棵 Markdown 清单，再在前端组装成树（`workspaces.listMarkdownFiles`）：

- git 仓库：`git ls-files --cached --others --exclude-standard -- '*.md' '*.markdown'`，天然遵守 `.gitignore`、能列出未提交新文件、只有一次进程调用。
- 非 git：退回有上限的递归遍历（5000 篇 / 50000 个目录项），跳过 `.git`、`node_modules`、`dist`、`.next`、`.turbo`、`coverage` 和以 `.` 开头的目录。遇到**本身是 git 仓库的子目录**（含 `.git`）不再逐项遍历，改在该目录里跑同一条 `git ls-files`，遵守它自己的 `.gitignore`，也不会因为工作区里放了几个完整仓库就把遍历上限用光。
- 超过上限时停止，后端返回 `truncated` 和没走完的顶层目录 `incompleteDirs`（最多 20 个）。树顶篇数写成「N+ 篇」；树底固定一条 warning 提示「工作区太大，A、B 没有列全。」（超过 3 个写「等 N 个目录」），带一个「继续加载」：用放大 4 倍的上限重取（`expanded: true`），之后该工作区的刷新沿用放大上限。放大后仍截断就不再给按钮，改写「已到加载上限，可以把这些目录单独加成工作区。」
- 清单只含相对路径，不读文件内容；不挂文件监听，只在这些时机重新获取：打开文档面板、每轮 Agent 结束、用户点树顶刷新按钮（「刷新文档列表」）、截断后点「继续加载」。

### 搜索与筛选

- 搜索框（「搜索文档文件名」）只按文件名过滤，匹配部分高亮，匹配项所在文件夹自动展开；不搜正文。
- 筛选只有「全部」和「本会话改过」。无结果写「没有匹配的文档」；「本会话改过」下没有改过的 Markdown 写「本会话还没有改过 Markdown」。

### 本会话改过

- 当前会话里 Agent 写过或改过的 Markdown，文件名右侧显示一个绿点（operational 语义色，`aria-label="本会话改过"`）。数据来自会话里已有的 `edit_diff` / `write_diff` 消息块的 `filePath`，换算成相对路径后只保留 Markdown，不新增后端能力。
- 「本会话改过」筛选只显示这些文件及其所在文件夹。不放图例：绿点和筛选按钮同名，含义自明。

### 展开状态

展开层级记在 `RightPanelContext`，不放在文件树组件里（树会随收起、切换标签反复挂载，放组件里会被清空）；换工作区清空；首次打开若有选中文件，自动展开到它所在的文件夹。

## 正文

### 操作栏

左侧是路径（工作区名与目录弱化，宽度不足时先隐藏；文件名主色）；有未保存内容时文件名旁显示圆点（`aria-label="有未保存的改动"`）。右侧依次：

1. 「预览 / 源码」切换。
2. 「大纲」：浮层列出本页 h2、h3，点击平滑滚动到标题；没有标题显示「没有标题」；预览、源码两种状态都可用（标题取自语法树）。
3. 「在 Finder 中显示」。
4. 「用默认应用打开」。
5. 「复制路径」：复制相对路径，tooltip 显示「已复制路径」。
6. 「展开 / 还原面板」与「收起 / 展开文件树」。

面板较窄（容器宽 < 460px）时先收起 Finder / 默认应用 / 复制路径三个次要操作，保证文件名、未保存圆点、展开面板和收起文件树始终可见。

### 预览、源码与编辑

- 打开文件默认是预览。预览和源码**都能直接编辑**，共用同一个编辑器，切换保留光标、撤销历史和滚动位置；两种状态都支持 ⌘F 查找。
- **保存**：⌘S / Ctrl+S，保存后重新读取 `mtime`，不弹成功提示，失败留在原处并显示错误条。切回预览显示的是未保存的当前内容。
- **未保存时离开**：切换到另一篇文档或关闭文档面板时，弹「保存 / 不保存 / 取消」（`DocsLeaveDialog`，挂在 `RightPanel`）。
- **与 Agent 改同一个文件**：以人为准，保存时直接写入，不做冲突检测。编辑期间 Agent 改了文件，照常出现「已变化」提示条（有未保存内容时说明保存会覆盖磁盘版本、重新加载会丢弃未保存改动），但不打断编辑；保存后提示条消失。
- 只写已存在的工作区内 `.md` / `.markdown` 文件（`workspaces.writeMarkdownFile`），不新建文件。超过读取上限而被截断的文件，预览和源码两种状态都只读，并提示「文件过大，请用默认应用编辑」，避免保存时丢掉截断部分。
- 安全边界：原始 HTML 不执行；外链只放行 `http`、`https`、`mailto`；远程图片不加载。

### 性能与新鲜度

- 只读取并渲染当前打开的那一篇，切换文件时释放上一篇；大文件沿用读取上限和「已截断」提示；长文档的增量渲染见 Markdown 编辑与渲染规范。
- 新鲜度由 `use-docs-draft.ts` 实现（等价于文件 Tab 的 `useFileFreshness`，但要同时处理未保存草稿）：Agent 把当前文档新加进「改过」集合、挂载、窗口聚焦、turn 结束这几个时机触发 `statFile` 校验 `mtime`，不轮询。检测到变化只显示提示条，由用户点「重新加载」，不自动替换正在读的内容；文件被删除或越界时显示失效说明。

## 打开入口

- 右侧面板标签「MD 文档」。
- 聊天里的交付卡、文件链接，目标是 Markdown 时打开文档面板并在树中选中、展开到该文件（`components/files/open-workspace-path.ts`）；原工作区文件树的入口全部指向文档面板。

## 空状态

- 没有选择工作区：提示先在顶部选择工作区。
- 工作区里没有 Markdown：正文区显示「这个工作区还没有 Markdown 文档」，文件树为空。
- 未选择文件：正文区提示「从右侧选择一篇文档」。

## 主题与样式

- 只用主题 token 和语义色，浅色、深色都要验过（见 [front-视觉token规范.md](front-视觉token规范.md)）；绿点用 operational 语义色，提示框用 info / success / 正文色 / warning / danger，代码高亮配色随主题翻转。
- 正文的强调色（引用竖条、文件路径、本地链接）默认是信息蓝，与链接色同一条规则，只作用于文档正文，不改应用全局强调色。

## 实施位置

`apps/desktop/src/renderer/` 下：面板外壳、正文区、目录树在 `components/right-panel/docs/`（`DocsPanel.tsx`、`DocsReader.tsx`、`DocsTree.tsx`、`DocsOutline.tsx`、`DocsLeaveDialog.tsx`）；树模型 `docs-tree-model.ts`；清单与草稿 / 保存 / 新鲜度 `use-docs-listing.ts`、`use-docs-draft.ts`；选中、草稿、展开、筛选、清单状态在 `components/right-panel/RightPanelContext.tsx`；编辑器在 `components/markdown-editor/`；展开盖住聊天区在 `components/SplitView.tsx`、`WorkbenchLayout.tsx`、`WindowChromeBar.tsx`；主进程 IPC `workspaces.listMarkdownFiles` / `workspaces.writeMarkdownFile`（`main/workspace-fs-service.ts`，契约在 `packages/util/shared/src/desktop-bridge/`）；浏览器 mock 数据 `mock/docs-fixture.ts`。

## 不做

新建、重命名、删除 Markdown；保存时的冲突检测与差异对比；把「用户改了某文件」告诉 Agent；正文全文搜索；文件监听；右侧常驻大纲栏；非 Markdown 文件的任何应用内渲染（图片预览不属于文档面板，保持原有方式）。
