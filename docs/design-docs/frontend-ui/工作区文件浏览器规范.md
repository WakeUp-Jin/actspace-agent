# 工作区文件浏览器规范

## 定位

在右侧面板里提供一个轻量的「工作区文件浏览器」：左侧一棵可折叠的文件树（rail），点文件在右侧以已有的渲染视图打开成普通 Tab。形态参考 Cursor 编辑器——树常驻在侧边、文件开成 Tab，而不是把树塞进单个 Tab 内。

它服务三类需求：

- 让用户随时翻看**当前会话工作区**里的真实文件（Agent 读过 / 建过 / 改过的产物）。
- 复用已有的 Markdown / 文本 / 图片 / HTML 渲染，统一「看文件」的入口。
- 为后续「消息内 path 点击直达」「会话级 diff 标记」「Kairos 配置编辑」预留同一套数据与组件地基。

本规范只负责文件浏览器本身（树 rail + 文件 Tab + 读盘 IPC）。右侧面板外壳、Tab 系统、各渲染视图的事实来源仍是 `右侧面板与文件渲染规范.md` 及其下属渲染专题（Markdown / HTML / Context）。

## 数据来源与边界

- 文件树的根 = **当前会话的 `workspaceRoot`**（`SessionListItem.workspaceRoot`，缺省由 main 端用 `BootstrapState.workspaceRoot` 兜底）。这与 Agent 文件工具（`read_file` / `list_directory` / `edit_file`）操作的根一致，所见即 Agent 所动。
- renderer **不直接访问文件系统**：树展开与文件读取全部走 preload + IPC（与全仓约束一致，见 `ARCHITECTURE.md`）。
- **UI 浏览强约束在 root 内**：即使读类工具的路径边界在 `workspace-guard.ts` 里被放开（`resolveReadablePath` 不做越界检查），文件浏览器是面向用户的可点界面，必须只暴露 `workspaceRoot` 子树，不允许 `..` 逃逸到整盘。这是浏览器入口和 Agent 读工具的**故意差异**。

## 形态：树 rail + 文件 Tab

- 文件树是**面板级常驻 rail**，渲染在右侧面板内、Tab 区左侧：`[文件树 rail][分隔线][Tab 条 + Tab 内容]`。
- rail 可折叠（自带折叠开关）；折叠时把宽度还给 Tab 区。首版宽度固定（约 `220px`），不做拖拽调宽。
- 点击树里的**文件节点**：先走读盘 IPC 取内容，再用稳定 id `file:<相对路径>` 调 `openTab` 开成普通 Tab；重复点同一文件只聚焦不堆叠（沿用现有 Tab 去重模型）。
- 点击**目录节点**：就地懒加载展开 / 折叠，不开 Tab。
- 文件 Tab 的 `kind` 由读盘结果的 `renderKind` 决定，**直接复用现有渲染视图**，不新增视图组件：
  - `markdown` → `MarkdownRenderView`
  - `html` → `HtmlRenderView`，`trust="file"`（本地文件走 strict CSP，见 `HTML渲染与沙箱安全规范.md`）
  - `image` → `ImageRenderView`，`src` 用 data URL
  - `text` → `TextRenderView`。若读盘结果带 `language`（ts/js/css/yaml/json…），用 **highlight.js** 做语法高亮，并复用 Markdown 已有的**主题感知 hljs 配色**；无 `language` / 截断 / 二进制时回退纯等宽 `<pre><code>`。

### 代码高亮的 CSS 复用

现有 hljs token 配色（`--md-hl-*` 变量 + `.hljs-*` 规则）被限定在 `markdown.css` 的 `.markdown-doc` 作用域内。为让代码文件 Tab 用上同一套**随主题翻转**的配色，需把这段 token 配色提取成一个**共享作用域 class**（如 `.act-code-hl`），让 `.markdown-doc` 与代码视图都包含它，避免两处各写一套颜色（违反主题硬约束、且易漂移）。`highlight.js` 是 `packages/desktop` 的直接依赖（无需新增包）。

## IPC 契约

新增两个 invoke 通道，契约定义在 `packages/shared/src/ipc.ts`，preload 暴露到 `window.actspace`，类型补进 `packages/desktop/src/global.d.ts`。

### `workspace:list-dir`（懒加载一层目录）

```ts
export type WorkspaceListDirInput = {
  /** 会话根；不传由 main 用 BootstrapState.workspaceRoot 兜底。 */
  workspaceRoot?: string;
  /** 相对 workspaceRoot 的目录路径，"" / "." 表示根。 */
  relativePath?: string;
};

export type WorkspaceEntryKind = "dir" | "file";

export type WorkspaceDirEntry = {
  name: string;
  /** 相对 workspaceRoot 的 POSIX 路径。 */
  relativePath: string;
  kind: WorkspaceEntryKind;
  /** 文件字节数；目录为 undefined。 */
  size?: number;
};

export type WorkspaceListDirResult = {
  /** 实际使用的根（绝对路径）。 */
  root: string;
  /** 规范化后的当前目录相对路径。 */
  relativePath: string;
  /** 目录在前、文件在后，各自按名字升序。 */
  entries: WorkspaceDirEntry[];
  error?: "not_found" | "not_a_directory" | "escapes_root" | "too_many_entries";
};
```

### `workspace:read-file`（读单个文件）

```ts
export type WorkspaceReadFileInput = {
  workspaceRoot?: string;
  relativePath: string;
};

export type WorkspaceFileRenderKind = "markdown" | "html" | "image" | "text";

export type WorkspaceReadFileResult = {
  relativePath: string;
  renderKind: WorkspaceFileRenderKind;
  /** text / markdown / html：UTF-8 文本；image：空。 */
  content?: string;
  /** image：data URL（base64）；其余空。 */
  dataUrl?: string;
  /** text 类的语法高亮语言（highlight.js 语言 id，按扩展名推断）；无法识别 / 截断 / 二进制时缺省，渲染回退纯等宽。 */
  language?: string;
  size: number;
  /** 文本超过大小上限被截断。 */
  truncated?: boolean;
  error?: "not_found" | "not_a_file" | "too_large" | "binary" | "escapes_root";
};
```

## main 侧服务规则

落在 `packages/desktop/src/main/workspace-fs-service.ts`，两个导出函数 `listWorkspaceDir` / `readWorkspaceFile`，由 `main/index.ts` 注册成 IPC handler。

- **根解析**：`workspaceRoot = input.workspaceRoot ?? roots.workspaceRoot`。所有相对路径基于该根 `resolve`。
- **越界保护**：复用 `guardWorkspacePath` 语义——`relative(root, abs)` 以 `..` 开头或为绝对路径即返回 `escapes_root`，**不读盘**。浏览器入口必须收口在 root 内。
- **目录忽略名单**（常量 denylist，避免一次性铺开大目录）：`node_modules`、`.git`、`.pnpm-store`、`dist`、`.next`、`.turbo`、`coverage`、`.DS_Store`。`.gitignore` 解析放 V2，V1 先用固定名单足够。
- **条目上限**：单目录列出超过 `1000` 条时截断并返回 `too_many_entries`（防超大目录卡 UI）。
- **排序**：目录在前、文件在后，各自 `localeCompare` 升序。
- **文件大小上限**：文本类 `2MB`，图片类 `5MB`；超限 `too_large`。
- **renderKind 判定**（按扩展名小写）：
  - `.md` / `.markdown` → `markdown`
  - `.html` / `.htm` → `html`
  - `.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.svg` → `image`（读 bytes → base64 data URL）
  - 其余 → `text`
- **语言推断（text 类）**：`renderKind === "text"` 时按扩展名映射 highlight.js 语言 id 回传 `language`，供前端语法高亮：
  - `.ts` / `.tsx` / `.mts` / `.cts` → `typescript`
  - `.js` / `.jsx` / `.mjs` / `.cjs` → `javascript`
  - `.css` → `css`；`.scss` → `scss`；`.less` → `less`
  - `.yaml` / `.yml` → `yaml`；`.json` / `.jsonc` → `json`；`.toml` → `toml`
  - `.sh` / `.bash` / `.zsh` → `bash`；`.py` → `python`；`.go` → `go`；`.rs` → `rust`；`.sql` → `sql`
  - 其余未在表内的扩展名：不回传 `language`，前端按纯等宽渲染（**不做 `highlightAuto` 猜测**，保持确定性、避免误判和性能抖动）。
- **二进制识别**：`text` 类读入后若含 NUL 字节判定为二进制，返回 `binary`（不把乱码塞进 Tab）。
- **截断**：文本超 `2MB` 时截断到上限并置 `truncated: true`，渲染侧给出截断提示。

## 安全约束

- renderer 零文件系统访问，全部经 IPC（与现有 visualize / context describe 同模型）。
- 浏览器只读，不提供写 / 删 / 重命名（V1）。
- 路径越界一律在 main 端拦下，错误码回传由 UI 呈现，不抛原始路径细节到日志噪声。
- 图片用 **data URL**，避免 renderer 直接 `file://` 撞 Electron CSP；HTML 文件走 `trust="file"` 的 strict CSP 沙箱。
- 颜色 / 图标必须走主题 token（`bg-surface` / `border-line` / `text-text-muted` / `bg-brand-soft` 等），禁 `#hex` / `text-black` / `bg-white`，浅深双主题都要验（见 `主题与配色规范.md`）。

## 入口

- 在右侧面板「`+` 新建对象」菜单（`RightPanelObjectMenu.tsx`）新增一项「工作区文件」（图标 `FolderTree` / `Files`）。点击**唤出并聚焦文件树 rail**（而非新增一个 Tab）。
- rail 自身带折叠开关，可随时收起。
- rail 的开关状态由 `RightPanelContext` 持有（如 `isFileTreeOpen` + `toggleFileTree`），与 Tab 列表解耦。

## V1 边界（本期做）

- 只读 + 单 root（当前会话 `workspaceRoot`）。
- `workspace:list-dir` 懒加载目录树（固定忽略名单 + 条目上限 + 目录在前排序）。
- `workspace:read-file` 读单文件（大小上限 + 二进制识别 + 图片 data URL + renderKind 判定 + text 类语言推断）。
- **代码/配置文件语法高亮**：ts/js/css/yaml/json 等 `text` 类文件按扩展名推断语言，用 highlight.js 高亮，复用 Markdown 的主题感知 hljs 配色（共享 `.act-code-hl` 作用域）。
- rail 组件：懒展开、文件夹/文件图标、主题感知、隐藏滚动条（`scrollbar-none`），点文件复用现有渲染视图开 Tab。
- 入口：`+` 菜单「工作区文件」唤出 rail。
- 浏览器 mock 无 IPC 时优雅降级（空态 / 禁用），不报错。

## V3 边界（远期）

- 文件编辑 + 保存：脏标记 / 撤销；写操作过 `guardWorkspacePath` + 审批。
- **Kairos 配置编辑器**：不走通用 fs 写。复用已有带 schema 校验的专用通道 `kairos:read-config` / `kairos:write-config`（4 份：`preferences.json` / `paths.json` / `blocklist.json` / `rule.md`，见 `agent-core/kairos-autonomous-mode.md` 与 `storage-and-observability.md`）。文件树只当导航入口，编辑保存仍走 Kairos 校验通道。

## 已知陷阱

- **性能**：必须懒加载逐层展开，绝不递归整个仓库；忽略名单 + 条目上限是硬要求（`node_modules` 会直接拖垮 UI）。
- **安全 vs 读工具差异**：读工具放开了越界，但浏览器入口必须收口在 root 内，二者是有意不同的策略，不要图省事复用 `resolveReadablePath`。
- **图片 / PDF 的 src**：renderer 不能直接 `file://`，V1 用 data URL；大图受 `5MB` 上限约束。
- **大文件**：读盘要有上限和截断提示，避免把几十 MB 文本塞进 DOM。
- **主题硬约束**：树和图标的颜色容易顺手写死，务必走 token 并在浅深双主题验证。
