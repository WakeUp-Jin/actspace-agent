# 前端设计文档

## 目标

为 `actspace` 设计一套桌面端界面原型。整体气质偏自有品牌，交互参考 Cursor，但视觉不走黑色工作台路线，而是以纯浅色蓝白为主。

## 设计原则

- 简约优先。
- 上下文绝对可见、可控、可收起。
- 所有复杂能力都服务于“让 DeepSeek 拿到更多上下文，做更多事”。
- 组件要像真实桌面应用，而不是网页聊天页。
- 当前阶段优先做大纲，再逐个组件细化。

## 布局策略

- 默认采用三栏结构：左侧会话列表，中间主聊天区，右侧上下文/辅助信息区。
- 初始状态默认只展示两栏，右侧折叠，保留展开入口。
- 中间区域始终是主工作区，承担聊天、工具流和最终回复展示。
- 应用至少包含两种主页面状态：聊天态与设置态。
- 设置态不是聊天态右侧面板扩展，而是独立布局切换。

## 主视觉

- 主色：蓝白。
- 气质：干净、克制、清晰。
- 风格关键词：桌面感、效率感、上下文感、轻量但专业。

## 输入区定义

底部输入区不是单一输入框，而是一个 Composer。

应包含：

- 文本输入框。
- 模式切换。
- 模型展示与选择。
- 附件/链接上传。
- 上下文入口与可视化入口。
- 发送按钮。

## 组件拆分

- 左侧会话栏：轻量列表。
- 中间消息区：消息流和工具流。
- 聊天输入框：模式、模型、附件、Context、发送。
- 右侧面板：文件预览、会话级 diff、Context。

## 消息渲染规范

不同消息类型使用不同组件，按模型执行顺序顺序展示。

- 用户消息：卡片化显示。
- 普通回复：正常文本块显示。
- 思考：默认折叠，点击展开。
- 读取文件：直接显示读取了什么文件。
- 搜索：直接显示搜索参数。
- 编辑：用 diff 显示修改内容，默认只展示 4 到 5 行，点击展开完整 diff。
- 工具调用序列：保持时间顺序清晰可追踪。

## 右侧面板

右侧面板的整体定位已单独拆到 `右侧面板与文件渲染规范.md`。当前文档先保留一个核心原则：

- `Context` 是唯一暂未细化的重点模块。
- 其他对象型内容按各自文件类型渲染。
- 右侧面板采用横向 Tab，支持多个对象并列浏览。

## Context 组件

`Context` 由聊天框底部的“上下文入口与可视化入口”打开，是当前会话的上下文控制面板。

### 组件排序

`Context` 内部组件按竖直方向顺序排列，当前先固定两个子组件：

1. 上下文组成子组件。
2. 上下文统计子组件。

### 上下文统计子组件

当前先展示两类统计信息：

- 会话总 token 消耗数。
- 触发的压缩次数。

后续如果再想到新的上下文管理信息，再继续往下补充。
