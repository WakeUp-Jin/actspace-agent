# 会话浏览按需加载

## 行为

- 文件夹首屏返回最近 10 条未归档会话摘要；Show more 按当前工作区与置顶分组继续取 10 条。列表摘要不携带消息正文。
- 启动恢复最近更新的可见会话；其余会话点击后读取。首次读取和向上加载按 20 个完整 Runtime turn 分页，包括 turn/start 前由 Inbox claim 产生的用户输入。
- 消息列表和正文分别显示加载、错误和重试。历史追加保持滚动锚点；快速切换丢弃过期结果。最近 3 个会话的首屏消息可复用，随后重新验证；已加载的较早消息在当前会话刷新时保留。
- 较大的工具记录（事件集合或工具投影 JSON 达到 24,000 字符）从浏览页拆开；普通工具先显示已有摘要行，点击原有右侧下拉箭头时读取详情，并保持展开状态；不额外显示“展开完整工具结果”文字入口。加载失败后收起并重新展开可重试。Agent / Explore 直接显示紧凑卡片，点击走已有 child Session 详情面板，不用通用加载按钮替换卡片。完整正文没有被改写或删除。屏幕外回合使用浏览器 content-visibility 减少布局绘制。
- 轨迹挂载时显式请求，关闭后普通会话刷新不再生成轨迹；使用统计沿用进入设置页面才请求。

## 派生索引与边界

Runtime 的 projection-cache 先问 storage `refresh(id, base)`，按后端 identity、codec 和 projection 版本判断复用：
- `unchanged`：直接返回上一次的读取结果，不重读整份文件、不重放。JSONL 后端在文件身份、大小、时间戳都没变时，还会重读末尾 4KiB 和上次读到的内容比对：时间戳按时钟刻度前进（Linux 上几毫秒），上次读取所在刻度内的等长改写不会改变时间戳，只看时间戳会把它当成没变。
- `appended`：JSONL 后端从上次读到的字节位置续读（文件身份 dev/ino/birthtime、末尾 4KiB 重叠校验和滚动 sha256 都对上才续读），只校验、重放和索引新增事件；结果与冷读逐项相等。
- `replaced`：文件被改写、截断或修复，按新快照完整重建。

末尾 4KiB 之前的内容按「只追加」信任：那里的原地改写，只有在文件大小不变而时间戳变了的时候才会被发现。Journal 只由持有写入租约的 writer 追加，修复走换文件（文件身份会变），所以这条路径不为它付整份重读的代价。

缓存最多保留最近使用的 3 个会话，并以 96MB Journal 字节为上限淘汰较旧的；最新的一个即使超限也保留。已经交出去的读取结果不会被后续追加改变。存储后端已验证过当前 codec 集的快照，`SessionStore.inspect` 不再重复整份校验。Turn/Request/call 索引在内存中派生，不读取磁盘 checkpoint。

主进程的 `RuntimeSessionController` 只常驻最近使用的 3 个空闲会话，其余关闭句柄（释放 writer lease）并在下次使用时 `resume`。以下会话不算空闲、不会被关闭：正在运行或排队的、有运行中子 Agent 或后台任务的、渲染进程正在显示或订阅的（经 `sessions.setObserved` 上报）、内存会话、打开着的侧边对话的父会话、英语学习的目标会话。释放与重新打开互斥，重新打开会等待正在进行的释放完成。

Journal 仍是恢复、模型上下文和完整导出的唯一事实源。浏览页不能用于 Agent resume。完整复制对话走 getSession，不使用当前加载的消息窗口。批量归档工作区先读取完整摘要集，不只归档已显示的 10 条。

冷读（缓存未命中或被淘汰）仍需完整读取与重放；列表逐会话读取摘要，当前不再使用后台 indexing 状态。37MB 的真实 Journal 冷读约 0.3s，命中约 0.3ms，追加后续读 3–11ms（本机基准，不是性能承诺）。

上下文估算先从完整请求计算，浏览页仅保存紧凑的请求预览和估算结果；不以截短后的预览重新估算 Token。完整 Context 详情仍走现有详情入口。
