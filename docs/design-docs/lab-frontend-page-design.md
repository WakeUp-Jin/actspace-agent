# Lab 前端页面设计

本文档是 Lab 前端页面的设计事实来源。它只约束 renderer 的页面布局、卡片、弹窗和交互边界；Lab 的产品愿景、数据模型、运行架构和晋升安全分别由同目录其他文档约束。

## 当前状态

- 状态：V0 renderer 页面已落地，运行时预置 mock 初始数据已清理；后端 Lab Runtime、IPC 和持久化尚未实现。
- 适用范围：Lab 首页、实验矩阵、阶段卡片、卡片详情弹窗、新实验弹窗、已完成实验弹窗。
- 核心决策：Lab 首页只展示进行中的实验；完成、拒绝、废弃、归档实验进入 `已完成实验` 弹窗。

## 实现边界

- 当前实现位于 `packages/desktop/src/renderer/components/LabPage.tsx`。
- 运行时没有预置实验数据；首屏默认展示空矩阵，新实验只从用户输入生成本地临时卡片。
- 测试样例数据只允许放在 `packages/desktop/src/renderer/test/**` 边界内。
- 样式采用 Tailwind utility 和 `LabPage.tsx` 内局部 class 常量，不新增 `.lab-*` 全局 CSS。
- 当前实现不新增 Electron IPC、preload bridge、main process 存储或 `shared` Lab 契约。
- 刷新页面后创建、编辑、推进、暂停和取消的本地临时状态会重置。

## 页面原则

Lab 首页要像一个实验台，不像普通项目管理看板。

- 四栏矩阵是页面主角。
- 顶部只保留必要操作。
- 页面不展示解释性副标题、全局统计条、搜索、筛选或 Agent 建议入口。
- 卡片只展示关键识别信息，完整属性进入弹窗。
- 细节不挤压四栏布局；详情通过弹窗承载。

## 顶部区域

顶部只保留：

```txt
Lab                                      [已完成实验] [新实验]
```

不展示：

- 搜索。
- Agent 建议。
- 筛选。
- 视图切换。
- 页面解释文案。
- `最近活跃 / 待评审 / 已晋升 / 阻塞 / 今日新增` 这类全局统计条。

原因：

- V0 的核心操作只有创建实验和查看历史实验。
- 统计应长在四列标题里，而不是额外占一行。
- 解释性文字会让实验台显得像产品介绍页，降低桌面工具的直接感。

## 主体：四栏实验矩阵

主体铺满顶部以下的可用空间。

```txt
+----------------------+----------------------+----------------------+----------------------+
| 假说构建      3   +   | 实证验证      2   +   | 能力锻造      2   +   | 晋升评审      1   +   |
+----------------------+----------------------+----------------------+----------------------+
| [主假说]             | [验证中]             | [CLI]                | [待评审]             |
| 让 Agent 锻造 CLI     | 3 组样例验证          | act-log-scan          | 候选 CLI 晋升         |
| CLI · 12m 前          | 证据 5 · 1 失败       | 已验证 · 2 子命令     | 高风险 · 4 检查       |
|                      |                      |                      |                      |
| [草稿]               | [通过]               | [skill]              |                      |
| 失败任务沉淀 skill    | 复盘验证记录          | frontend 验证 skill   |                      |
| Kairos · 昨天         | 证据 7               | 草稿 · 待补充         |                      |
+----------------------+----------------------+----------------------+----------------------+
```

每列标题包含：

- 阶段名。
- 当前进行中卡片数量。
- 添加按钮 `+`。

列标题不写解释性副标题，例如“不写可验证想法 / 证据与复现 / Skill CLI Tool / 风险与批准”。阶段名本身承担语义。

## 主区显示范围

主区只显示进行中的实验或阶段卡片。

不默认显示：

- `promoted`：已晋升。
- `rejected`：已拒绝。
- `abandoned`：已废弃。
- `archived`：已归档。

完成类实验进入顶部 `已完成实验` 弹窗。这样主页面保持“当前实验台”，完成实验进入“档案柜”。

## 阶段卡片

卡片默认只展示三层信息：

```txt
[状态或类型]
标题
元信息
```

示例：

```txt
[主假说]
让 Agent 锻造 Rust CLI
CLI · 12m 前
```

```txt
[验证中]
3 组样例验证
证据 5 · 1 次失败
```

卡片不展示：

- 长描述。
- 成功标准全文。
- 风险说明全文。
- 命令输出。
- 证据列表。
- 产物路径。

这些信息都放进卡片详情弹窗。

## 卡片类型

不同阶段卡片的第三行元信息不同：

| 阶段 | 标签例子 | 标题 | 元信息 |
|---|---|---|---|
| 假说构建 | `主假说` / `草稿` / `阻塞` | 假说标题 | 来源 / 更新时间 |
| 实证验证 | `验证中` / `通过` / `失败` | 验证主题 | 证据数 / 失败数 |
| 能力锻造 | `CLI` / `skill` / `tool` / `doc` | 产物名 | 验证状态 / 子命令或补充状态 |
| 晋升评审 | `待评审` / `已批准` / `驳回` | 评审主题 | 风险等级 / 检查数 |

卡片视觉：

- 圆角 6-8px。
- 白底、细边框。
- 状态用小胶囊表达，不整卡染色。
- 选中或 hover 可以使用细蓝边框或左侧 2px 蓝色线。
- 卡片高度保持紧凑，目标约 82-96px。

## 卡片详情弹窗

点击任意阶段卡片打开详情弹窗。

卡片详情弹窗展示的是“某个阶段卡片的详情”，不是整轮实验详情。因为一行实验包含四个阶段，每个阶段的字段不同。

通用布局：

```txt
+----------------------------------------------------------------+
| 卡片标题                                  [状态胶囊] [关闭]      |
+----------------------------------+-----------------------------+
| 主内容                            | 元信息                       |
|                                  | 所属实验                     |
| 阶段专属内容                      | 阶段                         |
|                                  | 创建者                       |
|                                  | 更新时间                     |
|                                  | 关联证据                     |
|                                  | 关联产物                     |
+----------------------------------+-----------------------------+
| [编辑] [推进到下一阶段] [⋯]                                     |
+----------------------------------------------------------------+
```

弹窗建议宽度约 720-860px。左侧主内容为主要阅读区，右侧元信息为属性区。不要把弹窗做成密集表单。

弹窗底部动作区保留两个直接动作：

- `编辑`：修改当前阶段卡片内容。
- `推进到下一阶段`：主操作。多数情况下 Agent 会自动推进，按钮用于人工确认或手动触发。

其他低频操作收进 `⋯` 图标菜单。V0 菜单只包含：

- `暂停`：暂时挂起当前实验。
- `取消`：取消当前实验。

### 假说卡弹窗

展示：

- 问题。
- 能力缺口。
- 假说。
- 成功标准。
- 风险预估。

操作：

- 编辑。
- 进入实证验证。
- 删除卡片。

### 实证卡弹窗

展示：

- 验证方案。
- 命令 / 工具调用记录。
- 证据列表。
- 观察结果。
- 失败记录。
- 结论。

操作：

- 编辑。
- 进入能力锻造。
- 标记失败。

### 锻造卡弹窗

展示：

- 产物类型：skill / CLI / tool / doc / dataset / prompt。
- 产物路径或引用。
- 使用契约。
- 验证方式。
- 已知限制。

操作：

- 编辑。
- 提交晋升评审。
- 标记为候选。

### 晋升卡弹窗

展示：

- 评审结论。
- 风险等级。
- 检查项。
- 证据引用。
- 人工审批状态。

操作：

- 晋升。
- 驳回。
- 继续实验。

## 新实验弹窗

点击顶部 `新实验` 打开。

V0 表单保持克制：

```txt
新实验

标题
问题 / 想法

[取消] [创建]
```

创建后默认在 `假说构建` 列生成一张本地临时假说卡。

V0 不要求用户一次性填能力缺口、初始假说、成功标准、风险、产物类型等复杂字段。这些内容可以在卡片详情弹窗里继续补。

## 已完成实验弹窗

点击顶部 `已完成实验` 打开。

```txt
已完成实验

[全部] [已晋升] [已拒绝] [已废弃]

实验标题                 结果      产物       完成时间
让 Agent 锻造 Rust CLI    已晋升    CLI        今天
失败任务沉淀为 skill      已晋升    skill      昨天
web_search 证据质量评估   已拒绝    learning   5月27日
```

规则：

- 默认按完成时间倒序。
- 点击某条实验打开完整实验详情弹窗。
- 完成实验不回流到主矩阵，除非用户选择“重新打开”或“继续实验”。

## 完整实验详情

完整实验详情不同于卡片详情。

入口：

- 已完成实验弹窗中的实验行。
- 未来可从某张卡片弹窗中的“查看整轮实验”进入。

展示：

- 实验标题和整体状态。
- 四阶段时间线。
- 所有阶段卡片。
- 所有证据。
- 所有产物。
- 评审记录。
- 历史状态变化。

V0 可以先只实现卡片详情弹窗，完整实验详情作为后续增强。

## 不做项

V0 页面不做：

- 搜索入口。
- Agent 建议入口。
- 筛选入口。
- 视图切换。
- 右侧详情面板。
- 底部选中实验摘要条。
- 全局统计条。
- 拖拽卡片跨列推进。

推进阶段必须通过明确动作生成下一阶段卡片，避免把实验生命周期简化成普通看板拖拽。

## 视觉约束

- 沿用 `docs/design-docs/front-全局视觉语言规范.md`。
- 蓝色只用于主操作、选中和少量运行态。
- 四列可以有非常浅的纸张色区分，但不能变成彩色看板。
  - 当前实现：四列容器都是白底 `bg-surface`，**只在列头**用 4-5% 阶段色块（hypothesis 蓝、verification 暖黄、forge 青、promotion 金）+ 左侧 3px 阶段色线作身份徽章，列体保持白色。
  - 反例：直接把整列底色染成 `#f3f7ff / #fff7ef / #eefbfc / #fffaf0` 这种饱和的纸张色，会让页面变成彩色看板。
- 卡片保持克制，优先边框而非重阴影。
  - 卡片不使用整卡染色或厚阴影；选中态用左侧 2px 蓝条 + `brand-soft` 40% 透明背景。
  - 标签胶囊采用低饱和度配色（13% 阶段色混白 + 阶段色文字），高度 18px、字号 11px。
- 图标按钮需要可访问标签；`+` 按钮 hover 时可显示 tooltip。
- 文本不使用负字间距。
- **不渲染空槽 placeholder**：阶段卡片少于若干张时，列体自然结束；不用虚线占位行强行撑满列高。空列只显示一行 `暂无{阶段}。` 提示。
