## 1. 执行前提与启动方式

### 1.1 版本和规则

1. 在仓库根确认 `git branch --show-current` 是 `main`，记录 `git rev-parse HEAD`、`git status --short`。不要 checkout 交接中的旧分支哈希；9 份实现均已合入 main。
2. 执行时若其他任务并发修改产品源码，记录版本并从所验main提交建立隔离检出；其HEAD对应main，即使Git处于detached也不切回旧refactor分支。不同Composer版本的片段不能拼成同版本通过。

   本轮整理时已有其他任务的文档改动：`docs/exec-plans/README.md`、`docs/exec-plans/tech-debt-tracker.md`、`docs/exec-plans/active/20261007-desktop-settings-write-consistency.md`。保留它们。
3. 当前启动与真实界面验证按[前端验证约定](../../FRONTEND_VERIFICATION.md)。旧总计划“不使用 Computer Use”“Sonnet 复核”和直接启动通用 Electron 的规定，属于此前实施阶段；本次按当轮 AGENTS 指令委派 Sol，并使用 workspace 专属开发 runtime。
4. 准备依赖或构建失败，记录为运行环境阻塞，不将尚未进入的界面项判为通过。只在缺少依赖时运行 `pnpm install`；本轮计划整理未运行构建、测试或任何启动命令。

### 1.3 启动入口

**B：浏览器 mock**，在仓库根：

```sh
pnpm --filter @actspace/desktop dev:renderer
```

从终端读取实际端口，依次使用 `/?mock=empty`、`streaming`、`long-session`、`approval-pending`、`remote-host`。端口冲突时可用 `VITE_DEV_PORT=5174 pnpm --filter @actspace/desktop dev:renderer`。mock 可验证界面和本场景已实现的交互，不能证明 IPC、落盘、真实 Host、系统对话框或实际工具执行。

**E-T：真实 Electron + 临时目录**，在仓库根：

```sh
FE_ACCEPTANCE_DATA_DIR=$(mktemp -d)
ACTSPACE_DATA_DIR="$FE_ACCEPTANCE_DATA_DIR" pnpm dev:log
```

记录生成的绝对路径；关闭后重启使用该路径，不能重新执行第一行。需要 Dock 重开时保持开发服务器和 main 进程运行。

**E-U/H：真实 Electron + 平时目录/历史目录**：

- 未设置覆盖变量时运行 `pnpm dev:log`，使用默认平时目录；macOS 当前默认为 `~/Library/Application Support/ActSpace`（以[数据目录解析代码](../../../packages/shared/src/data-root.ts)为准）。
- 平时使用自定义目录或历史副本时，在同一个启动命令中显式传入其绝对路径作为 `ACTSPACE_DATA_DIR`。
- U/H 与 T 顺序运行；切换目录先正常退出上一实例，记录新的应用 PID、数据目录与窗口，避免把另一实例的结果混入。

Computer Use 从 `logs/latest-dev.log` 的 **`[dev-runtime]`** 读取当次 `appName` / `appId`，优先按 appName 选择，不能按通用 `Electron` 选择。需要人工 GC 的 G7 单独用 `ACTSPACE_OPEN_DEVTOOLS=1 pnpm dev:log` 启动；其他组维持默认不弹 DevTools。

## 4. 已识别的边界与执行时判断

1. **未知提交不是模型报错**：`14-A3` 依赖 submit/receipt 结果未知，模型服务断开通常发生在任务已被接纳后。先记录实际状态；无法进入真实未知分支则未覆盖，不在计划整理阶段添加故障注入代码。
2. **describe 故障与 Host 离线不同**：`15-A6` 必须保持连接而使 describe 失败，再通过 Host 列表变化恢复。暂停 Host 导致心跳断线只覆盖 A5，不能替代 A6；缺受控环境则未覆盖。
3. **极矮窗口**：当前[窗口配置](../../../apps/desktop/src/main/window-security.ts)最小宽 480、高 760。`09-P3-4` 首先检查正常最小 Electron 窗口；浏览器 360px 高的翻转与下沿溢出独立记浏览器补充/已知现象，不宣称正常 Electron 覆盖。若 760px 下触发不了，专项翻转分支未覆盖。
4. **worktree 接线**：[当前规范“当前接线边界”](../../design-docs/frontend/front-workspace-git-worktree-context.md#当前接线边界)已说明 App.handleSend 的 Task payload 没带 runLocation/baseBranch；整理时[源码](../../../apps/desktop/src/renderer/App.tsx)也没有在该路径传递两者。这是源码发现，尚非本次实机结论。`09-P4-4` 仍保留真实操作与预期；未创建不能用菜单可点击或旧会话能打开判通过。
5. **历史已知问题不自动豁免**：重载恢复 run 的实时文本曾仅在结束后出现；480px 侧栏“复制”子菜单曾有左侧溢出；强杀后 30 秒内曾有 writer lock/失败缓存；跨会话发送失败附件恢复曾不完整。遇到时记录当前版本现象及原交接来源，不能预先标通过，也不保证它们仍存在。
6. **旧测试失败不是当前基线**：10–14 交接提及非 Git 中文分类失败，15 已记录 `7154f57d` 修复；不要将旧失败数沿用为 main 的可接受失败。17 的三处 settings 遗留问题已有[独立待决策计划](../../exec-plans/active/20261007-desktop-settings-write-consistency.md)，本次不通过注入真实数据写失败去扩展修复范围。
7. **mock 边界**：mock 不实现 hosts.call/preview/download、terminal.create、worktree 创建，标准 streaming 场景也不能证明真实 pending 队列。被注入快照证明的是外观，必须与真实队列/请求/产物证据分列。

## 5. 回传、证据与统一问题交接

- 专项、建议、R/V 各自保留逐项结果，禁止用“G5 通过”代替覆盖表。
- 简短回传格式：**项编号 + 通过 / 不通过 / 未覆盖 + 现象**。复合项有部分缺失时列出已验子项及剩余内容；有确定失败则整项“不通过”，没有失败但未验完整则“未覆盖”。
- 每条补充验证层（真实 Computer Use / 源码 / 运行时 / 推断）、main HEAD、环境 B/E-T/E-U/E-H、必要截图/日志链接。一份证据可支持多个明确编号；审批/断线/焦点的中间状态当场记录。
- `09-P5-1` 由其 16 个 P1–P4 子项汇总；`09-P6-1` 由六类明确操作汇总。不因 G1 mock 通过而把 Electron 汇总项记通过。
- 音频、IME、真实 Host、历史 profile 等前提缺失时写清具体限制。不要把“未覆盖”缩写成“不通过”，二者需要不同后续动作。
- 执行时在同一目录建立 `computer-use-acceptance-results.md`，逐项写结果；关键证据放 `screenshots/computer-use/`。现在只建立计划，不预填通过或伪造执行过程。
- 遇到 Bug 立即记录编号、最短复现、预期/实际、环境/版本与证据，不修复、不修改源码、不让子智能体修复，也不以修复为前提暂停整个验收。若 Bug 阻塞后续子项，关联该 Bug 并将这些子项记为未覆盖，继续其他可执行路线。

- 后续统一修复仍以 **main** 为目标，由另行安排的修复工作处理；本任务不提交/推送修复。后续修复完成、明确要求复验时，再记录新 HEAD 并定向复验失败项及关联 R/V；通过证据不跨版本直接沿用到受影响项。
