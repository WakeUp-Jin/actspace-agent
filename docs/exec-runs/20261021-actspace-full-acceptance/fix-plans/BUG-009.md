# BUG-009 修复与复验方案（已实现、已定向复验关闭）

对应[事实记录](../bugs/BUG-009.md)。用户已批准[集中修复计划](../../../exec-plans/active/20261022-acceptance-bugfix-review.md)的 D3 / A 批，以下原建议中的退出契约已确定为 SIGINT=130、SIGTERM=143、结构化 aborted，当前代码已实现。

统一 CLI 终止入口：首次 SIGINT/SIGTERM 转换为现有 Run 取消并等待 profile.shutdown 排空；5 秒预算或二次信号触发强制清理，仅处理本调用拥有的工具进程组。沿用工具端口的取消与 dispose 能力，不另造扫描 PID / 同名杀进程逻辑。

核对模块：apps/cli 的main/run控制、Runtime/profile shutdown、shell tool前后台进程与Session归属；Host已有自己的SIGTERM排空，不直接复制或改写其语义。

风险：退出等待永久挂起、第二次信号失效、错误清理其他Session进程、stdout结果重复、与持久化writer租约/恢复冲突。建议先按当前信号契约写真实进程用例，再决定最小实现边界。

复验：有输出/静默前台、后台与孙进程；SIGINT、PTY Ctrl-C、SIGTERM、二次信号和超时；检查CLI/工具无残留、Journal可恢复、任务不重放、结果与退出码符合最终约定。仅在专用测试目录和本轮PID验证。

2026-10-23：17 项进程回归和 13 项 CLI 单测通过，原始有输出/静默/真实 PTY 路线也在新构建通过。当前公开 run 为非交互审批，未提供“等待人工输入”的可达路径；其余扩展子项仍未覆盖，不提前关闭。逐项证据见事实记录末尾。
