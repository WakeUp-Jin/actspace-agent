# BUG-005 建议：恢复待审批请求的操作详情

> 当前授权（2026-10-23）：全部 Bug 可直接修复，无需逐项审批。以下原始建议中的暂缓限制已失效；实施与复验状态以 [Bug 索引](../bugs/README.md)和[修复执行记录](../../20261022-acceptance-bugfix/execution-summary.md)为准。

状态：[x] 已实现并于2026-10-23按原 Web 缺陷范围复验关闭。下文为初始方案记录；当前证据与未覆盖边界见 Bug 记录末尾。

- 问题与证据：[Bug 记录](../bugs/BUG-005.md)。
- 相关模块：Web SessionDetail / ApprovalCard、client 会话实时与历史投影、Host 审批请求恢复及工具准备执行信息。
- 当前判断：Web 使用 callId 关联工具块以取得 command，审批请求本身保存 digest 与资源摘要；刷新后按钮恢复但 command 缺失。可能是历史投影与 live 参数补充的差异，尚需逐层比较初次订阅与重新订阅的数据，不把推测当根因。
- 推荐方向：让待审批操作的展示信息可从 Host 校验过的数据稳定恢复，并与 requestId/callId 绑定；优先复用已有持久工具事实及投影。先确定参数在哪一层丢失，再在其归属模块修复，避免只加浏览器缓存掩盖恢复缺陷。
- 设计取舍：若既有持久事实不足，再评估最小审批展示摘要契约；不能直接把完整命令或任意参数写入共享存储，需核对脱敏、大小、兼容和授权语义。该取舍留到最终讨论。
- 风险：审批展示与实际执行目标不一致、敏感参数暴露、旧 Journal 兼容、迟到观察者显示陈旧数据；不能仅凭按钮可用判定恢复正确。
- 回归范围：待审批刷新/重连/新观察者、批准一次/拒绝/会话授权、多个工具与审批顺序、长参数和脱敏、390px浅深主题；检查 Desktop 远端观察是否共用受影响投影。
- 备选及验证：先对比刷新前后的 Host snapshot、client 工具块与 Web props；若已完整传递则在展示层修复，若事实缺失则单列契约方案。验收期间不扩大定位为实现或要求用户选方案。
