## 复现与证据

1. 在当前应用打开由旧 codec set 创建、当前仍可读写的已完成普通或工作树会话。
2. 使用侧栏右键或 Shift+F10 菜单执行“分叉”。
3. 菜单关闭，未创建新会话；main 日志出现 `SessionError: Fork codec digest mismatch.`、`INVALID_HEADER`。

真实原生三次复现及截图、AX、原始栈见 `tmp/codex-acceptance/20261022-acceptance-bugfix/c-current-native-20261023/report.md` 和 `fork-errors-original.txt`。预期是为兼容的历史前缀创建新会话、保留来源并正常显示；不兼容或不平衡前缀仍应拒绝。

## 根因与实际方案

`AgentApplication.forkMainSession` 原先复制父 Header 的 `createdWith`，仅替换 manifest。父 codec 摘要来自创建时环境，与当前 registry 不一致，`SessionStore.fork` 正确拒绝该新 Header。即使 codec 未变，Profile/Composition 等创建信息也可能陈旧。

由 `RuntimeSessionController.creationProvenance` 统一提供当前 Profile、Composition、manifest、plugins、codec set 和初始模式事实，普通创建、临时创建、分叉复用同一工厂。应用服务通过公开 session port 获取当前事实；父会话文件不变，lineage 与继承事件保留来源，初始模式继续继承。存储层的 codec、required event、平衡边界校验保持有效，不通过重写历史或放宽校验绕过错误。
