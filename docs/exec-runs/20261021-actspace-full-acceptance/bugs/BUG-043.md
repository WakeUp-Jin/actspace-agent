## 复现、证据与根因

真实 Composer 发送 `AUTO_CONTEXT_READS`，Runtime 连续读取五份自有大文件，64K 容量/约48K自动压缩阈值自然触发。session `23689925-493a-43c6-926e-0da9f7943210`，compaction `6a2da837-3572-408a-aad7-9ba2030c3f7d`；聊天/轨迹有203字摘要，Context→会话摘要→压缩摘要却显示“这一条没有可预览的内容”。原始报告：`tmp/codex-acceptance/20261021-actspace-full-acceptance/context-auto-native-20261023/report.md`。

`packages/context/engine/src/content-manifest.ts` 的 `describeContextContent()` 同时使用 `browseable` 控制短预览和全文读取，将 `summarizedConversation` 与普通 conversation 一并排除。设计明确要求“摘要允许短预览，目前全文接口只开放系统、工具、规则和 Skills”；因此全文边界正确，短预览条件错误。

## 修复方案与回归范围

拆开短预览和全文读取条件：摘要可返回最多600字符预览，仍不提供 `fullTextAvailable` 或内存全文 map；普通会话不返回预览/全文；持久化请求清单仍剥离预览。覆盖现行 compactionId 映射与旧 summaryIds、完整文本 Token 估算、当前投影和请求快照不落正文。
