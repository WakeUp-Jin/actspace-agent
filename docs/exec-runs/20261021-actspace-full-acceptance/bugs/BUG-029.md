## 预期与实际

- 预期行为及依据：[Workspace / Git / Worktree 规范](../../../design-docs/frontend/front-workspace-git-worktree-context.md) § Follow-up 状态行要求“工作树 hover / focus 显示原 Workspace 和 base branch”。该状态仍是只读事实，不应引入按钮动作。

- 复现频率：原缺陷在 1 个真实会话复现；修复后的组件回归为 1/1 通过。真实 UI 复验结果待补。

## 修复记录与后续复验

已按推荐方案修复：工作树来源标签可由键盘聚焦，通过共享 Tooltip 在 focus/hover 时展示完整原工作区路径及 base branch；保留只读非按钮语义，并增加主题感知的 `focus-visible` 焦点环。实现位于 `apps/desktop/src/renderer/components/composer/ComposerStatusRow.tsx`，无需修改现有设计规范，该规范已明确要求 hover/focus 均展示来源。

组件回归在旧实现下因无法按可访问名称找到来源标签而失败；修复后目标用例通过。整份 `composer.test.tsx` 109/109 通过，Desktop typecheck 通过。新增焦点停靠点可能影响 Composer 键盘顺序及窄窗占位，因此真实界面复验仍是关闭该 Bug 的必要条件。

定向复验结果：从输入框逐项 Tab 后，来源标签按预期获得焦点；focus 显示完整原工作区路径和 base branch；原生可访问树显示为非按钮容器；Escape 关闭提示且保留焦点，Tab/Shift+Tab 可往返；浅/深主题下 480 CSS px 窄窗均完整可见。hover-only 未能通过现有原生接口单独触发，VoiceOver 实际朗读未执行，两者均保留未覆盖。键盘可达性这一 Bug 已关闭；09-P5-2 仍因 hover、读屏及其它规范子项未覆盖而不能签收。
