## 复现与证据

真实 write_file 与 present_files 完成后，删除自有 HTML 产物，再点击对应下载按钮。实际仅显示 `Host operation failed`；预期明确说明源文件不存在、恢复文件后可以重试，不回显 Host 绝对路径。

## 根因与修复方案

`HostArtifacts.reference` 的 `realpath` 等源文件读取直接抛出 Node `ENOENT`，RPC 安全边界按未知内部错误返回通用文案。Web 已正确展示 RPC 错误。修复仅在 Host 源文件快照阶段将 `ENOENT` / `ENOTDIR` 转为无绝对路径的 `NOT_FOUND`，说明文件不存在及恢复后重试。持久化快照存储错误仍为内部错误，不能误报源文件缺失；已生成的不可变快照继续可读。

先补缺失、非法路径组件、恢复重试及存储错误不误分类的回归并执行红测，再实现、运行 Host 测试与构建。最后由原 Computer Use 子智能体在当前构建复验缺失提示、恢复后下载及旧快照不变。原失败证据保留，实际复验前不关闭。
