## 当前推荐方案（仅记录）

建议先明确“应隐藏的委派子会话”和“可独立发现的普通分叉”的共享分类契约，再让本地 IPC、共享列表投影、派生索引、快捷打开和远端映射使用同一依据。优先依据持久化的 lineage 语义区分，保留 fork 的来源关系，不清空 lineage 来绕过过滤。派生分类修正需同步处理已有索引失效与重建，避免只改 renderer 后旧缓存仍隐藏分叉。

理由：单独去掉侧栏过滤可能暴露 Explore 等只读子会话；单改一个映射也可能使搜索、分页、归档和快速打开不一致。最终需结合侧边对话的身份规则确认影响面，本轮不实施。

回归范围：普通与嵌套 fork 的创建/找回/标题/选中、父会话不变、重启与旧索引重建、搜索与分页、归档恢复；委派子会话仍不进入普通列表，侧边对话归属和 Host 隔离保持正确。未经修复及真实定向复验，不关闭本问题。
