# BUG-009：CLI 收到 SIGTERM 后静默工具子进程残留

- 状态：[x] 已复验关闭；原始信号路线、后台/孙进程与取消后恢复回归通过；超时/二次信号另有单元覆盖。
- 严重程度：P2，进程退出/资源回收不完整；本轮仅无害本地测试进程，无用户进程受影响。
- 验收点：P2-C02 活动子进程回收；关联 P2-R01 生命周期。
- 版本：主仓库 fix/settings-model-select，HEAD 00d6b763 + 当前未提交实现，当前构建 CLI/Runtime，macOS arm64。
- 方法：真实 CLI/Runtime、回环 HTTP 受控 Provider、full-access、独立 workspace/data-dir；静默子进程两次不同目录和PID，2/2 复现。

## 复现与事实

1. Provider 返回合法 bash 工具调用，仅执行专用目录的 node long-child.cjs，blockMs=5000。
2. 该测试子进程写自己的PID到专用文件，随后静默定时存活；确认PID仍在、工具尚未完成。
3. 仅向 CLI PID 发 SIGTERM，等待CLI退出，再等1秒核对原工具PID。
4. 两次 CLI 均由SIGTERM退出（Python returncode=-15），没有run_result；静默工具PID仍在，需验收脚本额外清理。

预期：终止CLI能在有界时间取消活动工具并回收本轮子进程；至少不能把CLI退出当作工具已结束。实际：CLI退出并未可靠回收静默工具。

初次“每秒写stdout”的工作进程在CLI退出后也退出，但可能受到关闭管道影响，不能据此证明主动回收；为排除该因素改用静默worker后两次复现。SIGINT与真实PTY Ctrl-C相同活动工具场景返回130/aborted，1秒后工具已退出，分别留证，不混同SIGTERM。
