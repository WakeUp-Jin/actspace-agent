## 复现步骤

1. 启动只监听 127.0.0.1 的 OpenAI-compatible 测试 Provider；配置随机合成 Key（格式不含 sk-/key-/token- 前缀）。
2. Provider 确认收到正确 Authorization，随后 HTTP400 的 error.message 故意回显该值。
3. CLI run 使用专用 workspace/data-dir、--json --persist --out；输入只有公开测试文本。
4. 不打印测试值，仅核对 stdout、stderr 和导出/持久化文件是否包含该值。

## 预期与实际

- 预期：凭据仅存在于 Host 解析与请求中；错误可诊断，但凭据不进入输出、Trace 和 Session Journal。依据 docs/SECURITY.md 凭据与错误脱敏边界及计划 P2-R02。
- 实际：CLI 退出1，错误为 invalid-request；stdout 和 stderr 均包含测试值；journal.jsonl、out/result.json、out/trace.jsonl 均包含该值。
- 两次均仅一次真实回环请求，服务端确认 Authorization 正确；不是把普通用户消息中的任意文本误当凭据。
- 触发条件：上游错误正文包含该请求的凭据且未匹配现有格式规则。不表示所有 Provider 正常请求都会泄露。
