## 根因及修复方案

`ReviewDiffCanvas.tsx` 为所有虚拟行使用共享长代码画布的 100% 宽度，文件/hunk 操作被 flex 推到画布右缘，图片则在画布中央居中，因而随另一文件的长行一起移到可视区外。

主智能体串行修复：复用现有虚拟列表测得的 viewport 宽度，为文件、hunk、图片/状态行及提示设置可视宽度与横向粘附；代码行继续共享稳定内容宽度和唯一横向滚动容器。不引入第二个滚动容器、不更改 Git 或 IPC。

回归范围：长文本与图片混合、文件/hunk 操作、横向滚动后非代码行、390→840 可视宽度变化、换行与单栏/并排、虚拟列表 DOM 预算。先运行新增用例证明旧实现失败，再修复并跑相关测试、类型检查、构建及要求的前端门禁；子智能体释放固定制品后才重建，最后由 gpt-6.1-sol 在当前构建做真实 Electron 浅深主题及窄窗复验。
