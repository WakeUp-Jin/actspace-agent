## 根因与修复方案

三个实际请求入口均消费了模型流，却没有将 usage 写入 Session 的辅助请求事实。现有辅助请求契约只接受工具内的图像识别，不能正确描述回合之外的标题生成和手动压缩。压缩和自动审核还复用了确定性 requestId。

扩展四种真实归属：图像识别、自动审核必须绑定实际工具的 Run/Turn/Step/call；标题只归属 Session；压缩归属 Session，可关联实际 Turn。复用一个流消费与持久化入口：开始事实落盘后才派发，结束事实落盘后才返回；采用 Prepared request 的实际路由、模型和唯一 attemptId，不重试、不伪造零用量。请求已完成但业务解析失败仍保留已发生的计量。自动审核的并发检查仅排除本次审核自身的计量事实，其他并发变化仍使审核失效。

补齐插件依赖、Usage 投影和用途展示，保留旧 Journal 兼容；辅助事实不能进入对话或 Context。按当前用户授权直接修复。
