# BUG-032：工作树 Review 刷新丢失执行目录，且未拒绝冲突身份

- 状态：已复验关闭；当前构建显式刷新、绑定目标及快速切换路线通过。
- 严重程度：P2；影响未注册工作树的 Review 刷新及目标一致性。
- 验收点：BUG-023 复验 / P2-D14。
- 发现方式：主智能体沿真实工作树验收入口补充真实 Git 目录及 IPC 集成测试。
- 版本：`fix/settings-model-select`，HEAD `00d6b763` 加本轮未提交改动。

## 复现与结果

1. 创建由持久化本地会话持有、未加入 workspace registry 的真实 Git 执行目录。
2. 通过 Review IPC 取得 snapshot，再以该目标刷新。
3. 刷新第一次解析成功，但随后丢弃 root，仅携带派生 ID 重新解析，返回无效工作区；预期继续读取同一授权执行目录。
4. 同形检查发现显式错误 workspaceId 与合法会话 root 一起传入时，fallback 忽略错误 ID；预期拒绝冲突。

## 根因与修复

`ReviewCoordinator.refresh` 把解析后的 workspaceRoot 置为 undefined，导致下一次解析将 `session-root:<sha256>` 当作 registry ID。刷新现保留完整解析后的 ID/root。Desktop shell 的 session-root fallback 同时核对显式 ID，拒绝不匹配输入。只读授权范围和 Git 写准入边界保持明确。
