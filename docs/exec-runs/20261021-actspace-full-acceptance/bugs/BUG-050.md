## 根因、方案与回归范围

`ComposerPalette.tsx` 仅给列表固定最高280px，整张卡片没有消费 Radix `--radix-popover-content-available-height`。安装版 Radix 的 size middleware 会公布可用高度，但不会替调用方缩短内容；flip 在两侧均不足时无法使完整内容入屏。

主智能体串行修复本面板：整卡采用可用最大高度和纵向 flex；搜索行不收缩，列表允许收缩并内部滚动。保留最高280px、锚点、自动翻转和键盘/焦点规则，不改共享 Popover、产品最小窗口或业务数据。

先添加真实 Chromium 布局回归并运行修前失败：合法最小高度、多行草稿的实测锚点几何，浅/深与480/1440宽度；验证整卡/搜索行边界、内部滚动和键盘活动行、搜索/返回/Esc回焦。另测空草稿和上下空间确实允许翻转的组件样例。后两者是工程组件证据，不能代签原生条件性子步骤。修后运行相关组件测试、Desktop类型检查/测试、renderer构建及前端门禁，再由明确Sol/high子智能体真实Electron定向复验。

同形排查覆盖 Composer 的其他 Popover 与共享 Select/Menu；不无证据扩大为全部浮层缺陷。必要设计/history随修复同步，工程通过不提前关闭Bug。
