F1-07 明确要求用途的 UI、轨迹/请求和用量一致；[费用设计](../../../design-docs/model-context/agent-model-catalog-and-usage-cost.md)要求保留请求/Token 与未知费用语义。工具活动本身不当作模型计费，但其内部实际发生的视觉模型调用应有独立可追踪用量，不能只保留工具活动而遗漏模型调用。

## 原推荐方案（发现时记录）

建议让 Host 内辅助 LLM 调用走统一、可持久追踪的请求生命周期，保存父工具/会话归属、实际模型与档位、独立 requestId 和规范化 usage，再由现有统计读模型汇总。优先复用生命周期机制，避免在 UI 按工具次数猜用量，也不要把视觉用量重复加到主 step/end。

后续需核对辅助调用的失败、重试、取消、缓存桶、未知价格与真实费用来源；回归主/视觉各计一次、父子归属、重启重放不重复、历史缺失事实的诚实呈现以及其他 Host 端。根因与数据兼容方案留到全部验收结束后讨论，本轮不改 Journal、不补算或修产品。

## 2026-10-23 已批准修复与自动化证据

确认根因：看图 Host 直接消费 LLM 流，未产生独立的持久请求事实；统计与轨迹只能读取主循环事实，因此两次实际视觉请求均缺失。修复采用独立 `llm/auxiliary-start` / `llm/auxiliary-end`，记录父 Session/Run/Turn/Step/Tool、逻辑调用与每次真实尝试、实际 PreparedCall route/model/requestId、终态及 nullable usage。dispatch 前及终结后的 flush 作为持久化屏障，终结失败不重发请求。插件缺少记录器时拒绝装载；Desktop、CLI、远端 Host 注入同一契约。

client、Usage SQLite 与轨迹按每次实际尝试计量，以逻辑调用关联重试；辅助事件不新增主助手消息。普通历史分页保留事件并按完整 Turn 回读，较大的父工具正文仍可延迟载入。SQLite 派生 schema 升至12、source cache 升至3，同时重建行与游标；只重放既有事实，不改历史 Journal、不补猜旧视觉请求。
