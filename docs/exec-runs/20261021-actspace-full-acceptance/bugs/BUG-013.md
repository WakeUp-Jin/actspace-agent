## 2026-10-23 定向复验结果

已在真实隔离 Chrome/扩展链路下逐项复验 locator、DOM、CUA 三入口。Backspace/Delete、选区删除、左右方向、Home/End、Shift选区、普通字符均在对应 input/textarea/contenteditable 场景触发预期默认编辑；多行 ArrowUp/Down 在修正 `white-space: pre-wrap` 的 fixture 后通过。原 Backspace 失败已不复现。

当时仍有两类失败（后续修复并关闭，见本记录末尾）：

- **Meta+A / ControlOrMeta+A**：三入口 × 三种编辑器各 9/9 失败；RPC返回成功，页面收到带 Meta 修饰位的 keydown/keyup，但选区仍为3–3，没有 beforeinput/input，预期选中0–6。
- **Enter**：三入口 × textarea/contenteditable 各6/6失败；RPC返回成功，只有 keydown/keyup，文本和值选区不变，没有 beforeinput/input，预期插入换行。

Meta+A 后单独发送普通字符的修饰键释放补验9/9通过，不能把全选失败归因于Meta未释放。准确步骤、事件、状态、逐项结果及修正fixture说明见`tmp/codex-acceptance/20261022-acceptance-bugfix/g011-g013-live/report.md`及同目录JSON。此结果是实际 Chrome/扩展链路验证，不是原生Computer Use；用户Chrome未操作。

- 真实交互复验：隔离 Chrome → 扩展 → NativeHost → Runtime Bridge 实际链路的有效矩阵 51/51 通过，覆盖三入口全选与 Enter、替换/删除/Shift 选区回归。首次 contenteditable 纯文本断言差异及规范 DOM 补验均保留，详见 [`G013 复验报告`](../../../../tmp/codex-acceptance/20261022-acceptance-bugfix/g013-retest/report.md)。
