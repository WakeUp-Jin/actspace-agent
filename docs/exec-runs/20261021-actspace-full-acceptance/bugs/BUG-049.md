# BUG-049：正常空模型响应缺少请求终态，主任务及子任务收尾失败

- 状态：已修复并复验关闭；CLI/Core 空响应生命周期范围通过，F3-02后续原生空态亦已独立验收通过。
- 严重程度：P2。
- 所属验收点：P2-C02；发现时阻塞F3-02空结果子样本准备，现已修复，原生子步骤另按其证据闭环通过。
- 发现：2026-10-23，F3-SEED 使用真实生产 CLI、持久化 Session、回环合成 Provider；不是原生验收证据。

## 复现、预期与实际

真实CLI输入ACTSPACE_F3_PARENT_EMPTY_20261023，模型调用explore，子响应为合法空content、finish_reason=stop和明确usage100/0/100。预期：子正常completed，空正文/摘要保留，request、step、turn全部收尾，父拿到正常工具结果。

实际：Provider依次记录parent-delegate、child-empty、parent-complete；子Journal在request/header及request/context后没有assistant/message或step/end/turn/end，只有失败run/child-terminal。父explore工具failed，错误为“Step … cannot end with open requests or tools.”；父收到失败工具结果后仍完成，因此CLI退出0不等于子成功。

原始证据位于本地parallel-20261023/f3-empty：provider.mjs、provider.json、requests.json、cli.log及cli-data。父52d79c1f-8bbc-44ee-82c6-bfea034bef92；子367d4b90-d4f5-42d0-a959-c2cce6d62870。只含自有任务与合成凭据；不修改原Journal。

## 根因与已授权方案

packages/core/agent-loop/src/loop.ts仅在output.content非空或failure存在时写assistant/message。Session invariant将该事件作为request终态，合法空结果被跳过，step/end因open request被拒绝。不是夹具取消、请求失败或伪造header造成。正常主任务也走同一分支。

主智能体串行修复：每个完成的模型请求均持久化一次assistant/message，content允许空数组，保留真实usage/stopReason及request身份；不伪造正文、不跳过invariant，不更改存储格式或旧Journal。先在拥有行为的agent-loop包新增主/子空done及后续轮次可写回归，观察修前失败后修复。

回归与影响：core-agent-loop全包、Session replay/关闭关系、失败/取消/重试/工具循环；类型检查、package生命周期及必要消费制品构建。构建前结束冻结批次，随后新数据目录重跑同一真实CLI链路，逐项核对子completed、空内容、工具成功、父完成、终态唯一及正常重开。之后继续F3原生健康样本与故障副本验收。共享Loop修复对Desktop/Host同样生效，但旧版UI证据不自动变为新版全范围证据。

同形排查：本Loop唯一成功输出条件漏终态；collectStream的text回填只处理内容聚合，不负责request关闭；legacy-proxy-wire-engine的空assistant过滤发生在Provider输入转换，不控制Journal终态，本次不改。

## 修复与关闭依据

冻结批次释放后由主智能体串行修复：去掉空content跳过消息的条件，每个完成请求均写唯一终态；新增主/子空成功响应、后续轮次及冷Journal重放回归。新增两条修前均因open request失败，原partial-output四条仍通过；修后Core全包51、当前Runtime集成6、真实CLI进程19通过，Core/Runtime类型检查、构建及58个workspace包边界检查通过。

真实生产CLI经受控HTTP合法空SSE复验：子空assistant/message seq11，step/end12、turn/end13、run completed14、child-terminal completed15，各终态唯一；父tool/result18为completed，父最终完成。另一个明确记录argv、独立Node PID40481和退出码0的冷进程，从原数据副本恢复后正常完成空主轮；旧父前缀及旧子全部字节不变。

实际消费的37个固定Harness文件与当前Runtime在规范化七个shared模块引用后逐字一致，38个artifact文件及7个Host模块integrity通过。原版本清单遗漏loop.ts，已保留原清单并补closure-manifest指纹，未倒改原始证据。最初未重建Runtime的失败及重复tool-call-id的夹具失败均保留，不混入通过样本。
