## 复现与事实

1. 在专用 committed 工作区创建普通会话和新工作树会话，两者均显示在源工作区分组。
2. 工作区菜单选择“归档全部”。普通会话 `c2477b0d…` 归档并消失，工作树会话 `c5e4acce…` 仍为未归档。

预期：分组菜单归档该工作区全部可归档会话。实际：工作树会话遗漏。

证据见[Git 专项终态报告](../desktop-git-20261022.md)，本地证据目录 `tmp/codex-acceptance/20261021-actspace-full-acceptance/desktop-git-20261022/` 下 `archive-all-final.png`、`session-roots.json`。后者显示两会话均无 workspaceId；工作树会话的 workspaceRoot 为新目录，而 worktree.sourceWorkspaceRoot 为 committed。

源码旁证：`sidebar/session-grouping.ts` 使用 sourceWorkspaceRoot 归组；`App.tsx` 的 handleArchiveWorkspace 按 workspaceId 或 workspaceRoot 选择候选，没有使用该来源路径。这与本次漏选一致；尚未验证全部旧会话、远端和带 workspaceId 的组合，不外推它们均失败。

## 当前推荐方案

建议先统一工作区归属的解析规则，让分组、归档候选和移除工作区操作复用同一明确规则，同时保留 Host 隔离。优先在现有归属函数边界内消除候选集与显示分组不一致，不修改历史 Journal 或强制补写 workspaceId。

推荐理由：只在归档回调加一个路径比较可能继续留下其它批量入口差异；共享规则可使“全部”的范围与用户看到的分组一致。风险是误纳入同路径的远端会话或隐藏工作区，需明确 Host、workspaceId、sourceRoot 的优先级。此建议未经讨论、未实施，不要求验收中决定。

定向复验：普通与工作树混组、缺失/存在 workspaceId、置顶、已归档、运行/待审批禁用、同路径不同 Host，以及归档后的当前会话回退与重启恢复。保留本次失败证据，修复后另做复验。
