## 记录约定

- 每个独立问题一份 `BUG-NNN.md`，从 `BUG-001` 开始，跨阶段连续编号；同一问题复现时补充原记录，关联所有受影响验收点。
- 状态按实际记录为“已登记 / 已定位待修 / 修复中 / 已修复待复验 / 已复验关闭 / 范围待确认”。当前按用户对全部 Bug 的授权直接修复，实际复验后才关闭；旧“待方案审核”状态须随推进更新。
- 建议应给出修法、理由、涉及模块、风险及回归范围；未确认根因写明假设与验证路径。跨模块问题同样进入修复闭环，无需再次审核。
- 修复状态与验收状态分别记录：方案批准、代码修改和自动化测试通过都不能自动将产品验收点勾为通过。
- 截图、录像及脱敏日志引用计划约定的 `tmp/codex-acceptance/` 证据路径；不记录密钥和未经脱敏的用户数据。
- 问题仅阻塞受影响项目；实际失败点记“失败”，尚未执行完的关联点记“未覆盖”，在覆盖台账中引用 Bug ID。
