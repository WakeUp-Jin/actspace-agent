## 修复前推荐方案（历史记录）

优先在协议适配边界保留“上游是否实际报告usage”及各字段存在性，区分缺失与明确0，再贯通LlmUsage与持久事实；下游只依据真实已知字段计算吞吐，缺输出token时显示不可用，保留有依据的TTFT/生成时间。避免在UI用正文长度猜token，或将所有0一概改成未知而误伤供应商明确报告0的情况。
