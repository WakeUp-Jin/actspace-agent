## 预期与实际

- 预期行为及依据：当所有参与汇总的 Token 字段都没有已知值时，显示“—”及未知请求数；供应商明确报告 0 时继续显示 0。混合已知和未知请求时显示已知小计，并说明另有多少请求用量未知。该语义依据 [Token / Context 设计](../../../design-docs/model-context/agent-token-usage-and-context-state.md)中 provider 未返回字段可为 `unknown / null`、Projection 不应补造精确数字的规则，以及 Usage 页面费用汇总对已知/未知样本的呈现模式。
- 实际现象：真实隔离 Electron 中，成功请求没有 usage；Journal、轨迹和请求日志均保留未知，但顶部 Token 概览与服务商聚合表显示 0。原始 HTTP / Journal / UI 证据见上方复验报告“观察与限制”。
- 复现频率：修复前在同一真实隔离复验中复现过单条缺 usage 请求；源码也确认旧聚合路径将 nullable 值折叠成数值 0。当时部分已知混合场景的真实 UI 尚未验收，现已完成，结果见下方复验记录。

## 实际修复方案

在 Usage read-model 中保留“已知和”与“未知请求数”两类事实：shared IPC summary 和 provider/model aggregate 提供逐字段未知计数；worker 在 SQL 中独立计数 nullable 字段，同时对已知值求和；renderer 根据两类事实显示“—”、明确的 `0`，或带未知数量说明的已知小计。缓存命中率在输入或缓存读取依据不完整时显示“—”，工具调用不参与 LLM Token 未知计数。

实际变更包括 `packages/shared/src/ipc.ts` 的 summary/aggregate 类型、`apps/desktop/src/main/runtime-v2/usage-read-model-worker.ts` 的 summary 与分组聚合 SQL、schema 13 派生索引重建、staging copy 的可写列选择、read-model 回归测试，以及 `apps/desktop/src/renderer/components/UsageStatisticsPage.tsx` 和 renderer tests。测试覆盖“全未知 / 明确零 / 已知与未知混合 / 工具行 / 范围与搜索 / 重建与重启”；修复前红测与修后绿测均保留在证据目录。

该实现保留已知值的可用汇总，不把缺失数据解释为零；独立计数让分项指标按各自数据完整度呈现。schema 升级会从 Journal 重建可派生索引，旧 Journal 本身不被改写。真实 Electron UI 曾是本 BUG 的关闭门槛，现已完成六项定向验收并通过，逐项结果见下方记录。
