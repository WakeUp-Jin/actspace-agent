# BUG-038：看图端口缓存启动时配置，设置修改后不生效

- 状态：[x] 已修复并经真实 Electron V1–V5 定向复验关闭。
- 严重程度：P2；首次配置需重启才能看图，替换或清除配置可能继续使用旧模型。
- 关联：F1-07、P2-D17；由 [OBS-001](OBS-001.md) 的重启对照进一步确认。
- 版本：主仓库 `fix/settings-model-select` / `00d6b763` 加未提交改动，macOS，隔离 profile 与本地受控 Provider，无商业调用。

## 复现与根因

原始真实 Electron 中，无模型启动后通过公开设置 API 配置聊天和看图模型，同进程实际 `inspect_image` 返回 `IMAGE_INSPECTION_NOT_CONFIGURED`；正常重启后相同配置与图片调用成功。原始时序与证据仍保留在 OBS-001。

新增回归在同一个 `createPorts` 实例内切换模型解析结果。修前首次配置、清除、替换三条全部失败；解析记录明确只发生在 `create-ports` 阶段。Desktop `tool-host-services.ts` 在端口工厂中解析并闭包捕获模型，而 Harness 比设置的有效期更长。UI 保存成功和主请求采用新设置均不能更新该闭包。

## 实际方案与边界

将视觉模型解析移到每次 `inspect_image` 调用边界，继续使用既有图片工具及 LLM inspector。下一次工具调用采用当前可用模型；无可用模型时返回既有未配置错误，不读取图片、不发辅助请求。正在执行的请求保留已准备的身份，后续设置变更由下一次调用读取。

保留 `default` route、固定 Host credential reference、Session-owned artifact 校验、辅助请求记录器与用量契约。CLI/通用 Node Host 的配置是组合时不可变输入，本次不更改其生命周期；Desktop 图片生成及搜索端口已有按调用取设置的边界，检查后无需改动。

注意：用途选择“跟随”并不等于禁用看图，当前解析器还会回退到可用的图片模型。清除路线需移除/停用全部可用视觉配置，不能把合法回退当缺陷。
