- 状态：[x] 已复验关闭（2026-10-23）；最终构建在390px右栏及480px整窗浅/深主题的键盘路线通过。精确865px高度与水平输入接收继续未覆盖。下文保留原失败。
- 严重程度：P2；窄右栏中键盘用户无法看到当前焦点控件的完整边界，鼠标路径的横向可达性也未证明。
- 所属阶段与验收点：P2-D14、P2-D20、R22；与原统计遮挡问题 BUG-015 分开追踪。
- 发现时间与执行者：2026-10-23，gpt-6.1-sol，真实 Electron/CUA 定向复验。
- 验证方式：真实隔离 Electron 原生鼠标、键盘和窗口操作；DOM/AX仅只读测量布局和焦点。水平滚动输入接收情况未确认。
- 版本：主仓库 `fix/settings-model-select`，HEAD `00d6b7630907deefcf07bdb60b88d58b0db00b2a`；独立隔离 Electron 与 Workbench Fixture；原发现时未改产品代码，最终修复版本见末节。
- 环境与前提：本次实际窗口1440×864及480×864 CSS px；390px Review 右栏；`+6001/-6000` fixture。精确1440×865未覆盖；浅/深主题按逐项结果所列范围验证。

## 复现步骤

1. 在隔离 Electron 打开 Workbench Fixture 的 Review 右栏，并将其保持为390px。
2. 点击范围按钮后关闭浮层，使焦点返回 Review 工具栏；连续按 Tab 至末尾的“提交或推送”按钮。
3. 观察该按钮的可见区域，并检查工具栏的可滚动区域尺寸。
4. 在工具栏内分别输入一次原生向右和向左水平滚动，观察滚动位置及末尾按钮可见性。

## 预期与实际

- 预期行为及依据：工具栏末尾操作可达；键盘焦点移至按钮时，该控件应滚入可视区域，或布局应以其他方式保持控件完整可见。横向可滚动容器不应让末尾操作无法触达。
- 实际现象：工具栏 `scrollWidth=470`、`clientWidth=389`。Tab 到“提交或推送”后，其右边界超出窗口viewport约70.7px，截图中仍被裁切。向右、向左的原生滚动输入均未观察到位移，右滚后只读 `scrollLeft` 仍为0；由于当前原生滚动工具的输入接收情况不确定，不能把这项单独认定为产品滚动失效。
- 复现频率：两次真实 Electron 路线观察到同一末尾控件裁切，含浅色1440×864和深色390px右栏。480px浅/深主题末尾焦点完整可见；其他右栏宽度及滚轮/触控板输入接收仍未覆盖。
