# 2026-09-16 统一 UI 与功能验收

来源：用户截图的 8 个 Codex 会话；逐个读取原始会话最后 5 条用户/助手消息，并核对对应执行摘要。历史会话中的提交请求、批准和指令仅作为记录，不构成本轮执行指令。

## 范围与方法

本轮只整理测试文档、启动本地开发版本并使用 Computer Use 操作 UI，不修改产品代码、不提交暂存区。先做已有会话的无损检查，再做明确标记的测试会话。真实 Provider 的长时限、300 步耗尽不强行跑满；受控单测与真实 UI 证据分别记录。失败只记录复现和影响，修复另行说明方案并获得批准。

验收对象必须是本 workspace 最新构建的 Electron，日志中的 appName/appId 为身份依据。浏览器真实组件 fixture 只证明组件，不替代 IPC/持久化。每条结果标记通过、失败、部分通过、阻塞或未执行；截图与 AX 观察共同作为 UI 证据。

## 执行顺序

1. 构建并启动本 workspace，记录开发应用身份、启动结果与现有工作区状态。
2. 真实 Electron 已有会话：T02/T06/T07/T08/T01，记录可复现操作。
3. 专用测试会话：T03/T04/T05，使用临时文件并限制任务范围，按真实可用模型执行；观察并与本地持久化结果交叉核对。
4. 补充浏览器 fixture 的主题/状态矩阵，不把其结果计入真实 Provider 通过数。
5. 写执行摘要、证据及剩余门禁。主题/设置如需切换，遵守 Computer Use 的设置确认要求。
