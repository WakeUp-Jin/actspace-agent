# Review 文件监听资源测试

用户要求：先测试是否真的占用大量资源，不修改产品实现。2026-10-08（Asia/Shanghai）。

## 测试点

- R1：真实 Electron 原空新建页空闲，记录同一进程集合的 CPU、内存足迹；初次菜单打开产生的短时交互单列，不当纯空闲峰值。
- R2：临时 Git 仓库 10,001 个 tracked 文件、20,000 个 ignored 依赖文件，打开 Review；记录稳定占用与正确差异。
- R3：ignored dist 连续写入约400次/秒，检查实际桌面 CPU、内存峰值与变化、可交互性；写入负载进程不计应用占用。
- R4：停止写入后的空闲恢复；切走 Review 后对旧根继续写入，观察残留监听是否有实际开销。
- C1：直接运行当前 compiled ReviewWorkspaceWatcher + ReviewCoordinator，无监听/只监听/监听并执行真实Git查询三组对照，统计通知、查询与命令数量、进程内存和CPU。独立组件结果不冒充桌面结果。
- C2：30个根、总计3,000个子目录，测监听保留增量与dispose释放。此为组件层多根压力，不声称真实UI逐个访问了30个工作区。

## 分组与测量

1. 原应用基线与临时仓库路线：gpt-6.1-sol 子智能体操作现有真实 Electron main69765；父采样。同一路线复用已选临时状态，不发送模型请求，不改真实项目内容。
2. 独立组件对照：Node v22直接加载本工作区已构建主进程模块，全部写入临时目录；测试脚本也在临时目录，不修改生产代码或构建文件。
3. 真实桌面负载与恢复：静态基线→构建产物连续写入→停止→切走后写入；关键状态截图为本地产物，不随仓库分发。

macOS top MEM用于实际进程内存足迹；ps RSS受压缩/换出影响，不能替代。CPU 100%代表一个逻辑核，可能超过100%；系统10逻辑核/16GiB。真实采样包含main、renderer、GPU和network四进程，不含Vite/tsc、负载脚本或短命Git子进程。组件层的process.memoryUsage/CPU亦不含Git子进程，查询次数另列。全程不输出凭据。

本轮属于测量，不预设性能失败，不进行修复或优化。几十秒压力测试不能证明小时级内存泄漏不存在。记录绝对占用与相对增量，避免将长期运行应用已有占用归因监听。

补充普通编辑对照：每秒保存一次唯一tracked文件，20个秒级样本，结束后恢复夹具原改动内容。组件层另用新进程`/usr/bin/time -l`对照不监听与查询链路，将已等待的Git子进程CPU纳入测量；不要把仅Node主进程CPU当完整Git链路CPU。
