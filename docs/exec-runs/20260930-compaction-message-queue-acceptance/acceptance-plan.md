## 一、验收点

以下全部纳入覆盖范围。操作可以合并，但结果须逐点报告；每点有多个子项时，必须列出未覆盖的子项。

### 上下文压缩

- **C01 手动压缩进行中**：在可压缩的会话发送 `/compact`，立即出现「正在压缩上下文」；耗时增长、不确定进度条可见，不展示虚构百分比。输入框为空时停止按钮禁用，悬停提示「压缩完成后可继续」，点击不停止压缩。
- **C02 完成与历史保留**：完成后出现「上下文已压缩 · N 条消息 · 耗时」分隔线；运行中块正确退场；旧用户消息、回复和工具内容仍在上方，摘要没有变成额外用户消息；继续对话正常。
- **C03 摘要操作**：durable 投影载入后，点击分隔线展开／收起摘要；Markdown 标题、列表和代码可读；点击复制后粘贴到测试草稿，内容一致。完成事件刚抵达但摘要尚未载入的短暂不可展开状态，单独记录而不立即判失败。
- **C04 无需压缩**：在确认不足压缩区域最小条目数的新会话发送 `/compact`，显示「对话还很短，暂时不需要压缩」，约 3 秒后消失；最终对话流不残留完成或失败分隔线。不能仅凭“聊了一轮”推断一定不足条目数。
- **C05 自动压缩成功**：真实模型请求达到实际阈值后，回复结束触发压缩；进行中／完成外观与手动压缩一致，原回复保留，回合正常结束。优先在 Chat 模式用设置中的阈值制造场景；记录实际触发依据，不把手动压缩当自动压缩通过。
- **C06 压缩失败与重试**：分别验证手动和自动压缩失败，显示错误状态、原因与可用的重试入口；恢复依赖后点击重试可以完成。自动压缩失败不把已经完成的回复改成失败；手动失败与队列暂停联动另见 Q08。
- **C07 压缩历史恢复**：成功压缩后切换会话再返回，以及正常重启应用后，分隔线的条数、耗时和摘要仍可查看，旧消息仍在。失败块目前不持久化，重启后消失按当前设计记录，不要求恢复。

### 消息队列与插入

- **Q01 运行中发送入口**：Agent 运行时，输入有效内容后按钮变为发送／加入队列；分别用 Enter 与点击加入两条带唯一标记的消息，输入清空、计数正确。输入为空时显示停止按钮；Shift+Enter 可换行，不误发送。
- **Q02 顺序自动发送**：当前运行正常结束后，队首自动发送为一个新回合；第一条完成后第二条再发送。顺序、正文、次数正确，无并发 `SESSION_BUSY`、重复或遗漏，清空后托盘消失。
- **Q03 删除、编辑与上移**：删除指定项只影响该项；编辑将正文及其附件／引用恢复到空输入框，移出队列并聚焦；有草稿时编辑禁用且提示先清空输入框；非队首项可上移，队首上移禁用。修改后的实际发送顺序与界面一致。
- **Q04 工具期间插入**：在真实工具执行期间点击「↳ 插入」，先出现「下一步读取」；被模型读取时，作为用户消息实时出现在当前回合的正确位置，模型后续响应包含唯一标记指令。不能等回合结束后才显示，也不能作为下一回合重复发送。
- **Q05 最终回复期间插入**：在无后续工具调用的最终回复仍流式输出时插入，当前回合继续增加一步并处理消息，而不是直接结束或留到下个回合。必须捕捉插入发生在最终回复期间的中间状态。
- **Q06 待读插入撤回与竞争**：在「下一步读取」期间撤回，消息回队列，当前回合不再消费它；若点击时已被读取，应以真实读取状态为准，不制造重复排队。另验证插入请求与回合结束竞争时，未接受的消息保留在队列，不丢失。
- **Q07 插入后立即停止**：插入后立即停止；未读项按原插入顺序回到队首，已读项留在对话中且不再排队；队列进入暂停状态。使用两条唯一标记区分“未读恢复”与“已读不重复”。
- **Q08 停止、运行失败与恢复**：分别制造用户停止、普通回合失败、手动压缩失败，剩余队列显示「已暂停」，不自动发送；点击「继续发送」恢复。另验证暂停后手动发送新消息会恢复队列，当前新消息完成后依次处理剩余项。自动压缩失败仍按已完成回合处理，验证队列能继续。
- **Q09 压缩联动与命令排队**：分别在手动和自动压缩中排普通消息；可以入队，插入禁用且有原因提示；压缩结束后自动发出。另在普通运行中排入 `/compact` 和后续普通消息：命令项标为「命令」、没有插入操作，依次执行命令和消息，队列计数与顺序正确。
- **Q10 等待审批**：触发真实工具审批后可以排队，插入禁用并提示「等待审批时不能插入」；批准后运行恢复，队列按实际运行结果处理。拒绝后按最终运行状态验证暂停或继续，不预设“拒绝某个工具必定使整个回合失败”。
- **Q11 会话隔离与后台发送**：A 运行中排队，切到 B，B 不显示 A 的队列或草稿；A 在后台完成后照常自动发送，侧栏运行状态更新；返回 A 可查看正确消息与顺序。B 的普通发送和草稿不受 A 影响。
- **Q12 附件与回复批注**：使用 UI 已交付的附件、回复批注入口，分别验证普通排队、编辑恢复和插入时正文及附属内容一致，数量摘要正确，模型能按测试内容响应，历史显示正确。`@` 文件 mention PoC 不算正式交付入口；文件引用仅在运行版本存在正式入口时纳入真实 UI 子项，否则明确未覆盖并单列自动化依据。
- **Q13 输入校验失败恢复**：排队后让测试附件／可达文件引用失效，自动发送被拒时显示原因、恢复正文和附属内容到草稿、队列暂停；插入校验失败时消息退回队列且可再次操作，不丢失、不显示成已读消息。只改专用测试文件；若当前附件已做缓存需根据真实校验时点选择能触发拒绝的场景。

### 视觉、键盘与生命周期

- **V01 双主题**：浅色、深色分别观察压缩进行中／完成摘要／失败、队列排队／已插入／暂停及更多菜单；文字、线条、操作色、禁用态和焦点可辨，颜色随主题切换，无明显残留样式。只声称实际逐一展示的状态通过。
- **V02 窗口与滚动**：常用尺寸和应用支持的最窄尺寸，检查长正文、多队列项及摘要；托盘内部滚动可达，Composer 不被挤出窗口，操作按钮可点，菜单和提示不被滚动容器裁切、窗口边缘定位合理。
- **V03 键盘、焦点与浮层**：Tab 到关键操作，Enter／Space 激活；更多菜单可用键盘进入，Escape 和点击外部关闭，关闭后焦点恢复且不会延迟重新打开；编辑后焦点回输入框。共用组件选代表位置，队列菜单和压缩摘要的特殊行为分别验。
- **V04 队列生命周期**：会话切换时内存队列保留；应用正常重启后未发送队列和草稿不承诺保存，托盘清空符合当前设计；已经消费的插入消息及发送历史应持久化。重启前处理完所有真实运行，不把主动重启造成的未发队列清空报成丢消息缺陷。

## 二、执行准备与检查依据

1. 先读启动日志与当前运行信息，确认实际代码基线。复用对应 workspace 的稳定 Electron 实例；需要启动时使用 `pnpm dev:log`，从 `logs/latest-dev.log` 的 `[dev-runtime]` 获取 `appName`／`appId`，用 Computer Use 选择该应用，不选通用 `Electron`。
2. 记录主题、窗口尺寸、Chat 自动压缩阈值、主模型与轻量任务模型等非敏感原设置；不记录 key。准备专用测试会话 `CU-短会话`、`CU-压缩`、`CU-插入`、`CU-后台A/B`、`CU-异常` 和专用测试附件，避免混入真实任务。
3. 确认连接了可用主模型、轻量任务模型，当前模式与工具／审批能力可用。用运行信息确认长会话存在可压缩区域；自动压缩先检查实际 token usage、阈值和 policy。Chat 阈值 UI 当前支持 50%–95%，可临时降到 50% 并记录原值，不能假定换小上下文模型一定会降低当前 runtime policy 的触发门槛。
4. 长会话优先用专用测试会话生成公开、可重复的多轮文本，满足区域和上下文占用要求；不通过改 Journal、伪造 usage 或直接调用内部压缩函数制造“真实通过”。若真实模型成本／时长不适合覆盖自动压缩，保留 C05 和对应子项为未覆盖，mock 证据单列。
5. 准备两种运行窗口：Agent 模式的无副作用工具步骤（例如只等待并输出标记），用于插入／撤回；明确要求不调用工具、输出足够长文本的任务，用于最终回复插入。示例插入指令：`收到 CU_STEER_01 后，请在下一步回复单独输出 CU_STEER_01_ACK`。每条排队消息使用不同标记核对顺序和次数。
6. 异常优先通过应用设置对专用模型服务使用暂时不可达的本地 endpoint 制造；记录并恢复原值，不删除密钥，不断开整机网络。先确认轻量任务路由，避免只破坏主模型却未触发压缩失败。若现有 UI 无法安全、可重复制造异常，标记真实链路未覆盖，受控 mock 只作补验；不为本轮验收修改产品代码。

## 四、证据与逐点报告

证据标签：

- **CU**：Computer Use 对当前真实 Electron 的操作、窗口状态、关键截图、AX 信息与即时观察记录。
- **RT**：与本次专用会话对应的脱敏运行信息／日志／Journal 摘要，用于核对回合、读取、压缩与持久化；它补充 CU，不替代 UI 操作。
- **AUTO**：定向测试、类型检查等工程证据，只写实际运行结果；既有执行摘要注明“历史记录”。
- **MOCK-CU**：显式 fixture 中的真实 Computer Use 操作，只证明该 fixture 的界面行为。
- **推断**：源码推导、未实际进入的运行状态，不计通过。

执行后在本目录写 `execution-process.md` 与 `execution-summary.md`。结果表至少包含：

| 验收点 | 结果 | 实际观察 | 证据 | 未覆盖子项／原因 |
| --- | --- | --- | --- | --- |
