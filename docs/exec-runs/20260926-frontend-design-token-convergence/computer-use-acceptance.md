## 分组执行路线

验收点定义覆盖范围；下面的操作分组用于复用页面和状态，不替代上表的逐项结果。

首轮已执行三个场景组：

1. **主工作区（E1、E2）**：面板开合 → Composer 输入/焦点/Review → 现有消息流 → 单次 Bash 审批拒绝。覆盖 A01–A06，保留布局、焦点与审批关键状态。
2. **非模型设置与扩展（E3）**：设置顶部 → 工具/Skills/英语学习扩展 → 图片生成配置弹窗 → 浅深色视觉。覆盖 A01、A07、A10、A11。图片生成弹窗仅用于公共弹窗外观与键盘检查，不验服务连接。
3. **窄屏与系统设置初探**：遇到重载及 EPIPE 后中断，相关验收未直接判通过。

恢复后按两个补验场景组完成：

1. **工作区/附件/窄屏（E4）**：原会话添加临时文本附件 → 确認卡片与发送状态 → 移除 → 缩窄窗口 → 侧栏抽屉 → 标题栏打开右侧浮层 → 关闭并恢复宽窗口。复用同一会话，覆盖 A04、A05、A09。
2. **系统外观/动效/弹窗（E5、E6）**：「跟随系统」→ macOS 深/浅切换 → 减少动态效果开关 → 弹窗 Tab/Esc 复现 → 恢复设置。覆盖 A08、A11，并明确记录 A13 的观察边界。

## 确认的问题：图片生成配置弹窗键盘焦点

1. 设置 → 通用 → 编辑图片生成服务配置。
2. 打开弹窗后按 Tab。
3. AX 焦点显示为背景控件「图片分析模型」，没有留在弹窗内。
4. 按 Escape，弹窗仍在；点击关闭按钮可以关闭。

这是实际键盘行为失败，不足以判断由本次 token 改动引入。恢复后在 `970493a` 再次复现。

源码辅助检查：`SettingsPage.tsx` 的弹窗已经调用 `useDialogFocusTrap`，并在 `role="dialog"` 容器的 `onKeyDown` 中处理 Escape 与 Tab。不能将问题描述为「没有 Escape 处理」。焦点处于容器外可能使容器收不到按键事件；这是排查方向，根因尚未确认。本轮不改代码。

## 运行异常与恢复

- 首轮出现主进程 EPIPE 错误窗口，之后页面进入 chrome-error 状态；没有判定为 token 改动所致。
- 补验开始时 Electron 只有默认欢迎页，5173 未服务。退出空窗口后执行 `pnpm dev:log`，依赖构建通过，shared / Electron watch 为 0 errors，Vite 启动并恢复应用。
- 恢复后的补验未再观察到 EPIPE 或自行重载；这不等于已经修复此前异常。
- `logs/latest-dev.log` 有启动缓存警告及原生菜单 `representedObject is not a WeakPtrToElectronMenuModelAsNSObject` 警告。界面还显示「20 个会话暂时无法读取」。这些记录不归因于本次改动。
- Electron 截图/AX 观察多次耗时约 60 秒，系统设置观察较快；未用截图间隔推算应用性能。
