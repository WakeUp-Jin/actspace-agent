# Bash 沙盒执行层（E5 第一期）落地

## 用户诉求

「E5 沙盒按设计文档约定不在本组计划内，这个 bash 工具的沙盒计划有没有实现？没有实现的话，开始实现吧。」

## 主要改动

按 `docs/design-docs/execution-safety/agent-bash工具设计文档.md` E5 章节与附录（Seatbelt 模板与生成契约）实现沙盒优先执行模型，exec-plan 见 `docs/exec-plans/active/20260704-bash-sandbox/`。

### 沙盒模块（新增 `packages/agent-core/src/tools/tools/bash/sandbox/`）

- `profile.ts`：Seatbelt profile 生成器。`(deny default)` 全拒基线 + essential allows（抽取自 srt `macos-sandbox-utils.ts`，保留 Apache-2.0 derived-from 归属声明）；读广域放行 + 敏感路径定向 deny（`~/.ssh` `~/.aws` `~/.gnupg` `~/.kube` `~/.docker` `~/.netrc`，last-match-wins 置后）；写只放行 workspace / 会话 tmp / 系统临时区 + 设备文件；网络第一期 `(allow network*)`。**路径零拼接**：全部经 `(param "X")` 由 `sandbox-exec -D` 注入。
- `index.ts`：`probeSandbox()` 运行时探测（真的用空 profile 跑一次 `/usr/bin/true`，嵌套沙盒环境探测不通过自动降级；模块级缓存 + `ACTSPACE_BASH_NO_SANDBOX` 逃生门）；`buildSandboxSpawn()` 写 profile 到会话 tmp、所有注入路径过 realpath、子进程 `TMPDIR` 指向会话沙盒 tmp。
- `violation.ts`：违规标注（输出模式匹配 EPERM / Operation not permitted / Read-only file system），命中时生成归因 + 升级引导文本。

### 权限层（`permissions.ts`）

- 沙盒可用时放宽：非 allowlist 命令由 ask → allow（reason 注明沙盒内运行）。hard reject 与 `ACTSPACE_BASH_ALWAYS_ASK` 优先级不变。
- `requiredPermissions: ["no_sandbox"]` 升级请求：无条件 ask（无视 allowlist 与沙盒放宽），riskLevel high，`allowSimilar: false`（逐条评估），经 sanitizedArgs 透传给 executor——**升级审批复用现有 scheduler ask 流程，零新增状态机**：requiredPermissions 到达 executor 即意味着审批已通过。
- 未知 requiredPermissions 值直接 deny 并列出支持清单。

### executor / render / definition

- executor：`config.sandbox === true`（生产链路 `createBashTool` 默认开）+ 探测通过 + 未获批真实环境 → spawn 换 `sandbox-exec -f <profile> -D … bash -lc`；`BashResult` / `BashBackgroundedResult` 增加 `sandboxed`；沙盒内失败扫描输出生成 `sandboxViolationHint`。
- render：回填文本带 `env: sandboxed|real` 行 + 违规标注段。
- definition：工具描述写明沙盒默认、证据清单、`$TMPDIR`、逐条评估与副作用提醒；新增 `requiredPermissions` 参数 schema。

### shared / bridge / 前端

- `BashPreview.sandboxed?: boolean`；selectors 透传。
- bridge：preview 回填 sandboxed（前台 + backgrounded），live `tool_finished` 流事件同样应用。
- `BashRunBlock`：`沙盒`（灰、弱化）/ `真实环境`（`bg-warm-soft text-on-warm`，醒目）徽标；缺省（历史数据）不显示。

### 附带修复：renderResult 覆盖 data 导致 preview 元数据丢失

写 bridge 测试时发现：scheduler `postProcess` 会用 `renderResult` 的回填文本**覆盖 `result.data`**，所以 bridge 里按对象形状读 `data.taskId` / `data.sandboxed` 的代码（含 E2 就存在的 `applyBashBackgroundPreview`）在真实链路上一直拿不到结构化数据——之前只有 mock 工具（无 renderResult）的测试路径能过。修复：`ToolResult` 增加 `structured` 字段，postProcess 覆盖 data 时保留原始结构化结果，bridge 优先读 `structured`、退回 `data`。

### 其他

- env 新增 `ACTSPACE_BASH_NO_SANDBOX` 逃生门。
- `ToolParameterProperty.items` 支持 enum。
- 修一处测试隔离偶发：bash_kill 用例断言前先 drain 前序用例 harvest 后异步落队的遗留通知。

## 待手工验收

3. 升级闭环：模型携带 `requiredPermissions: ["no_sandbox"]` 重试 → 弹审批卡片（reason 说明真实环境升级）→ 批准后成功，块上带「真实环境」醒目徽标。
4. 逃生门：`ACTSPACE_BASH_NO_SANDBOX=1` 启动后所有命令回到 allowlist ask + 真实环境。
