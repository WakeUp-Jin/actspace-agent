# 供应商代理与自定义连接修复

## 诉求

排查已配置密钥却无法使用的代理供应商、自定义中转请求被默认供应商拒绝，以及自定义名称编辑入口不明确的问题；用户确认实施。

## 原因与改动

- ProxyAgent 动态导入的 undici 未声明为生产依赖；补齐依赖和 Desktop/CLI deploy 初始化门禁，归类初始化异常。
- 通配路由预取默认模型凭据，适配器再将其覆盖到选中的模型；改为 Desktop 适配器统一解析所选模型的连接，隔离 Key、地址、代理和计价。
- 名称编辑原本藏在服务地址编辑入口；增加服务名称独立入口和协议格式展示，保留稳定连接 ID。
- 同步多供应商设计，增加连接链路、真实代理加载与名称编辑测试。

## 验证

- 新连接链路测试在旧代码上实际失败（3 个协议均被默认连接拦截），修复后通过；连接、思考选项和名称编辑 46 项通过（并行工作增加辅助模型测试后为 47 项）。
- LLM service 19 项通过，包括真实 undici 初始化和异常归类。
- 新生产 deploy 代理初始化通过；同一门禁在旧安装包上复现 ERR_MODULE_NOT_FOUND。
- 依赖闭包构建、Desktop 类型检查、Electron/Renderer 构建、文档检查通过。
- 实际修复后的 SDK 适配器向用户授权中转发送极短消息，流式返回 OK；刻意注入默认供应商的占位地址与 Key 未影响目标连接。
- 全量 Desktop 673 项中 670 通过、3 失败；当时存在并行修改。随后针对性重跑 79 项，78 通过，剩余“添加工作区”界面测试失败，不在本次修改范围。
- 未替换用户安装包；工作区其他修改完整保留。

## 同类检查

Desktop 主模型与图片辅助模型在适配器最终出口均只使用选中连接。CLI 的凭据和模型原本来自同一 provider 解析，未发现相同默认连接覆盖。共用代理依赖影响 Desktop 与 CLI，因此两个打包入口均增加门禁。

## 本地配置修正

按用户确认，通过 SettingsService 将既有自定义连接改为指定显示名称并补齐 API base 路径，备份原设置；不改变连接 ID 或 Key。当前运行的旧应用需重新加载配置，安装包未替换。新增详情入口已通过组件测试和构建；新版 Electron 窗口尚未验收。
