## 2026-09-07 | Task: 修复 Electron 开发运行包损坏导致启动退出

### 用户诉求与执行上下文

用户反馈 Vite 成功启动后 Electron 立即退出 1，确认方案后要求修复。Codex 在 macOS 当前工作区修复开发启动器，保留其他未提交改动；未提交或推送。

### 原因与修改

临时开发 app 与已安装 Electron 相比缺少 238 个文件，包括主 Info.plist、Helper 与框架资源。旧启动器只检查主可执行文件存在，因此错误复用残缺缓存。原始 Electron 的版本探针成功，缓存副本的同一探针失败，排除项目入口和 5173 端口为这次退出的原因；文件最初为何缺失仍未知。

- `scripts/electron-runtime-integrity.mjs`：相对安装包校验文件结构、普通资源大小、可执行位、符号链接及开发身份；避免每次启动散列大型二进制。签名或重命名会改变的文件不比较大小。
- `scripts/run-electron-dev.mjs`：缓存不完整时重建，暂存副本通过校验后才替换；异常退出打印 code / signal。
- 回归覆盖完整包、主程序仍在但 plist 丢失、嵌套 Helper 丢失/截断、错误链接和错误身份；同步前端启动验证文档。

### 验证

先用旧“只检查 executable”判据运行新测试，1 通过 / 3 失败；修复后 4 / 4 通过。真实残缺缓存被新判据拒绝并自动重建；随后 prepare-only 复用校验通过，修复后的版本探针返回 v39.8.10。

`pnpm dev:log` 完成依赖构建，shared 与 Electron watch 均无编译错误，5173 正常监听，系统应用列表显示专属 ActSpace 开发应用正在运行，未再出现启动 exit 1，主进程日志确认 `runtime v2 ready`。Computer Use 无法获得该应用句柄，故页面视觉及交互未直接验收。Chromium 另有用户磁盘缓存告警，未导致本次启动退出，未扩大范围清理用户数据。

开发进程管理与缓存测试合计 9 通过、1 个既有 opt-in 测试跳过。扫描开发启动脚本，未发现第二处同类缓存复用分支。文档门禁与 diff 空白检查通过。
