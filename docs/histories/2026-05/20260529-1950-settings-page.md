### [2026-05-29 20:20] 供应商 Key 改为"仅页面输入 + 加密存本机"（同一任务续）

承接上一条的供应商状态调整，进一步采纳"Key 不放 .env，直接页面输入、加密存本地"的方案：

- **去掉 .env 兜底与 `hasEnvFallback`**：`ProviderSettingsView` 回到单一 `hasApiKey`，只反映 safeStorage 里是否有用户在页面保存的 Key。`SettingsService` 移除 `providerEnvBaseline` 快照；`applyToEnv` 改为"有 UI 密钥则写 `process.env`，无则删除"，不再从 .env/外部 env 回填。卡片回到两态（已连接/未连接）。
- **根因记录**：旧实现把 .env 里的 Key 也算"已连接"，加上 `loadEnv` 只填充 `process.env` 中未定义的键、`buildEnv` 读取时 `process.env[k] ?? fileVars[k]`——只要 .env 文件还留着该键，`getEnv()` 永远读得到，UI 点"断开"对 agent 实际可用性无效。所以彻底断开必须从 .env 移除该键；UI 现在只认 secrets.json。另一直接原因：`pnpm dev` 下 Electron **主进程不热更新**，旧 main 仍在跑。
- **每轮实时读 env 已确认**：`buildAgentConfig() → resolveAgentEnvConfig()` 每轮通过 env proxy 读 Key，故页面改 Key 下一轮即生效，无需重启主进程（仅本次改 main 代码需重启加载）。
- **测试连接是真实请求**：DeepSeek 打 `/user/balance`、Kimi 打 `/v1/models`，看真实状态码。截图里"Kimi 鉴权失败 401/403"是 .env 里的 Kimi Key 无效/权限不足，非代码 bug。
- **文档**：`.env.example` 的 DeepSeek/Kimi 段注明"推荐在桌面端设置里填写、加密存本机；UI 断开只认页面 Key"。
- **测试同步**：`settings-service.test.ts` 改为断言"clearProviderKey 彻底删除、不回落 .env"与".env 裸 Key 不再视为已连接"。shared/desktop typecheck + 137 测试全绿。

待用户侧操作：重启 Electron app 以加载新 main；并从 `.env` 移除 `DEEPSEEK_API_KEY`/`KIMI_API_KEY`，之后在「设置 → 模型」重新连接。
