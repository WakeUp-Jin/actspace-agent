**Key Actions:**

- 基线：`main` 最近两次 `ci.yml` 的 `类型检查与测试` job 9–12 min，其中 Typecheck 1:47–2:33（`typecheck:contracts` 逐包 `tsc -p` + 73 个 `tsc --noEmit`），Test 6:16–8:54（desktop 一家 137–279 s；runtime 因 vitest 4 不再默认排除 `dist/` 而把测试跑了两遍）。
- P1：`tsconfig.package.json` 的 `exclude` 从 `["src/**/test", "tests"]` 改为 `["**/test", "**/tests", "**/*.test.ts"]`——原写法相对声明文件所在的根目录解析，对所有包都是空操作，`tsc -b tsconfig.desktop-deps.json` 因此在 `agent-service` 报 TS2307。两个自己覆盖 `exclude` 的包同步补上。根 `build:deps` 复用 desktop 的 `build:deps:dev`（`tsc -b` + esbuild 包 + prompts + 默认 harness），根 `typecheck` 改为 `build:deps` 加 apps / 图外包的 `tsc --noEmit`，删除 `typecheck:contracts`。本地 82 s → 24 s。
- P2：`typecheck-test` 拆成 `lint-typecheck`、`test-process`（根脚本与进程级测试，`pnpm test:scripts`）、`test-packages`（`pnpm -r --filter '!@actspace/desktop' --filter '!actspace' test`）、`test-desktop`（2 分片），互不 `needs`。四个 job 共用 composite action `setup-workspace`：pnpm / Node / install + `actions/cache` 恢复 `packages/*/*/dist`，key 带 SHA、`restore-keys` 退到同 lockfile。`check-action-pinning.sh` 跳过本地 `uses: ./` 并扫描 `.github/actions`。
- P3：desktop vitest 拆成 `main`（node 环境）/ `renderer`（jsdom）两个 project，CI 用 `--shard=N/2`。本地两分片 65 s / 68 s（原 136 s），main 单独 24 s → 18 s。
- 首轮 CI 暴露并修复四个问题：排除式 `--filter` 会把 workspace 根选进来导致 `pnpm -r test` 递归；`test-desktop` 漏装 ripgrep；`packages/**/dist` 的 `**` 跟进 `node_modules` 符号链接匹配 1.7 万个第三方 `dist`，缓存保存卡 5 min 以上；`SettingsPage` 是 `React.lazy`，分片后冷缓存首次打开超过 `findBy` 默认 1 s。
- `build` job / `release-package.sh` 复用缓存推迟，登记到 `tech-debt-tracker.md`。

### 🧠 Design Intent (Why)

- 用 `actions/cache` 而不是 artifact 在 job 间传产物：各 job 都从 install 开始并行，关键路径只取最长的那个；缓存 miss 时各自 `tsc -b` 冷编 9 s 级，比等上游 job 再下载便宜。
- 根 `typecheck` 不再 `pnpm -r typecheck`：`tsc -b` 已经用每个包自己的 `tsconfig.json` 全量检查过 packages，再起 60 多个 `tsc --noEmit` 是重复劳动。
- 修 `exclude` 而不是把 devDependencies 加进 references 图：测试文件本来就不该进 `dist/`，顺手也解决了 vitest 4 跑两遍的问题。
- 不新写 `scripts/build-deps.mjs`，直接复用 `build:deps:dev`：dev 启动和 CI 走同一条链，少一份要同步的清单。
