> 给 ActSpace 做一个产品宣传片，主要介绍 ActSpace 是什么、核心特点是什么、怎么使用；目的是让大家了解它并吸引大家来用。具体表达由你发挥。

### 🛠 Changes Overview

**Scope:** 新增 `apps/promo-video`（`@actspace/promo-video`）；`scripts/check-package-boundaries.mjs`、`apps/README.md`、`docs/ARCHITECTURE.md`、`apps/site/SCREENSHOTS.md`、`pnpm-lock.yaml`

**Key Actions:**

- **成片**：约 100 秒、1920×1080、30 帧，中文字幕、无旁白、带合成配乐。结构是「是什么 → 核心特点 → 怎么用 → 接下来」，共 12 个分镜：开场问题、品牌定位、一次完整任务、五项特点（上下文看得见 / 执行有边界 / 过程可追溯 / 结果可交付 / 成本可控）、一切皆插件与本地优先、三步上手、方向与状态、收尾地址。
- **可定位的时间线**：`src/timeline.js` 把所有 CSS 动画暂停，按「时刻 − 分镜开始时间」设置 `currentTime`；预览播放器和渲染脚本共用同一个 `seek(t)`。
- **渲染脚本**：`scripts/render.mjs` 用无头 Chrome 逐帧截图喂给 ffmpeg；`scripts/lib/chrome.mjs` 是只依赖 Node 自带 WebSocket 的最小 DevTools 协议客户端。支持整片、区间、单帧导出和无声输出。
- **首屏演示实录**：`scripts/capture-hero.mjs` 在官网页面里接管定时器、`requestAnimationFrame` 和动画时钟，逐帧推进并截图，得到与机器速度无关的 16:9 帧序列。
- **配乐**：`scripts/lib/music.mjs` 按分镜强度合成四层声音，输出确定的 WAV，每次渲染按当前时间线重新生成。
- **仓库接入**：`@actspace/promo-video` 加入包边界检查的应用豁免名单；`apps/README.md`、`docs/ARCHITECTURE.md` 登记新应用和它的依赖边界；`apps/site/SCREENSHOTS.md` 写明宣传片引用了哪些截图，换图要同步改镜头位置。

### 🧠 Design Intent (Why)

宣传片要随产品一起改，所以做成仓库里可以重新渲染的代码，而不是一份改不动的视频文件：文案、时长、截图换了，改对应分镜再跑一遍即可。

不用录屏、也不引入视频框架，是因为录屏的节奏取决于机器快慢，重做一次画面就变；按时刻定位的合成让每一帧都只由时间决定，预览看到的就是渲染出来的。

素材直接引用官网已公开、已脱敏的截图和首屏演示，不再维护第二份，也保证片子里的界面和官网一致。画面里的说法守住两条：能力状态不超出官网首页的标注（只有上下文管理引擎标「已上线」，Harness 自进化、Actor 与 Space 标「进行中」，Space 画面注明是演示），「怎么用」只写当前真实可行的从源码运行。

成片、帧序列和配乐都是可再生成的制品，不入库。配乐用脚本合成，避免引入有授权问题的音频素材；它只做过电平和频段的数值检查，没有经过人耳试听。

### 🤖 Execution Context

### 📥 User Query

> 第一版一般：中间太多官网的浏览播放，不吸引人，也不清晰，中间部分啰嗦。读一篇讲产品视频经验的帖子，按里面的经验优化调整，多出几版不同风格的视频供挑选。

### 🛠 Changes Overview

**Scope:** `apps/promo-video`（重写分镜与素材来源）、`apps/desktop/src/renderer/mock/scenarios`（新增取景场景）；`docs/FRONTEND_VERIFICATION.md`、`docs/ARCHITECTURE.md`、`apps/README.md`、`apps/site/SCREENSHOTS.md`

**Key Actions:**

- **三个版本**：`src/films/index.js` 里每个版本是一份分镜列表，`render --film <版本>` 输出各自的 MP4。`real`（38 秒，真实界面、一条任务讲到底）、`motion`（46 秒，重画界面的动效图形）、`short`（12 秒，卡点品牌短片）。第一版的 12 个分镜（官网首屏实录、五张截图的镜头推移等）全部删除。
- **真实界面的素材**：桌面端 renderer 的浏览器 mock 新增 `promo-draft` / `promo-demo` 两个场景，是一条前后连贯的演示任务（输入 → 读写文件 → `pnpm test` 待审批 → 点「运行」后给出结果、交付文件和带用量的回复）。`scripts/capture-ui.mjs` 按片子顺序真的去输入、点击、悬停，截 3 倍密度的整窗图，并把按钮和关键区域的位置写进 `meta.json`。
- **时间线驱动**：`src/timeline.js` 新增镜头、整幅画面切换、数字滚动三个按时刻计算的驱动；镜头和指针的位置全部来自截图时量出的数据，不手写坐标。
- **配乐**：改成 120 BPM，一小节 2 秒，分镜时长取 2 秒的整数倍；强度由分镜自己声明，可以在一个分镜内分段；加了底鼓。
- **文档**：宣传片 README 重写（三个版本、剪法上守的几条、和桌面端 mock 的耦合）；`?mock=` 场景表登记两个新场景；架构文档更新宣传片的依赖边界（不再读官网截图和首屏演示）。

### 🧠 Design Intent (Why)

第一版的问题和帖子里点名的几个坑是同一批：逐项罗列功能、每讲一点就清屏换一张裁过的截图、用官网的模拟演示代替产品本身。重剪时把它们反过来做成规则写进了 README：一条片子只说一句话；开头先给痛点和真实产品；跟一条具体任务走到底，同一个窗口一直留在画面里；完整窗口 → 真实点击 → 结果特写三级接力；窗口外只留一行短标题。

真实界面版需要一条前后说得通的任务，现有 mock 场景各自只覆盖一个界面状态，拼不成一条线，所以单独加了取景场景，而不是去改给界面验证用的场景。数据是演示内容，文档里写明不能拿它证明产品状态。

版本之间共用时间线、镜头、配乐和收尾分镜，差别只在分镜列表，所以多出一个版本的成本是几个分镜文件。动效图形版里重画的界面是示意，不会随产品自动更新，README 里写了要手动核对。

没有做旁白和实拍 / 生成画面：环境里没有语音合成或视频生成的密钥。配乐仍然只做过电平检查，没有经过人耳试听。
