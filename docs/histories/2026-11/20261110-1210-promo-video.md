- **渲染脚本**：`scripts/render.mjs` 用无头 Chrome 逐帧截图喂给 ffmpeg；`scripts/lib/chrome.mjs` 是只依赖 Node 自带 WebSocket 的最小 DevTools 协议客户端。支持整片、区间、单帧导出和无声输出。
- **首屏演示实录**：`scripts/capture-hero.mjs` 在官网页面里接管定时器、`requestAnimationFrame` 和动画时钟，逐帧推进并截图，得到与机器速度无关的 16:9 帧序列。
- **配乐**：`scripts/lib/music.mjs` 按分镜强度合成四层声音，输出确定的 WAV，每次渲染按当前时间线重新生成。
- **仓库接入**：`@actspace/promo-video` 加入包边界检查的应用豁免名单；`apps/README.md`、`docs/ARCHITECTURE.md` 登记新应用和它的依赖边界；`apps/site/SCREENSHOTS.md` 写明宣传片引用了哪些截图，换图要同步改镜头位置。

### 🧠 Design Intent (Why)

宣传片要随产品一起改，所以做成仓库里可以重新渲染的代码，而不是一份改不动的视频文件：文案、时长、截图换了，改对应分镜再跑一遍即可。

不用录屏、也不引入视频框架，是因为录屏的节奏取决于机器快慢，重做一次画面就变；按时刻定位的合成让每一帧都只由时间决定，预览看到的就是渲染出来的。

素材直接引用官网已公开、已脱敏的截图和首屏演示，不再维护第二份，也保证片子里的界面和官网一致。画面里的说法守住两条：能力状态不超出官网首页的标注（只有上下文管理引擎标「已上线」，Harness 自进化、Actor 与 Space 标「进行中」，Space 画面注明是演示），「怎么用」只写当前真实可行的从源码运行。

成片、帧序列和配乐都是可再生成的制品，不入库。配乐用脚本合成，避免引入有授权问题的音频素材；它只做过电平和频段的数值检查，没有经过人耳试听。
