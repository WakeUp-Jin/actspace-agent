# 功能与修复统一采用分支 PR 工作流

用户确定团队协作流程：独立任务分支开发，验证后推送并创建PR，由评审者审核合并，再同步本地main。

- 在REPO_COLLAB_GUIDE中明确分支、验证、推送、PR、人工合并和本地ff-only同步的顺序；CONTRIBUTING链接该规则。
- 禁止默认直接在main开发/推送，不复用已合并任务分支；误放main的提交先完整保留再按授权恢复。
- 本次确认侧栏与默认工作区已通过PR #4合并；本轮MN01–MN04修复迁到独立codex修复分支，旧验收与修复测试结果随提交保留。
- 新增用户可见修复更新日志。仅处理协作流程和交付，不增加产品修复范围。

这是既有Git协作流程的明确化，未达到新增学习文档的两项门槛。
