# 侧边对话（Side Chat）

## 目标

在桌面端右侧面板里，从当前主会话分出可长期保存、可多开的「侧边对话」。分叉时继承主会话截至上一轮结束的上下文，之后独立运行；默认 Plan（只读）模式，模型默认跟主会话一致。后端规则由新插件包 `@actspace/side-chat` 承担。

## 范围

- 包含：
  - `lineage.origin` 增加 `"side-chat"`；
  - 插件包（边界算法 + 边界提示词）；
  - `AgentApplication.openSideChat`、桌面 IPC、usage 目录列；
  - 右栏 `sideChat` tab 与 `SideChatView`、`+` / 启动列表入口、收起后重新打开；
  - `/side [问题]`；
  - 左侧会话栏隐藏侧边对话并显示数量；
  - mock 场景与文档。
- 不包含：
  - 从某条历史消息分出、嵌套分出、回流 / `send_message`；
  - 远端 Host（能力表里关闭入口）；
  - 侧边对话的消息队列（运行中输入框锁定，按钮变停止）；
  - 侧边对话的轨迹视图、轮次导航、回复批注。

## 风险

- `App.tsx` 里发送 / 停止逻辑与当前会话耦合深。缓解：先抽 `sendToSession(sessionId, …)` / `abortSession(sessionId)`，主会话改为调用它们，现有 composer 测试先跑通再接侧边对话。
- 两个 Composer 同时挂载，斜杠菜单的 DOM id 冲突。缓解：用 `useId` 加前缀。
- usage 目录 schema 加列。缓解：按现有 schema 版本机制迁移，并补 fallback 和 worker 测试。
- 旧版本读到 `"side-chat"` header 会报无效。已在设计文档写明，不做兼容层。

## 里程碑与任务

### B. 后端

1. **B1 Journal lineage**
   - 改动：`header.ts` 的类型和 `validateLineage` 接受 `"side-chat"`；`fork.ts`、`session-store.ts` 的 `origin` 联合类型同步；`delegationDepth` 同 fork。
   - 测试：journal 的 header 测试加合法用例，`SessionStore.fork` 加 `origin: "side-chat"` 用例。
2. **B2 插件包 `packages/side-chat`**
   - 文件：`package.json`、`tsconfig*.json`、`src/{manifest,plugin,boundary,prompt,index}.ts`。
   - `resolveSideChatBoundary(events)`：
     - 找最后一个 `turn/end`，用 `validateSessionEvents(prefix)` 确认已平衡；不平衡就继续往前找。
     - 返回 `{ boundarySeq, inheritedTurnCount, runningTurnExcluded }`。
     - 一轮都没结束时抛 `SIDE_CHAT_NO_COMPLETED_TURN`。
   - `plugin.ts`：
     - `session/created` → 用 `session.runtime.getOpen` 取会话；`lineage.origin === "side-chat"` 时 `registerMainSession(sessionId, 边界提示 source)`。
     - `session/disposed` → 移除注册。
     - 提供服务 `side-chat`。
   - 测试：`src/test/boundary.test.ts` 覆盖四种情况——
     - 空闲；
     - 运行中截到上一轮；
     - 工具调用未完成；
     - 一轮都没结束。

     `src/test/lifecycle.test.ts` 覆盖两种情况——
     - 侧边会话注册了提示词，普通会话不注册；
     - disposed 后移除。
   - 装配：`packages/runtime/package.json` 加依赖，`composition.ts` 里加一条与 english-learning 同形的条目（如 harness 定义也需要，同步 `default-harness-definition.ts`）。
3. **B3 `AgentApplication.openSideChat(parentSessionId, newSessionId)`**（`packages/agent-service/src/application.ts`）
   - 流程：
     1. 用 inspect 读父会话事件，调用 `resolveSideChatBoundary`；
     2. `store.fork({ origin: "side-chat" })`；
     3. 父会话不是 Chat 形态时追加 `agent/mode-set` 为 `plan`；
     4. 走 controller resume；
     5. 返回 `{ snapshot, inheritedTurnCount, runningTurnExcluded }`。
   - 接口和 CLI host-adapter 同步。
   - 测试：`packages/runtime/src/test/side-chat-fork.test.ts`，覆盖三点——
     - 父会话运行中分叉成功，且不含进行中的轮次；
     - 子会话的 header origin 为 `side-chat`，模式为 `plan`；
     - 子会话的上下文里有边界提示。
4. **B4 桌面 IPC**
   - 新增 `sessions.openSideChat({ parentSessionId })`，返回 `{ session: RuntimeV2DesktopSessionProjection, inheritedTurnCount, runningTurnExcluded }`。
   - 新增 `sessions.listSideChats({ parentSessionId })`，返回 `SessionListItem[]`。
   - 按「7 步」走：channel → 契约 → main 注册 → guard（`parentSessionId` 非空字符串）→ mock → 调用方 → `pnpm check:ipc-channels`。
   - `RuntimeV2Registry.openSideChat` 做 admission 并发出 `session-forked` 变更。
5. **B5 会话目录**
   - `SessionListItem` 加 `sideChatParentId?: string` 和 `sideChatCount?: number`。
   - `session_catalog` 加 `side_chat_parent_id` 列（schema 迁移）；分页查询排除侧边对话，并带出每个主会话的侧边对话数量；`listSideChats` 按父 id 查询。
   - `usage-catalog-fallback.ts`、`fixed-renderer-ipc.ts` 的 `toSessionListItem`、`packages/shared/src/session-list-page.ts` 同样处理。
   - 测试：`apps/desktop/src/main/test/` 下的 usage 目录测试加用例。

## 验证方式

- 命令：
  - `pnpm --filter @actspace/side-chat test`、`pnpm --filter @actspace/session-journal test`、`pnpm --filter @actspace/runtime test`、`pnpm --filter @actspace/agent-service test`
  - `pnpm --filter @actspace/desktop typecheck`、`pnpm --filter @actspace/desktop test`
  - `pnpm check:frontend-tokens`、`pnpm check:frontend-theme`、`pnpm check:renderer-bridge`、`pnpm check:ipc-channels`、`pnpm check:current-docs`
- 手工检查：
  - 浏览器 `?mock=side-chat`：浅色、深色、480px 窄窗截图；
  - 键盘走一遍：`+` 菜单的 Esc 和焦点回到触发器。
- Electron（交给用户）：
  1. 真实主会话运行中开侧边对话，确认分隔线文案；
  2. 侧边对话里问之前聊过的内容，确认它知道；
  3. Plan 下让它改文件，确认没有写工具；退出 Plan 后可以改；
  4. 两个侧边对话同时流式输出；
  5. 关 tab 后从 `+` 重新打开；
  6. 重启应用后侧边对话仍在，边界提示仍生效；
  7. 左侧会话栏只显示数量。
