## 只验收的工作边界

- 允许：读取源码与已有文档；执行现有构建 / 检查 / 测试；创建本次专用验收脚本、fixture 服务、证据和报告；在隔离环境中操作待验功能。
- 禁止：修改产品源码、正式测试、配置、原生按钮基线；应用自动修复；为通过门禁修改预期；提交、推送、合并；委派任何修复。
- 发现 Bug 只阻断它影响的子项。记录后继续其余可执行项目，不把整组操作失败当作其余项目都已验过。
- 不操作用户原有会话、原始设置与凭据，不关闭用户原 Electron / Chrome / Vite。创建、移除、归档和配置使用独立数据目录或明确 mock 边界。
- 临时数据目录 0700、临时配置 / 凭据 0600。已有 Provider 凭据只由隔离主进程使用，不打印、不进入截图、Journal 摘录或报告。结束删除临时凭据及原始会话记录，仅保留脱敏证据。
- 首次启动默认目录测试需同时隔离应用数据与默认工作区路径。不能仅设置 `ACTSPACE_WORKSPACE_ROOT` 就宣称验过正式首次启动兜底；先确认开发态 fallback 分支，并记录实际覆盖方式。
- 原生外部打开只针对本次创建的文件；Word / Excel 未安装时记录缺环境，不安装软件、不修改默认关联。

## 执行顺序与操作分组

### P0：批准后冻结基线并准备统一构建

1. 复读 HEAD / 工作区状态，确认新增或删除的功能没有超出台账；记录源码指纹和原进程清单。
2. 依次构建依赖、renderer、Electron，记录命令、开始 / 结束时间、退出码和日志。
3. 准备独立 Electron 数据目录、专用工作区、脱敏证据目录。先验证 preload / IPC / 会话创建的非空结果，再进入功能检查。
4. 规划时已提前完成的构建只记为准备记录；若批准执行时版本或产物改变，重新构建，不把旧产物当当前版本。

### P1：fixture 与设置路线

- **轨迹**：errors / complete → 记录类型、详情、关联跳转、JSON / 系统差异 → 搜索 / 清空 / 折叠 → 时间轴 → streaming / streaming-long 的表格、详情和节点稳定性。覆盖 T01–T05、T13–T18；只在异常或关键终态留截图。
- **模型与用量**：模型列表 → 已配置详情 → 返回 → 添加连接 → 内置 / Anthropic / 自定义服务配置 → 模型编辑 → 按入口返回；之后 turn-deliverables 三轮 → 用量弹窗 → 交付与改动卡 → Review → 设置开关。覆盖 M01–M05、U01–U04、D01–D03、D06。
- **侧栏**：sidebar → 搜索 / Esc → 分区折叠 / 更多 → 三种视图 → 归档三态 → 会话 / 工作区拖拽 → 恢复默认 → 重载。覆盖 SB01–SB06、SB08；fixture 不包含的状态不宣称通过。
- 完整主要交互先走 1440 浅色，再复用相同入口检查深色和 480px / 479px 的差异。480px 是边界，479px 用于核对“低于 480px 仅图标”。覆盖 V01–V02。
- fixture 优先使用仓库现有 `?mock=` / `trajectoryFixture=`；需要补充数据时只使用明确的验收网络路由或本地测试服务，不向产品源码或 DOM 注入实现。

### P2：真实 Electron 与 Provider 路线

- **自然完成样本**：通过 UI 关闭 Thinking 发短请求并完成，打开 Thinking 再完成；复用样本检查真实用量、模型名、TTFT / TPS 与重载历史，覆盖 T10、S01–S03、U05。
- **长输出停止样本**：运行中进入轨迹 → 保留同记录正文 / 预览两时点增长 → 新词搜索 → 清空 → 点击停止 → 观察停止状态结束 → 返回输入框并实际编辑草稿。覆盖 T06–T09；不以输入框“可见”替代“可编辑”。
- **受控失败样本**：人工无效 key 覆盖立即失败；隔离本地兼容 SSE 服务覆盖已有正文后的失败。服务需先真正输出，等合法终态 failed 后观察，不关闭窗口模拟产品失败，不把网络重试中误当最终失败。覆盖 T11–T12；逐项记录制造失败的方法。
- **真实交付样本**：专用工作区内让 Agent 创建文本报告 / CSV 并调用 present，验证轮尾改动、交付卡、预览、Finder 定位与已安装原生应用打开。覆盖 D04–D05 和 H02；临时文件不接触用户项目。
- **侧栏真实状态 / 工作区**：运行 A 后切 B，A 完成未读进入需要处理、打开 A 清除；执行隔离会话 / 工作区拖拽重启、归档恢复；全新 registry、已有 registry、移除最后工作区后重开。覆盖 SB04–SB08、W01–W05。
- **Harness 升级**：先看隔离已有历史的升级 / 恢复，再跑新请求和交付。新会话通过只证明当前启动可用，不能直接关闭“已有版本连续升级”项。覆盖 H01–H02。
- 真实 Provider 请求尽量复用样本，只有新信息支持时才重试；工具超时另记工具限制，不无限追加轮次追求通过。

### P3：工程验证与汇总

- 全量 Desktop 测试、相关包测试、类型与规则检查集中执行；计算性能与浏览器帧采样避开全量测试和其他重负载任务。
- 全量失败先保留完整日志和退出码；定向重跑只补充复现范围，不能删除首次失败或直接认定“与改动无关”。
- 完成源文件指纹核对、隔离凭据 / 进程清理，逐项汇总结果；每个子智能体都需提交覆盖、复现和必要证据。

## 关键通过标准与证据

| 项目 | 判定依据 |
| --- | --- |
| 真实增长 | 同 session / recordId，正文与预览至少两个有效时点长度增加；保存时间和长度。思考增长不能代替正文增长 |
| 新词搜索 | 新词此前不在可搜索正文 / 思考中；记录最后一次不存在、首次出现、设置 query 与命中时间。约 3 秒门槛按出现时间计，并报告轮询误差；已有命中词不能证明节流更新 |
| 停止 | 有 UI 点击记录、终止事件、停止中消失、Composer enabled / 可输入草稿；分别报告各时点，不用后台 aborted 代替 UI 恢复 |
| 错误 | 独立可见、不需展开、终态后即时更新、computed 颜色与截图支持红色；401 与中途失败分别结论 |
| TTFT | 按有效请求的首非空 chunk 时间减请求开始时间求和 / 次数，按 UI 同一舍入规则比较；记录样本是否包含思考首 token |
| TPS | 有输出 token 的有效请求：输出 token 总数 / 对应解码秒数总和；解码区间为首 token 到请求结算。不用字符数估 token，不要求流式尚未结算时已有 TPS |
| 长历史统计 | 宿主全 Journal 计时与 slim 窗口分开对照；重新加载历史仍与完整记录相符，不能只看数字非空 |
| 统计增量 | 比较 sessionStats 的状态 / revision，首 token 后后续 chunk 不逐条修改此统计；其他消息投影更新不等于统计失败 |
| 本轮计价 | 成功 / 失败重试各请求只计一次；未知费用不计为 0；明确已知、全未知、已知与未知混合、预估及真实 provider / model 的口径 |
| 流式计算 | 2000 chunk split p95 < 2ms；chunk 处理一次、首帧后纯 chunk 不重建定稿层 / 时间轴、逐帧等价；每项保留断言或计数 |
| 浏览器流式 | 同行 DOM 不重新挂载；帧间隔 p95 ≤16.8ms，并报告 max / 长帧与负载。p95 达标不代表零长帧 |
| 持久化 | 重载 / 进程重开后的真实存储结果；mock 内存状态不证明重启持久化 |

- 主智能体：范围 / 文档、源码与数据口径核对、工程检查、问题去重、报告汇总；本任务不承担修复。

- 证据目录：`tmp/codex-acceptance/20261015-main/<场景>/<运行编号>/`。每次运行生成唯一名字，边执行边保存 JSON；不覆盖上一次首帧、查询基线或终态。

## 阻断与收尾规则

- 工具报错、Provider 不可用、缺少原生应用或远端 Host：保留已完成子项，其余明确写未覆盖及缺少条件，不默认判产品失败。
- 版本变化：保留构建版本对应证据，最终版本门禁待重新冻结；不得把多个版本结果拼成同一版本全部通过。
- 产品 Bug：只记录，后续修复由用户另行安排。没有确认根因时写“线索 / 未定位”，不强行归责。
- 报告最终分为：通过项、失败项、未覆盖项、历史待复核项；工程全量通过与界面通过分别判定。没有未覆盖也没有失败才能称本范围整体通过。
- 清理仅关闭本次自建实例 / 服务，删除本次临时凭据和工作区；保留必要脱敏证据。核对源码指纹后报告允许的文档变化与任何外部变化。
