# 会话与长历史按需加载

状态：实现完成，2026-09-15。工程结果、并行改动造成的最终类型检查阻塞与尚未完成的真实交互验收见[执行摘要](../../exec-runs/20260915-progressive-session-loading/execution-summary.md)。

## 目标与约束

启动只请求每个工作区最近 10 个会话摘要，Show more 真正请求后续摘要；只打开最新可见会话。消息首次/向上翻页每次 10 个完整用户回合，保留工具关联和滚动锚点。统计保持按需，轨迹从普通读取中拆出。加载、错误、重试独立展示。

Journal 保持唯一事实来源。可删除重建的浏览索引不参与恢复、模型上下文、导出、复制完整对话。旧数据在后台建立索引；失败不能伪装空会话。缓存有界，切换防竞态。保留已有未提交改动。

## 数据流

```text
Sidebar → 摘要分页 IPC → Runtime 浏览索引 → Journal（仅索引缺失/过期时重建）
Conversation → 消息分页 IPC → 同一索引的回合页
Trajectory → 显式打开请求 → 轨迹投影
模型运行/恢复/导出 → 原有完整 Journal
```

## 实施与验证

1. Runtime 增加可重建的摘要/回合浏览索引，Desktop App/Registry 暴露浏览契约；用真实 JSONL fixture 验证缓存、追加、分页、重建及读取边界。
2. Shared/preload/main 增加摘要分页和消息分页 IPC；普通投影不生成轨迹；验证完整复制与分页投影一致性。
3. App/Sidebar/Conversation 接入真分页、局部加载错误、重试、切换隔离与滚动锚点；轨迹挂载时请求，关闭后停止请求。验证长会话、快速切换、正在运行与加载历史并行。
4. 运行依赖构建、受影响测试、desktop typecheck/build、文档与主题检查；查看真实 Electron，明确真实冷启动和性能证据的范围。
5. 同步设计、history 和执行摘要；完成后归档本计划。变更跨 Runtime、契约、Host、renderer 和测试，预计超过 8 个文件。

## 回退

回退代码即可恢复旧读取方式；浏览索引仅为派生缓存，不迁移或改写 Journal。无外部 API 或新依赖。
