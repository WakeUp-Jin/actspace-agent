## 目标

- 弹层、菜单、对话框、下拉选择只有一套原语，都基于 Radix，放在 `R/components/ui/`。
- 统一键盘和焦点行为：Esc 只关最上层；关闭后焦点回到触发器；对话框内 Tab 不出界；弹层 portal 到 body，不再依赖祖先 `overflow-visible`。
- 拆分 SettingsPage、Sidebar、ConversationView、WorkbenchLayout，单文件不超过 500 行。
- Composer 在 ConversationView 中只挂载一次；附件随会话草稿走，不再串到别的会话。
- 原生 `<button>` 的数量只减不增，由检查脚本把关。

## 决策记录

| 日期 | 决定 | 原因 |
| --- | --- | --- |
| 2026-10-05 | 不新建 `features/`。拆出的文件放在原组件旁的子目录：`R/components/settings/sections/`、`R/components/settings/dialogs/`、`R/components/sidebar/`、`R/components/conversation/`、`R/components/workbench/`。原组件文件保留在原路径，作为入口 | 测试都从现路径 import，搬目录只制造噪音；与 14 的决定一致 |
| 2026-10-05 | 类名工具统一为 `ui/cn.ts` 导出 `cn`；`Button.tsx` 的 `cx` 改为从 `cn.ts` 再导出，保持兼容；`Tooltip.tsx` 的本地 `cn` 删除 | 原语有很多文件，要共用一份 |
| 2026-10-05 | ContextPopup、ResponseAnnotationCommentPopover、ResponseAnnotationPill、WorkspaceChromeControls 的环境浮层用 **Popover**，不用 Dialog | 它们不阻断背景操作；做成模态会改变交互 |
| 2026-10-05 | ResponseSelectionMenu 用 Radix Popover 加虚拟 anchor（选区的 `getBoundingClientRect`） | 原来手算位置；改用 Radix 的碰撞检测 |
| 2026-10-05 | 附件纳入草稿：按 `draftKey` 存在 14 的 `SessionLocalStore`（字段 `attachments`），切换会话时换出换入；发送成功、清空草稿、会话 evict 时释放 blob URL。Composer 单次挂载，**不用 `key={draftKey}` 强制重挂** | 和文本草稿行为一致（切回会话附件还在）；重挂会丢焦点和 IME 状态，也会和 09 的 Composer 拆分冲突。05 原写的 `key` 方案改为这个方案。用户已确认（00 J4） |

| 2026-10-05 | `RightPanel.tsx` 本轮不拆 | 05 没有方案；超过 500 行记录到 tech-debt |
| 2026-10-06 | ResponseAnnotationPill 保留 HoverCard（悬停预览），不改 Popover；上面「环境浮层用 Popover」一行对它不适用 | 它已是 Radix 原语，没有手写定位和点外关闭；改 Popover 会丢掉批注定稿时确认的悬停预览。用户选 `pauses.md` P2 方案 A |
