## 3. 执行流程

### 3.1 每个任务（T）

1. **重新定位**：计划里的行号只作参考，以函数名、grep 结果为准。偏差大的写进 `execution-process.md`。
2. **修改**：只改该 T 列出的文件。需要改计划外的文件时，先判断是否属于 §4 的停止条件；不属于的，就在执行记录里写明原因。
3. **跑该 T 的「测试 / 验证」**。
4. **跑通用检查**：`pnpm --filter @actspace/desktop typecheck` 和 `pnpm --filter @actspace/desktop test`。
   - 结果必须等于「基线 + 本计划预期的变化」。
   - 出现基线以外的新失败，必须修好才能提交。
   - 修不好的按 §4 处理。
5. **更新 `execution-process.md`**：一行即可，写完成了什么、偏差和数字。这个更新与代码放在同一个提交里。
6. **提交**：在当前计划的子分支上提交，格式见 §5。

### 3.2 每个阶段（计划中以 S 或 P 分组的一组 T）

1. 跑该计划「验证方式」中的全部命令。
2. 计划要求 Electron 检查的，按 §8 用 CDP 执行，截图存到该计划执行记录目录下的 `screenshots/`。
3. 填写 `acceptance-handoff.md` 中对应阶段的一节（§6 模板）。
4. 派一个 Sonnet 子智能体做只读复核：
   - 读该阶段的 diff 和计划，核对是否超出范围、有无漏改、grep 门槛是否达到；
   - 结论写进执行记录；
   - 子智能体**不编辑任何文件**。

### 3.3 每份计划结束时

1. 补全 `execution-summary.md`（模板见 `docs/exec-runs/templates/`），重点写人工验证指引。
2. 完成 `acceptance-handoff.md`，并标注「可以交给验收」。
3. 更新 history 文件（§9）。
4. 更新本文 §11 的总进度。
5. 按 §5「每份计划的分支流程」把子分支 squash 合并回主线，写好提交信息；把主线提交的哈希填进 `acceptance-handoff.md` 和 §11。
6. 直接进入下一份计划，**不等待验收结果**。验收反馈到达后，按 §6.3 插入修复。

### 3.4 子智能体

- 只用于探索和验收复核，**不用于编辑**。
- 模型一律用 Sonnet 5.5，不指定 opus。
- 提示词中要求先读 `AGENTS.md`，并给出计划文件路径。

### 3.5 不使用 computer use

能做的验收都要做：
- CDP 截图和控制台日志；
- `Runtime.evaluate` 断言 DOM 和焦点；
- `Input.dispatchKeyEvent` 走键盘流程；
- `Emulation.setDeviceMetricsOverride` 模拟窄窗；
- 浏览器 mock 场景（13 之后）；
- 用 `ps` 检查子进程。

做不到的交给验收方（Codex），并在交接文档中写清步骤和预期：
- 系统浏览器是否打开；
- Dock 重开；
- 中文输入法；
- 真实远端 Host；
- 需要模型 key 的真实对话。

## 4. 停止条件

连续执行（E），**只有**以下情况停下：

| # | 情况 | 举例 |
| --- | --- | --- |
| 1 | 设计判断偏差：计划的前提与代码现状不符，继续做就要我替你做设计决定 | 14 T14 新旧合并结果不一致；16 T12 两份分组逻辑结果不同；11 T5 收紧后误拒合法路径；视觉与 demo 明显不符，又无法按规格修正 |
| 2 | 修不好的测试：基线以外的新失败，花了合理的排查后仍不能确定原因或修复 | 用多种方法尝试过仍失败 |
| 3 | 需要改协议：必须改 Runtime / Host / Session 协议，或改持久化格式，才能完成 | 15 中发现 `hostId` 无法在 desktop-adapter 中拼出 |

以下情况**也要停下**，因为它们超出了已获得的授权：
- 需要新增计划外的依赖包。已批准的只有 16 的 5 个 Radix 包。
- 需要删除或改写用户数据目录中的文件，或者需要推送到远端。
- 需要修改计划「不包含」中列出的内容。

**停下时的做法**：
1. 已完成的部分正常提交。
2. 在 00 的执行记录 `pauses.md` 中追加一条：时间、计划和 T、现象、证据、可选方案（每个方案都写优缺点）、我的建议。
3. 向用户报告，等待决定。
4. 用户决定后，写进对应计划的决策记录，然后继续。

**不需要停下的情况**：行号漂移、计数与计划不同、需要多拆一个提交、测试改写方式不同。这些写进执行记录，继续执行。

## 5. Git 与提交

### 分支（J2，2026-10-05 已定：子分支 + squash）

```
main
 └─ refactor/desktop-frontend          ← 主线：S0 一个提交，之后每份计划一个提交
     ├─ refactor/desktop-fe-10         ← 子分支：每个 T 一个提交
     ├─ refactor/desktop-fe-11
     └─ …（12、13、14、15、16、09、17）
```

- 不打 tag。验收方 checkout 主线上该计划的提交来验收。
- 主线分支全部完成、验收通过后，怎么合回 `main` 由你决定。

### 每份计划的分支流程

1. **开始**：`git switch refactor/desktop-frontend`，然后 `git switch -c refactor/desktop-fe-NN`。
2. **执行**：每个 T 在子分支上提交一次（规则见下文「提交规则」）。
3. **结束**：
   1. 确认子分支上工作区干净，验证全部通过；
   2. `git switch refactor/desktop-frontend`，然后 `git merge --squash refactor/desktop-fe-NN`；
   3. 用 `git commit -F <消息文件>` 提交，消息格式见下文「squash 提交信息」；
   4. 核对 `git diff refactor/desktop-fe-NN refactor/desktop-frontend` 为空。
4. **子分支保留**：
   - squash 之后 git 不认为子分支已经合并，删除要用 `-D`；
   - 我不删子分支，等全部验收通过后由你决定；
   - 子分支保留每个 T 的提交，用于定位问题、按 T 撤销，以及压缩后的进度恢复。
5. **按 T 撤销**（计划已经 squash 之后）：在主线上运行 `git revert --no-commit <子分支上该 T 的提交>`，核对后单独提交，提交信息中写明撤销的是哪个 T、为什么撤销。

### squash 提交信息

```
refactor(desktop-fe-NN): <计划名>

<一两句话：这份计划解决了什么问题>

任务：
- T0 <做了什么>
- T1 <做了什么>
- …（每个 T 一行；有偏差的注明「偏差：…」）

验证：
- typecheck 通过；test <通过数> / <失败数>（与基线对比：…）
- <该计划的 grep 门槛、脚本检查、CDP 检查结论>

执行记录：docs/exec-runs/20261005-desktop-fe-NN-<slug>/
子分支：refactor/desktop-fe-NN（<起始哈希>..<结束哈希>，共 <n> 个提交）

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

type 一般用 `refactor`；以测试为主的计划（12）用 `test`。

### 提交规则

- **子分支上一个 T 一个提交**；计划中写明分批的 T，每批一个提交。
- 子分支上的提交信息用中文，格式与仓库现有提交一致：`<type>(desktop-fe-NN): <内容>`。
  - type 取 `refactor`、`fix`、`feat`、`test`、`docs`、`chore`。
  - 例：`refactor(desktop-fe-14): 迁出流式块生成纯函数（T1）`。
- 提交信息末尾加：

  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  ```
- 不使用 `--no-verify`，不 amend 已有的提交，不 force push，**不推送**。
- 唯一允许的历史改写是 §6.3 中把当前子分支 rebase 到主线上。这些分支都只在本地、没有推送过。
- 提交前确认 `git status` 中没有不属于这个 T 的文件。

## 8. Electron 检查方法（CDP）

`pnpm dev` 无法传入 `--remote-debugging-port`（`scripts/run-electron-dev.mjs` 只 spawn `[appEntry]`），所以统一用构建产物启动。

```bash
pnpm --filter @actspace/desktop build
rm -rf /tmp/actspace-cdp-data && mkdir -p /tmp/actspace-cdp-data
cd apps/desktop && ACTSPACE_DATA_DIR=/tmp/actspace-cdp-data \
  node_modules/electron/dist/Electron.app/Contents/MacOS/Electron dist-electron/main/index.js \
  --remote-debugging-port=9222 &
curl -s http://127.0.0.1:9222/json          # 确认存在 type=page 的目标
node docs/exec-runs/20261005-desktop-fe-00-overall/tools/cdp-capture.mjs <out.png> [选项]
pkill -f "dist-electron/main/index.js --remote-debugging-port=9222"   # 用完必须清理
```

注意事项：
- `pkill` 只按上面这个完整模式匹配，**不要误杀 Lark 等也匹配 9222 的进程**。
- 默认用临时数据目录，不读写真实用户数据。
- 需要模型 key 的流程（真实对话）交给验收；UI 状态尽量用 13 之后的浏览器 mock 场景覆盖。
- 2026-10-05 实测：页面正常渲染；控制台只有 2 条 `Electron Security Warning (Insecure Content-Security-Policy)`，这是已知警告（见 11 J1）。

`cdp-capture.mjs`（S0-4 原样保存）：

```js

//        [--eval "<表达式>"] [--keys "Shift+F10,ArrowDown,Escape"] [--wait 500]

import { writeFileSync } from "node:fs";

const WebSocket = require("ws");
const args = process.argv.slice(2);
const out = args[0];
const opt = (name) => { const i = args.indexOf(name); return i > 0 ? args[i + 1] : undefined; };
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

const port = opt("--port") ?? "9222";
const targets = await (await fetch(`http://127.0.0.1:${port}/json`)).json();
const page = targets.find((t) => t.type === "page" && !t.url.startsWith("devtools://"));
if (!page) throw new Error("没有找到 page 目标");

const ws = new WebSocket(page.webSocketDebuggerUrl);
const pending = new Map();
const logs = [];
let nextId = 0;
ws.on("message", (raw) => {
  const msg = JSON.parse(raw);
  if (msg.id && pending.has(msg.id)) { pending.get(msg.id)(msg); pending.delete(msg.id); return; }
  if (msg.method === "Runtime.consoleAPICalled" && ["error", "warning"].includes(msg.params.type)) {
    logs.push(`[console.${msg.params.type}] ${msg.params.args.map((a) => a.value ?? a.description).join(" ")}`);
  }
  if (msg.method === "Runtime.exceptionThrown") {
    const d = msg.params.exceptionDetails;
    logs.push(`[exception] ${d.exception?.description ?? d.text}`);
  }
  if (msg.method === "Log.entryAdded" && ["error", "warning"].includes(msg.params.entry.level)) {
    logs.push(`[log.${msg.params.entry.level}] ${msg.params.entry.text}`);
  }
});
await new Promise((resolve) => ws.once("open", resolve));
const send = (method, params = {}) => new Promise((resolve, reject) => {
  const id = ++nextId;
  pending.set(id, (m) => (m.error ? reject(new Error(`${method}: ${m.error.message}`)) : resolve(m.result)));
  ws.send(JSON.stringify({ id, method, params }));
});

await send("Runtime.enable");
await send("Log.enable");
await send("Page.enable");
const width = opt("--width");
if (width) {
  await send("Emulation.setDeviceMetricsOverride", {
    width: Number(width), height: Number(opt("--height") ?? 800), deviceScaleFactor: 1, mobile: false,
  });
}
if (!args.includes("--no-reload")) { await send("Page.reload"); await sleep(4000); }

const expression = opt("--eval");
if (expression) {
  const r = await send("Runtime.evaluate", { expression, awaitPromise: true, returnByValue: true });
  console.log("eval:", JSON.stringify(r.result.value ?? r.exceptionDetails?.text));
}
const keys = opt("--keys");
if (keys) {
  for (const combo of keys.split(",")) {
    const parts = combo.split("+");
    const key = parts.pop();
    const modifiers = (parts.includes("Alt") ? 1 : 0) | (parts.includes("Control") ? 2 : 0)
      | (parts.includes("Meta") ? 4 : 0) | (parts.includes("Shift") ? 8 : 0);
    for (const type of ["keyDown", "keyUp"]) {
      await send("Input.dispatchKeyEvent", { type, key, code: key.length === 1 ? `Key${key.toUpperCase()}` : key, modifiers });
    }
    await sleep(150);
  }
  const focus = await send("Runtime.evaluate", {
    expression: "(() => { const el = document.activeElement; return el ? `${el.tagName} ${el.getAttribute('aria-label') ?? el.textContent?.slice(0, 40) ?? ''}` : null; })()",
    returnByValue: true,
  });
  console.log("focus:", focus.result.value);
}
await sleep(Number(opt("--wait") ?? 500));

const shot = await send("Page.captureScreenshot", { format: "png" });
writeFileSync(out, Buffer.from(shot.data, "base64"));
console.log(logs.length ? logs.join("\n") : "控制台没有 error / warning");
ws.close();
```
