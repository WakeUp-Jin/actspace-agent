# 流式内容变高要监听尺寸，而不是只监听数据

关联 history：`docs/histories/2026-07/20260703-1019-write-tool-scroll-and-diff-height.md`

## 是什么

聊天式界面里，自动滚到底部通常不能只监听 `messages.length` 或 `isStreaming`。当同一条消息里的工具预览、diff、代码块、图片或折叠区持续变高时，React 数据结构可能没有明显变化，但 DOM 高度已经变了。

这类场景应该监听容器尺寸变化，再决定是否滚动。

## 为什么需要

`write_file` 执行中会在同一个工具调用区域里不断展示写入内容。窗口已经在底部时，用户期望它继续跟随最新内容；但如果 effect 只在消息数组变化时执行，工具预览内部高度增长不会被捕获，结果就是会话窗口出现滚动条，却停在旧位置。

相反，如果每次 resize 都强制滚到底部，又会打断用户上滚查看历史。因此关键不是“永远自动滚”，而是：

- 用户原本贴近底部时，内容增长后继续贴底。
- 用户已经上滚离开底部时，尊重用户位置。

## 怎么做

把“是否贴底”维护在会话滚动容器上，并用 `ResizeObserver` 观察消息栈：

```ts
const observer = new ResizeObserver(() => {
  if (!stickToBottomRef.current) {
    return;
  }

  const container = scrollContainerRef.current;
  if (container) {
    container.scrollTop = container.scrollHeight;
  }
});

observer.observe(messageStack);
```

这个观察点应尽量靠近消息列表容器，而不是分散到每个工具组件里。这样以后其他工具预览、图片加载、异步渲染也能复用同一套滚动语义。

## 嵌套滚动容器要分别维护贴底状态

外层会话贴底不代表内部预览也会贴底。只要工具预览设置了 `max-height` 和 `overflow-y: auto`，它就拥有独立的 `scrollTop`；外层滚动到消息尾部，只能保证预览卡片可见，不能保证卡片内部的最新内容可见。

因此滚动所有权应按容器分层：

- 会话容器观察消息栈尺寸，负责让最新消息保持可见。
- 流式代码预览监听自身内容变化，负责让最新代码保持可见。
- 两层都维护自己的“用户是否仍贴近底部”状态；用户主动上滚哪一层，就只暂停该层的自动跟随。

流式预览适合在 DOM 提交后、浏览器绘制前更新 `scrollTop`，避免用户先看到旧位置再发生一次可见跳动。React 组件中可使用 `useLayoutEffect`，并在 `onScroll` 中根据距底阈值决定是否继续跟随。

## 长内容还需要局部滚动

自动跟随解决的是“最新内容可见”，但不等于让单个工具结果无限撑开会话。对于 diff、日志、表格这类可能很长的内容，应该给内容区稳定的最大高度：

```css
.file-diff-content {
  max-height: 420px;
  overflow-x: auto;
  overflow-y: auto;
}
```

这样展开长 diff 时，会话仍保持可控，用户需要细看时在 diff 内部滚动。

## 核心要点

- React 数据变化和 DOM 尺寸变化不是一回事。
- 自动滚动必须以“用户是否还在底部”为前提。
- `ResizeObserver` 更适合处理流式工具预览、图片加载、代码块展开这类布局增长。
- 长 diff 要使用局部滚动区域，避免把整个会话视口撑爆。

## 常见陷阱

1. **只监听消息数组**：同一条消息内部增高时不会触发跟随。
2. **无条件滚到底部**：用户上滚读历史会被拉回底部。
3. **完成态全量展开**：大 diff 会把会话变成一个超长页面，最新消息和后续操作都难找。
4. **只滚外层容器**：嵌套预览拥有独立滚动条时，卡片虽然可见，内部最新内容仍可能停在视口之外。

## 自检问题

1. 这个流式 UI 的高度变化是否一定伴随外层数据变化？
2. 用户手动离开底部后，自动滚动逻辑会不会抢走位置？
3. 单个结果内容很长时，是应该撑开整条会话，还是在局部区域滚动？
