# 工具完成状态不能等待动画

关联 history：`docs/histories/2026-07/20260726-0005-tool-finished-immediate-status.md`

## 是什么

事件驱动 UI 里，`tool_finished` 表示某个 `toolCallId` 已经完成。这个事实应该立即进入前端状态；最短展示时间、shimmer 或过渡动画只能影响视觉表现，不能延迟生命周期状态。

## 为什么会出问题

多个文件工具可能在很短时间内依次完成。后端即使按工具独立发送完成事件，前端如果为每个 running 状态保留固定的最短时长，多个定时器仍可能在相近时间触发，用户看到的就像整批工具等待最后一个后同时完成。

这会混淆两件事：

- 执行事实：工具何时真正完成。
- 视觉平滑：running 状态至少展示多久。

当视觉平滑覆盖执行事实时，UI 就不再可信。

## 怎么做

- 用 `toolCallId` 作为状态归属键。
- 收到 `tool_finished` 时立刻写入 `finished`、`isError` 和最终 preview。
- 如果确实需要动画，使用不改变业务状态的 CSS transition，或单独维护纯展示字段。
- 回归测试要在同批多个工具中逐个发送完成事件，确认只有对应工具结束 running。

## 核心要点

- 生命周期事件是事实源，动画不是。
- 批量调度不代表批量完成，串行执行也不应该批量刷新状态。
- 状态测试要观察事件之间的中间帧，而不只检查最终全部完成。
