Reusable engineering lesson

静态内容站不是一堆页面，而是一组构建契约。

当站点进入 monorepo、读取仓库 Markdown、部署到 project Pages 并支持手动主题时，真正容易出错的不是卡片 CSS，而是路径、数据、资源和主题之间没有显式契约。

四个边界AST 数据契约路径契约主题契约常见陷阱

四个必须同时成立的边界

数据内容从哪里来，怎样验证，失败时是否阻止发布。
路径源码位置、构建 cwd、站点 base 和最终 URL 如何对应。
资源图片固有尺寸、CSS 响应式尺寸和部署资源路径谁负责。
主题语义 token、第三方代码高亮和 system 模式怎样使用同一状态。
核心判断：静态生成不代表运行时简单。复杂度只是提前到了 build time，因此构建失败必须足够明确，构建输入必须足够可追溯。

用 AST 把 Markdown 变成可验证的数据源

正则适合寻找简单标记，不适合承担 GFM 表格、inline code、强调、链接和源码行号。把 Markdown 先解析为 AST，可以只选择符合约定的节点，再对每一行建立明确错误位置。

Markdown file
  → remark-parse + remark-gfm
  → select: heading(depth=2, YYYY-MM)
  → select: table(exact headers)
  → validate date / month / required cells
  → sanitize inline Markdown
  → ReleaseEntry[]
  → static pages

为什么解析错误应该让构建失败

更新页如果静默跳过一行，发布动作仍会显示成功，但用户看到的是旧数据或缺失数据。内容 schema 属于产品契约，违反契约与 TypeScript 编译错误没有本质区别。

monorepo 有三种“根目录”

根例子风险
仓库根lockfile、release、workspace scriptsAction 若从 package 目录运行，会丢失根 lockfile。
站点根Astro config、src、public、dist输出路径需要相对站点，而依赖安装可能仍在仓库根。
部署根/repo-name/开发环境的 / 正常，不代表 project Pages 链接正常。
可靠做法：从仓库根安装和执行 workspace 命令；让构建工具显式输出站点目录；所有内部 URL 经过同一个 base-path helper；读取跨包文件时从 import.meta.url 推导，而不是相信 process.cwd()。

主题状态必须传播到第三方产物

站点使用 html[data-theme] 手动切换，而代码高亮器常默认只生成 prefers-color-scheme CSS。两者各自正确，但组合后会出现“页面已变暗、代码仍使用浅色 token”的低对比度问题。

html[data-theme="dark"] .astro-code span {
  color: var(--shiki-dark) !important;
}

@media (prefers-color-scheme: dark) {
  html[data-theme="system"] .astro-code span {
    color: var(--shiki-dark) !important;
  }
}

任何有独立主题状态的第三方输出——图表、编辑器、代码高亮、嵌入式组件——都需要显式接入产品主题，而不是假设它会自动继承。

这次暴露出的通用陷阱

IMAGE SIZE

HTML 的 width/height 能防止布局抖动，但响应式 CSS 只改 width 时，height 仍可能保留固有像素值。全局 img { height:auto } 是关键配套。

ACTION PATH

部署 Action 的 path 往往同时决定工作目录和 lockfile 探测位置。monorepo 不能只把它指向子包；应检查 Action 源码，确认 build command 与 artifact path 可以独立配置。

STATIC SAFETY

静态站也会处理不可信 Markdown。只渲染需要的 inline 节点并经过 sanitize，比开启 raw HTML 后依赖作者自律更可靠。

VISUAL QA

类型检查与静态构建无法证明 Hero 没有遮挡。至少在一个桌面和一个移动 viewport 检查真实 production preview，并验证滚动宽度、主题和交互状态。

自检问题

  1. 如果 CI 从任意工作目录启动，内容解析器还能找到唯一事实源吗？
  2. 把站点从根域迁移到 project Pages 后，canonical、图片、robots 和内部链接是否仍一致？
  3. 手动选择 dark 时，所有第三方渲染产物是否真的切到 dark，而不是只改变页面背景？
