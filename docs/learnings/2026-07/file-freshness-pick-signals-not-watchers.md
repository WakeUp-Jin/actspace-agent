# 做「内容是否过期」时，先挑信号，别急着上监听器

关联 history：`docs/histories/2026-07/20260730-1200-right-panel-file-view-optimization.md`

## 是什么

界面上任何「读一次就留在屏幕上」的内容都会过期：打开的文件、目录列表、远端配置、别人也能改的记录。需求听起来是「加个文件监听」，但真正要决定的是**用什么信号知道它变了**，监听只是其中一种信号，而且往往是最贵的一种。

信号可以按三个维度排：**精度**（能不能定位到具体哪一个对象）、**成本**（新增了什么常驻设施）、**可用性**（是不是所有用户 / 所有环境都有）。

## 本轮的选择过程

需求方向本来是「用现成的 fs-watch 插件」。逐条对下来它不合格，不是因为实现不好，而是**属性不匹配**：

| 维度 | fs-watch 插件的实际情况 | 为什么不匹配 |
| --- | --- | --- |
| 可用性 | 用户可选安装、需要 Rust 工具链手动编译 | 内容新鲜度是**正确性**功能，不能有一半用户完全没有 |
| 作用域 | 监听根来自设置页配置，与当前 session 的工作区无关 | 用户很可能没把当前工作区加进去，静默失效 |
| 延迟 | 500ms 去抖 → 落盘 JSONL → 宿主轮询读取 | 三层延迟叠起来，为审计设计的管道当不了 UI 事件总线 |
| 边界 | 设计文档明确写了「不做插件与宿主双向通信」 | 让 renderer 依赖它的 JSONL schema 会破坏既有架构边界 |

换成两级信号，一行新设施都没加：

1. **复用已有的精确事件**（主力）：Agent 改文件时本来就会推 `edit_diff` / `write_diff` 消息块，里面自带 `filePath`。renderer 早就实时收到了，只是以前没人拿它做别的用途 —— 精度最高（知道是哪个文件）、成本为零。
2. **按时机重校验兜底**：读文件时本来就 `stat` 过，把 `mtimeMs` 一起带回来。之后只在**三个时机**各做一次 O(1) 的 stat：Tab 被激活、窗口重新获得焦点、当前 turn 结束。覆盖外部编辑器和 `git checkout` 这些第一级看不见的路径。

**关键是没有 `setInterval`。** 这三个时机的共同点是「用户此刻正要看它」—— 用户没在看的时候，内容过不过期没有意义。这个视角把「持续监听」换成了「按需校验」，成本从 O(时间) 降到 O(用户交互次数)。

## 可迁移的模式：精确事件 + 惰性兜底

```txt
第一级：系统内部已经存在的、带对象标识的事件  → 精度高、零成本、但只覆盖「自己人」改的
第二级：在「用户即将看到」的时机做一次廉价校验 → 精度低、成本 O(1)、覆盖所有外部改动
```

这个组合适用面很广：缓存失效（内部写操作主动 invalidate + 读取时校验 ETag）、列表刷新（自家 mutation 后局部更新 + 窗口聚焦时 revalidate）、配置热更新。SWR / React Query 的 `revalidateOnFocus` 就是第二级的成品实现 —— 值得注意的是它们也**没有**默认开轮询。

先问「系统里已经有谁知道这件事变了」，往往能省掉一整套设施。

## 检测到过期之后：不要自动替换内容

这是同一轮里第二个决定，比检测本身更影响体感：**发现变化只打 stale 标记 + 显示「已变更 · 重新加载」，替换必须由用户点击触发。**

因为用户可能正在读、正在选中文本、正在对着某一行截图。内容被自动抽换比看到旧内容更糟 —— 旧内容至少是自洽的，还带着「打开时」这个明确语义；抽换会让滚动位置和选区一起消失，而用户没做任何操作。

也没有做「自动重载」开关：两套行为都要维护、两套都要测，而收益只是省一次点击。

## 顺带一条：真要做实时监听，watch 父目录而不是文件

如果哪天真上 `fs.watch`（本轮推迟到 V2）：**监听已打开文件的父目录，按 filename 过滤，不要监听文件路径本身。**

因为编辑器和 Agent 普遍用**原子写**：写到临时文件再 `rename` 覆盖目标。`rename` 换掉的是 inode，而 `fs.watch` 盯的是打开时那个 inode —— 于是「保存文件」这个最该触发的动作，恰好是监听彻底失效的那一下，而且不报错，只是从此再也不响。这是文件监听里最反直觉的坑，几乎每个做过的人都踩过一次。

## 核心要点

- 需求说「加监听」时，先列信号的精度 / 成本 / 可用性，再决定要不要监听。
- 正确性功能不能建立在可选安装的组件上。
- 复用系统里已有的、带对象标识的事件，通常是精度最高且零成本的信号。
- 「用户即将看到」的时机就是最好的校验时机；不需要轮询。
- 检测到过期只提示，不自动替换用户正在看的内容。
- 原子写会让 watch 文件路径静默失效，要 watch 父目录。
