# 全局快捷键更新是一笔跨系统事务

## 问题

全局快捷键同时涉及两份状态：应用保存的配置，以及操作系统当前实际注册的组合键。若先写配置、再调用系统注册，组合键被占用时就会出现“设置页显示已启用，但系统不会触发”的分裂状态。

## 安全更新顺序

从旧快捷键切换到新快捷键时，顺序应是：

1. 保留旧快捷键注册。
2. 尝试注册新快捷键；占用或格式错误时立即停止。
3. 新快捷键注册成功后原子持久化新配置。
4. 持久化成功后注销旧快捷键。
5. 持久化失败时注销候选快捷键，旧快捷键继续工作。

关闭快捷键时顺序相反：先持久化关闭状态，再注销当前注册。这样写盘失败不会意外丢掉仍被配置为开启的快捷键。

## 为什么不能只看配置

系统注册是运行时资源，配置只是用户意图。设置页应分别表达：

- `enabled / accelerator / target`：持久化意图。
- `registered / error`：当前进程的真实注册状态。

两者不能用一个布尔值代替。应用启动时还必须重新注册，退出时必须注销；目标工作区或会话是否有效也应在每次触发时重新判断，而不是在保存设置时一次性证明。

## 事件不能假设 renderer 永远在线

主进程直接发送事件只适合已加载窗口。窗口正在创建或 renderer 尚未订阅时，事件可能丢失。可靠做法是让 main 保存一个待处理 request，事件只充当低延迟通知，renderer 挂载后通过类型化 IPC 显式消费并清除 request。

## 自检

- 新快捷键冲突时，旧快捷键是否仍然有效？
- 写配置失败时，候选快捷键是否被清理？
- renderer 尚未加载时触发，request 是否仍能被消费？
- 应用退出后，是否释放了所有系统级注册？
