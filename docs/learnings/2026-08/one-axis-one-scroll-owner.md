# 一条轴线只保留一个滚动所有者

## 是什么

在表格、代码审阅器、时间线等需要跨行比较的界面里，同一个方向的位移应由共同祖先统一管理。每个子项都设置 `overflow-x: auto` 虽然能避免单行溢出，却会让每个子项变成独立坐标系。

## 为什么行级滚动会出问题

当 Diff 的每一行都是横向滚动容器时，任何超长行都会生成自己的滚动条。用户看到的不再是一份可以整体平移的代码，而是许多彼此不同步的小视口：某行滚到右侧时，上下行仍停在左侧，列对齐和上下文比较随之失效。

隐藏这些滚动条也不能解决问题。它只隐藏了反馈，独立 `scrollLeft` 仍然存在，触控板或 Shift + 滚轮依旧可能只移动鼠标下方的一行。

## 正确的所有权

```tsx
<main className="overflow-auto">
  <div style={{ width: sharedContentWidth }}>
    <DiffRow />
    <DiffRow />
  </div>
</main>
```

- 外层 Canvas 拥有横向和纵向滚动位置。
- 子行只负责内容、背景和语义，不声明同轴 `overflow`。
- Word Wrap 打开时，共享内容宽度回到 `100%`，代码列负责折行。

## 虚拟列表的额外陷阱

虚拟列表只挂载当前视口附近的行。如果 Canvas 宽度完全依赖已挂载 DOM，滚到一条更长的代码时 `scrollWidth` 会突然增加，离开后又可能缩短。滚动条因此跳变，已有 `scrollLeft` 也可能被浏览器修正。

解决方法是从虚拟化之前的结构化行模型估算全局内容宽度，再让所有虚拟行共享它。对等宽代码可以使用字符列数近似，同时需要：

- 把 tab 展开到固定 tab stop。
- 为行号、增删标记和右侧留白预留列数。
- split diff 按两侧中更长的一边估算，再乘以两列。
- 对异常超长行设置合理的稳定宽度上限，避免创建不可控的超大布局面。

## 自检

- 同一方向是否存在祖先和子项两层 `overflow-auto`？
- 横向移动一行时，其他需要比较的行是否同步？
- 虚拟项挂载变化时，滚动范围是否保持稳定？
- 开启折行后，共享内容宽度是否真的回到容器宽度？
