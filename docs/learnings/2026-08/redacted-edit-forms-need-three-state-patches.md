# 脱敏编辑表单需要三态 PATCH 语义

当 Renderer 不能读取密钥、代理凭据或其他敏感原值时，编辑表单里显示的空输入并不等于“当前没有值”。它可能表示原值已存在，只是不能回显。如果保存逻辑仍把空字符串解释为无效或清除，就会出现两个问题：用户无法只修改其他字段，或者一次无关保存意外覆盖已有配置。

## 三种状态

更新契约应明确区分：

```ts
type SecretPatch =
  | undefined // 保持原值
  | string    // 替换原值
  | null;     // 清除原值
```

对象字段也遵循同一原则。例如服务商代理设置：

```ts
// 保持当前代理
{}

// 替换或首次启用代理
{ proxy: { enabled: true, url: "http://127.0.0.1:7890" } }

// 明确关闭并清除代理
{ proxy: { enabled: false, url: null } }
```

## 表单校验也必须知道当前状态

“代理开启且输入为空”不能一律禁用保存。只有当前没有已保存地址、用户又首次开启代理时，空输入才是错误。已有地址被脱敏时，空输入应配合“已配置；留空保持不变”提示，并在提交时省略字段。

## 为什么不能把脱敏值填回输入框

`http://127.0.0.1:••••`、`sk-••••` 只是展示值，不是可再次提交的配置。把它作为表单初值会让用户误以为能直接编辑，并可能把遮罩文本写回持久层。Renderer 只需要知道“是否存在”和必要的脱敏摘要，真实值继续留在主进程安全边界内。

## 测试重点

- 已有值 + 空输入：保存可用，提交时省略字段，原值不变。
- 已有值 + 新输入：提交新值并替换。
- 明确关闭：提交 `null` 或对应清除动作。
- 首次启用 + 空输入：阻止保存。
- 失败回滚：涉及普通设置与密钥文件时，两边必须恢复到同一旧状态。

这套模式同样适用于 API Key、Webhook secret、数据库密码和任何只允许写入、不允许读取的配置。对应变更记录见 `docs/histories/2026-08/20260802-1015-provider-removal-and-proxy-edit.md`。
