# 夹具必须表达它要证明的东西：关系、时间、可区分性

合并自：大列表 mock 必须复制关系不能只复制行（含点击关系与真实数据接入）、排序 UI 测试必须使用确定性时间 Fixture、用可区分的夹具判断是否读错了数据。

关联：`apps/desktop/src/renderer/trajectory/fixtures.ts`、[v2 多包插件化切换 history](../../histories/2026-08/20260826-0000-v2-package-cutover.md)、[P5 Cordis 与 Host 收敛 history](../../histories/2026-10/20261004-1310-p5-cordis-host-convergence.md)

主线：夹具不只是“能填满字段”，它要把被测行为所依赖的顺序、关联、来源差异编码出来，否则测试要么偶发失败，要么永远通过。

## 1. 依赖顺序，就显式编码顺序（确定性时间）

产品按 `updatedAt/createdAt/优先级` 排序时，fixture 的时间是决定展示顺序的输入。用 `new Date()` 批量创建，单测独跑稳定、全量并发偶发失败：连续创建的记录独跑时共享同一毫秒、稳定排序保留输入顺序；CPU 压力下创建跨多个毫秒，后创建的记录更新并被排前，“第 9 条不可见”的断言就挂了。问题不在排序算法，也不一定是测试间污染，而是 fixture 没表达它依赖的顺序。

```ts
updatedAt: new Date(Date.UTC(2026, 7, 26, 0, 0, 12 - index)).toISOString()   // Item 0 明确比 Item 9 新
```

不关心顺序时断言“渲染 8 条/展开后 12 条”，别借名称位置间接表达数量契约。排查顺序：单独跑失败用例 → 整个文件 → 反查产品路径里的排序/截断/分组 → 检查 fixture 是否用了当前时间、随机数、locale、时区、不稳定对象顺序 → 修输入确定性，不加等待、重试、放宽断言。

## 2. 依赖关系，就复制关系

轨迹里请求、消息、工具调用、结果通过 ID 相连，前端还用记录 ID 缓存行高、选中态、展开态。把轨迹重复 24 次时只改行号不改 callId，归并器会认为 24 份结果属于同一次调用；页面能滚动也不能证明虚拟化正确（重复 key 复用到错误记录）。给每个批次加统一 ID 前缀并递归改写 turnId/stepId/requestId/messageId/callId/parentCallId，批次内关联不变、批次间独立；时间统一偏移，否则批次重叠。三个不变量：展示记录 ID 不重复；调用数按倍数增长且每次调用仍只关联自己的结果；偏移前后 duration 不变、只有绝对时间变。

关系归属也要有身份：“工具属于前面最近一条 Assistant”只在线性日志成立；同一步可有多条消息、事件分批到达。用消息里的 callId 引用或工具携带的 `assistantMessageId`，位置只决定排版；找不到唯一归属就保留缺失。时间维度：今天的 bash 可能换了参数，昨天的调用仍展示当时请求里的定义，数据链是 call → request snapshot → tool definition，不是 call → 当前注册表。测试数据故意在 Assistant 与工具间插入另一条消息、在调用后更新同名工具定义，结果仍正确才证明没靠“刚好相邻”。测试分三层：纯函数验证 ID 配对，组件验证点击更换详情并展开，真实浏览器验证虚拟列表滚动与选中可见；还要确认挂载行数远小于总行数。

## 3. 接入真实数据：一致版本比字段齐全重要

先读摘要得版本 100，再读 Journal 已到 103，把 103 的轨迹装进标记 100 的响应，UI 会同时显示“仍在执行”和“工具已完成”，客户端版本缓存还会错误拒绝后续更新。每个投影固定到已读摘要的版本，拒绝缺失覆盖范围的数据，不取几个版本的最大值。加载更早历史后数据窗口变了而 Journal revision 没增长，不能只按 revision 去重历史请求：同 revision 可接受更完整的窗口，并让下一次实时刷新沿用该窗口起点。mock 字段名不能代替生产链路核对（User 正文在 `surface.node.content`，Tool 正文在 `modelOutput`，参数定义在 `inputSchema`）；通过真实 Journal 准入再投影，能暴露手写节点绕过的约束（Inbox claim 必须引用 enqueue 并同时生成 Surface）。

## 4. 验收夹具要让两种假设可区分

两台 Host 都发布名为 `workspace` 的工作区、用同一个模型，切换后界面仍显示 workspace，既符合正确读取也符合复用旧数据，截图判不了。做法：给两台 Host 设不同的工作区名、路径、模型，先核对服务端实际发布的数据；切换时同时检查目标标识、工作区、模型、发送状态；验证远端文件来源用内容不同的同名文件（只比文件名/路径排除不了误用本地内容）。UI 观察是证据，但“看到了什么”和“为什么如此”是两件事；假设被证据推翻时，修正验收结论比添加代码更可靠。
