# 把输入校验失败当作结果

输入不合法通常是用户可以修正的正常分支。把它直接抛成异常穿过进程边界，会让界面依赖包装后的异常文本，也容易把“没开始执行”显示成“运行失败”。

更清楚的做法是给发送准备阶段一个明确的拒绝结果：错误类型、可展示的文件名、稳定附件 id 和限制值。接收端先分辨拒绝，再处理成功运行的投影。不能对拒绝结果执行成功分支的数据解码。

错误位置用稳定 id，不能只靠文件名：两个不同目录的文件可以同名。展示只需要 basename；原始路径和堆栈不该进入普通错误提示。

删除失败附件时只清除它对应的问题。总量错误关联的是整个集合，需要按已知长度重算，删掉一个很小的文件未必解除超限。下一次真正发送仍须由主进程重新验证磁盘内容，UI 的计算不取代权威校验。

验证应覆盖四个层次：校验函数产生正确字段、IPC 可序列化且未启动任务、应用恢复草稿并删除临时消息、真实桌面窗口展示和交互正确。单纯断言一段中文文案无法证明这条链路。
