# 费用是带单位和依据的事实：0 不是未知，币种不跟随 UI 偏好

合并自：为什么费用 0 不能代替未知、成本/单位类指标的展示要忠于事实不跟随 UI 偏好。

关联：`docs/histories/2026-05/20260528-1702-kairos-usage-badge.md`、`docs/histories/2026-05/20260530-2358-deepseek-pricing-cny.md`、[使用统计更新记录](../../histories/2026-09/20260906-2340-usage-statistics-plan.md)

## 1. 金额要同时保存依据，0 不等于免费

接口返回 `cost: 0` 只说明有个数值字段。SDK 可能用缺省零单价乘 Token 算出零；代理可能根本没返回账单字段；供应商也可能明确报价为零——三者含义不同。金额要带：谁给出的、用了什么价格、对应哪个实际模型、币种、何时获取。Token 数可能是供应商精确返回，金额却是客户端估算，两者要有独立来源字段。

算例：3,000 输入 Token（2,000 缓存读取）、500 输出，每百万输入/缓存/输出单价 2/0.2/8 USD。先拆互斥桶，未缓存输入 1,000，费用 `(1000×2 + 2000×0.2 + 500×8)/1e6 = 0.0064 USD`；500 输出中含 400 推理 Token 时不能再收一次推理费；缓存已发生却没有缓存价应为未知，缓存 Token 为零时则不必因缺缓存价放弃其他桶。

价格会更新，所以请求开始时冻结该模型的费率与来源，随结果保存；历史回放只读当时记录，不拿今天的目录重算（税率、汇率、折扣、按量云服务同理）。SDK 归一化会丢信息：原始响应有实际金额，SDK 可能只留自己算的 cost，来源判断必须发生在丢失信息之前；对文档化的供应商字段可在协议适配层保留实际金额、计算层优先采用，不能因字段叫 cost 就信任任意端点。测试要穿过真实 SDK 用本地 stub 响应验证解析。展示层可以简洁，保存层仍保留完整价格快照以便排障。

## 2. 单位是数据的一部分，UI 按字段选符号

schema 里强制带单位（`LlmUsageCost = { total, currency: "USD" | "CNY" }`，距离/温度同理），formatter 按 `cost.currency` 分支，不写“产品面向中国用户所以全用 ¥”。硬改符号会用 UI 谎称事实：单价仍是 USD 数额，界面显示 ¥0.06，用户按此估预算实际差约 7 倍。

用户说“想用人民币看”，先判断是改事实还是改偏好：数据源是 USD 单价 → 产品要换计价货币，改 model-config 单价（按汇率一次性换算，不是只翻 `currency` 标签）并切 `currency`，UI 自动跟随；数据源已是 CNY 而 UI 偷懒写 `$` 才是 UI 问题。2026-05-30 DeepSeek 切 CNY 正是这样做的，零 UI 改动全自动从 `$` 变 `¥`，反向验证了此原则。

- 聚合多条数据时校验单位一致：混合时标 `MIXED`，UI 显式提示（`≈ $0.02` + “混合币种估算”），不偷偷挑一种加总；一致性校验必须在 selector 层就建立，否则某天加入 CNY 的国内 provider，统计会悄悄把“$10.50”加成“¥10.50”。
- 不在 selector 里硬编码汇率（`cost * 7.2`）；非换算不可时必须提示“按 X.X 汇率估算”，且汇率是注入的。
- 历史迁移：新事件用新单价，已写盘的 `llm_usage` 事件按事件内 `currency` 字段照常显示，不重算（避免双重换算）；这正是事件存完整 `LlmUsageCost` 的意义。
