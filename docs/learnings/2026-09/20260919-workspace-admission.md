# 选中路径、接纳工作区与初始化 Git 是三件事

目录选择器只证明用户选中了一个路径；它是否成为应用工作区，要由调用场景决定。同一个选择器也可能用于选择父目录或插件配置目录，因此不能把每次选目录都当成工作区注册。

## 为什么会出现“会话能打开，Review 却拒绝”

会话记录保存了路径，而 Review 从另一份工作区注册表确认允许操作的范围。如果创建会话只写前者，两份状态就会不一致。刷新 Review 不会修复缺失的注册事实，因为它仍然执行同一个校验。

## 修复应放在哪里

在用户明确选用工作区时完成注册，在统一的会话创建入口补齐。已有数据还需要恢复步骤：从可信的持久化会话摘要合并遗漏目录，保留已有 ID 和隐藏偏好。

不要在 Review 查询收到任意路径时自动注册：这样虽然能消除错误，却会让“检查是否已接纳”失去意义。注册工作区也不等于初始化 Git，前者只维护应用的本地清单，后者会修改用户目录。

## 怎么验证边界

测试要同时证明三件事：选用的 Git 目录能读取变更；未接纳的目录仍被拒绝；选用普通目录后没有生成 `.git`。再补旧数据恢复和重复启动测试，防止新入口修好了，已有会话仍然报错。
