# 搬运 Markdown 时，原文和渲染结果要分别检查

同一篇 Markdown 从一个站点搬到另一个站点，字面相同也可能显示不全；显示正常也不代表原文没有被修改。两种验证需要分开做。

## 为什么图片检查容易漏

Markdown 图片地址可以带括号，例如 `image%20(73).png`。遇到右括号就结束的正则会截断路径。文章还可能使用引用式图片和 HTML img，代码块中则可能包含仅用于演示的图片语法。

先用 Markdown AST 找出实际图片节点、引用定义和 HTML 节点，再检查资源存在性。图片迁移后比较 SHA-256，可以确认复制的是原始文件，而不是同名缩略图。

## 原文与平台语法分开处理

H1 移入站点 title、相对资源路径适配、折叠容器转换，是呈现层变更。每次适配都保留可逆映射，反向还原后与原文件逐字比较；不要顺手统一原文标点或改写代码。站点日期缺少发表证据时，记录使用的是源文件加入 Git 的日期。

## 相对链接依赖页面地址

同一个欢迎文档既渲染到 `/docs/` 又渲染到 `/docs/welcome/` 时，`../context/` 会分别落到两个不同地址。需要在构建阶段按照文章的规范路由解析，再加上部署 base；只在浏览器中动态修复会让无脚本阅读和复制链接得到不同结果。

测试同时覆盖根部署和子路径部署，并遍历构建后的实际 href/src。源码中的文件存在，不代表网页里的地址正确。

## 处理器也属于迁移边界

当前站点的 Astro 7 默认使用 Sätteri，不能假定 remark 插件仍由默认处理器执行。扩展前先确认当前处理器的插件接口；保留现有引擎通常比为一个链接转换切换整套 Markdown 渲染链更容易控制差异。
