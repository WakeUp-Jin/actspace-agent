# Fork 的文件所有权：复制消息还不够

会话历史中的图片通常只是一个文件 ID。复制历史后，即便页面还能显示消息文字，模型再次读取图片时也可能失败：文件仍属于父会话，子会话没有读取权。

把 fork 看成一个有边界的快照会更清楚：需要继承的是该边界前的消息，以及这些消息引用的资源。先复制资源得到新 ID，再把子历史的结构化引用同步替换，最后发布子历史。用旧 ID 到新 ID 的映射去重，就能让同一图片在消息、工具结果和请求快照里的多次引用仍指向同一副本。

独立副本比共享文件多占空间，但删除父文件不影响子会话；再次 fork 也遵循同一规则。共享文件则需要额外定义引用计数、回收及跨会话读取权限，不能只放宽 owner 校验。

两个容易忽略的边界：

- 不要在全文中替换 ID。普通文本可能只是用户讨论的内容，替换应依据文件引用的结构。
- 回滚只能删除本次独占创建的目录与文件。若目标会话早已存在，创建必须失败，不能把它当作本次残留清理。

可捕获异常时的清理与断电事务不是一回事。若需要崩溃一致性，还要单独设计 staging、提交标记和恢复扫描；普通 try/catch 不能承担这一保证。
