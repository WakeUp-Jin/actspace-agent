# 生成进度不等于执行结果

Agent 写文件通常经过两个速度不同的阶段：模型逐步生成完整参数，工具收到完整参数后才执行原子写入。把进度接在写盘阶段，会错过用户实际等待的大部分时间。

展示应以事实命名：生成时的字符量表示已收到的内容，不表示已保存，也不能当作最终 diff 的新增行数。覆盖文件和局部替换尤其需要完整旧内容才能计算 diff。

字符计数可以与内容预览解耦。流式扫描 JSON 的指定顶层字符串，只保留字段识别、转义、Unicode 代理对和累计值，不保存正文。不能直接统计 JSON 长度：路径、引号和 Unicode 转义都会被误算。也不能逐个 chunk 独立解析，转义和代理对可能跨分片。

计数粒度与刷新频率同样应分离：每个字符都可以内部计数，界面最多一秒发布一次，并取整显示。尾随定时器能在流暂时停顿后发布最后一批进度；prepared、finished、取消和 dispose 必须清理它，避免旧进度覆盖新状态。

自检：如果 Provider 只返回完整调用，应当显示什么？答案是诚实的阶段状态，而不是模拟一个增长数字。最终成功与增删统计仍只由工具真实结果决定。
