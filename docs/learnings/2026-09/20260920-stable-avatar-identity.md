# 为什么头像不能按列表位置分配

头像虽然只是装饰，却会变成用户识别对象的线索。如果同一个任务在消息里是蓝色角色，打开详情却变成紫色，用户需要重新核对任务名。

## 先找到稳定的身份

消息行 ID 不一定等于业务对象 ID：流式消息、历史投影、右侧列表可以各自生成行 ID。跨入口显示同一个角色，应优先使用共同的 child Session ID，而不是数组索引、任务标题或当前状态。

将稳定 ID 通过确定性散列映射到固定素材池，不需要本地存储，也不依赖组件挂载顺序。分页只加载部分消息时，同一对象仍能恢复原来的头像。

## 取舍：稳定不等于唯一

九张图片无法为任意数量的任务提供唯一头像，散列也可能在不足九个任务时碰撞。因此任务名仍是主要标识。若产品必须保证同一会话前九个任务不重复，需要在权威数据层持久化分配结果；不能在三个视图各自维护一份“已用头像集合”，否则分页和刷新会改变分配。

素材池的顺序和数量也是映射契约的一部分。随意重排或扩容会改变旧对象的结果；需要严格长期稳定时，应保存头像键或为分配算法引入版本。

## 身份和状态分开表达

头像回答“是谁”，状态图标加文字回答“在做什么”。状态变化不应该换头像，图片颜色也不应承担成功或失败的含义。这样既支持彩色角色，也能让深浅主题和减少动态效果模式独立处理状态反馈。

自检：排序或分页会换头像吗？流式记录和历史记录用的是同一个业务 ID 吗？去掉动画与颜色后，状态文字是否仍然明确？
