# 设置页的开放式分组与语义颜色

## 是什么

一个简洁的设置页通常不是“很多小卡片”，而是三层稳定语法：页面只有一个主标题，下面是按用户任务划分的分组，分组内部是连续的设置行。分组底色只负责建立轻微层级，行之间用 hairline 分隔；开关、下拉和按钮作为行的末端控件出现。

颜色也需要按职责分离。中性灰阶表达背景、选中和普通层级；主要确认动作使用 ink action；emerald 只表示启用、连接、运行健康或成功。这样“有绿色”不等于“整套黑绿主题”。

## 为什么需要

当页面标题、Section 标题、SettingGroup 标题和卡片标题都重复描述同一件事时，用户需要先读懂内部组件结构，再找到真正的设置。所有组都使用白底、边框、大圆角和阴影时，页面会像卡片堆叠，分组之间反而失去主题边界。

## 怎么用

```tsx
<PageShell title="工具" description="管理 Agent 可用工具和联网能力。">
  <SettingGroup title="代码库" headingLevel={3} description="读取、搜索和修改当前工作区中的文件。">
    <SettingRow title="读取文件" description="读取工作区中的文件内容。" control={<Toggle ... />} />
    <SettingRow title="Grep 搜索" description="按正则匹配文件内容。" control={<Toggle ... />} />
  </SettingGroup>
</PageShell>
```

避免下面这种重复结构：

```tsx
<PageShell title="工具">
  <SectionShell title="工具总览">
    <SettingGroup title="工具总览">
      {/* 同一标题出现三次 */}
    </SettingGroup>
  </SectionShell>
</PageShell>
```

## 核心要点

1. 页面 h2 只回答“我在哪个设置页”；h3 / h4 只回答“这一组设置解决什么任务”。
2. 组内连续行比逐行白卡更容易扫描，也更适合长说明和响应式换行。
3. `surface-subtle` 用来托住整组，输入控件应使用独立的 `surface`，否则控件会融进分组底色。
4. Operational emerald 是稀缺状态色，不要用它做普通导航选中、所有按钮或装饰强调。
5. 标题层级测试和主题 token 检查要一起跑；只看截图容易漏掉语义重复和浅深主题回流。

## 常见陷阱

- 为了“看起来有层次”给每个分组加边框、阴影和大圆角，最终形成 card-in-card。
- 把“工具总览”这种内部实现术语放在用户任务分组旁边，造成一个页面出现两个相同入口。
- 统一把品牌色替换成绿色，导致选中、操作、成功和运行状态无法区分。
- 组底和输入控件都使用 `surface-subtle`，浅色主题下控件边界会消失。
- 只验证一个页面或一个主题，未验证其他设置页和 dark/system 三态。

## 自检问题

1. 每个普通设置页是否只有一个 h2，且每个 h3 都代表一个独立用户任务？
2. 如果移除所有边框和阴影，用户还能通过组间距、组标题和 hairline 理解结构吗？
3. 页面上的 emerald 是否都能对应“启用、连接、健康或成功”这类真实状态？
