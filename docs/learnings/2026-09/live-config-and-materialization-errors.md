# 配置快照与分阶段错误

## 保存成功，不代表运行中对象已经更新

依赖注入时读取 Settings 并把对象交给闭包，得到的是那一刻的快照。设置界面即使显示新值，旧工具仍可能使用旧地址和密钥。对无状态请求端口，在每次调用开始读取最新配置，通常比重启整个 Runtime 更简单；请求开始后保持同一份快照，避免一半用旧地址、一半用新凭据。

测试不能只“改配置后创建一个新实例”。应创建一次端口，依次验证未配置、新增、替换、移除；这样才能发现旧闭包问题。

## 生图有两个外部阶段

生成 API 成功返回图片 URL，不等于图片已下载，更不等于本地会话产物已保存。把所有失败都叫无效响应，会让用户反复更换原本可用的生成服务。

分清请求、下载、解码、保存，就能回答该检查哪一段。错误诊断应保留允许列表内的系统码，而不是打印整个 error/cause：后者可能包含签名 URL、Token 或本地路径。

## 重试可能重复收费

下载图片失败后重新调用整个生成工具，可能再生成一张收费图片。没有独立下载恢复协议时，不能简单把这类错误标为可重试。保留部分成功产物、明确失败阶段，比无限重试可靠。

自检：配置是在启动时还是调用时读取？失败发生在付费操作之前还是之后？诊断是否包含敏感信息？一次 UI 成功是否被误当成长期稳定性证明？
