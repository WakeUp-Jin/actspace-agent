# 为什么没有附件也能让 React 页面卡死

React 比较 effect 依赖时看的是引用。组件里的 `const items = props.items ?? []` 会在缺省值场景下每次创建新数组；如果 effect 又更新组件状态，两个本来无害的操作就可能形成反馈循环。

```tsx
const items = props.items ?? [];
useEffect(() => {
  Promise.all(items.map(load)).then(() => setResult({}));
}, [items]);
```

没有数据不代表没有工作：`Promise.all([])` 仍会完成，`setResult({})` 仍是一个新状态。重新渲染后产生新数组，effect 又执行。异步回调还可能让问题表现为持续 CPU 和内存增长，而不是立即出现同步更新深度错误。

防护应覆盖三个环节：缺省集合使用稳定引用；没有待处理项时提前返回；结果相同时返回原状态对象。异步请求还要在组件卸载或依赖改变后放弃过期结果。

测试必须组合真实触发条件。图片恢复测试只证明有图时能加载；没有桌面桥接的纯文本测试会在 effect 的环境检查处返回。两者都不能覆盖“桥接存在、Session 存在、附件缺省”的反馈循环。

用 React Profiler 统计提交次数，比只断言没有 IPC 请求更有效：空数组循环可以一次 IPC 都不调用。为旧代码设置可控的提交次数上限，使回归测试能明确失败，而不是拖死整个测试进程。
