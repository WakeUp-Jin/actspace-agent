# 隐藏视图与销毁组件是两件事

切换到只读轨迹时，输入框不应占空间，但用户草稿也不该消失。这是布局可见性与状态生命周期的区别。

React 条件渲染把组件从树中移除，会销毁其本地 state 和 effects。再次显示时，草稿、附件或局部模型选择可能重新初始化。若产品要求切回来继续编辑，可以保持组件与 key 不变，用 `display: none` 隐藏整个输入区域；这样它不占布局、不进入键盘导航，又保留本地状态。

这个做法也有代价：隐藏不会停止所有后台工作。输入组件保留是为了保草稿，子任务详情的网络轮询则应在关闭或切换时停止。异步响应返回后还应检查本次 effect 是否已经失效，防止先打开 A、再打开 B，A 的迟到响应覆盖 B。

验证时不要只断言 CSS：先输入草稿、加入附件并选择模型，再切轨迹并切回，检查同一个输入实例仍在且数据保留；运行中的停止操作应放在可见的轨迹工具区域。
