# 相同单位不代表相同指标

Token 都是数量，但累计消耗与上下文占用回答不同的问题。

假设连续十次请求，每次送入约 50K Token。累计输入可接近 500K，但最后一次请求仍可能只占 50K。把累计量除以模型窗口，会把调用次数误当成窗口压力；缓存命中也不意味着对应内容不占上下文。

## 为什么只统一公式还不够

两个估算器即使都使用字符近似，也可能计算不同对象：一个对完整 JSON（含元数据）估算，一个对实际展示的分项求和。结果不能混在同一张面板里。总量、分项和百分比应由同一个请求快照、同一套估算口径派生。

缓存同样属于指标定义的一部分。如果详情只按会话 ID 缓存，它在后续请求完成后仍可能展示第一次打开时的值。可以按请求或版本号失效；轻量详情也可以在每次打开时刷新。

## 如何测试

故意让三个候选值不同：累计 usage 为 549K，整体 JSON 估算为 60K，分项合计为 49K。断言界面各入口都显示选定的 49K 口径，并验证增加累计消耗不会改变当前占用。再关闭详情、更新数据并重新打开，验证新值可见。

不要让所有测试数据碰巧都等于 50K：那样即使接错来源，测试也会通过。

自检：这个数字描述的是哪个请求、哪个估算器、哪个时间点？只要有一个答案不明确，就不应直接复用相同的展示类型。
