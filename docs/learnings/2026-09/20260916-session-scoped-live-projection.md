# 会话切换中的运行状态投影

会话切换不是运行切换。执行循环属于 Runtime 的会话 ID，renderer 的选中会话只是一个视口。如果把流式状态、工具 Map 和停止按钮绑定在一个全局 `active` 引用上，切换时清空引用会让后台任务继续执行，但 UI 丢失其事件；晚返回的历史快照还可能覆盖新会话。

可靠的投影至少需要三层键：`sessionId` 隔离会话，`agentRunId` 隔离回合，`toolCallId` 隔离工具。事件先写入所属会话的内存投影，只有当前选中的会话触发 React 消息渲染。历史读取要有 per-session version，完成回调先让旧读取失效，再合并稳定 ID，避免重复、倒退和旧响应串线。

审批查询和 Bash 任务更新也属于异步事件，不能只保护主消息读取。审批查询返回时要比较版本；Bash 更新按 `sessionId + taskId` 保存，不能用全局 task ID 覆盖另一个会话。

这套模式适用于多标签编辑器、下载管理器和后台任务面板：把“正在运行什么”和“用户正在看什么”建模成不同状态，切换只改变观察者，不改变生产者。
