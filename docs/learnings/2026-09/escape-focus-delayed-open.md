# 关闭浮层后，恢复焦点为什么会重新打开它

恢复焦点也是一次交互事件。若浮层通过 focus 延迟打开，Escape 中调用 trigger.focus() 就会排队新的打开任务；把 open 设成 false 只改变当前状态，无法取消已经排队的任务。

因此要区分“用户新发起的打开”与“关闭过程中产生的焦点事件”。主动关闭后先阻止旧回调，恢复焦点时阻止默认打开，再在下一次明确的点击、指针进入或重新聚焦时允许预览。不应靠增加关闭延迟来竞争两个定时器。

测试也要覆盖时间：先证明浮层确实打开，执行 Escape，检查焦点返回，再等待超过打开延迟检查仍关闭。最后验证新的交互可以打开，避免把功能永久锁住。只有检查焦点的测试会漏掉延迟重新打开。

自检：设置 open=false 是否取消定时器？程序调用 focus 是否触发事件？拒绝旧回调后，用户如何重新打开？
