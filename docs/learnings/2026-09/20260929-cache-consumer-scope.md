# 省略内容的缓存必须考虑谁读过

缓存可能做两种不同的事：复用计算结果，或者省略已经发送过的结果。两者需要的缓存键不同。

如果缓存直接保存文件正文，路径与版本足够定位可复用的值。但如果命中时只返回“文件没变，请复用之前正文”，它还隐含一个条件：当前消费者确实拿到过那份正文。文件状态相同，不代表消费者的历史相同。

Agent 的两个会话和父子会话拥有各自的上下文。进程级工具实例共享缓存时，必须把会话身份纳入这种省略型缓存的键。否则 A 读过之后，B 的首次读取就会失去正文，而工具仍报告成功。

隔离 sessionId 解决了会话间误命中，但不能自动证明同一会话永远保有正文：压缩或裁剪可能移除早先内容。更完整的策略应依据当前上下文可见性决定是否省略，或直接返回正文。这是后续设计问题，不应把本次会话隔离当成完整解决。

回归测试应检查两个独立消费者各自的首次读取，而不是只检查一个消费者连续读两次。同样，构建产物“存在”也不能证明它属于本轮成功构建；用显式构建完成屏障比固定等待时间更可靠。
