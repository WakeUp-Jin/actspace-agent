# 为什么同一个模型 ID 需要不同的本地标识

两个中转站都提供 `vendor/model`，但它们的 Key、地址、协议、限额可能完全不同。如果本地目录只以这个字符串为键，添加第二条连接会覆盖第一条；即使列表显示两个名称，实际请求也可能用错账号。

把上游模型名和本地模型标识分开：上游请求仍发送 `vendor/model`，本地标识包含连接 ID，例如 `provider:connection/relay-a/vendor%2Fmodel`。显示名称可以随意改，连接 ID 与已安装模型的绑定保持稳定。

一次请求依次解析“本地模型 → 绑定连接 → 协议、地址、凭据”。绑定连接不存在时必须明确失败。自动借用默认连接可能把请求发送给另一个账号，隐藏了配置错误。

最容易遗漏的是重启边界：写入器允许新凭据槽位，但读取器仍按旧格式过滤；或者模型清洗函数只保留旧字段，丢掉 connectionId。因此只测试保存返回成功不够，应在临时目录创建连接，重新构造服务，再验证模型与凭据解析。

还应测试两条连接使用相同上游模型名、并发创建、删掉其中一条后另一条继续工作，以及编辑失败后重启仍读取原 Key。传输适配器可以用 mock 验证选择了哪种协议；真实供应商兼容性仍需另行验证。
