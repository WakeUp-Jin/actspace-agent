# 消息流的间距为什么应该由父容器决定

同样是 14px 字号，两行之间仍可能忽大忽小：字号控制字形尺度，line-height 控制行盒高度，父级 gap、子级 margin、inline 元素的基线空间又分别占用高度。只改其中一个数字，常常只是抵消另一个容器的偏移。

## 将两类责任分开

组件负责自己的内容：标题行高、详情与标题的距离。消息容器知道前后是什么，因此负责相邻关系：工具接工具用紧凑间距，工具接正文留出阅读停顿。组件不应猜测自己外面的 gap，再用负 margin 补偿。

这意味着同一个 Read 组件放在主会话或子 Agent transcript 中，不必为每个父容器写不同的偏移。容器只需要根据消息语义选择间距；pending 审批等复杂块可保留常规间距。

## 怎样检查才可靠

1. 先检查 computed style 的字号、字重、行高，而不是只看 class。
2. 用相邻元素 bounding box 的 top/bottom 差值测真实间距；展开态把详情尾部留白纳入解释。
3. 再检查浅深主题和窄列，确认省略号、箭头与状态提示没有挤出容器。
4. jsdom 用来验证文件打开、详情展开、完成后收起等行为；真实浏览器才能证明几何尺寸。

常见陷阱是按钮继承了父层 16px，而旁边普通工具行是 14px；另一个是 inline 按钮在 22px 行盒外还留下父级基线空间。把标题按钮设为 flex 并显式指定行高，能让盒模型更容易预测，但仍应实际测量。

自检：如果要把一个工具组件放进新面板，是否必须加负 margin 才对齐？如果是，检查外部间距是否泄漏进了组件。
