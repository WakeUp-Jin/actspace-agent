# 隐藏视图不等于销毁组件：折叠、切换视图时的局部状态生命周期

合并自：折叠外层不等于重置内部状态、隐藏视图与销毁组件是两件事。

React 中隐藏容器与卸载组件是两件事。选哪种取决于产品想要的状态生命周期：保留（草稿）还是重置（展开状态）。

## 1. 想保留：用 `display: none` 隐藏，组件与 key 不变

切到只读轨迹时输入框不应占空间，但用户草稿不该消失。条件渲染会销毁本地 state 和 effects，再显示时草稿、附件、局部模型选择重新初始化。保持组件与 key，用 `display: none` 隐藏整个输入区域：不占布局、不进键盘导航、保留 state。

代价：隐藏不会停止后台工作。输入组件保留是为保草稿，子任务详情的网络轮询应在关闭/切换时停止；异步响应返回后检查本次 effect 是否失效，防止先开 A 再开 B 时 A 的迟到响应覆盖 B（见 [request id guard](../2026-06/request-id-guard-for-ui-refresh.md)）。验证不要只断言 CSS：输入草稿、加附件、选模型，切轨迹再切回，检查同一输入实例仍在、数据保留；运行中的停止操作放在可见的轨迹工具区域。

## 2. 想重置：不渲染 children，让旧状态卸载

仅用 CSS 隐藏活动组，里面每个工具的 `useState` 仍保存展开状态，再打开父组旧详情全部回来。产品要求“工作完成后所有详情回到收起”：先定状态生命周期——运行中的手动选择保留到工作结束，完成后的查阅是新的展示阶段；Worked 收起时不渲染 children，再打开时由组件默认状态初始化。

边界：
- 默认展开并不都是 `false`：Thinking 可能默认展开，失败 Bash 自动显示输出；完成后初始化仍要显式传入完成状态，避免重新挂载又自动打开。
- 卸载重置全部局部状态，可能同时丢草稿、请求缓存、审批状态；只有确认这些属于外部业务状态或可重读，才能用这种策略，不是所有表单的通用重置。

验证覆盖完整状态转换：运行中展开多个工具 → 单步完成但最终回复仍在输出 → 回复完成 → 打开 Worked → 逐个手动展开 → 普通重渲染。只看最后一帧看不出旧状态泄漏，也看不出手动展开被反复覆盖。
