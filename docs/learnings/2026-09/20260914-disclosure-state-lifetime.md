# 折叠外层，不等于重置内部状态

React 中，隐藏父容器与卸载子组件是两件事。仅使用 CSS 隐藏一个活动组，里面每个工具的 `useState` 仍然保存着展开状态。再次打开父组，旧详情会全部回来。

当产品要求“工作完成后所有详情回到收起状态”，应先确定状态的生命周期：运行中的手动选择保留到工作结束；完成后的查阅是新的展示阶段。Worked 收起时不渲染 children，让旧详情卸载，再打开时由组件默认状态初始化。

这里有两个容易漏掉的边界：

- 默认展开并不都是 `false`。Thinking 可能默认展开，失败 Bash 也可能自动显示输出。因此完成后的初始化仍需明确传入完成状态，避免重新挂载又自动打开。
- 子组件卸载会重置全部局部状态，可能同时丢弃草稿、请求缓存或审批状态。只有确认这些信息属于外部业务状态或可重新读取，才能采用这种策略；不能把它当成所有表单的通用重置手段。

验证必须覆盖完整状态转换：运行中展开多个工具 → 单步完成但最终回复仍在输出 → 回复完成 → 打开 Worked → 逐个手动展开 → 普通重渲染。只验证最后一帧看不出旧状态是否泄漏，也看不出手动展开是否会被反复覆盖。
