# 拒绝工具调用也必须完成协议结算

工具没有执行，不代表它可以从对话协议中消失。模型一旦返回带 call ID 的工具调用，后续请求就必须提供对应结果；否则 provider 会把整段历史判为不完整，下一轮普通文本也可能失败。

正确顺序是：记录调用 → 判断权限 → 写入明确拒绝结果 → 继续。权限拒绝是一种工具结果，不是跳过结果的理由。批次中一个调用不允许时，如果选择整批拒绝，就必须为整批每个 call ID 都写结果，并证明执行次数为零。

历史上已经缺结果怎么办？不要伪造成功，也不要为了续聊删除原日志。可以在请求投影层补充“没有记录结果、执行结果未知”的反馈，保留原始 Journal 用于诊断。这与新调用的明确 denied 有区别：旧历史缺记录不能证明从未执行。

验证至少包含：越界无副作用、每个call都有结果、下一轮可继续、旧历史可恢复、正常结果不重复。只测试“权限检查抛错”会漏掉整个对话被损坏的后果。
