# 学习文档编写指南

触发学习记录后，先读这份文档，再决定要不要写、写在哪、怎么写。主题索引见 [README.md](README.md)。

## 格式与命名

- **Markdown 是唯一格式**。不再写 HTML 教程：HTML 难以 diff、难以合并、读取成本高。需要图示时用 Markdown 里的 `text` 代码块画结构，或用表格对比。
- 目录：`docs/learnings/YYYY-MM/`，月份是文章首次写入的月份，日期信息由目录承担。
- 文件名：`topic-slug.md`，英文 kebab-case，不带日期前缀，名字描述结论或模式（如 `one-axis-one-scroll-owner.md`），不要只写关键词（`scroll.md`）。
- 历史文章里已有的 `YYYYMMDD-topic-slug.md` 保持原名，不批量改名；已有大量外部文档引用这些路径，改名只会制造断链。同一篇文章合并后沿用保留下来的那个文件名。
- 新增、合并、改名、删除任何文章，都要同步更新 [README.md](README.md) 的主题索引。

## 收录门槛

写之前按顺序过四关，任何一关不过就不要新建文章：

1. **先搜同主题**。在 `README.md` 和 `docs/learnings/` 里用关键词搜同一类教训。已有文章讲同一件事时，**扩写那一篇**（补充新场景、新反例、新的验证方法），不新建，也不在两篇里各写一半。
2. **只收反复出现的教训**。命中下列至少两条才值得写，并且必须有证据说明它会再次出现（重复踩坑、跨模块出现同类问题、多次修复同一根因）：
   - 同一类 bug 修复了两次以上，或根因跨多个模块；
   - 设计选择有非显而易见的取舍，下次容易凭直觉选错；
   - 重构暴露出一个通用的职责或边界问题；
   - 某个第三方行为/平台特性与直觉相反，需要记住原理；
   - 一个验证方法曾经被证明会假阳性/假阴性。
3. **读代码读不出来**。能从代码、类型、注释、`AGENTS.md`、设计文档里直接读到的内容不写；只写“为什么这样、哪里会错、怎么自检”。纯 CRUD、重命名、格式调整、依赖升级、一次性业务逻辑，在 history 里顺带一句即可。
4. **一篇一个教训**。一篇文章只讲一个可以一句话说清的结论。两个结论共用一个关键词不等于同一个教训，不要为了控制篇数合并；也不要为了凑全一篇讲多件事。

写完一次学习沉淀后，若发现同时改了多篇相关文章，在 history 的“学习沉淀”里列出被扩写的文章，而不是新增并列文章。

## 文章结构

不强制模板，下面是常用骨架，按需取舍：

```text
# 标题：用结论或模式命名（不是“关于 xxx”）

一段话：问题现象和一句话结论。
关联：对应 history / exec-run 的路径（如 docs/histories/YYYY-MM/xxx.md）。

## 为什么会这样       现象、根因、反例（尽量给最小可复现的错误写法）
## 稳定的做法         正确的建模或顺序，带代码或时间线
## 怎么验证           能让这个问题真的失败的测试或观察方法
## 自检               2–3 个能直接用来 review 的问题
```

写作原则：

- 读者是开发者本人，语言教学化而不是流水账：重点是“为什么”和“怎么想”，不复述代码。
- 保留一个具体反例或时间线，抽象结论没有场景支撑就没有说服力。
- 引用 `packages/…`、`apps/…`、`scripts/…`、`docs/…` 路径、函数名、事件名时，写完后确认它们仍然存在（`grep` 一下）；`pnpm check:current-docs` 会检查反引号里的这四类路径，没有「历史」「已删除」等标注的失效路径直接报错。
- 链接 history 或 exec-run 说明“从哪次变更提炼的”，路径要真实存在。

## 合并与历史符号

- 合并多篇文章时保留每一个独有的结论、例子和代码路径，开头用“合并自：…”注明来源，不留空壳文章。
- 代码被删除或重写后，文中提到的符号不要悄悄删掉教训，而是在首次出现处标注“（历史：该符号/模块已移除，现为 `xxx`）”，教训本身仍然有效时保留。
- 仍然成立的结论优先写成“现行规则”；一次性的决策经过留在 history，不进 learnings。
- 文章不再成立（被新的设计推翻）时，直接改写结论并说明新旧差异，而不是并存两份相反的说法。

## 自检清单

提交学习文档前：

1. README 的同主题分组里已经有这个教训吗？能扩写就不要新建。
2. 它会再次发生吗？有第二个证据点吗？
3. 删掉这篇文章，读代码和现有文档能得到同样的信息吗？
4. 标题是不是一句结论？一句话能不能说清核心点？
5. 引用的代码路径、符号、history 链接都存在吗？
6. 已更新 `README.md` 索引了吗？
