# 原地更新为什么不等于保留旧版本

插件支持热更新，只能说明系统能变成新状态；它不保证旧任务还能继续使用更新前的状态。

假设 Run A 持有工具实例 X。Loader 把 X 替换成 Y 时，会释放 X，再让依赖者连接 Y。即使 Run A 的变量仍指向 X，X 内部的连接也可能已经关闭。保留 JavaScript 对象引用，不等于保留资源的可用性。

如果 Y 启动失败，Loader 重新创建 X′，只是恢复了旧实现。X′ 不是原来的 X，也没有自动恢复 X 的运行状态。因此“配置回滚成功”和“旧任务未受影响”要分别验证。

要让新旧任务并存，需要让 X 与 Y 暂时同时存在，由明确的使用者决定何时释放 X。Cordis 管实例资源，应用管任务持有关系。服务命名域解决找哪个实例，不会替应用计算任务是否结束。

复用未变化实例也有同样的陷阱。一个工具注册表的代码没变，但新插件会向它注册内容；共享该实例，可能让旧任务看到新工具。判断可复用时，要问“谁会写入这个实例”，而不只是“它的文件有没有变”。

自检：

- 新实现失败后，旧任务持有的对象是否仍可使用，还是只重建了一个同名对象？
- 两个组合共用实例时，谁最终释放它？
- 服务隔离后，事件和注册表的写入是否也被隔离？
