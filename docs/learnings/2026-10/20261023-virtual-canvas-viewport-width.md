# 虚拟滚动画布：内容宽度与可视宽度要分开

一个 Diff 窗口只有 390px 宽，但其中某行代码需要 5000px。为了让所有代码行共用横向滚动条，虚拟列表的内容层会被撑到 5000px。这时，行里的 `width: 100%` 指的是 5000px，并不是窗口宽度。

这个区别会影响普通 UI：图片在 5000px 中居中，就会出现在约 2500px 的位置；文件标题用 `flex: 1` 撑开，右侧按钮也会被推到画布尽头。图片可能已经成功解码，按钮也在 DOM 中，但用户看不到它们。检查数据加载和按钮是否存在都无法证明界面正常。

## 两种宽度，两个职责

代码行使用稳定的内容宽度，保证长行进入、离开虚拟挂载范围时，横向滚动范围不跳变。文件标题、图片、状态提示和操作按钮使用滚动容器的可视宽度。

让这两者共存，可以保留宽的虚拟行作为定位层，在非代码行里面放一个较窄的容器：

```text
scrollport：390px，唯一的横向和纵向滚动容器
└─ content：5000px，提供稳定的横向范围
   └─ absolute row：5000px，负责纵向虚拟定位
      └─ sticky left:0 surface：390px，负责图片与操作
```

`sticky` 的父容器必须保留完整画布宽度，否则横向粘附很快就会到达父容器边缘。代码行继续使用宽画布，不要给每行加独立横向滚动条。

## 观察到尺寸变化，不一定意味着组件会重绘

纵向虚拟列表通常只在可见索引或滚动状态变化时通知 UI。如果窗口从 390px 变成 840px，但仍然显示相同的行，读取虚拟列表内部的宽度并不保证 React 会重新执行。

尺寸观察需要同时更新实际使用宽度的 UI。可以复用已有 ResizeObserver，仅把测得的可视宽度保存为布局状态；不必新增另一个观察器，也不要把它混进业务数据。测试应覆盖“只改宽度、行数不变”的情况。

## 如何验证

- 同时放长文本、短文本、图片和带操作按钮的行，关闭换行。
- 在横向位置 0 以及向右滚动后，核对图片和操作仍位于可视区内。
- 仅改变窗口宽度，检查它们立即跟随，不靠滚动或切页触发更新。
- 保留长文本的统一横向滚动范围和虚拟 DOM 数量约束。

单元测试可以检查测量输入和宽度约束的响应；没有浏览器布局引擎的测试无法证明实际坐标与可见性。视觉缺陷仍需在真实运行界面检查并保留关键截图。
