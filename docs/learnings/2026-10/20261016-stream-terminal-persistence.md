# 流式正文必须在终态完成持久交接

用户看见的流式正文通常来自临时状态，刷新后的正文来自持久记录。两者如果只在成功完成时交接，停止和报错就会让已经显示的内容消失。

流处理需要保留三个事实：消息身份、已收集内容、结束原因。迭代器抛错时不能新建一个空结果，否则既丢正文也丢消息身份；停止信号后迭代器可能直接结束，没有最后一个 aborted 事件，所以迭代结束后仍需检查信号。

终态写入时，应让消息事件和展示记录引用同一份部分正文。没有执行的工具调用不能因为正文需要保留而进入可执行路径或形成悬空工具上下文。错误原因与部分答案是两种信息，界面应同时保留。

验证不能只断言运行变成 failed 或 aborted。还要比较最后一个 chunk 与终态消息的 ID，检查持久展示记录，并从事件重新播放后确认正文仍在。另用真实界面刷新检查临时层到持久层的交接，避免后端通过而前端丢失。
