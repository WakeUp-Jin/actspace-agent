# 为什么文件写成功，界面却找不到它

同一个目录可以有两个名字：用户选择的别名路径，以及文件系统解析符号链接后的真实路径。它们指向相同位置，却不是相同字符串。

例如工作区是 `/tmp/project`，权限系统批准的文件是 `/private/tmp/project/report.md`。直接用前者对后者计算 `relative` 会得到越出工作区的路径。界面的安全过滤因此正确地拒绝把它当成工作区产物，但用户看到的是文件已写入、产物卡却没出现。

解决方法是在拥有文件系统访问权限的生产端统一坐标：先对工作区做 realpath，再和已经验证的 canonical 文件路径计算相对路径。权限检查继续使用真实资源；展示 metadata 使用相对路径。Renderer 不应自行猜测 `/tmp` 与 `/private/tmp` 的关系，这种硬编码也覆盖不了任意符号链接。

有三个边界需要保留：

- 新文件还不存在时，从最近存在的真实父目录拼接剩余路径。
- 被明确授权的工作区外文件仍返回绝对路径，不能伪装成工作区产物。
- 展示用的规范化不能替代执行前的 admission 复验，尤其不能绕过符号链接目标和资源类型检查。

自检：测试是否真的创建了符号链接？是否同时覆盖新建、修改、删除和外部授权目标？只测试字符串替换，验证不了文件系统的真实身份。
