# iframe坐标是布局在某一时刻的快照

浏览器点击最终使用顶层视口坐标。点击frame内部元素时，需要把元素在frame内的位置与各层frame偏移相加；这个加法本身很简单，真正容易出错的是测量时序。

`scrollIntoView` 不只滚动当前文档，也可能滚动包含它的祖先文档。因此“进入frame时记录偏移 → 滚动叶元素 → 使用旧偏移点击”并不可靠。即使元素大小不变、frame路径正确、RPC返回成功，鼠标仍可能点到47px以外的位置。

正确顺序是：准备frame和执行上下文 → 完成所有必要滚动 → 读取叶元素与各层frame当前位置 → 转成顶层坐标 → 发出点击。最终读偏移必须只读，否则测量某一层时再次滚动，会使刚测过的其他层立即失效。

这类测试应模拟滚动前后偏移不同，验证动作发生在最后一次测量之后，而不是只给固定坐标检查加法。再用独立reload的真实跨源frame页面核对点击副作用，不能仅断言RPC成功。页面持续动画等并发布局变化仍是另一边界，不能由这一回归推断全部解决。
