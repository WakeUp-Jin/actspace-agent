# 用可区分的夹具判断是否读错了数据

看到界面切换后仍显示同一个名字，不一定是状态没有刷新：新对象可能本来就有相同名字。只有输出足以区分数据来源，测试才能证明“没有串读”。

例如，两台 Host 都发布名称为 `workspace` 的工作区，并使用同一个模型。切换后界面仍显示 workspace，既符合正确读取，也符合错误复用旧数据；这张截图无法在两个假设之间作出判断。

更有效的验证分三步：

1. 为两台 Host 设置不同的工作区名称、路径和模型，先核对服务端实际发布的数据。
2. 从第一台切换到第二台，同时检查目标标识、工作区、模型和发送状态。
3. 若要验证远端文件来源，使用内容不同的同名文件。只比较文件名或路径，无法排除误用本地内容。

UI 观察是重要证据，但“看到了什么”和“为什么如此”是两件事。修复前应把截图与目标对象的真实配置对照；假设被证据推翻时，修正验收结论比添加代码更可靠。
