# 当前上下文不能决定历史附件的可访问性

聊天界面可以继续展示模型已经忘记的内容。压缩改变的是下一次模型请求的输入；用户历史、附件归属和保留策略有各自的生命周期。

假设消息 M 引用了图片 A。压缩后当前消息列表只剩摘要 S，历史中仍有 M。如果读取 A 时仅检查当前消息列表，A 会被误拒；如果清理暂存时也这样判断，A 还可能被误删。图片文件和元数据都在，依然会出现冷启动后预览失效。

判断资源是否可读，应组合三个条件：该会话有持久引用、资源属于该会话、实际字节符合元数据。当前投影可作快路径，缺失时再查已验证的持久历史。不能把文本中碰巧出现的 ID 当作引用，也不能因为全局磁盘存在就允许读取。

同一个区分也适用于垃圾回收：从模型输入移除不等于用户删除。清理只能依据资源自己的保留规则，不能借用更短寿命的投影。若将来加入删除或撤销事件，应明确更新持久授权规则，再处理历史引用；不能一直把旧 append 当作永不撤销的授权。

回归应覆盖正反两侧：压缩后仍可读取；无引用、跨会话、媒体不符或字节篡改仍被拒绝；清理保留历史附件并删除确实未提交的暂存。只验证“文件存在”或只验证新上传，都抓不到这个生命周期错位。
