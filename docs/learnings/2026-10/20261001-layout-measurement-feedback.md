# 布局测量不能依赖自己的判定结果

输入框常见规则是：单行时与按钮同排，折行时独占一排。问题在于，两种布局中的按钮宽度也可能不同。如果先读取当前按钮宽度，再推算“单行输入框能有多宽”，测量值就依赖于刚刚选定的布局。

这样会形成反馈：inline 测得折行 → stacked 测得单行 → inline 再次折行。React 的 layout effect 每次都更新状态，最后抛出 Maximum update depth exceeded；没有错误边界时，整个页面可能消失。

解决方法是固定测量条件，并隔离测量副作用。Composer 复制当前输入网格，在不可见、不可交互、脱离布局的副本上应用 inline 网格，读取 textarea 的 scrollHeight；再切回实际网格规则测量目标高度。副本沿用控件内容、字体继承、gap 和响应式断点，不需要 JavaScript 重新推算按钮宽度。真实输入框只在目标高度变化时更新一次。

最初的修复曾在真实输入框上同步切换网格，再用 finally 恢复。它消除了状态反馈循环，却没有消除浏览器内部副作用：输入框暂时变窄、变矮时，scrollTop 也会改变。即使同一帧恢复了尺寸，输入法提交后也未必恢复光标可见区域。因此，“用户看不到临时布局”不等于“临时布局没有副作用”。独立测量节点也必须同步内容和 CSS，并及时移除，不能成为第二套手算布局。

测试时不要只把 scrollHeight 固定为一个数；要模拟“不同布局产生不同测量值”。旧代码应实际失败，新代码应稳定收敛。jsdom 没有布局引擎，所以仍需浏览器跨断点检查。
