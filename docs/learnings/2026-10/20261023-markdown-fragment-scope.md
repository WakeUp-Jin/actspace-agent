# 多条 Markdown 回复如何共享一个页面

一条文档里唯一的脚注 `fn-1`，放进聊天列表就不再唯一。浏览器按整页查找 ID，可能跳到前一条回复。解析器的防 DOM clobbering 前缀只能避免与页面全局变量冲突，固定前缀并不能隔离多份文档。

## 文档身份与目标身份

每条回复需要稳定的文档前缀，引用、定义和回链在同一前缀下生成。前缀属于回复的挂载生命周期，不能按内容哈希生成：流式每次追加都换哈希，会让已有链接身份不断变化。再把目标查找限制在当前回复内，避免文档之间相互导航。

无障碍关联也要一起处理。脚注的 `aria-describedby` 指向说明标题；如果只改正文脚注 ID，说明标题仍重复，读屏关联也可能错位。引用、定义、回链和说明标题应作为一组检查。

## 链接分类与应用导航

桌面应用通常禁止任意窗口打开本地 file URL。如果所有 Markdown 链接都加 `_blank`，页内fragment也会进入外开路径，随后被安全边界拒绝。正确做法是在渲染层区分页内目标、工作区文件和外链，并保留导航限制。

滚动只解决视觉位置；键盘用户还需要焦点进入目标。不可聚焦的定义可临时添加 `tabindex=-1`，失焦后移除；回链本身是可聚焦链接。不要修改顶层hash来模拟聊天内部导航，否则会污染应用URL和历史。

验证时放两条包含同名脚注的回复，点击第二条的引用和回链，并在流式追加后检查目标身份不变；同时确认HTTPS仍正确外开、应用窗口与URL保持稳定。原生界面测试补齐安全策略与真实滚动环境，组件测试只证明自身行为。
