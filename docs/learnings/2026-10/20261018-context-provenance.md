# 为什么上下文展示应保留来源，而不是解析提示词

将规则、技能目录和系统提示词拼成一个字符串后，模型能读取它，但界面很难可靠地区分它们。正文里也可能出现同名 XML 标签或 Markdown 标题；这些文字不能证明内容来自哪个插件。

应在拼接前保留一个小的结构化记录：`id` 标识具体贡献项，`owner` 标识提供者，`content` 保存该版本正文，`provenance` 记录文件路径等来源。请求快照同时保存最终输入。展示按元数据分类，审计用实际输入核对，两者职责不同。

这个设计有三个容易忽略的边界：

1. **展示标签不是消息角色。** 将 AGENTS.md 显示为“规则上下文”，并不意味着它从 system 变成 user。角色必须另行标明。
2. **历史精简也必须保留身份。** 若只保存全文、丢弃来源，重载后仍会失去分类。首份和变化份保留，未变化引用前份，可以兼顾大小与可解释性。
3. **无法对应时要承认未知。** 适配器若改写最终输入，原来源已不一定对应实际正文。应显示全文回退，不能用漂亮的分类制造错误证据。

XML 可以帮助人或模型阅读文本，但不能代替可靠的来源契约。自检时可以问：删除所有标签后，我是否仍能知道提供者？重载旧记录后，分类是否仍与请求实际内容一致？
