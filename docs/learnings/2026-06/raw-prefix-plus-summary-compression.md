# Raw Prefix Plus Summary Compression

长工具输出压缩时，不要只在主上下文里留下模型摘要。更稳健的做法是：

```text
[压缩标记]
[原始输出前 N 字符]
...
[模型摘要]
...
```

这是一种把**高保真锚点**和**语义压缩**组合起来的上下文工程模式。

## 为什么需要

模型摘要擅长提炼，但不保证逐字保留细节。工具输出开头经常包含路径、命令、文件头、表头、错误上下文、版本信息或输出格式说明；这些内容一旦被摘要改写或漏掉，后续推理会变脆。

原始前缀提供一段不可稀释的事实锚点，摘要则负责覆盖更长范围里的关键结论。两者组合，比单独摘要更适合 Agent 工具回填。

## 适用场景

- 工具输出很长，不能完整放进上下文。
- 输出前段含有结构信息或定位信息。
- 完整原文可以通过重跑、分页读取或 rawOutputRef 找回。
- 摘要模型可能省略路径、行号、数字、错误码等细节。

## 常见陷阱

- 不要在 fallback 截断路径里重复拼原始前缀。没有摘要模型时，确定性头尾截断本身已经保留头尾，再额外拼前缀会让兜底输出膨胀。
- 压缩标记要明确说明内容不是完整原文，并给出恢复路径。
- 原始前缀长度应是固定预算，不要随输出无限增长。

## 本仓库落点

这次变更把非 bash 工具的 flash 摘要成功路径改为“压缩标记 + 原始输出前 2000 字符 + flash 摘要”。bash 仍走既有的逐字头部 + 文件路径策略。
