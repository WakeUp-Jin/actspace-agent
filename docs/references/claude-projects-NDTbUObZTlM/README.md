## 中文功能摘要

视频把新版 Project 描述为围绕目标组织 Agent 工作的容器：每个项目有一个主会话，主 Agent 委派多个 Thread；工具调用和产物制作在 Thread 内完成。项目容纳记忆、Artifacts 和 Routines。[S1]

创建时填写名称与目标，可稍后补 Context；创建后项目固定到左侧，可修改名称和图标。演示请求主 Agent 同时开展两项调查，两个 Thread 独立工作并产生产物。线程可显示工作中、等待用户和受阻等状态。[S1]

Library 汇集产物与文件；产物支持直接编辑或对局部留评论。Usage 可查看项目总量、主会话与各线程占比、模型，并跳转到具体线程。Design 以项目产物的方式打开设计画板。[S1]

手机端可进入同一项目、打开 Thread 和产物，用评论或语音提出修改。作者还说明，新 Thread 获得创建时的项目记忆；主会话负责委派，而 Thread 不能继续创建 Thread。这并不能证明已有 Thread 会持续同步后续记忆。[S1]

另一份章节摘要补充了需要截帧核对的细节：Library 中的邀请/链接分享、将网页形式的产物转换为可编辑幻灯片、设计画板中的颜色与字体修改，以及手机端的项目信息和用量入口。邀请/链接分享、幻灯片、局部评论、手机设置及用量已取得画面证据；设计属性的完整修改过程仍未覆盖，详见截图报告。[S2、截图索引]

## 已从真实视频画面确认的布局

依据 [截图图文索引](gallery.md)，桌面主要采用三栏：左侧是全局导航和固定项目，中间是项目主会话，右侧是可切换的 Threads / Library 等项目面板。

- 项目标题位于主会话顶部；旁边可见 Overview、设置和更多菜单。
- 线程总览按 Waiting on you、Working、Idle、Resolved 分组；Blocked 作为等待用户的线程条目说明出现，不是独立分组。
- 主会话中嵌入可打开的线程条目及产物关联；打开 Thread 后右栏显示线程会话，底部有独立输入框。
- 产物编辑使用更大的覆盖视图：左侧展示文档、网页、画板或幻灯片，右侧保留对应线程会话。
- Library 支持文件夹、列表和网格切换入口；截图记录了列表展示。
- Usage 有输入区附近的浮层和 Settings 内的详细页；详细页含缓存读写分类、模型维度和线程维度。
- 手机端用页面导航与底部输入替代桌面并排布局；产物评论会弹出输入浮层和系统键盘，Usage 使用底部 Sheet。

仍不能据此确定精确栏宽、可拖动范围、全部主题表现、完整重命名流程与记忆同步机制；这些需要独立产品或实现验证。

## 后续设计时需要独立决定的问题

以下是针对 actspace 的设计问题，不是视频已经给出的实现方案：

1. Project 与现有 Workspace、Session 是怎样的关系？项目是否可以跨目录？
2. 主会话是否严格限制工具使用？现有 Subagent 如何映射为可持久浏览的 Thread？
3. Project 记忆更新后，已有 Thread 是收到快照、显式同步，还是始终读取共享信息？
4. 产物归属如何同时保留创建 Thread 与 Project 的索引，避免资源库复制多份文件？
5. “等待用户”“受阻”“失败”是否需要不同的处理入口？
6. 用量是否包含缓存 Token，统计周期如何定义，如何避免多级汇总重复计数？

截图已可用于布局讨论；最终功能实现方案仍需按仓库规则先描述并获得批准。本轮没有修改产品代码。
