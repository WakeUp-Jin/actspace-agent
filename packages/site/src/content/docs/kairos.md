常规 Agent 等待用户指令，Kairos 则按计划醒来、观察数据源并在明确边界内采取行动。它拥有独立 prompt、短期记忆、tick 调度和监控界面。

## 一次 tick

Kairos 被唤醒后会执行一套稳定例程：

1. 读取当前时间、任务表和允许的数据源。
2. 检查自上次成功 tick 之后的变化。
3. 根据场景规则决定是否行动。
4. 把过程写入轨迹，将长期有用的信息沉淀为笔记或 brief。
5. 必要时调用通知工具提醒用户。

失败 tick 不应推进观测游标，避免下一次运行错过尚未处理的增量。

## 独立人格与规则

Kairos 的 system prompt 留有人格插槽。用户可以选择预设，也可以编辑 `soul.md`、规则和任务表。人格影响表达与关注方式，但不能覆盖工具权限和数据访问守卫。

## 工具边界

Kairos 使用自己的工具白名单。监听目录和 briefs 等数据源可以只读开放，写入能力按专属守卫判断。

它不会因为“是自动任务”就获得更宽权限。高风险操作仍应经过与主 Agent 一致的安全边界。

## 模型生命周期

即使还没有选择可用模型，Kairos 配置通道仍然可编辑。选择可用模型后，当前进程会创建 Controller 与 Runtime，不要求重启应用。

## 通知

Kairos 可以通过专属通知工具写入通知中心。每次 tick 有数量上限，通知持久化在本地并保留滚动容量，避免主动 Agent 把界面变成噪声源。

Kairos 也能结合文件监听插件和 [Skills](../skills/) 构建更具体的主动工作流。
