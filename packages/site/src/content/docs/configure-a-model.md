ActSpace 将“服务商连接”和“模型用途”分开管理。一个服务商负责 API Key、Base URL、代理与目录；一个模型则可以被选择为主会话、轻量任务、Explore 或 Kairos 的运行模型。

## 添加服务商密钥

打开设置中的服务商区域，选择 DeepSeek、Kimi 或 OpenRouter，填写对应密钥。密钥应保存在主进程的安全存储边界内，不进入 renderer 或 session 事件。

OpenRouter 的模型调用 Key 与账户管理 Key 是两个不同用途。只有需要查询账户余额时才配置 Management Key。

## 安装和启用模型

服务商连接建立后，可以从目录中安装模型。Composer 只展示当前已经启用并可用于主会话的候选模型。

模型记录还包含上下文窗口、输入模态、推理能力和价格等元数据。目录刷新会同步更新已安装模型的能力快照。

## 为不同任务选择模型

ActSpace 不要求所有任务使用同一个模型：

| 用途 | 说明 |
| --- | --- |
| 主会话 | 处理当前用户任务和工具循环 |
| 轻量任务 | 标题生成、压缩或其他低成本辅助工作 |
| Explore | 隔离的小范围代码探索 |
| Kairos | 主动模式的定时观察与行动 |

这种分工让响应质量、延迟和成本可以独立取舍。

## 代理是服务商级配置

代理属于服务商连接，而不是全局开关。启用代理时，只有该服务商的网络请求使用对应 transport，其他服务商保持原有连接方式。

## 无法选择模型时

按下面顺序检查：

1. 服务商是否已经启用。
2. API Key 是否存在，最近一次显式测试是否失败。
3. 模型是否已经安装并启用。
4. 当前用途是否允许选择这个模型。
5. 目录刷新后是否重新拉取了 Composer 候选。

配置完成后，可以阅读[一次 Agent Turn](../agent-turn/)理解模型请求如何进入执行循环。
