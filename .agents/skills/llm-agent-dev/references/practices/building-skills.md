# 构建 Skills 的经验教训

Skill 不只是"Markdown 文件"——它是文件夹，可以包含脚本、资源、数据，Agent 能发现、探索并操作这些内容。Skill 最有魅力的两个能力：渐进式披露和执行脚本。

## Skill 的九大类型

基于 Anthropic 团队在 ClaudeCode 中数百个活跃 Skill 的实践分类：

**开发相关（6类）：**
1. **库与API参考**：说明如何正确使用库/SDK，包含代码片段和易错陷阱
2. **产品验证**：描述如何测试和验证代码（常配合 Playwright 等工具）
3. **数据获取与分析**：指导如何访问数据库或监控平台 API
4. **业务流程自动化**：将重复工作流自动化为一键命令
5. **代码脚手架与模板**：生成特定功能的模板代码
6. **代码质量与审查**：在开发流程中强制执行代码检查

**运维相关（3类）：**
7. **CI/CD与部署**：获取、推送和部署代码
8. **事故处置手册**：接收警报 → 调查流程 → 生成分析报告
9. **基础设施运维**：日常维护和操作流程

## Skill 设计的核心经验

### 库与API参考类 Skill 的结构

包含两个核心部分：
- **参考代码片段文件夹**：真实的使用示例（不是文档，是可工作的代码）
- **问题清单（Gotchas）**：使用该库时的常见陷阱和注意事项

问题清单的价值远大于正常使用文档——正常用法 LLM 大概率已经知道，陷阱和边界情况才是 Skill 真正的增量价值。

### 产品验证类 Skill 的设计

核心是"如何证明代码正确运行"。通常包含：
- 验证步骤的脚本（可执行）
- 预期结果的描述
- 失败时的诊断指引

### 业务流程自动化 Skill

设计关键：保留执行日志。Agent 根据日志进行统计和整理，形成可审计的执行记录。

## 从实践中提炼的 Skill 设计原则

### 不要陈述显而易见的内容

专注于哪些能推动模型跳出常规思维的信息。LLM 已经知道的基础知识不需要写进 Skill。

### 建立"注意事项"部分

基于 Agent 使用该 Skill 时遇到的常见失败点来编写。这是一个不断迭代更新的内容。

### 利用文件系统与渐进式加载

Skill 的核心设计之一——按需动态加载，不要一次性注入所有内容。SKILL.md 是目录，具体内容按需读取。

### 避免过度约束模型

提供约束时条件适当放松，让模型根据具体场景灵活调整。解释"为什么"比规定"必须怎样"更有效。

### 存储代码脚本文件

将可执行脚本放入 Skill 文件夹。Agent 可以直接运行这些脚本，简化复杂流程。这是 Skill 超越纯文档的核心能力。

## Skill 描述字段的编写

描述字段不是 Skill 的总结，而是触发条件的说明。要稍微"pushy"——确保在需要时被触发，宁可 over-trigger 也不要 under-trigger。

错误示例："一个关于部署流程的 Skill"
正确示例："当用户需要部署代码、发布新版本、配置 CI/CD、或处理部署失败时使用此 Skill"

## 注意事项

- Skill 的价值在于"增量知识"——模型不知道的、容易出错的、项目特有的信息
- 可执行脚本是 Skill 的杀手锏——将多步骤流程封装为单个脚本调用
- Skill 的 description 触发准确性比内容质量更重要——再好的 Skill 不被触发就没有价值
- Skill 是动态的，需要随使用反馈不断迭代优化
