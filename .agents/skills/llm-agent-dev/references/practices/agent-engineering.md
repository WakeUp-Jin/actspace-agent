# 编程 Agent 工程实践：来自 OpenAI 与 Anthropic 的实战经验

本文提炼了 OpenAI 和 Anthropic 团队在构建长期运行编码 Agent 过程中的核心工程经验。

## OpenAI 的实践经验

OpenAI 团队的实验目标：让 Codex 在几周内交付百万行代码的项目，且被数百名内部用户使用。团队的工作不再是编写代码，而是**设计环境、明确意图并构建反馈循环**。

### 关键设计

**三层代码审查**：Agent 完成任务后经过自身审查、本地审查 Agent、云端审查 Agent。所有审查通过才进入下一步，否则审查结果回注给 Agent 修改。

**文档库的渐进式加载**：使用 AGENTS.md 作为文档目录，存放文档路径和简要介绍。是否读取、读取什么完全由 Agent 自主决定。这样上下文利用效率极高。

**代码库结构性规则**：定义依赖顺序规则（类型→配置→存储库→服务→运行时→UI），通过自定义代码检查器强制执行。检查器发现的错误信息自动传递给 Agent。

**决策信息的文档化**：团队讨论确定的设计决策必须落入文档库，否则 Agent 获取的信息不完整，长期运行中会偏离正确方向。

### 核心启示

- 提供执行反馈功能，形成反馈回路
- 从通用规律中找特殊约束，针对具体场景设计控制规则
- 最佳实践是"文档渐进式加载"——让 Agent 自主决定需要什么信息

## Anthropic 的实践经验

### 两种常见故障模式

1. 上下文窗口填满后模型失去连贯性（"上下文焦虑"）
2. Agent 自我评估时倾向给予高度赞扬，导致评估模块失效

### 解决方案

**上下文重置**：完全清除上下文并启动新 Agent，配合结构化交接机制传递前一个 Agent 的状态和后续步骤。不是压缩，是重置。

**评估与执行分离**：不要在同一个 Agent 中既执行任务又评估结果。独立的评估 Agent 有效降低"评估宽容"问题。

### 三层 Agent 架构（规划-执行-评估）

- **规划器**：接收简短提示，扩展为完整产品规格说明
- **生成器**：循环执行，每次从需求清单中选取一个子任务
- **评估器**：使用 Playwright MCP 模拟用户操作，基于评分标准打分

### 值得借鉴的实践

**Agent 间通信使用文件**：一个 Agent 写入文件，另一个读取。简单、可审计、无需复杂的进程间通信。

**将主观判断变为客观标准**：不问"这个设计美观吗？"，而问"是否符合我们的设计原则？"。评估标准分为：设计质量（整体感）、原创性（非模板化）、工艺（技术执行）、功能性（可用性）。

**Harness 是动态的**：随模型能力升级，某些模块会成为阻碍需要删除。Opus 4.6 的能力使得任务拆分和开发契约变得不再必要。优化 Agent 不只是换模型，而是调整整个运行空间。

## 从实践中提炼的原则

1. 构建审查模块——Agent 输出经过独立审查 Agent 验证，审查不通过则回注修改
2. Agent 间消息传递使用文件——简单有效，可审计可回溯
3. 审查需要"规范"——将主观判断转为客观评分标准
4. 简单有效原则——Harness 随模型升级动态调整
5. 多智能体核心架构：**规划 → 执行 → 评估**
