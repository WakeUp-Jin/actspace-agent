# Bash 工具与安全权限

Bash 工具是 Agent 最强大也最危险的能力——它可以执行任意系统命令。安全设计的核心不是"禁止使用"，而是"分层防护"。

## 多层安全检查

权限验证函数（check_permissions）在工具执行前进行多层拦截：

**第一层：基础参数检查**
command 不能为空。看似简单但防止了空调用的无意义循环。

**第二层：控制字符拒绝**
检测命令中的控制字符（\x00-\x08 等）。这些字符可能导致 shell 解析和代码分析工具的分词不一致，是注入攻击的常见载体。

**第三层：Unicode 空白拒绝**
检测看起来像空格但实际不是的 Unicode 字符（\u00a0、\u2000-\u200b 等）。它们在终端显示为空格，但 bash 可能将其当作命令分隔符。

**第四层：危险删除路径拦截**
当检测到 rm/rmdir 命令时，检查目标路径是否为系统关键路径（根目录、用户主目录、驱动器根目录及其直接子目录）。通配符删除（`*` 或 `/*`）一律拦截。

**第五层：eval-like builtin 拦截**
拦截 eval、source、exec 等会把参数当"代码"再执行的 shell 内建命令。但对安全使用方式留有例外（如 `command -v` 只查询不执行）。

**第六层：超时参数清洗**
对用户传入的 timeout 做范围约束（最小 1 秒，最大 10 分钟），防止无限等待或极短超时。

## 只读命令识别

维护一个只读命令白名单（ls、cat、grep、git status 等）。只读命令在审批流程中可以自动通过，无需用户确认。

对于 git 命令，需要进一步判断子命令：`git status` 是只读的，`git push` 不是。

## description 设计

Bash 工具的 description 需要明确引导 LLM 的使用方式：
- 说明工作目录持久化但 shell 状态不持久化
- 明确列出"应使用专用工具"的场景（find→Glob、grep→Grep、cat→Read）
- 给出具体的使用规范（引用含空格路径、用绝对路径、用 && 链接依赖命令）

这种负面指引对 LLM 的行为约束非常有效——如果不写，LLM 倾向于把所有操作都通过 Bash 执行。

## 执行器设计

executor 需要处理：
- 进程创建和超时管理
- stdout/stderr 的捕获和合并
- 退出码的正确传递
- 工作目录的状态保持（跨调用持久化 cwd）

参考代码: `examples/bash-tool.ts`

## 注意事项

- 安全检查在 check_permissions 中实现，不要混入 handler——分离关注点
- 对于多段命令（用 && 或 ; 连接），需要逐段检查每个子命令
- 白名单方式（允许已知安全命令）比黑名单（禁止已知危险命令）更安全，但两者可以结合使用
- eval-like 拦截的安全例外必须精确到具体 flag，避免过度放行
