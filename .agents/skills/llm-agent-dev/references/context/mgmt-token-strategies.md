# Token 压缩策略

当上下文压缩被触发后（见 `mgmt-compression.md` 的触发条件），需要选择具体的压缩执行策略。本文覆盖三种移除策略、消息优先级系统、策略选择机制。

## 三种移除策略

### 中间移除策略（MiddleRemovalStrategy）

保留对话的开头和结尾，移除中间的消息。

适用场景：短对话中开头和结尾通常最重要（系统指令 + 最近交互），中间部分包含较少关键信息。

执行流程：
1. 将可移除消息分为三组：开始组（前 N 条）、结束组（后 M 条）、中间组（剩余）
2. 中间组按优先级排序（低优先级在前）
3. 从中间组开始，按优先级从低到高移除，直到达到目标 Token 数
4. 如果中间组移除后仍未达标，才从开始组或结束组移除低优先级消息

### 最旧移除策略（OldestRemovalStrategy）

优先移除最早的消息，保留较新的消息。

适用场景：长对话中最近的消息通常更相关，旧消息的价值递减。

执行流程：
1. 将可移除消息按优先级和时间戳排序（先按优先级低→高，同优先级按时间旧→新）
2. 从排序列表中依次移除，直到达到目标 Token 数
3. 低优先级的旧消息最先被移除，高优先级消息即使很旧也尽量保留

### 混合策略（HybridStrategy）

不直接执行压缩，而是先分析对话特征，自动选择中间移除或最旧移除中更合适的一种。

## 消息优先级系统

所有策略在执行前都会先为每条消息分配优先级，决定哪些消息优先保留、哪些优先移除：

| 优先级 | 分配条件 |
|--------|---------|
| CRITICAL | 系统消息（system role） |
| HIGH | 工具消息、对话开头/结尾位置、长消息（>800 tokens）、包含函数调用的消息 |
| NORMAL | 不满足以上任何条件的普通消息 |
| LOW | 短消息（<20 tokens）且不包含问号 |

已有优先级标记的消息保持不变，不会被重新分配。

## 策略选择机制

混合策略通过三层筛选确定最终使用哪种压缩策略：

### 第一层：基于供应商/模型

| 供应商 | 模型 | 推荐策略 | 原因 |
|--------|------|---------|------|
| OpenAI | GPT-4 | 混合 | 平衡的开始和结束保留，适合通用对话 |
| OpenAI | O1 | 中间移除 | 需要更多上下文的推理模型 |
| Anthropic | 所有 | 最旧移除 | 保留更多结束消息，适合 Anthropic 的对话风格 |
| Google | 1.5 | 中间移除 | 大上下文模型，更保守的压缩 |
| 本地模型 | 所有 | 混合 | 上下文通常较小，需要更激进的压缩 |

如果第一层选出的不是混合策略，则直接使用该策略，不进入后续层级。

### 第二层：基于对话特征

仅当第一层选出混合策略时才进入此层。通过分析对话特征确定使用中间移除还是最旧移除：

**输入数据**：消息总数、平均消息长度、压缩比例（目标 Token / 当前 Token）、最近 5 条消息的 Token 占比、是否包含长消息/系统消息/工具消息。

**压缩严重程度**：目标 > 80% 为轻度，> 60% 为中度，≤ 60% 为重度。

**选择规则**（按优先级）：

1. 轻度压缩且对话较短（<20 条）→ 中间移除（置信度 0.8）
2. 重度压缩且对话较长（>30 条）→ 最旧移除（置信度 0.9）
3. 最近消息 Token 占比 > 40% → 中间移除（置信度 0.7）
4. 包含长消息且非轻度压缩 → 最旧移除（置信度 0.6）
5. 包含工具或系统消息 → 中间移除（置信度 0.7）

### 第三层：置信度自适应

当第二层输出的置信度 < 0.6 时，触发自适应方法：

1. 分别执行中间移除和最旧移除两种策略
2. 计算每种策略的效率分数
3. 选择效率更高的策略结果

**效率计算公式**：

```
效率 = 令牌减少率 × 0.6 + 消息保留率 × 0.4
```

令牌减少占 60% 权重（核心目标），消息保留占 40% 权重（尽量减少信息损失）。

**示例**：15 条消息，9000 Token，目标压缩到 6000 Token。

- 中间移除：压缩后 6200 Token，保留 12 条 → 效率 = 0.311 × 0.6 + 0.8 × 0.4 = 0.507
- 最旧移除：压缩后 5800 Token，保留 10 条 → 效率 = 0.356 × 0.6 + 0.667 × 0.4 = 0.480

中间移除虽然令牌减少更少，但保留了更多消息，综合效率更高，因此被选中。

## 注意事项

- 无论使用哪种策略，消息优先级分配都是前置步骤，确保重要消息不被轻易移除
- 压缩触发使用基于 Token 使用率的动态判断（默认阈值 90%），而非固定轮次
- 压缩检查有频率限制（默认间隔 5 秒），避免频繁触发
- maxToken 根据 LLM 供应商和模型动态计算，不是写死的值
- 每次更新 Token 总数时进行全量重新计算，因为压缩操作和优先级调整会改变计数
