# 《ActSpace 诞生记》视频内容

一部 2 分 54 秒的短片，讲 ActSpace 从第一条开发记录到第 176 天是怎么做出来的。素材只有两样：`docs/histories/` 里的 696 篇开发记录，和 git 提交历史。没有旁白，字都在画面里；配乐一首，从头到尾不剪接。

这份文档是片子的内容底稿：讲什么、为什么这么排、每个节点和数字从哪来、风格和配乐是怎么定的。画面的实现在 `src/origin/`，怎么渲染见 [README](./README.md)。

## 1. 定位

| 问题 | 回答 |
| --- | --- |
| 和产品宣传片的区别 | 宣传片讲「它是什么、能做什么」；这部讲「它是怎么来的」，不介绍功能。 |
| 给谁看 | 关注 ActSpace 的开发者、自己也在用 Agent 写代码的人、可能来贡献的人。 |
| 想让人记住的一句话 | 它不是一次做对的，是一遍一遍改出来的。 |
| 「不容易」怎么讲 | 不喊辛苦，只摆事实：凌晨的时间戳、起不来的应用、后端整个重写、亲手删掉做好的功能、被 bug 逼出来的规范。 |
| 规格 | 174.1 秒，1920×1080，30 帧。数据截到 2026-11-12（提交 `bf566305`，第 176 天）。 |

## 2. 故事线

全片一条线：做出来 → 推倒 → 再做出来 → 删掉 → 较真 → 回头看。每一章都有一个转折，没有转折的节点不进片子。

| 章 | 讲哪一段 | 转折 |
| --- | --- | --- |
| 开场 | 两个数 | 写下 86 万行，删掉 41 万行：差不多每写两行，就删掉一行 |
| 01 第一夜 | 第 1 天下午到第 2 天凌晨 | 第一次提交没有一行产品代码；凌晨应用起不来；窗口终于弹出来，是空白的 |
| 02 第一句话 | 第 3 天深夜 | 空白的窗口里，第一次流出模型的回复 |

| 片尾 | | 它不是一次做对的，是一遍一遍改出来的。 |

为了让人愿意看完，做了这几个取舍：

- **开头 12 秒不放片名。** 先给两个数和一句话，最后一行才说这是什么。这一段配乐只有和弦；片名在鼓进来的那一拍出现。
- **一条时间轴贯穿全片。** 画面底部始终是 5 月到 11 月的时间轴和「第 N 天」，观众随时知道讲到哪了。第 03 – 05 章在时间轴上方叠一条代码量曲线，重写那一下的断崖是全片最重的一个画面。
- **一个画面只说一件事。** 每小节（2.9 秒）最多进来一句话；字少、字大，不需要暂停就能读完。
- **数字都能核对。** 片中出现的每个数都由 `scripts/origin-stats.mjs` 对着截止提交数出来，口径见第 7 节。
- **引用的话不改写。** 第 01、06、07 章里带引号的话都摘自仓库里的记录或设计文档，省略的地方用省略号标出，画面上注明「摘自开发记录」。
- **控制在 3 分钟内。** 展开讲的三章（01、03、04）各 23 秒；后面五章一共 70 秒，每章 12 到 18 秒。

## 5. 风格

- **和宣传片、官网是一家。** 同一套纸色底、墨色字、紫色点题，标题用思源宋体，正文思源黑体，数字和时间戳用 JetBrains Mono。片名和片尾用官网的色块舞台。
- **明暗交替就是节奏。** 白天顺利的段落用浅色底；深夜、重写、出问题的三章（01、04、07）用深色底。明暗一共换六次，都落在小节线上、配乐换和弦的那一下。
- **不放录屏和截图。** 界面只用一个抽象的窗口框示意；模型的第一句回复用灰条代替，因为记录里没有留下原文。
- **动效只有三个重音。** 开场的方格被掏空、重写时曲线断崖、做减法时功能被划掉。其余都是同一种上移淡入和数字滚动。
- **字号。** 正文不小于 22px（按 1080p），时间戳、坐标刻度、出处和口径这类小字 20px，没有更小的。一行说完，不换行解释。

## 6. 配乐

**曲目**：Blue Skies，HoliznaCC0，专辑《Lazy Summer Lofi》，2022。Lo-fi 器乐，82 拍/分，2 分 56 秒。和产品宣传片的配乐（《The Good Times》）是同一位作者。

**授权**：[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)（公有领域），可商用，不需要署名。来源：<https://freemusicarchive.org/music/holiznacc0/lazy-summer-lofi-1/blue-skiesmp3/>，页面上标着纯器乐、不是 AI 生成。音频不入库，渲染时下载到 `.cache/music/`。片尾写了一行曲名和作者，是礼貌，不是义务。

**为什么换成它**：第一版用的是一首钢琴加弦乐的电影配乐（Scott Buckley《Chasing Daylight》），看过的反馈是「配乐感觉不太好」。这一版换了路子：

- **和宣传片用同一类声音。** Lo-fi 器乐，同一位作者，两部片子放在一起是一家。片子讲的是一个人带着一群 Agent 写代码，将近一半的提交在夜里；这类音乐常被人拿来当写代码时的背景音。
- **选多人听过的。** 在这位作者时长合适（2 分半到 4 分钟出头）的 160 首 CC0 器乐里，先按结构筛，再看 Free Music Archive 上的数字。这一首约 2.6 万次播放、2500 次下载（2026-11）。
- **结构和故事对得上，一个音都不用剪。** 成片的第 0 秒就是曲子的第 0 秒，一直用到最后一个音。

| 44 – 55：那层高音回来（和 16 – 27 一样） | 较真的后半、谁在写、回头看 |
| 56 – 58：尾奏，鼓停，几个音收住 | 片尾 |

每个分镜的长度都写成「几小节」，都从双数小节开始（这首曲子两小节换一次和弦），所以每次换镜头都落在换和弦的那一下。片名对着鼓进来、「越长越多」对着那层高音进来、曲线断崖对着鼓停下、「再长一遍」对着鼓回来、「较真」的第三句话对着高音回来、片尾对着尾奏，这几处有单测守着（`scripts/test/origin.test.mjs`）。混音只加一个固定增益调到 −16 LUFS，不做动态压缩；开头不淡入（第一个音就在第 0 秒），结尾淡出。

**需要你亲自确认的一点**：做片子的 Agent 听不到声音。上面的分段是按波形和频谱量出来的（哪一小节有鼓、有低音、哪个频段多了东西），「多了一层高音」具体是什么乐器说不出来；好不好听、情绪对不对，仍然要听一遍成片再定。如果还是不对，下面三首是同一位作者、同样 CC0 的备选，点开就能试听：

| 备选 | 拍速 / 时长 | 和现在这首的差别 |
| --- | --- | --- |
| [First Snow](https://freemusicarchive.org/music/holiznacc0/winter-lofi/first-snowmp3/)（《Winter Lofi》） | 82 拍/分，2:54 | 拍速一样，鼓的进出也在同样的小节上；尾奏短一小节，片尾要收短一点 |
| [Come Again](https://freemusicarchive.org/music/holiznacc0/busted-guitar-lofi-edit/come-again/)（《Busted Guitar (LOFI EDIT)》） | 80 拍/分，3:03 | 段落一样，慢一点，成片会变成 2 分 58 秒；前奏的头两小节比较轻 |
| [Laundry On The Wire](https://freemusicarchive.org/music/holiznacc0/lazy-summer-lofi-1/laundry-on-the-wiremp3/)（《Lazy Summer Lofi》） | 80 拍/分，3:00 | 段落一样，四首里下载量最高；但前奏比正文轻得多，冷开场那 12 秒会很安静 |

这三首和《Blue Skies》是同一个骨架：4 小节前奏、24 小节、停 4 小节、24 小节、尾奏；鼓都在第 4 小节进来，第 28 小节停下，第 32 小节回来。所以换它们只要改 `src/origin/soundtrack.js` 里的拍速、地址、曲名和尾奏到第几小节为止，再把 `src/origin/cues.js` 里片尾那一镜改成相应的长度；其余分镜不用动。

换别的曲子：先不改代码试听，`render --film origin --music <文件> --music-start <秒>`；定下来后改 `src/origin/soundtrack.js`（拍速、地址、曲名、分段）和 `src/origin/cues.js`（每镜几小节），再跑一遍测试。只用授权清楚、允许商用的成品曲子，不用生成的音乐。

## 8. 说法的边界

片子里刻意没说、或者只说到某个程度的地方。改文案时不要越过这些线。

- **只有上下文管理引擎标「已上线」**，Harness 自进化、Actor 与 Space 标「进行中」，和 README、官网首页、`docs/roadmap.md` 一致。Kairos、Lab、fs-watch 只作为「做过又删掉的东西」出现。
- **「后端重写」不等于全部重写。** 08-22 的决定是自研新的 Agent Core、整体替换 Session 和 Runtime；具体的工具实现作为迁移资产保留，前端那一轮没有动。片中只说「后端，重写」和那一次提交的文件数、行数。
- **引号里的话摘自开发记录的 User Query 一栏**，那一栏有的是原话，有的是 Agent 转述，所以画面写「摘自开发记录」，不写「原话」。
- **没有说「06-14 开源」。** 那一天只是把许可证从 MIT 换成 Apache-2.0。
- **没有说这是业余项目，也没有猜开发者的作息原因。** 只摆了提交时刻的分布。
- **没有编模型的第一句回复。** 记录里只写了返回一段固定的探测文本。
- **「开发者只有一个」指的是人。** 截止日之前的非合并提交来自仓库所有者本人（401 次）、云端 Agent（138 次）、依赖机器人（1 次）和第 173 天合入的一位外部贡献者（2 次）。

## 10. 以后怎么改

- **更新到新的日期**：改 `src/origin/data.js` 里的 `cutoff`，跑 `node scripts/origin-stats.mjs`，把输出抄回 `data.js`；再对一遍第 3、7 节和「回头看」那一镜。曲线和时间轴会自己跟着数据变。
- **改某一镜的文案**：只动 `src/origin/scenes/` 里对应的文件。引号里的话要回到出处核对。
- **改长短**：只改 `src/origin/cues.js` 里的小节数，并保证换章节仍然落在曲子换段落的地方（测试会拦）。
