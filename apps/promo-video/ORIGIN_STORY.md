# 《ActSpace 诞生记》视频内容

一部 2 分 32 秒的短片，讲 ActSpace 从第一条开发记录到第 176 天是怎么做出来的。素材只有两样：`docs/histories/` 里的 696 篇开发记录，和 git 提交历史。没有旁白，字都在画面里；配乐是一首木吉他曲，从头到尾不剪接。

这份文档是片子的内容底稿：讲什么、为什么这么排、每个节点和数字从哪来、风格和配乐是怎么定的。画面的实现在 `src/origin/`，怎么渲染见 [README](./README.md)。

## 1. 定位

| 问题 | 回答 |
| --- | --- |
| 和产品宣传片的区别 | 宣传片讲「它是什么、能做什么」；这部讲「它是怎么来的」，不介绍功能。 |
| 给谁看 | 关注 ActSpace 的开发者、自己也在用 Agent 写代码的人、可能来贡献的人。 |
| 想让人记住的一句话 | 它不是一次做对的，是一遍一遍改出来的。 |
| 「不容易」怎么讲 | 不喊辛苦，只摆事实：凌晨的时间戳、起不来的应用、后端整个重写、亲手删掉做好的功能、被 bug 逼出来的规范。 |
| 规格 | 151.9 秒，1920×1080，30 帧。数据截到 2026-11-12（提交 `bf566305`，第 176 天）。 |

## 2. 故事线

全片一条线：做出来 → 推倒 → 再做出来 → 删掉 → 较真 → 回头看。每一章都有一个转折，没有转折的节点不进片子。

| 章 | 讲哪一段 | 转折 |
| --- | --- | --- |
| 开场 | 两个数 | 写下 86 万行，删掉 41 万行：差不多每写两行，就删掉一行 |
| 01 第一夜 | 第 1 天下午到第 2 天凌晨 | 第一次提交没有一行产品代码；凌晨应用起不来；窗口终于弹出来，是空白的 |
| 02 第一句话 | 第 3 天深夜 | 空白的窗口里，第一次流出模型的回复 |
| 03 越长越多 | 第 3 – 83 天 | 不到三个月，18 个节点，11 万行代码 |
| 04 推倒重来 | 第 83 – 102 天 | 仓库安静了 10 天 → 决定重写后端 → 一次提交 1,780 个文件，代码量曲线断崖 |
| 05 再长一遍 | 第 102 – 164 天 | 第 116 天，开发记录里第一次出现「用 ActSpace 开发 ActSpace」；38 天后代码比重写前还多 |
| 06 做减法 | 第 165 – 169 天 | 一天之内删掉三个做好的功能 |
| 07 较真 | 第 169 – 171 天 | 内存涨、修过的 bug 又回来、近 3G 的占用，换来一份规范和两条检查 |
| 08 谁在写 | 全程 | 记录是一群 Agent 写的，开发者只有一个，将近一半的提交在夜里；第 173 天来了第一个外部贡献者 |
| 09 回头看 | 第 176 天 | 八个数，然后是「它还在长」 |
| 片尾 | | 它不是一次做对的，是一遍一遍改出来的。 |

为了让人愿意看完，做了这几个取舍：

- **开头 10 秒不放片名。** 先给两个数和一句话，最后一行才说这是什么。这一段是曲子的四小节前奏；片名在第一段起头的那一下出现。
- **一条时间轴贯穿全片。** 画面底部始终是 5 月到 11 月的时间轴和「第 N 天」，观众随时知道讲到哪了。第 03 – 05 章在时间轴上方叠一条代码量曲线，重写那一下的断崖是全片最重的一个画面。
- **一个画面只说一件事。** 字少、字大，不需要暂停就能读完。要紧的句子一句一句进来，对着曲子的小节线（一小节 2.6 秒）；排得密的地方对着半小节线。
- **数字都能核对。** 片中出现的每个数都由 `scripts/origin-stats.mjs` 对着截止提交数出来，口径见第 7 节。
- **引用的话不改写。** 第 01、06、07 章里带引号的话都摘自仓库里的记录或设计文档，省略的地方用省略号标出，画面上注明「摘自开发记录」。
- **控制在两分半上下。** 展开讲的三章（01、03、04）各 20 到 22 秒；后面五章一共 60 秒，每章 10 到 18 秒。

## 5. 风格

- **和宣传片、官网是一家。** 同一套纸色底、墨色字、紫色点题，标题用思源宋体，正文思源黑体，数字和时间戳用 JetBrains Mono。片名和片尾用官网的色块舞台。
- **明暗交替就是节奏。** 白天顺利的段落用浅色底；深夜、重写、出问题的三章（01、04、07）用深色底。明暗一共换六次：「第一夜」的头尾落在小节线上，另外四次都在曲子起新一句的那一下扫弦上。
- **不放录屏和截图。** 界面只用一个抽象的窗口框示意；模型的第一句回复用灰条代替，因为记录里没有留下原文。
- **动效只有三个重音。** 开场的方格被掏空、重写时曲线断崖、做减法时功能被划掉。其余都是同一种上移淡入和数字滚动。
- **字号。** 正文不小于 22px（按 1080p），时间戳、坐标刻度、出处和口径这类小字 20px，没有更小的。一行说完，不换行解释。

## 6. 配乐

**曲目**：Orbit (Instrumental Version)，Josh Woodward，专辑《Addressed to the Stars》，2016。同名歌曲的无人声版，木吉他扫弦：音频标签模型只认出吉他，没有认出鼓、贝斯、合成器和人声。94 拍/分，2 分 32 秒。[作者的曲目页](https://www.joshwoodward.com/song/Orbit)上写的弹法是标准调弦、变调夹夹在第 10 品，所以吉他弹在高音区，最低的空弦音在 147 Hz 上下。

**授权**：[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)，可商用，可改编，**必须署名**。来源：<https://freemusicarchive.org/music/Josh_Woodward/Addressed_to_the_Stars_1995/JoshWoodward-Orbit-NoVox_1885/>，页面上标着不是 AI 生成。作者在自己网站的 [FAQ](https://www.joshwoodward.com/faq) 里写了署名的要求：留着曲名、他的名字和他的网站；片子里放在片尾就行，发到 YouTube 还要写进简介。成片片尾卡最下面一行就是署名；发布时简介里要加的那两行见第 9 节。音频不入库，渲染时下载到 `.cache/music/`。

表里量的是两首曲子的原文件。成片里的音轨（加了增益、过了限幅器、压成 AAC）又量了一遍，和原文件基本一样：尖锐度最高 2.5 acum，粗糙度平均 0.06、最高 0.59。

《Blue Skies》的和声几乎是原样一圈一圈地回来，低频一直垫在下面；《Orbit》从头到尾是木吉他扫弦，没有低频乐器。两点要说在前头：这把吉他弹在高音区，声音偏亮，这一首平时的尖锐度（中位数 1.0 acum）比上一首（0.8）还略高，少的是冒出来的尖峰——如果听下来还是觉得尖，多半是这个原因，下面的备选里巴赫那一首最柔；它是一首有段落的歌，和弦进行会回来，只是不是原样循环。

候选来自 Free Music Archive 的下载榜和各流派的收藏榜：只留授权是 CC0、公有领域或 CC BY，页面标着不是 AI 生成，时长在两分半到五分半之间的曲子，再去掉噪音、金属、说唱这类流派，下载并量了 753 首，每一首都用音频标签模型查了乐器和有没有人声；排在前面的 25 首再量尖锐度和粗糙度。《Orbit》的标签是吉他、木吉他、扫弦，没有查到人声（FMA 页面的「Instrumental」一栏写的是 No，和曲名对不上，所以单独核对了这一项）。它在 FMA 上不算热门（约 8900 次播放、2400 次下载，2026-11）：这一次是按上面的指标选的，不是按人气。

**曲子的结构和片子怎么对**：成片比第一下扫弦早一帧开始，一直放到余音收完，中间一个音都不剪；余音收完，画面再留一小节。

混音：一个固定增益（+7.4 dB）把整体响度调到 −16 LUFS 上下（成片量出来是 −16.2 LUFS，真峰值 −1.3 dBFS），后面接一个限幅器。吉他扫弦的起伏大，扫得最重的几下加了增益会过载，由限幅器压回去：全片不到 2% 的时间被压了 0.5 dB 以上，最多压 3.5 dB 左右，其余时间它不动声音。开头不淡入，结尾跟着余音淡出。

## 8. 说法的边界

片子里刻意没说、或者只说到某个程度的地方。改文案时不要越过这些线。

- **只有上下文管理引擎标「已上线」**，Harness 自进化、Actor 与 Space 标「进行中」，和 README、官网首页、`docs/roadmap.md` 一致。Kairos、Lab、fs-watch 只作为「做过又删掉的东西」出现。
- **「后端重写」不等于全部重写。** 08-22 的决定是自研新的 Agent Core、整体替换 Session 和 Runtime；具体的工具实现作为迁移资产保留，前端那一轮没有动。片中只说「后端，重写」和那一次提交的文件数、行数。
- **引号里的话摘自开发记录的 User Query 一栏**，那一栏有的是原话，有的是 Agent 转述，所以画面写「摘自开发记录」，不写「原话」。
- **没有说「06-14 开源」。** 那一天只是把许可证从 MIT 换成 Apache-2.0。
- **没有说这是业余项目，也没有猜开发者的作息原因。** 只摆了提交时刻的分布。
- **没有编模型的第一句回复。** 记录里只写了返回一段固定的探测文本。
- **「开发者只有一个」指的是人。** 截止日之前的非合并提交来自仓库所有者本人（401 次）、云端 Agent（138 次）、依赖机器人（1 次）和第 173 天合入的一位外部贡献者（2 次）。

## 9. 发布时

- **封面**用冷开场的最后一帧：白底，「＋ 写下 859,599 行」「− 删掉 410,173 行」「差不多每写两行，就删掉一行。」「这是 ActSpace 的头 176 天。」导出办法：`render --film origin --stills 10.1`，图在 `out/stills-origin/`。
- **标题**可以直接用片中的话，例如「每写两行，就删掉一行：ActSpace 的头 176 天」。
- **简介**里放仓库和官网地址，再加配乐署名。配乐是 CC BY 4.0，要署名：片尾卡上已经有一行，按作者的说法，YouTube 以外的平台这样就够了；但片尾卡放不了链接，所以每个平台的简介里都加上这两行。第一行是作者给的写法，曲名、名字和网址不要改：

  ```text
  Music - "Orbit (Instrumental Version)" by Josh Woodward. Free download: https://www.joshwoodward.com/
  Licensed under CC BY 4.0: https://creativecommons.org/licenses/by/4.0/ （用在片中时没有剪接，只调了音量，结尾淡出）
  ```

- **发 YouTube** 这两行是必须的，而且要在上传的时候就写进简介，不要发完再补。作者在[授权页](https://www.joshwoodward.com/license)写明：用了他曲子的视频会被自动检查有没有署名，没有的会被认领，广告收益归他。实在不方便署名，他另卖免署名的授权，20 美元一首。

## 10. 以后怎么改

- **更新到新的日期**：改 `src/origin/data.js` 里的 `cutoff`，跑 `node scripts/origin-stats.mjs`，把输出抄回 `data.js`；再对一遍第 3、7 节和「回头看」那一镜。曲线和时间轴会自己跟着数据变。
- **改某一镜的文案**：只动 `src/origin/scenes/` 里对应的文件。引号里的话要回到出处核对。
- **改长短**：只改 `src/origin/cues.js` 里的小节数，并保证换章节仍然落在曲子换段落的地方（测试会拦）。
